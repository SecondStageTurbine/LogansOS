# OT-61 C2.2 — the per-content-process memory quota (A2): design

**Status:** approved by the PM 2026-10-27 13:25: hierarchical accounts, Atrium buffers charged to the creator, C2.2b as the next lane. **Built** on this branch. §13 answers the PM's six questions, and §14 records where the build differs from §1–§11. Seat S4. Base: `main` `217b4edb`.
**Rung:** ADR-078 C2, amendment A2 (`docs/RESEARCH-2026-07-22-ot61-browser-closure-crosscheck-FINDINGS.md` §Claim 5).

## 1. The gap, measured on `main`

A content process's frames come from the global buddy allocator, and nothing caps the total per process:

| Channel | Path | Per-call cap | Per-process cap |
|---|---|---|---|
| anonymous heap | `SYS_MAP_REGION` → `Pmap::allocate_user_region` | 16 MiB | none |
| anonymous VM | `SYS_VM_MAP` → `Pmap::allocate_user_region_guarded` | 16 MiB | none |
| thread stacks | `thread_create_for_current_placed` → `allocate_user_region_guarded` | 16 MiB | 16 threads |
| page tables | `Pmap::map_user_locked` and both region allocators | — | none |
| ELF image + initial stack | `spawn_user` → `Elf::load_into` / `allocate_user_stack` → `map_user` | module size | — |
| Atrium buffers | `SYS_BUFFER_CREATE` → `SharedPixelBuffer::create` | 64 MiB | **none** (any number of buffers) |

So a memory bomb drives global exhaustion. During that window every other process's allocation fails, and std aborts whichever process asks next, not necessarily the bomb. "An OOM kills only the content process" is not true today.

**Not in this table, and out of C2.2's scope** (§8): kernel-heap objects (handles, IPC queues, kernel thread stacks from the fixed `HEAP_SIZE` heap) and process count. Those are a different resource with a different failure mode, not buddy frames.

## 2. The rule

> **I-18 (proposed): a process's frames never exceed any limit on its account chain.** Every buddy frame a process causes to be allocated is charged to its memory account *before* the allocation and released when the frame is freed. A charge that would exceed any account on the chain fails, and the allocation returns `ENOMEM` to *that* process.

The trip is local: the process that asked gets `ENOMEM`. A std process then reaches `handle_alloc_error` → abort (exit 134). Other processes never see the failure, because the global pool is not exhausted, provided the budget tree's root is set below free RAM (§5).

## 3. Accounts: hierarchical, lock-free

```text
MemAccount { limit: u64 /* frames; u64::MAX = none */, used: AtomicU64, parent: Option<Arc<MemAccount>> }
```

- **charge(n):** walk from the process's account to the root. At each level `used.fetch_update(|u| (u + n <= limit).then(|| u + n))`. On the first refusal, release `n` from the levels already charged, then fail. Atomics only: no lock, so it is safe at IF=0, under `Pmap::inner` or `FRAME_ALLOC`, and from any CPU. CP-37 is N/A.
- **release(n):** `fetch_sub` at every level.
- **Who has which account:**
  - init's account is unlimited.
  - A child spawned without a budget **shares** its spawner's account (the same `Arc`), so today's behaviour is unchanged.
  - A child spawned **with** a budget gets a new account whose parent is the spawner's.
  - So a browser launched with budget *T* bounds *all* its content processes together, and each content process with budget *B* is bounded alone.
- **Budgets only narrow.** A child's account is nested under the spawner's, so no budget can escape its parent's limit. That is why setting one needs no capability (§6).
- **Accuracy.** A rollback after a partial walk can make a concurrent sibling's charge fail spuriously for an instant. That is conservative: never over a limit, never a leak.
- **Pure logic lives in `kernel/src/mm/mem_account_logic.rs`**, host-tested through `tools/mem-account-logic-tests` (the `#[path]` pattern). It covers charge, release, nesting, rollback, `u64::MAX` and overflow. It is the same shape as `cap_graph_logic`.

## 4. Charge points (all in code this lane owns)

| Where | Charge | Release |
|---|---|---|
| `Pmap::new` (PML4) | 1 | `Drop` |
| `map_user_locked`: new intermediate table | 1 each | `Drop` / not freed today by unmap (tables are kept; unchanged) |
| `map_user` (a caller-supplied frame: ELF, initial stack) | 1 | `Drop`; `unmap_user` hands the frame back to its caller, so it releases 1 |
| `allocate_user_region` / `_guarded` | 1 per page | `unmap_user_range` per page; `Drop` |
| `unmap_user_range` | — | 1 per freed frame |
| `map_borrowed_region` | **0** (not this Pmap's frames) | — |
| `SharedPixelBuffer::create` | `pages` to the **creator's** account | when the buffer drops (it holds the `Arc<MemAccount>`) |

- `Pmap` keeps `charged: AtomicU64`. `Drop` releases exactly that count once, after its frees. That avoids re-deriving what the walker freed, since BORROWED_LEAF frames are skipped by the walker and were never charged.
- The charge comes **before** `with_frame_alloc(allocate_frame)`. If the allocator then fails, the charge is released. A quota failure and a global OOM both surface as `ENOMEM`; `SYS_MEM_INFO` (§6) tells them apart in tests.
- Granting a buffer to the compositor does not move its charge: the creator pays until the last reference drops. That is the right owner for a client-created surface, and it bounds a client that creates and grants buffers in a loop.

## 5. "Trips before global exhaustion"

- The quota guarantees containment *relative to the budget tree*.
- The global guarantee needs the root of the content tree to be smaller than what the system can spare. The launcher (init, or the browser bundle's spawner) sets the bundle budget at spawn from `frames_free` minus a reserve.
- C2.2 ships the mechanism and the scenario that proves it. The production budget numbers are policy for C2.3 (`servo-host-smoke`) and the browser bundle, which this design names and does not fix.

## 6. ABI

- **`SYS_SPAWN_BUDGETED` (new, 0x52):** `(name_ptr, name_len, handles_ptr, n_handles, budget_bytes)`. It is `SYS_SPAWN` plus a byte budget, rounded up to frames.
  - `budget_bytes == 0` means `EINVAL`. A budget can't widen; the nesting makes that structural.
  - The spawn's own frames (PML4, ELF, stack) are charged to the new account, so a budget too small to load the module fails the spawn with `ENOMEM`.
  - It is a new number rather than a fifth argument to `SYS_SPAWN`, so existing callers that leave `a4` uninitialised can't trip it.
  - libneo gets `sys_spawn_budgeted`, and `sys_spawn_client_budgeted` alongside K1a's `sys_spawn_client`.
- **`SYS_MEM_INFO` (new, 0x53, read-only):** `(out_ptr)` → a 32-byte v1 record of the caller's own account:

  | Bytes | Field |
  |---|---|
  | 0..4 | version |
  | 4..8 | flags (bit 0 = has its own budget) |
  | 8..16 | used frames |
  | 16..24 | limit frames (`u64::MAX` = none) |
  | 24..32 | global free frames |

  It ships with a **hand-laid byte oracle** (the format/ABI rule), kernel encoder vs libneo decoder, in the same tests crate.
- **A4:** both syscalls join `tools/ot61-pal-manifest.toml` only if the std overlay calls them. In C2.2 it doesn't, so std keeps aborting on `ENOMEM` as today.

## 7. Kill-switch and invariant budget

- **Feature `mem-quota`**, off by default.
  - **Off:** no account field, no charge calls (the charge sites compile to nothing), no new syscalls. `.text`/`.rodata` are identical to the previous layer for default, desktop and usb-host, checked with the section-hash comparison K1a used.
  - **On, with no budget ever set:** every account is init's unlimited one, so behaviour is identical and only counters move. A scenario proves `used` returns to its baseline after every child exits.
- **New invariant I-18**, named here with its guard in the same build: the KATs, the `mem_quota` scenario and the release-to-baseline check. It goes in the ledger, which is still one page after the row.

## 8. Scope cuts (named, not hidden)

- **Kernel-heap objects and process count** are not buddy frames. A content process that loops on `SYS_SPAWN`, IPC channels or handles exhausts the fixed kernel heap instead. Threads are already capped at 16 per process.
  - The fix is a per-account **object** budget (handles, channels, spawns), metered like frames.
  - Proposed as **C2.2b**, after this lane. It is the same account object with a second counter, so this design leaves room for it: `MemAccount` gains `objects: AtomicU64` later without an ABI change. `SYS_MEM_INFO` v1 reserves nothing for it, and a v2 record adds it.
- **No reclaim and no OOM killer.** The trip is a local `ENOMEM`, and abort is the process's own choice. That is enough for "kills only that process".
- **Page tables freed by unmap:** `unmap_user_range` keeps intermediate tables today. They stay charged until exit. That is bounded, at most one table frame per 2 MiB of address space touched, and documented.

## 9. Evidence plan (QEMU, `NEO_SMP=4`, scenario `mem_quota`, `neo-test-mem-quota = ["neo-test", "mem-quota", "browser-runtime"]`)

init spawns roles from one `mem-quota-probe` module:

1. **Local trip.** A child with budget 8 MiB maps 1 MiB regions until `ENOMEM`. It reports `used ≤ limit`, that the trip came at the quota (`SYS_MEM_INFO`: global free still ≫ 0), and how much it got (≥ 8 MiB − spawn overhead). Exit 51.
2. **Neighbours unaffected.** While role 1's child is pinned at its limit, an unbudgeted sibling maps and touches 16 MiB successfully.
3. **std abort kills only the child.** A real-std child (std-real-smoke crate, new bin) with budget 4 MiB grows a `Vec` until abort (exit 134). init and the sibling keep running.
4. **Hierarchy.** An intermediate child with budget 12 MiB spawns two grandchildren at 8 MiB each. Their combined maps trip at 12 MiB, at the intermediate account.
5. **Buffers are charged.** A budgeted child creates Atrium buffers until `ENOMEM` (with the atrium feature), and its budget bounds them.
6. **No leak.** After every child exits, init's `used` is back to its pre-scenario baseline, exactly.
7. **Falsifiers**, each run once and reverted:
   - remove the charge in `allocate_user_region`: role 1 never trips, and the scenario fails;
   - skip the release in `Pmap::Drop`: the baseline check fails;
   - charge only the leaf level, with no walk to the parent: role 4 fails.
8. **Regression** with `mem-quota` on: the std and thread battery, `cap_rooted_open`, `desktop_session_boot`, and the spawn and teardown scenarios (`sched_spawn_reap_spawn_heavy`, `cap_survive_exit`).

## 10. Concurrency pitfall bank

| Pitfall | This lane | Discriminator |
|---|---|---|
| CP-37 lock from IRQ and non-IRQ | N-A: no lock, atomics only | by construction; a grep-check that `mem_account_logic` takes no lock |
| CP-1 lock ordering | N-A: no new lock taken inside `Pmap::inner` or `FRAME_ALLOC` | — |

## 13. The PM's questions (2026-10-27), answered from the code

**1. Shared and borrowed frames: who pays, and can another process's hold make allocation unbounded?**

- **Tensor shares** (`sys_tensor_share`) are metadata only: a new handle on the same arena slot, with no new frames. Under C2.2, a budgeted process creates no tensor storage at all (see 2), so it cannot drive tensor memory by creating and handing out shares.
- **Atrium buffers** are charged to the creator, once, in `SharedPixelBuffer::create`, before any frame is allocated. The buffer holds the charge (`_charge: Option<ChargeLedger>`) until its last reference drops. A handle granted to the compositor, or a compositor mapping's pin, keeps the charge on the creator's account. Closing its own handle therefore does not let a creator create more: the account is credited only when the frames are actually freed. Unbounded allocation through another holder is impossible, because the creator's budget counts every buffer that still exists.
- **Borrowed leaves** (`map_borrowed_region`, the only cross-process frame mapping in the kernel) charge the mapper nothing. The owner (the buffer) was charged exactly once at creation. The mapper's `Pmap` does charge the *intermediate tables* it allocates for the mapping, since those are its own frames.
- **Copy-on-write:** there is none for user memory. The only COW in the kernel is NeoFS's on-disk block COW (`fs/neofs/inode.rs`), which is filesystem metadata (see 2).

**2. Kernel-owned frames allocated on a process's behalf: charged or exempt, and why.**

| Class | Decision | Why it can't be grown without bound by a user process |
|---|---|---|
| DMA arena, graphics arena | exempt | reserved once at boot (`dma_arena::init`, `graphics_arena::init`); fixed size. Atrium buffers drawn from the DMA arena are charged to their creator like buddy-backed ones. |
| Block-I/O DMA buffers (`drivers/block/dma.rs`) | exempt | one per in-flight request, freed on completion; at most one per thread, and a process has at most 16 threads. |
| IOMMU page tables | exempt | driver-owned, sized by device mappings, not by process requests. |
| Tensors: create, model load, inference outputs, KV cache, migration | **refused** to a budgeted process (`EPERM`) | One check in the storage allocators (`HostTensorStorage::allocate_*`, device `alloc`) covers every path without a syscall list. Kernel threads (the residency daemon) are never budgeted. Charging tensors instead of refusing them is a later rung. |
| Kernel heap: IPC queues, handles, NeoFS block cache, kernel thread stacks, process count | out of scope here → **C2.2b** | a different resource (the fixed kernel heap, not buddy frames). Threads are capped at 16 per process. NeoFS writes need a RootDirCap with WRITE (K1a), which a content process is not handed. |

**3. Account lifetime.**

- `MemAccount.parent` is a strong `Arc`. A child account keeps its parent alive, so the chain walk in `charge`/`release` can never reach a freed account.
- Accounts form a tree, never a cycle: a child is created only by `MemAccount::child`, under an existing account. So the `Arc`s always free.
- Holders of an account: a `Pmap`'s ledger, an Atrium buffer's ledger, a child account, and the `root_mem_account` static (init's root, never freed).
- An account therefore outlives its last process while a live buffer or a child account still references it. When those go, it frees, and so do its ancestors in turn.
- **Drop order:** `Pmap::drop` frees every frame, then calls `release_all` once (checked under `neo-test`). Its `ledger` field drops after that and releases nothing more, because `release_all` is idempotent. `SharedPixelBuffer::drop` frees its frames, and its `_charge` field drops after, releasing the charge. In both cases the credit follows the free, never precedes it.

**4. No underflow or double release, on every path.**

- `ChargeLedger.held` is the single source of what an owner may release. A release beyond it is refused (`Underflow`) and changes nothing. `MemAccount::release` uses `checked_sub` and never wraps. Both count refusals in `underflows`, and the `Pmap` paths assert under `neo-test`.

| Path | Kernel site | Host KAT |
|---|---|---|
| map success → drop | `alloc_user_frame`, `Pmap::drop` | `path_map_success_then_drop` |
| failed map (allocator empty after the charge) | `alloc_user_frame` releases 1 | `path_failed_map_releases_its_charge` |
| unmap range, then drop | `unmap_user_range` releases per freed frame, after the frees | `path_unmap_range_then_drop_does_not_double_release` |
| `unmap_user` (frame handed back) | releases 1 when a frame is returned | `path_unmap_user_hands_the_frame_back` |
| `map_user` replacing a live leaf | releases 1 (two charges, one leaf) | (kernel-only; no charged caller replaces today) |
| a release the owner didn't charge | refused by the ledger | `path_ledger_refuses_to_release_what_it_did_not_charge` |
| failed spawn (CP-89) | the dropped child `Pmap` | `path_failed_spawn_cp89` |
| an owner's early return | the dropped ledger (RAII) | `path_dropped_ledger_releases_what_it_holds` |
| a buffer outliving its creator's handle | the buffer's `_charge` | `path_buffer_charged_to_creator_until_last_reference` |

- **End-to-end:** `mem_quota` ends by asserting that init's `used` is back to its baseline, and that the root account's `used` is 0 and its `underflows` is 0 after every user process is reaped.

**5. I-18** is in `docs/complexity-governance.md`, with a Rule-2 note. The table is 18 rows and still fits one page, but the next consolidation must compress I-14…I-18 before any I-19.

**6. CP bank:**
- **CP-37/CP-56 are N/A:** accounting takes no lock. Every operation is a CAS on an `AtomicU64`, safe at IF=0 under `FRAME_ALLOC` and `Pmap::inner`.
- **CP-89:** a failed spawn keeps what it charged.
- **CP-90:** two CPUs charging one account chain.

Both new entries are in `docs/concurrency-pitfalls.md`, in the table and in full.
- The tensor check takes the scheduler lock, through `current_mem_budgeted`, exactly as `current_pid()` already does from the same syscall paths. That adds no new lock order.

## 14. Where the build differs from §1–§11

- **`SYS_MEM_INFO` bytes 24..32 report frames in use system-wide**, not free frames. Free frames would need a free-list walk under `FRAME_ALLOC` that a user could trigger in a loop. Proof that a trip is local comes from role 2 instead: a neighbour maps 16 MiB while the budget is full.
- **Tensors are refused, not charged**, for a budgeted process (§13.2).
- **The scenario has no Atrium-buffer role.** `mem_quota` runs without the compositor. Buffer charging is covered by the host KATs, and exercised (charged to root) by `arthur_compositor` with `mem-quota` on.
- **The std-abort role uses libneo's allocation-failure exit (137)**, not real std (134): the same "the allocator failed, only this process ends" property, without the std overlay build in this scenario.
- **The kill-switch is byte-exact in `.text`/`.rodata`.** That required keeping `sys_spawn_impl` and `spawn_user` as the functions that hold their closures. The budget is a `cfg` parameter of `sys_spawn_impl`, and `spawn_user`'s body is a local macro, so no symbol moves with the feature off. `.data` differs only in panic-location line numbers.
