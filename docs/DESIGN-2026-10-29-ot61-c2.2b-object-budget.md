# OT-61 C2.2b — a per-account budget for kernel-heap objects: design

**Status:** design for the PM, not built. Seat S4. Base: `main` `8c49ac81`.
**Rung:** ADR-078 C2 ("a content OOM/crash kills only that process"), the half that C2.2's frame quota
leaves open (`docs/DESIGN-2026-10-27-ot61-c2.2-mem-quota.md` §8).

## 1. The gap, from an inventory of `main`

C2.2 bounds a process's **buddy frames**. The kernel's own heap is a different pool: one fixed region
(`HEAP_SIZE_DEFAULT` = 4 MiB, `kernel/src/mm/heap_policy.rs:25`; larger but still fixed with the model
features), mapped once at boot and never grown (`mm/heap.rs:147-202`). A failed allocation from it has no
`alloc_error_handler` and no `try_reserve` on kernel paths, so it panics the kernel. A content process
that fills it takes everyone down.

An audit of every syscall that leaves a kernel-heap object behind found that nothing counts them per
process. The one per-process count limit is 16 threads (`MAX_THREADS_PER_PROCESS`,
`sched/process.rs:517`).

| Vector | Heap cost per step | Per-process cap today |
|---|---|---|
| Any handle install (`install_cap` / `install_minted_locked`): derive, channel create, grant, open, tensor share, fence, focus | one `HandleTable` slot (the Vec never shrinks; `process.rs:1380`, `1519`) + one `derivations` node + the object itself | **none**: `HandleTable` has no slot limit |
| `SYS_CHAN_CREATE` | `Arc<Channel>` + 2 handles | none, and no capability needed |
| `SYS_SPAWN` | `Process`, `HandleTable`, `ThreadRegistry`, `Box<Thread>` + a **32 KiB heap stack** (`sched/thread.rs:57`, `276`) | none; about a hundred blocked children fill a 4 MiB heap |
| A child that exits unwaited | a `COMPLETED_EXIT_CODES` entry, forever (`process.rs:1725-1728`, "growth is currently unbounded") | none |
| `SYS_THREAD_CREATE` | `Box<Thread>` + 32 KiB heap stack | 16 |
| `SYS_BUFFER_MAP` | one pin `Arc` per map, kept until the Pmap drops (`mm/pmap.rs:1011`) | none |
| UDP socket bound | up to 16 queued datagrams × 2 KiB | none; **appears to outlive the process** (§6) |
| TCP connection / listener | up to 64 KiB receive queue | none; **appears to outlive the process** (§6) |
| `SYS_MODEL_LOAD` outside preload | a fresh `Arc<Model>` with metadata | none |

**Bounded already, no change:** futex waiters (64 global), wait-any (16 global, 4 per pid), tick sleepers
(8), `sys_wait` waiters (4 per target), ARP/NDP pending frames (16 each).

## 2. The rule

> **I-19 (proposed): a process's kernel-heap footprint never exceeds any object limit on its account
> chain.** Every persistent kernel object a process causes is charged, in bytes, to its account
> *before* it is created, and released when it is destroyed. A charge that would exceed a limit fails,
> and the syscall returns `ENOMEM` (or `EAGAIN` for spawn and thread create) to that process. The
> kernel heap itself is never asked for memory the chain has refused.

Like I-18, the trip is local. The global guarantee needs the root's object limit to sit below what the
kernel heap can spare (§5).

## 3. Accounts: a second counter on the same chain

- `MemAccount` gains `obj_limit` and `obj_used` (bytes), beside the frame `limit` and `used`. They are
  charged with the same lock-free, CAS-per-level walk and the same rollback (CP-90). An object charge and a
  frame charge are independent: a process can hit either.
- **Same tree.** An unbudgeted child shares its spawner's account; a budgeted spawn sets both limits. Budgets
  only narrow.
- **Per-object ledgers.** Each charged object carries what it charged, the way `Pmap` carries a
  `ChargeLedger`, and releases exactly that in its `Drop`. So a release never re-derives a size and never
  double-releases.
- **The unit is bytes, as a declared weight per object kind**, not `size_of` measured at run time: a handle
  slot plus derivation node is a constant, a channel adds its `Arc<Channel>`, a spawn adds the process
  structs plus the kernel stack, and a socket adds its maximum queue. The weights are constants in
  `mem_account_logic.rs` with a host KAT asserting each is at least the real `size_of` (and, for a
  socket, its queue bound), so they can only over-count.

## 4. Charge points (choke points, not every call site)

| Choke point | Charges | Released in |
|---|---|---|
| `HandleTable` install (every path ends here) | the handle-slot weight, plus the object's own weight when the install creates the object | handle removal / `drain` (the `Detached` drop, #183) |
| `spawn_user_body!` (charged to the **parent**'s account) | process + kernel stack weight | the child's last reap |
| `thread_create_for_current_placed` | thread + kernel stack weight | `Thread::free` |
| `COMPLETED_EXIT_CODES` insert | entry weight, to the **parent** | `sys_wait`, or the parent's teardown (which also stops the leak) |
| `Pmap` buffer-map pin | pin weight | the Pmap drop |
| socket / TCP create | socket weight including its maximum queue | socket close, **and process teardown** (§6) |

**Why the parent pays for a spawn:** the child does not exist when its structs are allocated, and a
budgeted child's own account is nested under the parent anyway. Charging the parent is what bounds a spawn
loop.

**Handle-slot reuse.** The table never shrinks, so a slot's weight is charged when the Vec grows and kept
until teardown, while the object's weight is released at removal. A loop of create-and-close stays flat
because a freed slot is reused.

## 5. "Trips before the kernel heap is exhausted"

The root account's object limit is set at boot to the kernel heap's size minus a reserve for the kernel's
own allocations (drivers, NeoFS cache, IPC). The reserve is a named constant, measured at the end of the
C2.2b scenario's boot and checked by the scenario (the heap's high-water mark stays below
`HEAP_SIZE - reserve`). Per-content budgets come below that, as C2.2's do.

## 6. Bugs the inventory found, outside this design (separate lanes)

1. **One syscall panics the kernel (product image).** `SYS_TENSOR_WRITE` and `SYS_TENSOR_CREATE` copy a
   user-chosen length into a kernel-heap `Vec` before any size check (`arch/x86_64/syscall.rs:2318`,
   `:2166`, through `copy_user_bytes` at `:1474`). Reported to the PM on 2026-10-29 with a proposed fix,
   to land before C2.2b.
2. **Sockets and TCP state appear to outlive their process.** `BOUND_SOCKETS`, `CONNECTIONS` and
   `LISTENERS` hold `Arc`s, and process teardown has no socket cleanup. Not yet traced end to end. If
   confirmed, it is a leak regardless of budgets, and §4's socket release needs it fixed.
3. **`COMPLETED_EXIT_CODES` grows forever** for children nobody waits on (the code says so). §4 bounds it
   per parent; the parent's teardown should also clear its children's entries.
4. **The NeoFS block cache has no eviction** that the audit found (`fs/neofs/cache.rs`). It is kernel
   memory a reader with a NeoFS file can grow. Not a per-process object; it needs its own cap.

## 7. Kill-switch and invariant budget

- Feature `obj-quota`, implying `mem-quota` (the accounts are shared). Off: no field, no charge call;
  `.text`/`.rodata` identical to the previous layer, by the section comparison C2.2 used.
- On with no budget set: every account is init's unlimited one, so behaviour is unchanged and only the
  counters move; the scenario checks the root's `obj_used` returns to its baseline.
- New invariant I-19, with its guard in the same build. The ledger's page-fit alarm is still raised
  (complexity-governance §3.1), so I-19's row must be one line, with the detail in this design.

## 8. ABI

- `SYS_SPAWN_BUDGETED` gains an optional object budget. Either a new number (`SYS_SPAWN_BUDGETED2`, 0x54),
  or a reserved argument that is 0 today; §10 asks which.
- `SYS_MEM_INFO` v2: the v1 record plus `obj_used` and `obj_limit` (bytes 32..48), with a hand-laid byte
  oracle. v1 callers keep their 32 bytes.

## 9. Evidence plan (QEMU, `NEO_SMP=4`, scenario `obj_quota`)

1. **Handle loop.** A child with a 64 KiB object budget creates channels until `ENOMEM`; its handle count
   at the trip is within one weight of the budget; init and a sibling still create channels.
2. **Spawn loop.** A child with a small budget spawns blocked grandchildren until `EAGAIN`; the count fits
   the budget; the kernel heap's free space stays above the reserve.
3. **Unwaited exits.** A child spawns and abandons exiting grandchildren; its `COMPLETED_EXIT_CODES`
   charge stops at its budget, and its own teardown returns it.
4. **Baseline.** After every child is reaped, the root's `obj_used` is back to its start, exactly.
5. **Falsifiers**, each run once and reverted:
   - remove the install charge: role 1 never trips;
   - charge the child instead of the parent at spawn: role 2 never trips;
   - skip the release in the handle drop: the baseline check fails.
6. **Regression** with `obj-quota` on: the capability battery (`cap_graph_revoke`, the `cap_revoke_*`
   set, `cap_survive_exit`), `mem_quota`, `servo_host_smoke`, the std and thread battery, IPC
   (`ipc_heap_kill_smoke`), and `desktop_session_boot`.

## 10. Concurrency pitfall bank

| Pitfall | This lane | Discriminator |
|---|---|---|
| CP-90 two CPUs charging one chain | the same CAS walk for the second counter | the KAT hammer; roles 1–2 at `NEO_SMP=4` |
| CP-89 a failed spawn keeps what it charged | the parent's object charge is released on every spawn error path | role 2's refused spawn |
| CP-92 no park under `CAP_GRAPH` | the install charge is atomics only, so it may run under the lock | by construction |
| CP-56 hidden `Drop` under a lock | releases happen in object drops, which #183 already moved after the unlock | #183's witnesses, armed in every run |
| CP-37 | N-A: no lock | — |

**SMP core:** it touches every handle install and spawn, so the review needs a cross-family lens:
GPT-6.1-Sol at high effort, and Muse for the containment claim.

## 11. Cost (cycles and gates)

One kernel lane, one 4-shard gate. About six charge sites, a second counter in an existing module, one ABI
extension, one scenario. Expected one or two build→gate cycles; the unknowns are the per-kind weights and
the socket teardown in §6.2.

## 12. Decisions for the PM

1. **Unit:** bytes with declared weights (recommended), or plain object counts per kind? Counts are simpler,
   but a 32 KiB stack and a 40-byte handle are not the same resource.
2. **Who pays for a spawn:** the parent (recommended) or the child?
3. **ABI:** a new `SYS_SPAWN_BUDGETED2`, or a reserved argument on the existing call?
4. **Order:** the tensor-length fix (§6.1) first, as its own PR; then the socket-teardown trace (§6.2);
   then C2.2b. Or fold §6.2 into C2.2b.

## 13. Build notes (2026-10-29)

What the first build (`claude/ot61-c2.2b-obj-quota`) settled, against §1–§12:

- **Rulings applied.** Bytes with declared weights, the parent pays for a spawn, and the child's own objects charge the child's account (PM, §12).
- **ABI.** `SYS_SPAWN_BUDGETED` takes `a0`–`a4` and never checks `a5`, so a non-zero sixth argument is silently ignored today. By the PM's rule that rules out reusing it, so the build adds **`SYS_SPAWN_BUDGETED2` = `0x54`** `(name, len, handles, n, frame_bytes, obj_bytes)`. `frame_bytes` 0 means no frame budget of the child's own; `obj_bytes` 0 is `EINVAL`. **`SYS_MEM_INFO` v2** is selected by passing 48 as the length (v1 callers keep their 32 bytes); bytes 32..40 hold the object bytes used and 40..48 the limit, version 2. Both the kernel encoder and libneo's independent decoder are checked against hand-laid bytes.
- **Weights** (`sched::process::obj_weights`) are built from `size_of` of the structures each charge pays for, plus their queue bounds, so they can only over-count:
  - **any handle:** its slot and per-slot weight counted three times (a doubling table), plus twice its derivation entry;
  - **plus, by kind:** a channel, an open file, a UDP socket with a full receive queue, a TCP connection with both windows full, a listener, a dial capability's host name, a model's metadata;
  - **a spawn:** the `Process`, its first `Thread` and the 32 KiB kernel stack;
  - **a thread:** the `Thread` and its stack.

  An object shared by several handles is counted once per handle.
- **The root's object limit** is the kernel heap less `OBJ_HEAP_RESERVE`, half the heap (2 MiB of the 4 MiB default). The scenario checks the root's count returns exactly. The reserve is not yet measured against the heap's high-water mark, which needs a heap high-water counter on the default build; that is a follow-up.
- **The invariant** extends I-18 rather than adding I-19: same chain, second resource. The governance ledger's page-fit note forbids a new row until the I-14…I-18 prose is compressed.
- **Charge points in this build:**
  - every handle install a process can cause (`install_cap*`, `derive_handle`, `derive_net_dial_cap`, the spawn's inherited handles), recorded per slot and released at `remove`, `remove_cap_ids`, `drain` or the table's drop;
  - the spawn (an `ObjCharge` the child's `Process` holds until it drops);
  - `SYS_THREAD_CREATE` (held by the `Thread`, released by `Thread::free`).
- **Deferred to a second build:**
  - **socket queues beyond the handle weight**, since closing sockets at teardown is #202;
  - **buffer-map pins**;
  - **`COMPLETED_EXIT_CODES`** (OT-91).
- **Error codes.**
  - A refused handle is `ENOMEM` from channel create and derive. Channel create takes its first endpoint back out, so nothing is left installed.
  - The other install sites keep their existing `EINVAL` mapping for every install error.
  - A refused spawn or thread is `EAGAIN`.
- **Kill-switch.** With `obj-quota` off, `.text` and `.rodata` are byte-identical to `main` for the default, `mem-quota`, desktop, usb-host and product kernels.
