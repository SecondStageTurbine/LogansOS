## 0. The A3 result — both consumers converge on FIVE primitives, not two parallel sets

The load-bearing A3 finding: **`std::sys` and SpiderMonkey's native pthread port want the SAME POSIX/futex-shaped primitives.** Designing for one designs for both — with one exception noted per row. So C1's ABI is **five** unified, cap-confined primitives, each replacing a C0 `neo-std-pal` loud stub:

| # | Unified primitive | `std::sys` need (real interface) | SpiderMonkey pthread need (cited) | Convergence |
|---|---|---|---|---|
| P1 | **futex** (wait-on-address + wake-N, **absolute** monotonic deadline) | `sync::mutex::futex`, `sync::condvar::futex`, **`sync::rwlock::futex`** — all **futex-backed** | `pthread_mutex_*` (`Mutex_posix.cpp:34-102`), `pthread_cond_*` incl. **absolute-monotonic** timed wait (`ConditionVariable_posix.cpp:25-39,68-151`), pthread rwlock | **Exact** — build the futex, build **{mutex, condvar, rwlock}** in *userland* on it (amended: absolute deadline, rwlock covered) |
| P2 | **thread** (`create(stack,entry)`/`join`/`detach`/`yield`/`sleep`/`set_name`/`self_id`, **stack bounds + guard page**) | `thread::Thread::new(stack: usize, init: Box<ThreadInit>)`, `join`, `set_name(&CStr)`, `yield_now`, `sleep(Duration)`, `available_parallelism`, `current_os_id`, `DEFAULT_MIN_STACK_SIZE=64KiB` | `pthread_create(attr{stacksize,guardsize}, start)`, `join`, `detach`, `pthread_setname_np`, `pthread_self` (`PosixThread.cpp:39-131`); stack bounds **provided at creation** (vs its `NativeStack.cpp:77` dlsym fallback) | **Exact** shape; the only delta is *who allocates the stack* (§1.P2) |
| P3 | **TLS key** (`create(dtor)`/`set`/`get`/`delete`, **destructors run at thread exit**) | `thread_local::key::LazyKey::new(dtor: Option<unsafe extern "C" fn(*mut u8)>)` → `create`/`set`/`get`/`destroy` | `pthread_key_create(dtor)/setspecific/getspecific/key_delete` | **Identical** — std's key API *is* pthread_key; one ABI serves both verbatim |
| P4 | **clock** (monotonic + realtime, defined ns resolution) | `time::Instant::now()` (monotonic, nondecreasing), `SystemTime::now()` (realtime) | `clock_gettime(CLOCK_MONOTONIC/CLOCK_REALTIME)` (`TimeStamp_posix.cpp:91,184-189,316`) | **Exact** — one `clock_gettime`-shaped call, two clock ids |
| P5 | **VM** (`map`/`unmap`/**`protect`**, **W^X enforced**, guard pages) | our `#[global_allocator]` growth + guard pages | GC `Memory.cpp:236-269,889-948,1057-1126` reserve/commit/decommit/**protect**; **JIT** `mprotect`→exec is DEFERRED (A1) | Shape converges; **W^X-relaxed exec is the ONE thing we do NOT build** (the A1 rung) |

**Why this matters:** a naïve design would build a Rust-thread ABI and later discover pthread needs `detach` + a guard-size attr + `setspecific` semantics it doesn't fit — a C1 redo. Freezing on the POSIX superset (detach, guard page, key destructors, monotonic condvar deadline) up front serves both. The **futex convergence (P1)** is the biggest win: **we build ONE wait/wake primitive**, and both `std`'s futex mutex/condvar AND pthread's mutex/cond are implemented in *userland* on top of it (exactly as glibc/Rust do on Linux) — no separate mutex/condvar syscalls.

## 1. Per-primitive ABI (grounded in the kernel machinery that exists)

Each primitive = a `SYS_*` (new core block **0x40–0x4F**, keeping C1 grouped; next free core is 24+ but a fresh block is cleaner) + a `libneo` shim + the `neo-std-pal` / overlay wiring that satisfies the C0 stub + a cap gate (§4).

### P1 — futex (`SYS_FUTEX_WAIT`, `SYS_FUTEX_WAKE`)  *(amended: absolute deadline; RwLock covered)*
- **ABI.** `futex_wait(uaddr: *const u32, expected: u32, deadline_ns: u64 /* 0 = infinite */) -> i64` (returns 0 = woken, `-ETIMEDOUT`, `-EAGAIN` if `*uaddr != expected` at entry — the lost-wakeup guard). `futex_wake(uaddr: *const u32, count: u32) -> i64` (returns # woken). Linux-futex semantics, the subset `std`+pthread use.
- **Amendment 1 — the deadline is an ABSOLUTE monotonic instant with exact sentinels.** The arg is `deadline_monotonic_ns: u64`: **`u64::MAX` = infinite (no timeout), `0` = already-expired** (return `-ETIMEDOUT` immediately after the value check). Not a relative timeout — `pthread_cond_timedwait` and Rust's `sys::pal::unix::futex` both do a **one-time** monotonic→absolute conversion (`futex.rs:24-40,70-92`) precisely because a relative timeout restarts on every spurious re-wait, losing the deadline. The userland condvar computes the absolute deadline **once** (`SYS_CLOCK_GETTIME(CLOCK_MONOTONIC)` + the requested delta); the kernel wakes with `-ETIMEDOUT` when `now >= deadline`. Mozilla's condvar does the identical absolute conversion + spurious-wake-recheck (`ConditionVariable_posix.cpp:30-33,68-84,110-151`; `PlatformConditionVariable.h:40-49`).
- **Amendment 2 — RwLock is a third covered consumer; preserve the wake count.** The futex builds `std::sys::sync::rwlock::futex` (`rwlock/futex.rs:94-160,172-260,264-325`) and Mozilla's `RWLock_posix.cpp` **in userland** — no new kernel primitive. `futex_wake` **must return the count woken**: Rust's rwlock uses it to decide the writer→reader fallback (`rwlock/futex.rs:318-329`). Frozen convergence: **futex → {mutex, condvar, rwlock}**, all userland. (Mozilla's mutex owner-ID/error-check/adaptive-spin, `Mutex_posix.cpp:35-121`, are userland policy over the same futex — no PI/robust/requeue/fairness syscall needed.)
- **Kernel realization (reuse, do not reinvent).** The kernel's `sched::block_current_into_with_guard(guard, installer)` + `wake_thread_token(token, ret)` pair is **explicitly the named futex substrate** (`scheduler.rs:1372-1373`: "the primitive every future blocking syscall (futex, …) consumes"), and IPC's `EndpointState` park/wake (`ipc/mod.rs`) is the worked example. C1 adds a **kernel wait-queue keyed by the futex's *physical* address** (translate `uaddr` via `Pmap::translate` so aliased mappings key the same queue): `futex_wait` re-checks `*uaddr == expected` **under the queue guard**, then `block_current_into_with_guard` parks the `Box<Thread>` into the queue slot while the guard releases atomically on the new stack (the **lost-wakeup-free** discipline — CP-8/CP-17 publication order: the compare-and-park is atomic w.r.t. a concurrent `futex_wake`). `futex_wake` drains up to `count` parked threads via `wake_thread_token` (generation-checked → a stale wake is a safe no-op; SMP cross-CPU sends the reschedule IPI). **Timeout:** a monotonic deadline (`timer::TICKS`, P4) checked on the timer tick / a bounded wake.
- **A3:** `std`'s `futex_wait`/`futex_wake` (its `sys::sync::futex` calls) and pthread's mutex/cond (which lower to the same two ops) both bind here. **Concurrency-critical (AAG lens):** the compare-then-park must be atomic against wake (the guard covers it); a spurious wake is permitted (both consumers tolerate it); no lost wakeup, no thundering-herd unboundedness (`count` bounds the wake).

### P2 — thread (`SYS_THREAD_CREATE`, `SYS_THREAD_JOIN`, `SYS_THREAD_DETACH`, `SYS_THREAD_EXIT`, `SYS_SCHED_YIELD`, `SYS_THREAD_SETNAME`, `SYS_THREAD_SELF`, `SYS_THREAD_GET_INFO`)  *(amended: + stack-info query)*
- **ABI.** `thread_create(entry: extern "C" fn(arg) -> !, arg: usize, stack_size: usize, guard: bool) -> tid|errno`; `thread_join(tid, *mut exit_code) -> 0|errno`; `thread_detach(tid)`; `thread_exit(code) -> !`; `sched_yield()`; `thread_set_name(ptr,len)`; `thread_self() -> tid`. `available_parallelism` = a stat read (SYS_SYSSTAT cpu count, exists). `sleep(dur)` = `futex_wait(dummy, dummy, absolute_deadline)` (reuses P1 — no new syscall; deadline computed absolute per P1.1).
- **Amendment — `thread_get_info(tid) -> {tid, usable_low, usable_len, guard_low, guard_len}`** (a new 0x40-block slot; downward-stack semantics explicit), for `self` or a same-process tid; **validity defined through thread exit/reap**. **CORRECTION (per the RETURN — my earlier "GC stack scan" relay was WRONG):** the demonstrated consumer is **stack-*limit* enforcement**, not a scan — `JS_SetNativeStackQuota` derives the native stack limit from the base (`jsapi.cpp:1526-1536`), which `JSContext::init` stores (`JSContext.cpp:116-118`) from `GetNativeStackBaseImpl` — POSIX `pthread_getattr_np(pthread_self())` + `pthread_attr_getstack` (`NativeStack.cpp:93-115`), whose **glibc `__libc_stack_end`/`dlsym` main-thread fallback (`:67-90`) does not exist** in our static/no-loader port. So `thread_get_info` is the first-class replacement the private CRT's `pthread_getattr_np`/`pthread_attr_getstack` bind to. **Populate it for the INITIAL process thread too** (not only `thread_create`). **Kernel change:** the current `Thread` carries **no** user-stack bounds (`thread.rs:87-125`) and `new_user` takes only `user_rsp` (`:309-315`) — C1.1 adds `{usable_low, usable_len, guard_low, guard_len}` to `Thread` and records them on create + for the adopted initial thread.
- **Amendment — the child entry is a TLS-free bootstrap trampoline.** `thread_create`'s `entry` is a runtime trampoline that runs with **no TLS yet**: it (1) records/queries its bounds, (2) installs the C1.2 TCB/key block + per-thread `errno` cell (a TCB slot — real in no-JIT GC VM code, `Memory.cpp:260-271,894-907`, but **not** another syscall), then (3) calls the application start routine. The exact engine needs neither caller-supplied stacks nor detach-at-create — it sets only stack size (`PosixThread.cpp:49-57`) and detaches later (`:75-79`); no `pthread_cancel` use found.
- **Kernel realization.** `Thread::new_user(name, pid, entry_rip, user_rsp, Arc<Pmap>)` **already exists** (`thread.rs:309`) and the scheduler **already has** `same_process_user_prep` (`scheduler.rs:775`: skips CR3, updates TSS.rsp0 — "multi-thread within one user process, Phase 1.5+"). So the address-space sharing is free (`Arc<Pmap>` clone). C1 fills the enumerated gaps: **(a)** `thread_create` allocates the new thread's **user stack** from the caller's `Pmap` (P5 `allocate_user_region`, R+W+NX) with a **guard page** (P5) below it, builds `Thread::new_user` with `entry_rip=entry`, `user_rsp=stack_top`, `arg` in the first argument register, and `try_push_ready`s it; **(b)** a **per-process thread refcount** (`Process` gains a thread set/count — today `thread_count:1` is hardcoded `process.rs:1451` and *any* reap deregisters the process `process.rs:1732`) so the `Pmap`/`Process` is dropped only on the **last** thread's reap; **(c)** **join/detach/exit-status** plumbing (a per-thread exit-status slot + a futex/token wait, mirroring the existing `ProcessWaitQueue` shape) — `join` blocks on the target's done-word via P1.
- **A3:** serves `std::sys::thread::Thread::new(stack, init)` (std boxes the closure; our `entry(arg)` runs a trampoline that calls it) AND `pthread_create` (detach + guardsize + join exit-value all present). **Mem-safety (AAG lens):** the new thread's stack + guard, the `arg` handoff, and the refcount teardown (no use-after-free of a shared `Pmap` on the last reap) are the review surface.

### P3 — TLS (`SYS_THREAD_SET_TLS` + userland keys)
- **ABI.** `thread_set_tls(base: usize) -> 0|errno` sets the calling thread's **FS.base** to `base` (an `arch_prctl(ARCH_SET_FS)` analogue). TLS **keys** (`create(dtor)/set/get/delete`) and **destructor-at-exit** are implemented **in userland** (`neo-std-pal`) over a per-thread TLS block the thread self-allocates (P5) and installs via `thread_set_tls`; the key table + destructor list live in that block; `thread_exit` (P2) runs the registered destructors before the exit syscall.
- **Kernel realization.** Today FS.base is **never set per-thread** (`context.rs:18` "no per-thread TLS yet"); the ELF loader ignores `PT_TLS` (which is why C0.5's `has-thread-local=false` target emits none — the loader gap was structurally unreachable). C1 adds: FS.base save/restore in the context switch (per-thread `fs_base: u64` on `Thread`, `WRFSBASE`/MSR on switch-in) + the `thread_set_tls` syscall. **This does NOT require loader `PT_TLS` support** — the thread self-installs its TLS base at startup; the loader stays PT_LOAD-only.
- **A3:** std's `thread_local::key::{LazyKey(dtor), create, set, get, destroy}` and pthread's `pthread_key_create(dtor)/setspecific/getspecific/key_delete` are the **identical** userland key API over `thread_set_tls`; both run destructors at thread exit. This keeps the *kernel* ABI tiny (one FS.base setter) while satisfying both key APIs in userland.
- **Amendment 1 — iterated key destructors (the RETURN's unconditional redo-forcing catch).** A single "run each destructor once" pass is **wrong**: pinned Rust `std` creates keys with destructors (`key/unix.rs:23-31`), its value destructor **schedules cleanup for a later round** (`os.rs:222-242`), and the key-path cleanup callback **re-establishes its key as `RUN`** then runs `thread_cleanup` only on the next round (`guard/key.rs:33-57`). So at exit the userland layer must: **clear each non-null slot BEFORE calling its destructor** (so a destructor sees null unless it re-arms); **rescan** the keys when a callback establishes a new value; **repeat up to `PTHREAD_DESTRUCTOR_ITERATIONS` (POSIX four passes)**; then `thread_exit`. Key deletion/reuse needs a **generation check** so a stale destructor can't target a recycled key. No kernel-ABI change. (Battery: a destructor that **re-arms** its key runs again in a later pass; "exactly once" holds only for a non-repopulating destructor.)
- **Amendment 2 — native-TLS is KEY-ONLY-ENFORCEMENT FIRST, with an EXACT recipe; `PT_TLS` a reserved rung.** My "runtime-key only" bet **diverges** from a real reachable path: `MOZ_THREAD_LOCAL` expands to compiler-native `__thread` whenever `HAVE_THREAD_TLS_KEYWORD` is defined (keys are only the fallback, `ThreadLocal.h:145-169,238-250`), and **unguarded** `TlsContext` (`Runtime.cpp:58`) + `TlsGCContext` (`GC.cpp:291`) are initialized **before `JitInit`** (`Initialization.cpp:147-170`, `GC.cpp:928-940`) — **so no-JIT does NOT remove this TLS.** Worse, Mozilla's configure defines `HAVE_THREAD_TLS_KEYWORD` from a *link-only* `static __thread` probe (`toolchain.configure:2472-2501`), so a **static link can succeed carrying TLS the runtime can't instantiate**. Rust has the same fork (`sys/thread_local/mod.rs:1-8,26-47`; native `#[thread_local]` at `native/mod.rs:56-119`; the mozjs wrapper's `thread_local!` state `rust.rs:161,311-317`). An FS.base block serves *keys*, **not** compiler-assigned FS-relative offsets; and the loader excludes `PT_TLS` (`elf.rs:12-13,151-162`), so it never builds a per-thread `.tdata`/`.tbss`. **The ratified decision:**
  - **Primary — structurally enforce key-only TLS (exact recipe):** keep Rust **`has-thread-local=false`, set `singlethread=false`**; replace the C0 overlay's forced `no_threads` route with a **Neoplutarch OS-key/PAL route**; force Mozilla **`HAVE_THREAD_TLS_KEYWORD` off**; and a **build-time gate (A4-scanner shape) that REJECTS any final ELF containing `PT_TLS` or `SHF_TLS`** (or a `__thread` symbol). Define the private FS-based TCB/key-block locator **without `__thread`**, installed in the bootstrap trampoline (P2) before std/CRT/engine code, with a reserved errno cell. **C1.2 OPENS with this spike:** do both consumers compile+link clean under the key-only gate?
  - **Reserved rung (the A1-JIT pattern) — implement static `PT_TLS`/TCB.** If the spike proves a consumer genuinely **cannot** build key-only: parse `PT_TLS`, copy `p_filesz`, zero through `p_memsz`, honor `p_align`, build the x86-64 static-TLS/TCB layout for the initial **and** every child thread, install FS before its first user instruction (local-exec only; a dynamic loader/DTV can still defer). No extra syscall beyond the FS-base op, but the loader + bootstrap work is real. A **named, justified rung**, not a surprise.

### P4 — clock (`SYS_CLOCK_GETTIME`)
- **ABI.** `clock_gettime(clock_id: u32, *mut u64 nanos) -> 0|errno`; `clock_id ∈ {CLOCK_MONOTONIC=1, CLOCK_REALTIME=2}`. Monotonic is **nondecreasing** with a defined resolution.
- **Kernel realization.** `timer::TICKS` (100 Hz, `timer.rs:44`) already gives monotonic uptime (surfaced coarsely via `SYS_SYSSTAT.uptime_ticks`); C1 adds a dedicated syscall returning ns (`TICKS × 10_000_000`), optionally refined by the calibrated `tsc_hz()` (`forward_perf.rs`) for sub-tick resolution — **but hermeticity (CI rule): TSC rate differs by runner under TCG**, so the *monotonic contract* (nondecreasing, defined coarse resolution) is the gate; TSC refinement is a non-gated nicety. Realtime = a boot-epoch base + monotonic delta (no RTC dependency in C1).
- **A3:** `std::time::Instant`/`SystemTime` and `clock_gettime(MONOTONIC/REALTIME)` both bind here; the P1 futex timeout uses the same monotonic source (one clock, consistent deadlines).

### P5 — VM (`SYS_VM_MAP`, `SYS_VM_UNMAP`, `SYS_VM_PROTECT`)
- **ABI.** `vm_map(size, prot, guard: bool) -> va|errno` where `prot ∈ {RW (R+W+NX), RX (R+X), RO (R+NX)}` — **generalizes** the existing `SYS_MAP_REGION`(6) which only ever maps R+W+NX. `vm_unmap(va, size) -> 0|errno`. `vm_protect(va, size, prot) -> 0|errno`. **`guard:true`** leaves an unmapped page below the returned region (thread stacks pass this).
- **Kernel realization.** `Pmap::allocate_user_region(size, flags)` is the mmap workhorse (`pmap.rs:341`); `Pmap::unmap_user` **already exists** (`pmap.rs:291`, incl. TLB fence + shootdown) — C1 just **wires it to a syscall**. `vm_protect` is a **new perms-only `Pmap::protect`** method (the leaf-replace mechanism + shootdown exists in `map_user_locked`; C1 adds a perms-only entry point). **W^X (A1):** `check_user_flags` (`pmap.rs:54`) already rejects `WRITABLE && !NO_EXECUTE` on map; **`vm_protect` MUST route through the same check** so a transition **to** W+X is refused — the W^X negative battery. Guard pages: the monotonic cursor skips a page (leaves it unmapped) below a `guard:true` region; a stack overflow faults into it (contained to the process).
- **A3:** serves our `#[global_allocator]` growth (RW), SpiderMonkey GC reserve/commit/decommit/**protect** (`Memory.cpp`), and thread stacks+guards (P2). **The one deferral (A1):** no `prot` value yields W+X, and no future JIT `RW→RX-with-prior-writes` executable-generation path is introduced — that is the separate, kill-switchable, invariant-budget rung (§4).

## 2. W^X enforcement model (A1) — enforced here; JIT-relax is the future budgeted rung

- **The invariant (already true, kept true):** a user page is **R+W (NX)** or **R+X**, **never W+X**. Enforced today by `check_user_flags` on every map path (`pmap.rs:54`) + the ELF loader's `PF_W|PF_X` refusal. C1's **only** new writable/executable surface is `vm_protect`, and it routes through the **same** `check_user_flags` — so a `vm_protect(va, RX)` on a page that was RW is allowed (the page had no prior *executable* content and is re-permissioned atomically with a shootdown), but there is **no API that produces a simultaneously-writable-and-executable page**. The **W^X negative battery** (C1.0 gate) proves `vm_map(_, W+X)` and `vm_protect(_, W+X)` both return `-EINVAL`.
- **What C1 does NOT build (the A1 reservation, ADR-078 §4):** JIT needs runtime-generated executable code — the first-ever W^X-*violating* mechanism (write machine code, then execute it). That is a **new cross-cutting invariant** requiring a named, justified, **kill-switchable** (interpreter-only fail-safe) budget rung in the build that adds it. C1 introduces **no** such path: `vm_protect` cannot reach W+X, and SpiderMonkey runs **no-JIT** (C3, interpreter) so its `ProcessExecutableMemory.cpp` mprotect-to-exec is never exercised. The MonoTonic bound: C1 keeps the browser's usable end-state honest — everything works under W^X except JIT, which is the deliberately-deferred decision.

## 3. The slice ladder (justified by dependency depth + battery independence)

**Do NOT land it all in one build** (dispatch). Three slices, ordered so each has a self-contained gate battery and the hard concurrency core is isolated:

### C1.0 — VM (map/unmap/protect, W^X, guard) + the clock  ← **the first slice to build**
- **What:** P5 (the three VM syscalls + `Pmap::protect` + guard pages + W^X on protect) + P4 (`clock_gettime`). Kernel + libneo + a **no_std VM smoke** (exercises the syscalls directly — **decoupled from the C0.5 overlay**, so C1.0 can build on current `main` + neo-std-pal without waiting on the real-`std` path).
- **Why first:** *single-threaded* (no scheduler/thread changes → smallest blast radius), the **crispest self-contained negative battery** (W^X), and the **prerequisite** for everything downstream — thread stacks + guard pages (C1.1) and SpiderMonkey GC. Reuses the most existing code (`unmap_user` exists; W^X-check exists; `allocate_user_region` exists) → highest confidence.
- **Battery (QEMU, per ADR-078):** **W^X-negative** (`vm_map`/`vm_protect` to W+X → `-EINVAL`); map→write→protect(RX)→execute→protect(RW) round-trip; **guard-page** (write below a guarded region → the process faults, containment holds, governance intact); unmap→access-faults; **clock-monotonic** (two reads nondecreasing, resolution within bound). Kill-switch: all behind a `browser-runtime` feature/cap; default build bit-for-bit unchanged.

### C1.1 — threads (create/join/detach + stack/guard + stack-info) + the futex
- **What:** P2 (thread lifecycle + per-process refcount + join/detach/exit-status + the amended **`thread_get_info` query** [populated for the initial thread too] + the TLS-free bootstrap trampoline + `Thread` gaining user-stack bounds) + P1 (the futex, with the amended **absolute-deadline** `futex_wait`/`deadline_monotonic_ns`, the **preserved wake-count** return, and its userland **{mutex, condvar, rwlock}** layers). Threads use C1.0's `vm_map(guard:true)` for stacks; join/timed-wait use C1.0's clock as the absolute-deadline timebase.
- **Battery add (per the RETURN):** **rwlock contention** (read/write lock, writer→reader fallback exercises the wake-count) alongside mutex contention.
- **Why second:** the **concurrency core** — the AAG-heaviest, interdependent (a useful thread needs join = a futex wait; the futex battery needs ≥2 threads). Isolating it in its own slice keeps the contention/lost-wakeup review focused.
- **Battery:** **contention** (N threads increment a shared counter under a futex-mutex; sum exact); **timeout** (`futex_wait` deadline returns `-ETIMEDOUT`); **lost-wakeup-free** (wake-races-wait: a wake that arrives between the value-check and the park is not lost — the compare-under-guard proves it); **guard-page** (a recursing thread overflows its stack into the guard → only that thread's process faults); **refcount** (spawn N, join all, assert the `Pmap`/process is reaped exactly once, no leak, no early-drop).

### C1.2 — TLS (FS.base per-thread + keys + iterated destructors) — **opens with the P3 key-only spike**
- **Opening spike (the amended P3 decision):** before freezing the TLS model, **prove both consumers compile+link clean under the key-only build gate** — the A4-shape scanner that fails the browser-runtime build on a native-TLS relocation / `.tdata` / `.tbss` / `__thread` leak-in. If clean → key-only TLS, no loader work. If a consumer genuinely can't → the reserved `PT_TLS` rung is named+justified+built in that same change (the A1-JIT pattern). **Report the spike result before cutting the TLS syscalls.**
- **What (assuming key-only):** P3 (per-thread FS.base save/restore in the context switch + `thread_set_tls` + the userland key layer running the **amended iterated ≤4 destructor passes**) + the build-time key-only gate. Needs C1.1 threads.
- **Why last:** rides on threads (per-thread state) and is the smallest kernel delta (one FS.base setter); the userland key layer is where std's `LazyKey` and pthread's `pthread_key` both bind.
- **Battery:** **TLS isolation** (two threads see distinct per-key values); **iterated destructor** (a destructor that re-sets a key → the re-scan re-runs it, converging within ≤4 passes; runs before the exit syscall); FS.base survives a context switch; **the key-only build gate fires** on a deliberate `__thread`/`.tdata` leak-in (A4-style falsification).

**Post-C1:** the real-`std` (and, at C3, SpiderMonkey no-JIT) threaded smoke exercises all three on-target — but that integration is C2/C3's, not C1's. C1 delivers the primitives + their unit batteries.

## 4. Cap-confinement, kill-switch, invariant budget (I-14)

- **Cap-confined (the `NetDial` pattern).** The authority to create threads / map memory / set TLS is a **new `Handle` variant** (`process.rs:506` — "new capability types land as additional variants here") + a rights module, minted as a **root cap installed into a browser process at spawn** (like `root_net_dial_cap`), and **every C1 syscall gates** on `handles.lock().get(h)` + variant-match + `has_meta(USE) && has_semantic(...)` before acting (the `sys_net_dial_impl` shape, `syscall.rs:3595`). A non-browser process without the cap gets `EPERM`. *(C1.0's VM may reuse the existing implicit-per-process authority initially and add the explicit cap with C1.1's thread cap — decided at C1.0 build; the gate pattern is fixed here.)*
- **Kill-switch (Rule-1).** All C1 syscalls live behind a default-off `browser-runtime` feature; disabled ⇒ the syscalls are `ENOSYS` and the kernel/userland are **bit-for-bit the pre-C1 build** (the `net-dial-cap` feature-swap precedent, `syscall.rs:696`). The default build is unaffected.
- **I-14 fault containment.** A fault in a browser thread (guard-page overflow, a bad `vm_protect`, a futex on a dead address) is **contained to its process** — separate `Pmap`, the reaper drops it, governance (`INFLIGHT`/`RECENCY`/`ARENA`/`TABLE`) is never touched (the futex/thread paths take **no** AI-governance lock; they take the scheduler's leaf lock + the futex queue's leaf lock only). A browser thread monopolizing a CPU degrades within the process (the scheduler preempts); governance liveness is unaffected.
- **Invariant budget.** C1 adds **no new cross-cutting invariant** — the primitives are new *syscalls/caps*, not new ledger invariants. It **preserves** W^X (I-… / Bible 12.3) and I-14. The **one** future invariant C1 *names but does not add* is **A1 (W^X-relaxed JIT)** — reserved for its own budgeted, kill-switchable rung (§2, ADR-078 §4). A2 (per-content-process memory quota) is untouched (a C2 rung).
