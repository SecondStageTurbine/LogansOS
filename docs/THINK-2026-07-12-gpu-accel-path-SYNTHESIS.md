## 0. One breath
Both families independently converged on the same architecture: **one kernel-owned Intel GT substrate with two adapters (the existing compute driver + a new capability-gated graphics adapter), a real software-render floor as the first build and the permanent kill-switch, WebRender/GL-first for the browser (NOT wgpu-first), a wgpu/Vello route kept open behind a renderer-agnostic surface/buffer/fence/damage seam, GPU-submit as a scarce capability (no raw submit for renderers) backed by the silicon-proven per-context PPGTT, and I-14(c) solved by moving the iGPU from its current VT-d identity/passthrough domain into a translated/fenced domain — not swiotlb bounce-fencing.** They also independently surveyed the same uncomfortable ground truth: **Phase-6 brought up exactly ONE of the iGPU's three subsystems (compute/GPGPU on the render ring); the display engine and the 3D/render pipeline are literally zero lines, and the GPU is today the least-contained DMA device in the machine.** The divergences are four, all Oracle refinements that graft cleanly.

## 2. The four divergences — all resolve as grafts (Oracle refines Janus)
1. **The browser's software floor = `swgl` (Oracle), not a generic CPU rasterizer.** `swgl` is Servo/Mozilla's own software-GL implementation of the exact subset WebRender uses (what Firefox ships on blocklisted GPUs, lives in the WebRender tree). Running WebRender on `swgl` exercises the **real `surfman`/GL present contract** — the same seam hardware GL later replaces — so the **browser's correctness battery runs on Rung 0 with zero GPU code**, and Janus's hardware GL adapter (`surfman-neo`/`libneogl`) becomes the Rung-2 swap-in *behind that same surfman device seam*. **GRAFT: browser floor = `swgl` (Oracle) → hardware GL adapter = `surfman-neo`/`libneogl` (Janus). They compose exactly.** (tiny-skia/Vello-CPU stays the *compositor* floor; Blitz/Vello-CPU stays the explicitly-limited OT-60 reader.)
2. **Rung 1 = a bounded display-engine takeover (flip + vblank), taken EARLY (Oracle), not deferred with full modeset (Janus GFX-8).** Both agree: inherit Limine's mode, defer *full* modeset (EDID/GMBUS/pipe/PLL/watermark) as the recovery contract. The graft splits the scope Janus lumped into GFX-8: **take the page-flip + vblank ISR early** (a real hardware present-fence replacing G1's software-measured one — the tear-free/vsync surface OT-52's "must be beautiful" + OT-45's latency-is-beauty presume), because it's bounded (flip + plane-address + vblank, keep the mode); **keep full modeset a separate later "only-if-required" slice** (Janus's caution — display-engine is a trap graveyard, blind-hardware, its own gated dispatch). **GRAFT: Rung 1 = flip+vblank+real-present-fence (early, bounded); full modeset = deferred (Janus GFX-8 scope).**
3. **Rung 2 (hardware raster) — DEFER to measured evidence (both agree), + a `2b` feasibility spike (Oracle's insight).** Both explicitly decline to commit Rung 2 and keep the seam renderer-agnostic so 2a-vs-2b is a swap-in decided by Rung-0/1 data. Oracle adds the load-bearing insight: **2a (WebRender-over-GL) needs the 3D pipeline (Mesa-scale, disjoint from all Phase-6 work), whereas 2b (Vello-on-compute) maps onto the GPGPU substrate we already silicon-proved** (Vello is a *compute-shader* rasterizer, same shape as our `GPGPU_WALKER`+EU kernels). If 2b holds, the desktop gets accelerated raster *reusing our asset* rather than building a greenfield GL stack. **GRAFT: don't decree Rung 2; add a small `2b` feasibility spike — does Vello's tiled-compute model port onto our EU-compute path the way matmul/GELU did, or is the gap (general compute-shader runtime + a Vello port) as large as the 3D pipeline? Evidence decides, not decree.**
4. **OT-59 gates the FIRST GPU ISR (Oracle) — the cross-lane constraint Janus's THINK missed.** The first GPU interrupt in the whole system is Rung 1's vblank/flip-complete ISR, whose wake path is **exactly the CP-14/15/16 wake-race family OT-59 is closing.** **GRAFT (adopt): Rung 0 (no GPU IRQ) proceeds NOW; Rung 1's first GPU ISR must NOT land until OT-59 closes.** This is the value of a panel member who carries the OT-59/pitfall-bank context — the browser-focused seat structurally wouldn't have caught it.

## 3. The buildable shape (the slice ladder, merged + gated)
- **Rung 0 — software floor — BUILDABLE NOW, in parallel with OT-59 (no GPU IRQ, no gate contention).** = the G1 compositor slice-1 (the two ratified kernel objects: shared-pixel-buffer + InputFocus) + tiny-skia/Vello-CPU composition into `fb::blit_rgba` + **the browser's `swgl` floor** (wire Servo's existing `swgl` surfman device to our present surface). **Delivers: the desktop's first composited Workfield pixels AND the browser's correctness harness — with zero display-engine or 3D bring-up.** It is the kill-switch (accel-off ≡ this, bit-for-bit).
- **Rung 1 — display engine (flip + vblank + real present-fence) — GATED ON OT-59** (first GPU ISR; blind-hardware ⇒ the failure-mode/discriminator-section rule applies; inherit Limine's mode). Delivers tear-free vsync present — "the GUI is where the PL lives, and it must be beautiful."
- **The DMA/VT-d + cap-submit hardening** (move iGPU to a translated domain, honor RMRR, `GpuSubmitCap` + per-context PPGTT witness) — kernel-touching, queues behind OT-59; this is the I-14 containment for the least-contained device.
- **Rung 2 — hardware raster — DEFERRED to measured evidence** (2a WebRender-over-GL / 2b Vello-on-compute), behind the renderer-agnostic seam; preceded by the 2b feasibility spike. Full modeset (Janus GFX-8) is a separate "only-if-required" blind-hardware dispatch; Limine's boot mode stays the recovery contract until it independently proves replacement.
