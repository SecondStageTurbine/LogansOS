## Section 373 checks

- **FAIL — decline/refusal/write failure preserves the old zone, RTC mode and clock.** Decline now works: Back returns to the preceding page without emitting `Outcome::Confirm` (`userland/setup-core/src/lib.rs:451-456`), and only that outcome invokes the clock operation (`userland/neo-init/src/desktop_session/setup.rs:75-88`). Kernel refusal also works: `confirm_zone` returns before either settings call or the zone/readout assignments (`userland/neo-init/src/desktop_session.rs:8507-8519`); an already-confirmed clock returns false without a second call (`userland/neo-init/src/desktop_session/setup.rs:365-374`). However, after kernel acceptance, **both `set_wm` statuses are discarded** (`userland/neo-init/src/desktop_session.rs:8524-8525`), then the selected zone/RTC mode is installed, the clock redrawn and `Ok(true)` returned regardless (`userland/neo-init/src/desktop_session.rs:8527-8538`). `set_wm` can return `STATUS_SETTING_STORE` when commit fails (`userland/neo-init/src/desktop_session/settings.rs:418-438`); write/read-back checks are at lines 313-323. Concrete counterexample: start with zone 0 and local RTC (the defaults), choose New York id 105, accept the kernel confirm, and make the zone record's `write_whole` return false. The stored zone stays 0, but the live clock becomes New York/EDT and the wizard reports confirmation success. To exercise both keys, choose Etc/UTC id 0 from those defaults and fail the RTC-mode write: stored `rtc_local` stays true while live `rtc_local` becomes false. Separate commits also permit a successful zone write followed by a failed RTC-mode write. The kernel offset is already committed before these failures, so checking a status after the syscall alone cannot provide the requested transaction. The refusal control injects `EALREADY` before persistence and does not cover these failures.

- **PASS — scenario leg declines and checks stored id/clock unchanged (source witness).** `SETUP_TZ_SKIP` enters Time zone, types `new y`, selects the match, then Esc returns to Welcome and skips (`tools/xtask/src/login_scenarios.rs:466-482`). The decline leg requires that route and rejects a confirm log (`tools/xtask/src/login_scenarios.rs:1983-2011`). Its shared `unchanged` witness rejects application of keys 4/5, rejects confirmed UTC and EDT, requires exactly one settings write (the initial defaults), and checks the journal remains near the original RTC instant without TIME_UTC (`tools/xtask/src/login_scenarios.rs:1943-1980`). Thus preservation of the stored id is checked through absence of any subsequent settings write/application; this is a fresh-default test, with no separate post-decline disk read-back or arbitrary pre-existing-zone comparison. The refusal leg calls the same witness after requiring errno 114 and `confirmed=0` (`tools/xtask/src/login_scenarios.rs:2013-2034`). Registration: `tools/xtask/src/main.rs:3642-3660`. These are source verdicts, not runtime passes.
