2. **Static `_S5` decode — FAIL.** THINK:125-130 scans for `_S5_` preceded by `NameOp` and accepts the sole static package, but never resolves the AML namespace path. A valid DSDT can define `Method (\_S5, 0) { ... }` and separately `Scope (\_SB) { Name (_S5, Package (0x02) { Zero, Zero }) }`. The byte scan sees one `NameOp _S5`, accepts `\_SB._S5` as the root sleep object, and programs SLP_TYP 0 instead of failing closed on the dynamic root `\_S5`. Parse/resolve the root namespace sufficiently to prove the accepted Name is exactly `\_S5` and reject a non-static root object; add this counterexample to the host KAT. This is a wrong shutdown state, not merely a diagnostic concern.

3. **Restart order — PASS.** The FADT reset-register-first chain and bounded 8042, conditional CF9, triple-fault fallbacks are coherent at THINK:150-177. The corpus table correctly routes OptiPlex/M75q/MSI through the FADT SMI command at `0xB2` with values `0x73`/`0xBE` (:56, :59-60); it does not assume CF9 for them. The distinction between guest shutdown and guest reset is available in QMP’s `SHUTDOWN` and `RESET` events, as used by THINK:305-309 and :313-316 ([QEMU QMP Reference](https://www.qemu.org/docs/master/interop/qemu-qmp-ref.html)).

4. **Clean shutdown and NeoFS durability — FAIL.** K2 says that after a five-second no-progress overrun it logs dirty count and continues, claiming copy-on-write superblocks preserve the last durable generation and the volume remains consistent (THINK:185-196). That consistency claim does not follow from the described drain/flush sequence, and the failure path does not honor OT-87’s uncertain-flush rule.

   Concrete cut: a metadata-changing operation publishes a new root and higher-generation superblocks. `write_superblock_copies_cached` dirties all three copies (`kernel/src/fs/neofs/inode.rs:2549-2571`); the cache submits roles in Data, Inode, RootDirectory, FreeMap, Superblock order (`kernel/src/fs/neofs/cache.rs:25-39,547-583`), then performs a single device flush after all dirty writes (`cache.rs:591-605`). If that flush errors, or the K2 deadline expires while it is unresolved, the allowed OT-87 model permits the device to persist all three new 512-byte superblocks but none of the newly referenced root/directory blocks. All old copies have been replaced; mount selects the highest valid generation and validates its root (`kernel/src/fs/neofs/mount.rs:247-277,305-307`), so the new candidates fail validation and no older generation remains. This is a volume-unavailable/integrity failure, not just loss of un-fsynced recent content. OT-87 explicitly says a failed flush can persist an arbitrary subset in any order, and forbids advancing after it (`origin/main:docs/THINK-2026-10-27-ot87-installer.md:463-498`, durability rules in §4.7).

   The design must specify a commit protocol that preserves a recoverable old generation until data/metadata durability is established, and treat unsupported/failed/timed-out flush as uncertain rather than clean. The current cache skips the barrier when `supports_flush()` is false and clears `flush_required` (`cache.rs:591-605`); a shutdown path must fail closed or explicitly weaken its guarantee there. It also needs to say which read-back verification is required: OT-87 uses read-back for content verification while warning it does not prove persistence. The current `fsync_regular` early-returns for a read-only mount (`kernel/src/fs/neofs/inode.rs:352-364`), so the proposed “mark read-only, then global fsync_regular” must retain a shutdown-only drain path after write freeze (THINK:191).

5. **Power capability — PASS.** The objectless, non-derivable/non-grantable `PowerControl` capability is kernel-minted for neo-init; the syscall checks the action right and returns EPERM without it (THINK:249-273).
