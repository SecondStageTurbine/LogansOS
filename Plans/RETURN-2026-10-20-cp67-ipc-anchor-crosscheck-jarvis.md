# RETURN: CP-67 IPC-anchor cross-check (Jarvis / Codex)

**Reviewed:** `claude/cp66-followups` at `2e3eecba916ecb94fafe2f27e0bdb0c5a96fe778` against `origin/main` `8d3b146d`

**Verdict:** **MERGE-WITH-NITS**

CP-67 closes the product-reachable syscall leak. The unsafe borrow in `with_channel_anchor` remains valid across park, migration, and resume because scheduler ownership moves only `Box<Thread>` values; every normal return takes the anchor from the resumed thread, and every force-killed route reaches `Thread::free` with the anchor still owned there. I found no product correctness blocker.

## Finding

### N1 — low, test-only: one older direct-channel kill probe still owns channel clones on the raw-freed stack

`q8c_foreign_target_blocker` obtains a by-value clone of `Q8cForeignFixture` (`kernel/src/test_harness.rs:10194-10199`, `:10207`). That clone contains two `Arc<Channel>` fields (`:10145-10155`). The thread then calls `Channel::recv` directly and parks (`:10216-10220`), bypassing `with_channel_anchor`; the scenario's killer force-stops that process (`:10283-10288`). Its stack therefore retains both cloned channel counts when raw-freed, exactly the CP-30 shape.

**Repro:** instrument `neo-test-q8c-blocked-kill-foreign-parked` with `Arc::strong_count` baselines for `foreign_channel` and `target_block_channel`, run the existing kill, call `reset_q8c_foreign_state`, and reap. Both counts remain one above the no-frame baseline. The existing `frame_audit` does not detect this heap/Arc leak.

**Impact:** feature-gated test hygiene only. Production channel operations enter through the four syscall helpers, and the other direct kernel callers are test code that either borrow a static channel without cloning it or complete normally. This does not reopen CP-67 for shipped code. Suggested follow-up: have this stand-in enter the real syscall dispatcher, or avoid the by-value fixture clone across its direct park.

## Numbered refutation

1. **Borrowed pointer and migration.** `Thread::alloc_from_slab` writes the value once into slab-backed heap storage and returns a `Box<Thread>` (`kernel/src/sched/thread.rs:186-198`). Scheduler current/ready/token/endpoint ownership is uniformly `Box<Thread>` (`kernel/src/sched/scheduler.rs:171-180`, `:244-345`; `kernel/src/ipc/mod.rs:79-102`). Rotation and every blocking primitive use `mem::replace` to move that box, not the payload (`scheduler.rs:799`, `:1632`, `:1687`, `:1747`, `:1817`). Cross-CPU rendezvous likewise transfers the box between ready rings (`:1929-2007`). Thus the `ipc_anchor` slot address borrowed at `scheduler.rs:1333-1351` is stable. Extraction cannot free it while its frame is executing: IPC blocking releases the channel and scheduler locks only after switching to the new stack, and the OT-31 reap order requires the scheduler lock before freeing a zombie.

2. **Take-back is from the right thread.** A blocked call resumes after `context_switch_with_release2` only when its own box has first been installed as that CPU scheduler's `current`; all scheduling paths set `current` before switching (`kernel/src/sched/scheduler.rs:799-804`, `:1687-1693`). The resumed primitive then reads `current.blocked_return` (`:1727-1730`), after which `with_channel_anchor` takes the same current thread's slot (`:1351`). `continue_current_after_receive` only enqueues the producer and sets defer credit; it does not replace the consumer currently executing (`kernel/src/ipc/mod.rs:659-665`). Same-CPU front wake also only enqueues. I found no route where `op` can return under another thread's `current` box.

3. **Every park exit drops exactly once.** Normal rendezvous and its success/EFAULT branches remove the peer box and wake it (`kernel/src/ipc/mod.rs:152-174`, `:225-246`, `:324-356`, `:388-422`); the resumed frame takes and drops its own anchor. Immediate EPIPE/no-park paths return through the same take-back. `close_peer` wakes a peer or foreign waiter with EPIPE and zombifies only an owned exiting waiter (`:567-610`). Terminate and fault-kill sibling drains extract the waiter before zombifying it, so the frame never resumes and `Thread::free` clears the still-present anchor (`kernel/src/sched/thread.rs:217-236`). If a wake makes the thread Ready and `kill_thread_by_pid` wins before it runs, the same reap path drops it. The branches are exclusive: endpoint extraction transfers the one `Box`, and a normal take-back leaves `ipc_anchor=None`, making the later natural reap a no-op for that field.

4. **Last-count drop and lock context.** Normal take-back moves the anchor out while briefly holding the scheduler lock, releases that lock, then drops the returned `Option<Arc<_>>` (`kernel/src/sched/scheduler.rs:1351-1353`). Reap removes the zombie while holding the scheduler lock, releases it, and only then calls `Thread::free` (`:2480-2518`); `Thread::free` clears the anchor before returning storage to the slab and holds no scheduler or channel-state lock (`kernel/src/sched/thread.rs:217-236`). Interrupts are masked, which is already the established context for dropping the stack, pmap, and process anchors and using the heap. A product IPC waiter itself owns an anchor, so the channel's last count cannot disappear while that waiter remains in its state. The direct test-only exception is N1.

5. **Cycle lifetime.** The temporary `Channel -> EndpointState -> Box<Thread> -> Arc<Channel>` cycle replaces the old frame-owned count one-for-one. Rendezvous takes the waiter out and its eventual return removes the back edge. `close_peer` first replaces/extracts endpoint states, then wakes or zombifies after releasing the channel lock (`kernel/src/ipc/mod.rs:570-610`), so closing every handle or losing the peer still breaks the cycle. Syscall handle closure invokes `close_peer`, as does process teardown; there is no product state where handles disappear without extracting/waking the parked box. Force-kill improves over the old code because reap now clears the back edge instead of losing a destructor on the raw stack.

6. **Nesting and reentrancy.** The only production blocking `Channel::{send,recv,grant,recv_grant}` calls are the four syscall implementations, and all four use `with_channel_anchor` (`kernel/src/arch/x86_64/syscall.rs:5346`, `:5371`, `:6737`, `:6751`). A user thread cannot enter another syscall while the first is live; interrupt handlers do not dispatch user syscalls or call these channel operations. The channel methods themselves do not re-enter the helper. Therefore the `debug_assert!(ipc_anchor.is_none())` at `kernel/src/sched/scheduler.rs:1339-1343` is upheld in product. Direct kernel calls are feature-gated tests; the killed by-value-clone exception is N1, while static-borrow callers own no channel clone and the cross-CPU/wait-any callers rendezvous normally.

7. **`sys_grant` early drop.** After rights validation, the payload contains only `grantor_pid`, `source_cap_id`, and offered rights; the cloned source handle is dropped at `kernel/src/arch/x86_64/syscall.rs:6724-6738`. `complete_grant` deliberately re-fetches the grantor and resolves `source_cap_id` under the current handle table (`kernel/src/sched/process.rs:1858-1916`), then derives the child from that fresh handle. Revocation/removal while the grantor is parked therefore produces the existing `GrantorBadCap`/EPIPE result; retaining the old clone never granted authority and is unnecessary for lifetime safety. Tensor sharing captures its slot only from the freshly re-resolved handle.

8. **Tests.** `ipc_kill_caller` invokes `syscall_dispatch_for_test`, which calls the real `syscall_dispatch` (`kernel/src/test_harness.rs:18354-18360`; `kernel/src/arch/x86_64/syscall.rs:2912-2914`). The bound pid/pmap changes only how the stand-in enters ring 0; channel lookup, helper, endpoint park, terminate extraction, zombie queue, reap, and `Thread::free` are production code. The negative control restores both frame ownership and the grant source clone: each killed channel remains at count 2 instead of 1, and the grant leaves the model one above baseline, so its first-failure and per-leg logs discriminate the intended leak. The rendezvous receiver genuinely parks before the sender runs and both processes fully exit/reap before the count check; count 1 plus successful 1/1 results covers the take-back path, while a double drop would invalidate the live harness `Arc`/channel use. QEMU execution was unavailable locally, noted below.

9. **Composition.** `ipc_anchor` needs no `kill_protected` entry because an IPC-parked box is owned by the endpoint and is intentionally extractable; its owned anchor makes raw reap safe. `admission_section` and `inference_lifecycle` protect Ready/token-parked inference frames instead. Production inference/admission code does not call a blocking channel operation, and production IPC syscall code does not enter either inference section, so the fields do not overlap or change the CP-65/66 predicate.

10. **Other branch changes.** The B1c marked-entry probe now calls `syscall_dispatch(SYS_INFER_RUN, ...)` for both inventory and graph cases (`kernel/src/arch/x86_64/syscall.rs:2379-2383`), so an arm-wide wrapper would be observed. The small clippy edits are behavior-preserving: redundant integer casts and an immediately-invoked closure were removed, and the context-switch counter re-export is gated on its actual consumer. I ran the exact blocking clippy command for all five new matrix arms; their feature strings match real `kernel/Cargo.toml` features and the workflow passes each through `--features "${{ matrix.features }}"` (`.github/workflows/ci.yml:780-811`, `:854-862`). The `guarded_clone` NOTE's reachability claim is accurate: `reservation::try_migrate` is called only by the residency daemon and the debug seam, while `residency_daemon::start()` has only two callers, both in `test_harness.rs` (`kernel/src/test_harness.rs:13797`, `:17108`; start at `kernel/src/ai/residency_daemon.rs:307`).

11. **Anything else.** I exhaustively checked `Thread::free` call sites: live zombies are removed from scheduler ownership before free; other sites free unstarted threads with `ipc_anchor=None`, and the OT-31 quarantine releases its lock before free. No second product finding survived re-verification.
