4. **Input still works without the wait — PASS.** The USB port service starts before the evidence block and enumerates ports every 25 ticks, so a keyboard or mouse arriving after the summary is still picked up; the user sees the desktop first and can then use the device. For a touchpad whose initialization succeeded but has not reported motion yet, its service thread also starts before the evidence block and remains active; later reports go through the normal input routing, so the user can move/click after the desktop appears. A touchpad whose initialization actually failed remains unavailable: initialization is synchronous and the service returns when `READY` is false, with no later retry. That limitation also existed on the old hold path, which immediately held on `!READY` rather than retrying initialization.
