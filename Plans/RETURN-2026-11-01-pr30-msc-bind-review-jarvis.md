# Relay 238: PR #30 review — USB mass-storage binding

Reviewed head: `6792c984fc44b0b3815cf00c2981ebd47ef0e2e7` (`pr30`).

- **PASS — Read-only and the Zenbook rule.** The disk's `write_block` always returns `BlockError::Unsupported` (`kernel/src/drivers/usb/msc.rs:318-321`). Generic `submit(Write)` is stopped at the registered `GuardedDevice` by `write_allowed` (`kernel/src/drivers/block/mod.rs:480-495`); direct `write_block` is stopped by the same guard (`kernel/src/drivers/block/mod.rs:511-517`). With no sealed marker, the guard arms no writable extents (`kernel/src/drivers/block/mod.rs:410-427`), so both public write paths refuse. The install-claim-only bypass still calls the inner device's `write_block` (`kernel/src/drivers/block/mod.rs:575-583`), which returns Unsupported for this disk.
- **PASS — DMA containment and bounded waits.** Both transport buffers are allocated from the DMA arena (`kernel/src/drivers/usb/msc.rs:361-367`), and every bulk submission fences its transfer length before handing the address to xHCI (`kernel/src/drivers/usb/msc.rs:191-200`, `203-215`). The event ISR routes transfer events through `IrqSafeMutex` queues (`kernel/src/drivers/usb/xhci.rs:485-519`, `895-903`); no governance lock is taken there. A transfer with no completion exits `wait` after `WAIT_POLLS` iterations (`kernel/src/drivers/usb/msc.rs:38-40`, `124-136`) and is classified as an error (`kernel/src/drivers/usb/msc.rs:139-146`).
- **FAIL — Hot-unplug lifecycle.** On detach, hotplug removes the address-tree subtree only (`kernel/src/drivers/usb/xhci_hotplug.rs:148-152`); it does not notify the MSC driver or unregister its block device. The MSC bind registers `MscDisk` at `kernel/src/drivers/usb/msc.rs:487-501`, and there is no corresponding unregister path. Concrete input: pull the stick during a block read, then look up/read that registered device again. The in-flight read can fail, but the stale block-device handle remains registered and can target the detached slot. Its transport and DMA buffers remain retained by the registry, so this code does not currently free them; it also has no detach synchronization or stale-handle invalidation.
- **PASS — Binding.** `find_bot` accepts only interface class `0x08`, subclass `0x06`, protocol `0x50` via `is_bulk_only_scsi` (`kernel/src/drivers/usb/msc.rs:58-71`; `kernel/src/drivers/usb/msc_logic.rs:47-50`). Other interface tuples are skipped, and `probe` returns false when no matching interface with both bulk endpoints exists (`kernel/src/drivers/usb/msc.rs:74-81`).
- **PASS — Kill-switch.** `usb-storage` is an opt-in feature, absent from the default feature list (`kernel/Cargo.toml:77`, `kernel/Cargo.toml:401-405`); both MSC modules and the driver registration are gated on it (`kernel/src/drivers/usb/mod.rs:48-52`, `264-268`). With the feature off, the MSC driver is not registered and the existing offer path leaves the interface unclaimed.
