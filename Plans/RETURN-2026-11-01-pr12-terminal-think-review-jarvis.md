# RETURN: PR #12 terminal THINK review (Jarvis)

Reviewed PR head: `d32637b347d715d53508e113b0daffe145a5d7a2` (`docs/THINK-2026-10-31-l1a-terminal-window.md`).

- **FAIL — Client protocol, framing, and flow control** (`docs/THINK-2026-10-31-l1a-terminal-window.md:66-76, 122-126, 154-156, 205-206`). A terminal that stops draining the child's stdout/stderr pipe has no specified behavior: the plan defines nonblocking writes only from terminal to child, but not the child's write semantics, pipe capacity, backpressure, or whether a blocked writer can recover. Concrete case: a child continuously writes output while the terminal is not scheduled to read; it can fill the pipe and block indefinitely. The plan also needs to define the shared term-page access ordering (the child is said to publish with Release, but the terminal's corresponding acquire/read protocol is not stated; see lines 99-102 and 115-126).
- **FAIL — Escape subset and byte oracle** (`docs/THINK-2026-10-31-l1a-terminal-window.md:163-190, 192`). The parser subset names many needed output controls and answerbacks, but the actual key-encoder byte mappings are delegated to OT-88, and the proposed hand-laid escape input/grid table is not present; §5.2 only says it will be made later. Thus this THINK does not yet provide a concrete byte oracle to establish that kibi and the line-editing shell work. For example, it does not give expected input bytes for arrow keys under normal and DECCKM modes or any expected grid row for a listed output sequence.
- **FAIL — Input security and paste** (`docs/THINK-2026-10-31-l1a-terminal-window.md:214-245`). The lock-route argument and handle-rights restriction address keys typed while locked, and OSC 52 is disabled. But paste is not specified as an input event: §5.1 says bracketed-paste mode is accepted while “nothing pastes yet,” while §6 asserts there is no paste source. It never defines whether paste is disabled, or how pasted bytes are marked/escaped so embedded controls cannot be mistaken for ordinary typed input. Concrete case: a paste containing `ESC [ 200 ~`, `ESC c`, or `0x03` has no defined path or representation in the terminal protocol.
- **PASS — Kill-switch** (`docs/THINK-2026-10-31-l1a-terminal-window.md:247-254`). With the module off, it is absent from the image and allowlist and has no Home intent; the plan explicitly says the WM gains no code path with it off and existing desktop captures remain unchanged.
- **PASS — Prior-art survey** (`docs/THINK-2026-10-31-l1a-terminal-window.md:277-293`). The survey records a head, last-commit date, and licence for vt100, vte, termion, and kibi, and states what each is used for. The relative “about a year” description for termion is consistent with its listed 2025-11-21 commit date as of the 2026-10-31 review date. The deferred target-build and scrollback checks are called out explicitly.
