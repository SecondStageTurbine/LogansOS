# RETURN: relay #95, OT-87 R2 model from NeoFS review

**Reviewer:** Chad, GPT-6-Luna, high effort
**Overall:** FAIL — one source-label defect in checklist item 4. The reviewed code preserves model precedence and pin enforcement in the cases checked; the failure is that Arthur can report the wrong source in a mixed-source boot.
**RAG:** healthy (`ollama=true`, `qdrant=true`). No tests were run for this review.

1. **The pin can't be skipped by the path — PASS.** `pin_for` normalizes the absolute path before `neofs_pin` compares it (`kernel/src/neofs_model.rs:26-35`). The shared normalizer removes empty and `.` segments, pops `..`, and thus maps `/neofs//x`, `/neofs/./x`, `/neofs/a/../x`, and `/neofs/x/` to `neofs/x` (`kernel/src/fs/mod.rs:1579-1601`). The pin matcher requires a direct child of `/neofs/`; nested paths and unpinned names return `None` (`kernel/src/boot_model_logic.rs:157-174`).

2. **The hash compared is the pinned quantity — PASS.** NeoFS hashes every file byte in logical-block order and compares the result to the inode's whole-file BLAKE3 (`kernel/src/fs/neofs/inode.rs:1474-1498`). The verified cache key includes generation, size, block count, and content hash (`kernel/src/fs/neofs/inode.rs:1127-1143`); write and truncate clear it after installing a new record (`kernel/src/fs/neofs/inode.rs:1301-1304`, `1332-1335`). The returned hash is the inode's content hash and generation (`kernel/src/fs/neofs/inode.rs:1212-1225`), which the path check compares against the existing model/vocab pins (`kernel/src/neofs_model.rs:40-79`).

3. **The bytes built are the bytes that passed — PASS.** The model path checks before reading and rechecks the verified hash and generation after reading, before building from the owned byte buffer (`kernel/src/arch/x86_64/syscall.rs:2590-2615`). NeoFS writes use copy-on-write data blocks and install a new inode record with a new generation (`kernel/src/fs/neofs/inode.rs:236-289`), while reads on an open file validate its captured generation (`kernel/src/fs/mod.rs:341-352`). The vocab pin is checked on read-open (`kernel/src/arch/x86_64/syscall.rs:5893-5902`); a rewrite during the subsequent reads makes the handle stale, and a rewrite after the vocab bytes have been read cannot change the owned bytes already parsed by Arthur (`userland/neo-arthur/src/main.rs:2760-2803`).

4. **Source order in the kernel and in Arthur — FAIL (source label only).** Kernel preload checks boot modules first and skips NeoFS whenever any boot module names the model, even if that module later fails its pin (`kernel/src/boot_modules.rs:530-535`, `595-608`). Arthur retries a model or vocab from NeoFS only when the corresponding boot path returns `ENOENT` (`userland/neo-arthur/src/main.rs:2732-2745`, `2867-2885`). The two preload lookups also distinguish boot and NeoFS records (`kernel/src/boot_modules.rs:703-729`). However, the displayed `model_source` is also mutated by vocab fallback: with a valid boot model module, no boot vocab module, and a valid pinned vocab on NeoFS, `try_load_sidecar` sets `model_source=Neofs` on vocab `ENOENT` (`userland/neo-arthur/src/main.rs:2737-2745`), then the model load succeeds from the boot-module path (`userland/neo-arthur/src/main.rs:2871-2885`). `preload_boot_model` prints that field as the model source (`userland/neo-arthur/src/main.rs:2693-2702`), so this input predicts `ARTHUR model source=neofs state=ready` although the model came from the boot module. This is a reporting defect; it does not show NeoFS overriding the boot model or bypassing either pin.

5. **Locks and stacks (CP-74, CP-56, CP-82) — PASS.** Syscall-side model check/recheck is inside `vfs_body_if_on` (`kernel/src/arch/x86_64/syscall.rs:2583-2615`); vocab verification is wrapped the same way (`kernel/src/arch/x86_64/syscall.rs:5887-5902`). NeoFS preload and vocab checks run inside `inference_stack::run_checked` (`kernel/src/boot_modules.rs:623-632`), and the preloader is called after the scheduler is initialized (`kernel/src/main.rs:809-821`, `885-895`). The verified-content mutex is released before hashing and reacquired only to store the cache entry (`kernel/src/fs/neofs/inode.rs:1460-1471`).

6. **Scenarios — PASS.** The ordinary NeoFS scenario requires a matching digest, a successful preload, Arthur's ready source line and a reply (`tools/xtask/src/main.rs:16808-16831`). The damaged scenario requires `match=false`, `errno=-74`, the disk-damaged reply, and rejects both a `NEOFSMODEL loaded` line and a `model_kind` line (`tools/xtask/src/main.rs:16833-16851`); therefore, skipping the pin and building the flipped model would fail the serial check. Module-wins requires a boot-module load and forbids NeoFS consultation (`tools/xtask/src/main.rs:16853-16873`). The off control requires the existing absent reply and forbids any NeoFS/model-kind line (`tools/xtask/src/main.rs:16874-16888`).
