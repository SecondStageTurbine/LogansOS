# DISPATCH: neo-shell richer builtins — fs commands + `status` → Jarvis

**Date:** 2026-06-20
**From:** PM (Claude)
**To:** Jarvis (free main-tier). New branch off `origin/main` HEAD: `codex/neo-shell-fs-builtins-jarvis`.
**Status:** DISPATCHED. **Make `neo-shell` feel like a shell — and show off how lean the OS is.** Today it's `exit` / `arthur` / `spawn` — a launch-and-converse REPL. This adds (a) the filesystem builtins a user expects (`help`, `ls`, `cat`, `pwd`, `cd`, `echo`) over the **existing, proven fs ABI** (no new syscalls), and (b) a **`status` command** backed by one small **aggregate** observability syscall (`sys_sysstat`) — the "3 processes, 4 MB, 4 cores" demo for the bare-metal boot. The fs builtins are mostly host-testable logic; `status` adds the one new (read-only, aggregate) syscall. **Pipes/redirection + a per-process `ps` are deliberate follow-ons, not this build.**

## 0. The decision this build makes
Turn the minimal REPL into a usable interactive shell for the "boot → look around → talk to Arthur" experience, **reusing the landed fs ABI** (`sys_open`/`sys_read`/`sys_readdir`/`sys_close`), **plus** a `status` command that visibly demonstrates the OS's leanness on real hardware. `status` is backed by an **aggregate-only** stats syscall — system-wide counts (processes, memory, cores, uptime) with **no per-process identity** — so it shows "how few are running" **without** violating the capability keystone (no process *enumeration*; that's the deferred OT-9 / ADR-014 observability lane). Existing commands (`exit`/`arthur`/`spawn`) unchanged.

## 2. ISCs
- **ISC-1 — The fs builtins (over the existing ABI).** `ls [path]` (`sys_readdir` on a dir cap → list entries), `cat <file>` (`sys_open` READ + `sys_read` loop → stdout), `pwd` (print the shell's cwd), `cd <path>` (update the shell's cwd with path resolution), `echo <args...>`, `help` (list commands). **No new syscalls** — compose the landed fs ABI. Existing `exit`/`arthur`/`spawn` unchanged.
- **ISC-2 — Pure-logic split (host-testable, the `shell_logic.rs` discipline).** Extend `ParsedCommand` + put **command parsing, argument handling, path resolution (relative/absolute against cwd, `.`/`..` normalization), and output formatting** in `shell_logic.rs` as pure functions → host KATs. The thin `main.rs` layer does the actual syscalls.
- **ISC-3 — cwd state + path resolution.** The shell tracks a current directory; `cd`/`ls`/`cat` resolve relative paths against it. Resolution (incl. `..` not escaping root, trailing slashes, empty) is pure-logic + host-tested (an independent table of input→resolved cases — the oracle).
- **ISC-4 — Error handling (no crash, clear messages).** File-not-found, not-a-directory, permission-denied (EPERM/EACCES from the cap layer), oversize-line, bad-args → a clear message to stderr/stdout, shell continues. Never panic on user input.
- **ISC-5 — `sys_sysstat` — the aggregate observability syscall (the one kernel change).** A new native syscall `sys_sysstat(buf_ptr, len) -> isize` that fills a small fixed `SysStatV1` struct with **system-wide aggregates only**: `process_count`, `frames_used` (and/or bytes), `cores_online`, `uptime_ticks`/ms, kernel name/version. **Reads existing kernel state** (the process registry, the frame allocator's used count, the APIC online-CPU count, the timer) — no new bookkeeping. **Capability-clean by construction: aggregates, NEVER per-process identity** (no pid list, no names) — so it discloses nothing the cap model forbids and needs no handle. **Rigorously validate the userland buffer** (mapped+writable+len, the `sys_inspect`/`sys_getrandom` pattern; `copy_process_snapshot_to_user`-style). **Kill-switch `kernel-sysstat` default-OFF ⇒ `SYS_SYSSTAT` returns `ENOSYS`, kernel bit-for-bit today** (equality regression); the ISO/demo build enables it. **New `unsafe` = the validated struct write** (SAFETY-doc'd). No new invariant (a read-only aggregate over existing state).
- **ISC-6 — The `status` shell command (userland).** Calls `sys_sysstat`, formats the aggregates into a human line/table (`processes: N   memory: X   cores: M online   uptime: …`), **gracefully reports "observability disabled" on `ENOSYS`** (feature off). The formatting is pure-logic in `shell_logic.rs` → host KAT (given a `SysStatV1`, the rendered string is exact). A `libneo` wrapper over the syscall.
- **ISC-7 — Standards.** The **fs builtins (ISC-1)** add **no syscalls / no kernel change**; the **only kernel change is `sys_sysstat`** (ISC-5, feature-gated default-off ≡ today). Existing `exit`/`arthur`/`spawn` behave identically. SPDX on any new file. `fmt`/`clippy --workspace --all-targets -D warnings` via Docker (kernel clippy blocking — there's now a kernel touch). ADR/ANSPEC note: `sys_sysstat` is the aggregate-only first slice of OT-9/ADR-014 observability; the per-process `ps`/procfs stays deferred (it needs the capability-scoped design OT-9 is about).

## 4. Scope guard
The fs builtins (`help`/`ls`/`cat`/`pwd`/`cd`/`echo`) + the `status` command + the **aggregate** `sys_sysstat` syscall + the pure-logic + the scenario **only**. **Do NOT** build pipes/redirection (`|`/`>`/`<` — a follow-on: fd-dup + multi-process plumbing), a per-process **`ps`/`top`/procfs** or any **process enumeration** (capability-scoped observability = the deferred OT-9/ADR-014 lane — `sys_sysstat` is aggregates-only on purpose), job control, history, or line-editing; or touch the `arthur`/`spawn`/`exit` semantics. The only kernel change is the feature-gated `sys_sysstat`. New `unsafe` limited to its validated buffer write. No new invariant.
