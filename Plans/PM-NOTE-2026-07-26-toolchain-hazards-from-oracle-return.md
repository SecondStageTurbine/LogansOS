# PM NOTE: two toolchain hazards surfaced by Oracle's arthur-perf return (2026-07-26)

Recorded so they don't get lost. Neither blocks the arthur-perf merge (`32c8ca7`, already landed clean); both are standing hazards the whole roster should know.

## Hazard 1 — a file-sync tool is SILENTLY corrupting edits (DATA-INTEGRITY, PL-actionable)
Oracle reported: an edit to `kernel/Cargo.toml` was **silently diverted** to `kernel/Cargo (# Edit conflict 2026-07-26 46rc0gC #).toml` while the write tool **reported success** — the real file was untouched. Caught only because the build then failed. The **same tool produced the `# Delete conflict 2026-07-24 …#).o` strays** in the shared root tree (the ones the prior handover §12 said "do not touch"). This can silently drop **any coder's work** and make a green-looking edit a no-op.

- **Standing rule for every coder (effective now):** after any file edit, **`git diff` (or `git status`) to confirm the intended file actually changed** before building/committing. A "write succeeded" from the tool is NOT proof the file changed. If a `(# … conflict … #)` sibling appears, the edit went to the wrong path — re-apply to the real file and delete the stray.
- **PL action (your environment):** the file-sync/edit layer in the worker trees is corrupting writes under some condition (looks like a sync-conflict rename). Worth investigating/disabling — it's a silent-data-loss vector, not just cosmetic. The `(# … conflict … #)` strays are its fingerprint.
- **✅ RESOLVED (2026-07-26): it was Proton Drive.** `E:\AI Automation\AltimitNeo` (the whole worker-tree root) was inside **Proton Drive's** continuous-sync scope; Proton raced the coders' git `.git/index` + cargo `target/` writes and sidelined the loser into `(# Edit/Delete conflict … #)` copies while the write tool reported success. **Fix applied: the repo path was excluded from Proton Drive sync.** Standing rule for the roster: **a live git+build tree must never live inside any continuously-synced/mirrored folder** (Proton Drive, OneDrive, Dropbox, Resilio, etc.) — the sync client and git both own the files and fight, and the sync client wins silently. The `git diff`-verify-every-edit rule stays as belt-and-suspenders, but the vector itself is gone.

## Hazard 2 — `neo-test`-gated clippy debt is INVISIBLE to CI (structural coverage gap)
Oracle found **~70 clippy errors under the scenario feature** (e.g. `kernel/src/fs/mod.rs:787` `collapsible_if`), **all in `#[cfg(feature = "neo-test")]` code**. The blocking kernel clippy in CI runs **default features**, where that code isn't compiled — so CI structurally cannot see it. Pre-existing (not from arthur-perf — `forward-perf = []` pulls in nothing), but it's a debt pocket of the same class as the pre-`[skip ci]` rot that accumulated invisibly.

- **Tracked lane (not urgent, behind WiFi/browser):** add a CI clippy pass under the scenario/`neo-test` feature set (or a representative matrix) so this class stops being invisible, then clean the ~70. Candidate owner when a slot frees: a host-only/consolidation seat (Prometheus-scoped is fine for the *scan/inventory*; the *fixes* are a main-tier coder). Do NOT fold into a feature build — it's its own hygiene lane.
