## Section 382 checklist

1. **PASS — read-only status operation; short buffer rejected before copy.** `kernel/src/arch/x86_64/syscall.rs:6604` returns `EINVAL` for null or `out_len < 56`, before pointer validation, snapshot construction or copy. The size rule is `kernel/src/net/if_status_logic.rs:176`. The only output is the user-memory write at `kernel/src/arch/x86_64/syscall.rs:6610`, through `write_user` at `:1752`. `kernel/src/net/if_status.rs:27` reads network state and builds a local record; it does not configure the interface, advance DHCP or service the device. CDC-ECM's getter is explicitly pure at `kernel/src/drivers/usb/cdc_ecm.rs:774`; its writer is in the service path at `:853`. Scratch allocation, lock and Arc bookkeeping are incidental kernel writes, as with other read-only syscalls; no network state is written.

2. **FAIL — the complete snapshot can mix different writer states (F1 below).** `kernel/src/net/if_status.rs:28` obtains the DHCP lease and releases its lock, `:30` independently snapshots links, `:42` independently reads carrier, and `:57` can independently read IPv4. No common lock or sequence validation spans them. `dhcpv4::CLIENT` is a `spin::Mutex<DhcpClient>` at `kernel/src/net/dhcpv4.rs:23`; `bound_lease` holds it at `:386`. The ACK writer takes that same lock at `:220` and fills the lease at `:169`, but that protects only the DHCP portion. Identity's writer takes its separate `REGISTRY` at `kernel/src/net/identity.rs:141` and writes the link at `:143`; its reader takes that lock at `:241`. The driver's carrier writer uses an atomic swap at `kernel/src/drivers/usb/cdc_ecm.rs:721`; its getter loads at `:775`. These are separate consistency domains. `kernel/src/net/if_status.rs:16` and the THINK at `docs/THINK-2026-11-02-setup-menu.md:716` explicitly permit disagreement, which does not satisfy this dispatch's stronger requirement. Concrete input and schedule: F1.

3. **PASS — lock order, syscall context and driver isolation for the added path.** Among the network subsystem locks, the new snapshot holds no guard across the next helper (`kernel/src/net/if_status.rs:28`, `:30`, `:39`, `:57`); DHCP's existing `CLIENT -> INTERFACES` edge (`kernel/src/net/dhcpv4.rs:174`, `kernel/src/net/ipv4.rs:249`) gains no reverse edge. The registry helper returns an Arc after releasing the device lock (`kernel/src/drivers/net/mod.rs:86`), before calling any driver getter. Identity's registry is IRQ-safe (`kernel/src/net/identity.rs:18`), as is the device registry (`kernel/src/drivers/net/mod.rs:33`). SFMASK clears IF on syscall entry (`kernel/src/arch/x86_64/syscall.rs:703`), and the periodic net writer also runs IF-off (`kernel/src/net/periodic.rs:118`). None of the new path takes an AI-governance lock or calls driver service, TX, RX, a wait or a flush. The reached driver getters are immutable fields/atomic loads at `kernel/src/drivers/usb/cdc_ecm.rs:764`, `:768`, `:774`; `kernel/src/drivers/usb/mt7601u/mod.rs:4828`, `:4831`, `:4834`; and `kernel/src/drivers/net/virtio_net.rs:336`, `:340`, `:344`. RTL8125 uses immutable identity/MAC and one PHY-status register read (`kernel/src/drivers/net/rtl8125.rs:629`, `:633`, `:637`, `:623`). No driver/ISR mutex is taken by these getters.

   Wording qualification for the PR table: "no two [locks] are ever held at once" should say no two **network subsystem** locks. The IPv4 fallback clones its address Vec while holding `INTERFACES` (`kernel/src/net/ipv4.rs:294`, `:299`), reaching the heap lock (`kernel/src/mm/heap.rs:119`). That existing helper does not establish a new inversion here. Likewise, the registry snapshot can make four sized passes (`kernel/src/net/identity_logic.rs:165`, `:188`), so "four short lock holds" is not a literal count.

4. **PASS — independent hand-laid byte oracle and field checks.** `tools/net-if-status-abi-tests/src/lib.rs:28`, `:44` and `:60` contain literal 56-byte leased/no-device/no-lease examples, independent of both production implementations. `:107` pins every struct offset and flag value; `:145` compares the kernel builder's raw memory with the literals; `:164` checks the independent libneo decoder field by field. ## F1 — mixed lease/link record has no single observation instant

**Location:** `kernel/src/net/if_status.rs:28` through `:59`. **Priority:** P2; blocks the explicit consistency requirement in this review.

Concrete input: interface 0, `cdc-ecm`, MAC `52:54:00:12:34:56`, registry link and driver carrier up, DHCP bound to `10.0.2.15/24`, router `10.0.2.2`, DNS `10.0.2.3`, expiry 86400 and clock 400.

1. CPU A calls the syscall with a valid 56-byte output buffer. It copies that lease under `CLIENT` at `kernel/src/net/dhcpv4.rs:386` and releases the guard on return to `if_status.rs:28`.
2. Before A snapshots the links, CPU B invalidates the lease, then processes link-down and refreshes the identity registry. Concrete writer sites are `kernel/src/net/dhcpv4.rs:201` through `:204` (conflict invalidation; expiry at `:193` through `:194` is another invalidation), `kernel/src/drivers/usb/cdc_ecm.rs:721` (carrier), and `kernel/src/net/identity.rs:141` through `:143` (registry link).
3. A reads the now-down link and carrier, then `kernel/src/net/if_status_logic.rs:159` accepts the saved lease solely because its `ifindex` still matches.

The source-state sequence is `(lease present, link up) = (1,1) -> (0,1) -> (0,0)`. The returned record instead has flags `0x0a` (`PRESENT | LEASE_BOUND`), IPv4 `10.0.2.15`, and `lease_secs_left=86000`, i.e. `(1,0)`. That combination never existed during this execution. The page reads only once (`userland/neo-init/src/desktop_session/setup.rs:49`), so a future call is not a repair of this result.

I compiled and ran the actual `kernel/src/net/if_status.rs` and `if_status_logic.rs` by path in a temporary host harness, replacing the source APIs with controlled stubs. Its link-snapshot stub performs the above invalidation/link-down schedule after the lease helper returns. It asserted and printed:

```text
production snapshot with scheduled source seams: flags=0x0a ipv4=[10, 0, 2, 15] lease_secs_left=86000; source states were (lease,up)=(1,1)->(0,1)->(0,0); returned (1,0)
```

This is a deterministic composition counterexample using production snapshot logic, not a claim of a live SMP/QEMU reproduction. The normal host KAT never includes that locking/composition module.

Required correction: publish/copy a coherent status record, or validate a version protocol that covers all writers contributing to it, including the default-interface choice, lease, link and carrier (and IPv4 fallback). Preserve the existing lock-order and ISR isolation; merely taking `CLIENT` for longer cannot serialize the other writers. Add a controlled writer-interleaving discriminator, then correct the CP-13 table claim to match the enforced protocol. A deliberate best-effort ABI would require an explicit contract change from the PM; it does not pass the present dispatch.
