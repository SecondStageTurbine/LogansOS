- FAIL — **2: The release check is only an exact-tag check; it does not establish that the checkout is the release's content, and it accepts any tag name.** `tools/xtask/src/tzdata.rs:334-336` never runs `git status`/`git diff-index`, and `git describe --tags --exact-match` accepts any tag. Concrete counterexample: in a copy of the clean 2026e checkout, change the `Africa/Abidjan` offset in `africa` from `0:00` to `1:00`; HEAD is still at tag `2026e`, `git describe` still returns `2026e`, and the generator succeeds. Fix: before running `zic`, require `git status --porcelain --untracked-files=no` to be empty (or `git diff-index --quiet HEAD --`) and restrict the tag to the release pattern (e.g. `^[0-9]{4}[a-z]+$`, or pass `--match` to `git describe`).

- FAIL — **3: There is no allocation and a bad zone id is safe, but the "no panic on any input" claim fails at the `i64` bounds.** `tz.rs` is pure (`no_std`, no `alloc`/`Vec`/`String`); `zone(id)` is `Option`-returning and the unknown-id fallback to `ZONES[0]` at `tz.rs:94-96`, `:207-211`, `:214-216` is panic-free, including `u16::MAX`. Concrete failing inputs in a debug/test build (the branch's KAT profile, where overflow checks are on):
  - `utc_to_local(i64::MAX, 105)` (`America/New_York`) panics with `attempt to multiply with overflow` at `tz.rs:164`, through `transition_local`'s `(first + day - 1) * 86400 + t.time` called from `offset_at`.
  - `utc_to_local(i64::MIN, 105)` panics with `attempt to add with overflow` at `tz.rs:177` (`utc + rule.std_offset as i64`).
  - `local_to_utc(i64::MAX, 105)` and `local_to_utc(i64::MIN, 105)` panic in the same arithmetic (`tz.rs:219-230`).
  In a release build overflow checks are off, so these wrap silently instead of panicking: the result is still wrong at the same inputs. The public functions take `i64`, so "any input" includes these; a caller can pass an RTC reading or computed instant directly. Fix: use checked/saturating arithmetic and return a defined result (or reject a documented range with `Option`/`Result`), and add an extremes KAT to `tools/tz-logic-tests`.
