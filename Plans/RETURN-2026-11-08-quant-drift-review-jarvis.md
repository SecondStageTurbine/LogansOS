## Review

- **Kernel's real path — PASS.** `src/lib.rs:22-42` path-mods the kernel's actual forward, GGUF, ops, model, tensor and tokenizer modules; `src/model.rs:4-8` identifies calls to the shipped forward functions. The crate is host-only.
- **All inputs pinned — PASS.** `fixtures/quant-drift-kat-2026-11-08-control.json:5-20` records the `.neom` SHA-256/BLAKE3, upstream GGUF SHA and revision, F16 reference SHA/revision, llama.cpp commit, corpus source/text hashes, token count, offset and window BLAKE3. The float32 safetensors revision and SHA-256 are in `fixtures/quant-drift-model-identity-2026-11-08.json:4-8`. The control-C result file itself omits input identities, but the pinned identity record covers that float32 input.
- **Identical IDs and window across runners — FAIL.** Prompt IDs are generated once from Arthur's `.vocab` and passed to all runners (`ref/run-control.sh:55-57, 87-127`); `src/report.rs:368-378` rejects differing prompt IDs. However, the three PPL inputs are not the same in the reproducible control script: llama.cpp and transformers receive `corpus-window.u32`, extracted from offset 6,144 (`ref/run-control.sh:58-62, 97-127`), while the `.neom` receives full `corpus.u32` with `--corpus-tokens 2048` and no `--corpus-offset 6144` (`ref/run-control.sh:87-94`; default offset is 0 at `src/main.rs:248-256`). `src/report.rs:368-462` does not validate corpus window metadata. The committed `.ours.tsv` records offset 6,144 (`fixtures/quant-drift-kat-2026-11-08-control.ours.tsv:6-11`), which the checked-in script as written cannot reproduce.
- **Bars A/B/C, exact thresholds — PASS (calculation).** A applies exact generated-token identity and ΔPPL ≤0.5%; B applies ΔPPL ≤10%, teacher-forced top-1 ≥90%, and identical boot reply (`src/report.rs:489-531`, `src/main.rs:495-513`). C applies top-1 ≥98% and ΔPPL ≤1%, with no extra tolerance (`src/main.rs:295-312`). The bar implementation adds no tolerance. The recorded B/C verdicts are present in `fixtures/quant-drift-kat-2026-11-08-control.json:823-825` and `fixtures/quant-drift-control-C-f16.json:1-14`.
- **Hermetic test/no corpus text — PASS.** `tests/quant_drift.rs:36-45` returns successfully when `QUANT_DRIFT_NEOM` is unset; the test reads corpus tokens only when `QUANT_DRIFT_CORPUS` is set (`:104-120`). The branch adds no corpus text file; scripts and README say the text is downloaded and not committed (`ref/run-control.sh:27`, `README.md:55-57`).
- **Licences and source copying — PASS, with a dataset metadata caveat.** The README lists llama.cpp MIT, transformers Apache-2.0, PyTorch BSD-3-Clause, Qwen Apache-2.0, and WikiText CC-BY-SA; implementation files use public library APIs and the llama runner is a new harness (`README.md:112-129`, `ref/llama_drift.cpp:1-16`, `ref/fp32_ref.py:14-20`). No upstream source is copied, and no corpus text is committed. The pinned Salesforce WikiText repository metadata also advertises GFDL alongside CC-BY-SA, while its dataset card says CC-BY-SA 4.0; the README's narrower `CC-BY-SA-3.0` wording (`README.md:129`) does not capture that upstream metadata discrepancy. The dispatch's broader CC-BY-SA description is accurate; the source metadata should be reconciled before treating the version-specific note as definitive.

## Finding

The core review blocker is the control-script corpus offset mismatch. As checked in, running `run-control.sh` would compare perplexities from different windows, so the emitted A/B perplexity comparison would not satisfy the dispatch's same-window requirement. The committed artifact records the intended offset, but does not make the runner reproducible as written. No test suite was run for this review.
