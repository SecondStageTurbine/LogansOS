## Checklist

1. **PASS — `fill_bytes`.** `random_neoplutarch.rs:17-26` uses `chunks_mut(64 * 1024)` and checks every syscall result against that chunk’s full length. Empty input iterates zero times; exact 64 KiB, 64 KiB + 1, and unaligned lengths are handled by the same chunking. The kernel caps calls at 65,536 bytes, validates the user buffer, fills a kernel-side buffer, copies only after success, and returns the full length (`kernel/src/arch/x86_64/syscall.rs:5142-5179`; `kernel/src/rng/mod.rs:24-25`). A short result panics rather than returning with bytes unfilled; the current syscall implementation returns either the full length or an error.

2. **PASS — no weak fallback.** The overlay routes target `neoplutarch` to this module (`apply-overlay.py:221-228`). Non-full returns, including `-38` and other errors, panic (`random_neoplutarch.rs:20-25`); the `kernel-rng`-off syscall path returns `ENOSYS` (`syscall.rs:5182-5186`). Pinned toolchain rust-src confirms `DefaultRandomSource::fill_bytes` and generic `hashmap_random_keys` use this route, so RandomState also fails closed; its key counter is not a substitute entropy source.

3. **PASS — scenario detects missing source and missing chunking.** The 200 KiB direct `DefaultRandomSource` check initializes buffers to zero and checks every 64 KiB chunk for a nonzero byte and compares two fills (`userland/std-real-smoke/src/entropy.rs:67-80`). With H1’s no-call/no-source implementation, both buffers remain zero and check 4 fails. With H2’s one-call implementation, 200 KiB exceeds the kernel cap and returns `EINVAL`; the overlay panics and the scenario’s required zero exit fails. The eight-state hash check is explicitly described as keying behavior, not proof of source randomness (`entropy.rs:55-66`); check 3 was removed for the stated counter reason (`entropy.rs:69-71`).

4. **PASS — A4 manifest and negative tests.** `SYS_GETRANDOM` is allowed and has provenance (`tools/ot61-pal-manifest.toml:45,62`). G1’s source scan rejects referenced syscall tokens missing from the manifest (`userland/neo-std-pal/a4_gate.rs:109-120`), and its negative test removes each C2 syscall and requires a G1 finding (`tools/xtask/src/ot61_c05_tests.rs:158-187`). G2 changes `0x190` to `0x191` and requires refusal (`ot61_c05_tests.rs:203-212`). The built-ELF backstop also restricts syscall instructions to sanctioned trampolines (`tools/xtask/src/main.rs:6281-6334`); the manifest association itself is enforced by the patched-source G1 scan.

5. **PASS — staging and F7.** `std_real_bins_for` maps `std_real_smoke` to smoke, panic, and entropy; `std_threads` to threads and thread-abort; and `std_entropy` to entropy (`tools/xtask/src/main.rs:5490-5501`). Harness spawn paths match those maps (`kernel/src/test_harness.rs:2170-2193,2213-2236,2251-2267`). The selected map drives both staging and scenario build (`main.rs:5688-5691,6972-6977`). F7 counts `module_path:` entries and rejects counts above eight (`main.rs:16742-16755`); its test accepts eight and rejects an injected ninth (`main.rs:18061-18071`).

6. **PASS — kill-switch.** The PR body reports byte-identical default, desktop, and usb-host kernels with `NEO_BUILD_ID=kill-switch-fixed`. Independent diff inspection shows the only kernel changes are the `neo-test-std-entropy` feature and test-harness scenario blocks (`kernel/Cargo.toml:370-372`; `kernel/src/test_harness.rs:153-154,1082,2170-2192,2251-2268`); production syscall/RNG implementation is unchanged. The byte-identical builds are author-reported, not reproduced in this review.

7. **FAIL — prior-art completeness.** PR #164’s “Pitfall bank and prior art” body paragraph names Rust std’s own `sys/random/*`, pinned rust-src and license, plus Hermit’s `random/hermit.rs`; it does not name the required `getrandom` crate or its MIT/Apache-2.0 license. This is the checklist-only gap described above, not a code defect.
