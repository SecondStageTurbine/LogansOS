# RUN SHEET: the 0.1 "Arthur Preview" one-boot showcase, image A9 on the OptiPlex 7080 (PL + Janus)

**Why.** The PL asked (2026-10-27) whether any hands-off boot has shown all five 0.1 rungs together. **None has.** Each
rung is proven on its own (`Plans/MILESTONE-2026-07-29-logansos-0.1-arthur-preview.md`), and the earlier one-boot runs
(3b, 2026-08-26; B1, 2026-10-20) never returned. The Zenbook boots have no network lease and no NeoFS volume.

**Why A9 can do it now.** Image A's kernel features are `desktop` → `product` → `boot-neofs` + `boot-eth0`, plus
Arthur's real model. So the shipping image carries every rung's code, and OT-82's "product isn't the product" no
longer applies to image A. The OptiPlex has what the Zenbook lacks:
- the `sda` NEOFSv1 volume (rung 5);
- the ASIX USB-Ethernet dongle with its proven lease (rung 4).

**Image:** A9 (`target/b1-model/A9-main-149431a1.iso`, BLAKE3 `7e990c2f…`, relay #84), already on the KINGSTON stick.
Booting it on the OptiPlex writes nothing to the OptiPlex's NVMe. It does write the `sda` NeoFS volume, which is
exactly rung 5.

**Runbook:** `docs/runbook-baremetal-arthur-optiplex.md` (`git fetch origin && git show
origin/main:docs/runbook-baremetal-arthur-optiplex.md`). Serial capture is via PuTTY to
`C:\Users\<user>\neoplutarch-serial.log`. The serial log is the deliverable. Note the runbook's 2026-10-21 warning:
the Kingston stick is no longer the Ubuntu control stick, so boot the stick from the OptiPlex's **F12 one-time boot
menu**, not from `efibootmgr`.

## The two boots (PL)

**Setup:**
1. Plug in the ASIX USB-Ethernet dongle (connected to the router), the KINGSTON stick (A9), a USB keyboard and a mouse.
2. Leave `sda` connected.
3. Start PuTTY logging, and keep the log open across both boots.

**Boot 1:** press F12 and pick the KINGSTON stick.
1. **Rung 1:** the boot reaches the desktop without any key press.
2. **Rung 2:** the desktop shows. The intro card should say your changes will be kept. Close it with **Esc**, then
   click between two windows (the Arthur bar and the Lens) and type in each.
3. **Rung 3:** click the Arthur bar and ask **"What's 2+2?"**. A reply appears.
4. **Rung 4:** nothing to do; it's on the serial log.
5. Power off with the button (there's no shutdown command yet, OT-90).

**Boot 2:** press F12 and pick the KINGSTON stick again.
1. **Rung 5:** the intro card should **not** appear. That's the flag boot 1 wrote, read back.
2. Ask Arthur anything once more.
3. Save the PuTTY log.

## What the serial log must show (Janus reads it)

| Rung | Boot | Line |
|---|---|---|
| 1 | 1 and 2 | The banner `build 149431a185eb… \| debug-assertions=on overflow-checks=on ub-checks=off`; no panic |
| 2 | 1 | The desktop session up; two `ROLE_TEXT` surfaces; focus switches; input to the focused client only |
| 3 | 1 and 2 | Arthur's `REPLY:` with `provenance=real_silicon` |
| 4 | 1 and 2 | `eth0: link up ip=<a nonzero lease> … fence_refusals=0` |
| 5 | 1 | `boot-neofs` mounted `sda` read-write; `DESKTOP intro flag write=ok` |
| 5 | 2 | The intro is skipped because the flag exists (`intro skipped reason=introduced`, or the equivalent line) |

## Expected failures and how to tell them apart

| Failure | What you'd see | Cause |
|---|---|---|
| No lease | `eth0: … absent` or no `link up` line | The dongle isn't plugged in, or isn't the ASIX one; or a link or DHCP problem (the 2026-08-01 runs 1–2 signatures: `frames=0` means RX was never armed) |
| `boot-neofs` doesn't mount `sda` | The mount line names an error, or another device | `sda`'s required `hello.txt` and `model.neom` stubs are missing (OT-73 note: both are load-bearing), or the guard refused it |
| The intro card shows again on boot 2 | `intro flag write=failed` on boot 1, or no write line | A NeoFS write or fsync failure; read the line's error |
| Arthur doesn't load | `ARTHUR model state=…` | Image A loads the model from the stick's boot modules (not `sda`), so this would be a boot-module issue, the same path as on the Zenbook |
| The boot stops before the desktop | The last serial line | OptiPlex-specific: a framebuffer or ACPI difference from the Zenbook. Image A's fb progress console also shows the last stage on screen |
| The box won't boot the stick at all | F12 doesn't list it, or Limine doesn't start | The UEFI boot order or Secure Boot. The stick boots on the Zenbook, so check the OptiPlex's firmware settings |
