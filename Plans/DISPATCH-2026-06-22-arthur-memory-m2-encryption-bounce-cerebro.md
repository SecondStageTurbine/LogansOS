## 0. Why green was not safe
The `arthur_memory_encrypted` scenario runs the generic `_ipc_smoke()` and, on exit 0, prints a **hardcoded** banner `encrypt_write=ok … counter_persist=ok crypto_erase=ok kill_switch=ok` (`kernel/src/test_harness.rs:1492`). **None of those tokens is an independent assertion** — they are emitted whenever neo-arthur exits 0. So "green" proves only *"arthur-with-encryption boots and exits 0 over a single smoke,"* not any crypto property. That is why B1–B3 below sailed through. **A gate that cannot fail when the crypto is wrong is not a gate** (the byte-oracle / falsifiable-CI discipline). Fixing the scenario to actually falsify the crypto is part of this build (B5).

## 1. The five defects (all PM-confirmed from source on `317b8d9`)

### B1 — Memory corruption + silent key-loss (functional, **HIGH**). The headline.
Both M2 writers **append** where they must **whole-file-rewrite**:
- **`.mem`:** `append_record` (`userland/neo-arthur/src/main.rs`) opens the category file with `OPEN_ROOT_TEMPORARY` (`=0`, **no truncate**) and calls `drain_file` (reads to EOF to position the offset) before `sys_write`, so **each `remember` appends a self-framed AEAD blob** `version(1)||nonce(12)||ct||tag(16)`. But `load_records` → `decrypt_for_read` → `decrypt_file` decrypts the **entire file as ONE blob** (version@0, nonce@[1..13], tag@last-16). ⇒ the **2nd `remember` of a category makes the next `recall` fail authentication** (Poly1305 tag mismatch over the concatenation) → fail-closed → memory silently degrades to "empty/ephemeral." (M1 works because plaintext is line-delimited and the reader line-parses; M2 reused M1's append I/O without either a multi-blob reader or a rewrite.)
- **`.key`:** `persist_key_file` has the **identical read-to-EOF-then-write** pattern, so the key file **grows by `KEY_FILE_LEN` (48 B) per save**. On the next load, `read_key_file` rejects any length `!= 48` → `ensure_key` receives `None` → **generates a fresh key** → **all prior ciphertext is permanently undecryptable** (an accidental, silent crypto-erase) from the 2nd save across reboot onward.

### B2 — Nonce-reuse crash-safety is not provided by the claimed mechanism (crypto, **HIGH**).
ISC-4a's *"write-ahead persist the counter BEFORE encrypting"* is **mis-ordered**: `persist_key_file` (main.rs:~406) flushes the counter **before** `encrypt_for_write` (~414) advances it inside `reserve_next_nonce`, so it persists the **pre-advance** value (does nothing useful). `MemoryEncryption::persist_key_write_ahead` is a **no-op stub** (`Ok(())`). The only thing actually preventing reuse is `apply_rollback_safety` on load — which calls `extract_nonce_from_file` reading **only the first blob's nonce** (`bytes[1..13]`). That is correct **only** in a single-blob whole-file-rewrite model. **Therefore the B1 fix must be the single-blob model** (below); if B1 were "fixed" while keeping multi-blob, `apply_rollback_safety` would have to scan the **max** nonce across all blobs or a crash → **nonce reuse under one key → ChaCha20-Poly1305 catastrophic break.** The durability story must be made real: flush the **advanced** counter + `sys_fsync` **before** the `.mem` write.

### B3 — `burn_key` does not zeroize the in-memory key + un-flagged `unsafe` (crypto, **MEDIUM** + ISC-5 violation).
`burn_key` (`memory_encryption.rs`) does:
```rust
let mut zeroed_key = [0u8; KEY_LEN];
unsafe { core::ptr::copy_nonoverlapping(&ck.key as *const _ as *const u8, zeroed_key.as_mut_ptr(), KEY_LEN); }
self.keys[idx] = Some(CategoryKey { key: zeroed_key, counter: ck.counter });
```
This **copies the real key INTO** the buffer named `zeroed_key` — the in-RAM key is **preserved, not wiped.** Primary on-disk crypto-erase (caller overwrites `.key` with CSPRNG + unlinks) is intact, so the NIST 800-88 across-reboot property holds; but the in-RAM defense-in-depth is a no-op. Also **ISC-5 said "no new `unsafe` — if you reach for unsafe, STOP and flag"**; this added an unflagged `unsafe` block for what a safe `self.keys[idx] = None;` (or `key: [0u8; KEY_LEN]`) does correctly.

### B4 — Byte-oracle binds the crate, not M2's functions (oracle, **MEDIUM** — the standing format-oracle rule).
The RFC 8439 §2.8.2 KAT (`arthur_lib.rs`) is **real and correctly raw-sourced** (✓ honors "exact bytes from raw source, never WebFetch"). **But** it exercises the `chacha20poly1305` crate + an **inline** format reconstruction — **not** M2's own `encrypt_plaintext` / `decrypt_file` / `nonce_for`. `counter_nonce_uniqueness` even builds nonces at bytes `[4..12]`, whereas the implementation's `nonce_for` uses `[0..12]` of the `u128` LE — so the test does not validate the real nonce derivation. **No KAT binds M2's actual on-disk bytes to a hand-computed expectation** — exactly the ADR-028 gap the format-oracle rule closes. Add a KAT that calls `encrypt_plaintext`/`decrypt_file` directly and asserts the exact `version||nonce||ct||tag` bytes for a fixed key+counter+plaintext.

### B5 — The scenario is non-falsifiable for the crypto (test-validity, **MEDIUM**). See §0.

## 2. The fix (ISCs)
- **ISC-1 — single-blob whole-file-rewrite for `.mem` (closes B1+B2).** On `remember`: **decrypt the existing category blob → plaintext records → append the new record line → re-encrypt the WHOLE plaintext as one AEAD blob → write it as the entire file** (one nonce, counter += 1 per save). On `recall`: decrypt the single blob → line-parse → find. After this, `apply_rollback_safety`'s single-nonce scan is **correct** and the counter advances by exactly 1/save. **The file must be truncated/replaced, not appended** — `OPEN_ROOT_TEMPORARY` does not truncate and there is **no O_TRUNC flag** (only `OPEN_ROOT_TEMPORARY=0` / `OPEN_CREATE_REGULAR=1<<0`, `libneo/src/lib.rs:503`). So either **unlink + `OPEN_CREATE_REGULAR` a fresh inode** before writing, or **surface a truncate primitive as a NeoFS/libneo dependency** (state which; prefer unlink+create if it's atomic enough for ISC-3, else flag the FS gap). Apply the identical whole-file-rewrite to `.key` in `persist_key_file` (no growth; always exactly 48 B).
- **ISC-2 — real write-ahead durability (closes B2).** Persist the **advanced** counter (post-`reserve_next_nonce`) **and `sys_fsync` the `.key`** *before* the `.mem` write+fsync. Order: `reserve/advance counter → persist+fsync .key → write+fsync .mem`. A crash between leaves the counter advanced (fresh nonce next boot) — never a reused nonce. Make `persist_key_write_ahead` real or delete it and document the caller ordering as the contract (no misleading no-op). Keep batch-reservation if you keep it, but the single-blob model means counter += 1/save is the simple correct path — batch is optional.
- **ISC-3 — `burn_key` actually wipes (closes B3).** Replace the inverted `unsafe` copy with `self.keys[idx] = None;` (or zero the key array) — **no `unsafe`.** Keep the on-disk burn (CSPRNG overwrite of `.key` + unlink). Confirm post-burn `recall` fails (key gone) and the category re-keys cleanly on the next `remember`.
- **ISC-4 — direct-function byte-oracle (closes B4).** A host KAT that calls **M2's** `encrypt_plaintext`/`decrypt_file` with a fixed key+counter+plaintext and asserts the **exact on-disk bytes** (`version||nonce||ct||tag`) against a hand-laid fixture, plus the real `nonce_for` layout. Keep the RFC 8439 crate KAT (it's good) — add the M2-function one.
- **ISC-5 — falsifiable scenario (closes B1+B5).** Rework `arthur_memory_encrypted` so the `=ok` tokens are **real assertions**, not a fixed banner. Minimum: (a) write **≥2 records of one category**, recall **both** correctly (catches B1 `.mem`); (b) **persist → reboot → recall** survives (catches the `.key` growth — this is the two-boot flow, not the single-boot smoke); (c) flip one ciphertext byte → recall **fails closed**; (d) `burn` → subsequent recall **fails**, then re-`remember` succeeds. The banner must reflect these checks; a FAIL must be reachable when the crypto is wrong.
- **ISC-6 — standards + kill-switch unchanged.** Kill-switch `arthur-memory-encryption` default-OFF ≡ M1 plaintext bit-for-bit (the equality anchor stays). SPDX; `fmt`/`clippy --workspace --all-targets -D warnings` via Docker (kernel clippy blocking). **No new `unsafe`** (B3 removes the only one). No new invariant. ADR-… M2 amendment recording the single-blob model + the B1–B5 corrections.
