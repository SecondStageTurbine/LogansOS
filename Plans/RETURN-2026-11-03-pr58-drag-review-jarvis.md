# PR #58 review — smooth window dragging

Reviewed head: `d0fbc1908c89e262e1c9d3887bcc963a9e1f2b64`.

- **FAIL — damage tracking:** `userland/neo-init/src/desktop_session.rs:510-542,1056-1070`. The compositor recomposes only the old/new outline edges (and cursor damage), but unions their rectangles into one `written` bounding rectangle and commits that single rectangle. For example, with a 656×442 outline moved from `(100,100)` to `(700,500)` in one coalesced pointer update, the commit includes the unchanged area between the two sets of edge strips, outside the actual changed-pixel union. The output plane remains composed correctly, but presentation damage is larger than the changed region. The frame-change repaint uses old/new reach union and subtracts already painted overlap at `:742-775`; this does not fix the drag-frame commit expansion.
- **PASS — pointer coalescing and release:** `userland/neo-init/src/desktop_session.rs:4952-4958,5001-5017,5110-5138`. `poll` drains records until the queue is empty, updates position and buttons for each, and detects an all-buttons-up release before ending the move grab. A move action breaks the loop without consuming or discarding later queued records; they remain for the next poll.

The 100 ms frame maximum is about 1.7× the reported worst fixed run (60 ms); the 6 s release budget exceeds the 3.52 s worst reported fixed run while catching the earlier 5.7 s pre-fix measurement on a fast runner. The PR's final PM comment reports all gate shards and matrix jobs green on `63c7110a`.
- **PASS — feature off:** `userland/neo-init/Cargo.toml:83-91` keeps pointer dragging behind `desktop-pointer`; `desktop-pointer` off compiles out `pointer_tick`, `move_window`, and `repaint_reframed` (`userland/neo-init/src/desktop_session.rs:401-419,571-572,741-742`).
