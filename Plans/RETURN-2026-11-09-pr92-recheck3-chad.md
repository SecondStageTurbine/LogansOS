## Section 379 checks

1. **FAIL — every error path ends in reconciliation from the re-read record.** The five ordinary rejection paths do converge: no sample/readout (`userland/neo-init/src/desktop_session.rs:8516-8517`), non-RTC basis (`:8519-8521`), unplaceable reading (`:8524-8525`), failed store (`:8528-8532`), and kernel refusal, after attempted restore (`:8541-8549`). The shared `reconcile` reads the store, assigns both zone and RTC mode, resolves the clock using the boot resolver, and redraws (`:8569-8588`; boot uses the same resolver at `:8415-8419`). This fixes the two original cases when the selected record can be read.

   Two exceptions prevent the dispatch's unqualified PASS:
   - **Failed reconciliation reads silently retain cached state.** `settings::reread` reads both copies but returns `current()` if neither decodes (`userland/neo-init/src/desktop_session/settings.rs:450-455`). Read failures are represented as missing/empty/partial bytes by `login::read_small_up_to` (`userland/neo-init/src/desktop_session/login.rs:211-227`). Concrete case: start with generation 1 defaults cached, let the full generation-2 New York record land but report fsync failure, then fail both settings-file opens during reconciliation. `commit` has not updated the cache (`settings.rs:349-359`), so reconciliation applies the old defaults although generation 2 remains on disk and the next successful boot selects New York. The re-read failed; cached state is not proof of the durable record. There is no retry or distinct unresolved-store result. If neither copy is actually valid, boot also takes a different fallback (presence-file migration, `settings.rs:295-313`), while `reread` retains the cache.
   - **Presentation errors escape the common step.** After a successful store/kernel confirm, `scene.present(...)?` returns directly at `desktop_session.rs:8560` without reconciliation. The presentation inside reconciliation can also return before `Confirmed::Reconciled` at `:8587`. These are real `Result` paths (`Scene::present`, `:1019-1024`), not ordinary confirm refusals. Inject an error in the clock-readout presentation after the successful confirm to exercise the first bypass. The live fields may already match the store in that case, but the required final re-read step does not occur.

2. **PASS — both requested scenarios have live == re-read-record assertions (source-level coverage).** The fsync-style injection writes the actual bytes and then forces the operation's result false (`settings.rs:349`; armed at `:406-407`). `login_setup_tz_fsync_fail` requires failed write/store/skipped-confirm lines (`tools/xtask/src/login_scenarios.rs:2181-2197`). The refusal/rollback control arms a pre-write failure in `restore` (`settings.rs:427-430`); `login_setup_tz_rollback_fail` requires New York stored, EALREADY, failed rollback write and failed restore (`login_scenarios.rs:2199-2212`). Both invoke the shared witness at `:2132-2179`: it requires generation 2/file b/zone 105/rtc 1 re-read, live New York/local RTC/confirmed UTC with offset -14400, the EDT readout, reconciled wizard state, UTC journal times, and a second boot selecting generation 2 and confirming with the same zone/mode/offset. Missing reconciliation or retaining the old live clock fails that witness. Both scenarios are registered and enabled (`tools/xtask/src/main.rs:3672-3690`; features at `userland/neo-init/Cargo.toml:240-241`). These tests do not inject reconciliation-read or presentation errors.

3. **FAIL — error visible on any failure; PASS — THINK states the rule.** Every returned `Confirmed::Reconciled` installs the notice "Couldn't save the time zone. In use: <zone>." and updates the wizard from the reconciled zone (`userland/neo-init/src/desktop_session/setup.rs:372-390`). `Wizard::rows` renders the notice under the title (`userland/setup-core/src/lib.rs:348-353`); the host test checks its exact wording, row budget, review state and one-time lifetime (`userland/setup-core/src/tz_tests.rs:253-296`). The THINK explicitly states store-first ordering, reconciliation after any failure, and the error notice (`docs/THINK-2026-11-02-setup-menu.md:199-212`). However, a presentation error at either `desktop_session.rs:8560` or `:8587` propagates through `setup.rs:367` and `:78`, before the notice is installed; the session returns the code (`desktop_session.rs:1240-1243`). Thus the visible-error guarantee covers returned reconciliation outcomes, not every error in the confirm. Reconcile/read failures also need an explicit unresolved outcome rather than silently claiming the cached zone is the store's selected record.
