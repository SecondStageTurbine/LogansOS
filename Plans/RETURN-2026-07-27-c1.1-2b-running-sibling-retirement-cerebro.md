## What shipped

Three new parts, all behind the `force-kill-sibling-retire` kill-switch (default OFF):

1. **`Process::killing`** — monotonic set-once flag, published `Release` by **both** forced-teardown
   entries (`terminate`, `fault_kill_current_user`) **before** any scan.
2. **`retire_current_if_process_killing()`** at two return boundaries — end of `syscall_dispatch`,
   and `reschedule_ipi_body` gated on `from_ring3`.
3. **`retire_running_siblings(pid, send_ipi)`** — peer-CPU `current.pid` scan → `send_reschedule_ipi`;
   folded into `terminate`'s drain loop, fired once from the `#PF` frame, re-fired from the reaper.

Two additions the dispatch did not specify but which are **correctness requirements**, not polish:

- **`thread_create` is refused while `killing` is set.** A sibling still in ring 0 could otherwise
  spawn threads faster than the drain retires them, so the drain never converges. It is also the one
  path that reaches ring 3 crossing no boundary check.
- **The scan skips the calling CPU.** For `fault_kill` the caller *is* a thread of the dying process;
  counting it makes a drain-to-zero loop wait forever for a thread that only retires after the loop.

**Why it reads through `Thread::process`, not `PROCESSES` (the C1.1 dependency):** `terminate`
deregisters the pid *before* every sibling has retired, so a registry lookup answers `None` —
"nothing to do" — at exactly the moment the answer must be "retire now". This is the concrete reason
2(b) stacks on C1.1.

## Pitfall-bank consult

| Class | Verdict | Discriminator / guard |
|---|---|---|
| CP-7 EOI ordering | **INTRODUCES → guarded** | EOI precedes the retire in `reschedule_ipi_body`; the retire diverges so the asm epilogue/`iretq` never run and EOI-after would never happen (wedged LAPIC). Exactly-one-EOI holds on both paths. |
| CP-15 stranded wakeup / EOI-only IPI | **GUARDS (adopts the pattern)** | Flag set by the killer *before* the IPI, acted on at the target's return path, nothing load-bearing in the handler body — the `TIF_NEED_RESCHED` shape. |
| CP-19…CP-28 AP-idle IPI delivery | **N-A** | The target is by construction *running*, not halted in `sti;hlt` nor mid-per-CPU-init. Single-IPI insufficiency is handled by re-scanning, not by delivery assumptions. |
| CP-30 raw-stack `Arc` leak | **INTRODUCES → guarded** | `exit()` abandons the kernel stack, so both hooks sit where it owns nothing: after the syscall body returned, and only when the interrupt came `from_ring3`. |
| CP-35 migration reservation | **N-A** | Retirement uses the existing `exit()`/zombie/reap path, which already accounts `live_count`. No new placement path. |
| CP-36 Ready→Running invisibility | **CLOSES the containment half** | Memory-safety half remains C1.1's. |
| Return-boundary race | **Guarded** | Monotonic flag + re-scan: a thread that passes the check and *then* has the flag set is still `current`, so the next pass finds and IPIs it. |
| **CP-38 (new)** | Added | Running threads cannot be enumerated; flag-at-boundary + IPI; the three ordering traps. |

## Decisions the PM should rule on (not buried)

1. **The negative control is `ignored`, not gated.** The dispatch asked for teeth as a gated
   scenario. The escape reproduces only ~1-in-3 (measured 1 PASS / 2 FAIL; "green" only via xtask's
   retry — the retry-masks-flake hazard). The flakiness is a property of the **baseline bug**: the
   worker's threads all live on CPU 0 (admitted to the creator's CPU; only IPC rendezvous relocates
   them) sharing it with the BSP drain loop, so a spinner cycles between `current` and the ready
   ring, and whether `terminate`'s scan loop exits with it `current` (escapes) or `ready` (caught) is
   a coin flip. Determinism needs the spinner **alone on an idle CPU**, i.e. cross-CPU placement of a
   *user* thread — a bigger change than 2(b). Shipping a flaky gated scenario would violate the
   hermeticity rule, so: teeth are met by **captured evidence**, reproducible via
   `cargo neo-test force_kill_sibling_retire_off --include-ignored`. **Accept, or fund the placement
   work?**
2. **KNOWN RESIDUAL — the pure ring-3 spinner.** A sibling that never syscalls reaches no boundary of
   its own, so the retire-IPI is its *only* mechanism and the bounded drain loop is a real (remote)
   escape window. Every thread that *will* syscall is guaranteed by the flag alone. Closure = hook
   the **timer tick** as a second interrupt-return boundary; deliberately not done here (the timer
   ISR carries a "no pushes between the rbp anchor and the call" alignment invariant across two asm
   variants, and the CP-30 gate needs `from_ring3` threaded through both). Recorded in CP-38.
3. **Cross-family AAG is REQUIRED for this merge** (SMP-core rule): a Codex or Qwen refute-lens on
   the IPI / return-boundary ordering. An all-Claude panel is what missed the C1.1 seams.
