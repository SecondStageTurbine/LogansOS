## 0. The decision this build makes
O1a built the arena but changed no ownership surface — `Handle::Tensor` and `Model::weights` still hold `Arc<Tensor>` directly, so every production tensor is still `strong_count ≥ 2` for its handle's lifetime and the proven policy layer still governs only executor-pass intermediates. O1b flips the surfaces onto the arena: **handles and models stop holding the `Arc` and start naming a `SlotKey`; use mints through the O1a gate; handle clone/drop drive `retain`/`release`.** The instant this lands, an idle model weight is `strong==1 && weak==0` at its slot — **claimable, demotable, daemon-managed for the first time.** This is the build the whole O1 line exists for.

## 1. The conversion (minimal, semantics-preserving)
- **`Handle::Tensor`** becomes `{ slot: SlotKey, meta: TensorMeta, cap_id, rights }` — `meta` caches the immutable id/shape/dtype so metadata queries never mint. The `Arc<Tensor>` field is gone. **Handle clone → `arena::retain(slot)`; handle drop → `arena::release(slot)`** (free-on-last-handle, the GEM `handle_count` analogue). `cap_id`/`rights` ride unchanged.
- **`Model::weights`** becomes `Vec<SlotKey>` (each weight `alloc`'d into the arena at load; the `Model`'s drop releases them). `Model` queries that need only metadata use cached meta; anything touching weight bytes mints.
- **Every byte-touching use mints + drops:** `sys_inf_run` operand resolution, `sys_tensor_query`'s data path, the sharing-hash computation, and the grant/share capture (`process.rs:964`'s `tensor.clone()` → mint the slot for the duration of share registration). Mint = `arena::mint(slot)` → parks across an in-flight migration, returns the live `Arc`; **drop it the moment the use completes** so the slot returns to claimable.
- **Sharing/dedup semantics preserved exactly.** A grant copies the `SlotKey` (N handles → 1 slot → 1 `Arc` → 1 physical copy — the §9.7 invariant, intact); the dedup registry keeps its `Weak<Tensor>` against the slot's `Arc`, so deduped tensors stay `weak > 0` ⇒ unclaimable (today's behavior, zero regression). A *granted RO-shared* tensor (not deduped) idle at its slot becomes daemon-managed — correct: sharing fixes *which physical copy*, not *pinned residency*; demote-and-refetch preserves the one-copy invariant because the slot is still one `Arc`.

## 2. ISCs
- **ISC-1 — `Handle::Tensor` → SlotKey + cached meta.** Convert the variant; wire clone→`retain`, drop→`release`. Audit every `Handle::Tensor { tensor, .. }` match site (`process.rs` ~548/677/964; `syscall.rs` ~830/888/925/973/1278) — each either reads cached `meta` (no mint) or mints for a byte-touching use. No site keeps a long-lived `Arc`.
- **ISC-2 — `Model::weights` → `Vec<SlotKey>`.** Weights `alloc` into the arena at `sys_model_load`; `Model` drop releases them; weight-byte access mints. Model metadata queries use cached meta.
- **ISC-3 — Use-site mint/drop discipline (REQUIRED — I-4/I-9).** Every byte-touching path mints for exactly the duration of use and drops immediately after. While minted: `strong ≥ 2` ⇒ unclaimable ⇒ **I-9 pin-on-use now protects production tensors by the same mechanism as pass intermediates.** A use that outlives its need (a stray retained `Arc`) is a bug — it would silently re-pin a weight; assert slots return to claimable after each op.
- **ISC-4 — Syscall-semantics invariance (REQUIRED — the kill-switch, Rule 1).** With no memory pressure and the daemon off, **every syscall-observable result is bit-identical to `Arc`-in-handle semantics** — the indirection is invisible except to eviction. Prove it: the full prior scenario family + the `sys_tensor_query`/grant/share/revoke/drop syscall tests, unchanged outputs. Stale-key safety (I-13) now has a production consumer: a `SlotKey` in a dropped/revoked handle must fail-safe (the generation check), never alias a reused slot.
- **ISC-5 — The production payoff gate (REQUIRED — the point of O1).** A scenario: load a model; run an inference (weights resident); apply device-memory pressure from another tenant while the model is **idle between inferences**; assert (a) the **idle weights are demoted** by the daemon (`bg-demote`/eviction trace names a weight slot), residency ≤ capacity; (b) the **next inference transparently re-fetches** them (placement/migration round-trips), output **byte-identical** to the no-pressure reference; (c) a weight that is an operand of an **in-flight** op is **never** demoted (mint pins it — the I-9 production assertion, run *under* daemon pressure). This is the line the whole build exists to turn green.
- **ISC-6 — `live_slots()` scaling (the O1a carried item, bounded).** O1a flagged `live_slots()` as an O(n) `Arc`-bump under the table lock per daemon walk. Since O1b changes the daemon's production-slot population (real models come and go), fix the walk to **not bump every slot's `Arc` under the lock** (e.g. snapshot `SlotKey`s under the lock, mint lazily outside it, or walk without retaining non-candidates). **Bounded:** if a correct fix needs more than changing the walk's reference discipline, BLOCKER to PM — do not redesign the daemon here.
- **ISC-7 — Standards.** Strict superset (daemon-off + no-pressure ≡ pre-O1b syscall semantics bit-for-bit, ISC-4); SPDX; **no new `unsafe`**; `cargo fmt`; host suite (handle/model conversion unit tests + the full P1–P4b/O1a/`infer_*`/accounting/admission/**sharing/grant/revoke** regressions) green; `shard-coverage`; `clippy -D warnings`; builds on+off; lockdep clean. **Open the ANSPEC §9.13 ownership-model section** (handles-name-slots, mint-on-use, the GEM/fd-table lineage, handle-count lifecycle, the I-4/I-9/I-13 wiring) + **ADR-043**.

## 3. Gate (two-stage — QEMU NEO_SMP stress loop, no OptiPlex)
**Expected-failure-mode analysis (the conversion's surface):** a stray long-lived mint silently re-pinning a weight (ISC-3 — assert post-op claimability); a dropped/revoked handle's stale `SlotKey` aliasing a reused slot (I-13 generation check — the production consumer); a grant/share refcount drift (the §9.7 one-copy regression); a handle-count leak (slot never freed on last close — the O1a slot-balance check, now driven by real handle drop); semantics drift in a syscall return (the ISC-4 equivalence family).
- **Stage A (you):** builds (on+off); conversion unit tests + the full regression family incl. sharing/grant/revoke; clippy; fmt; shard-coverage; the ISC-4 syscall-equivalence proof; slot-balance under real handle drop.
- **Stage B (QEMU):** the ISC-5 production payoff scenario + the family at NEO_SMP=4 (N≥50 on the pressure/race scenarios), all green; weights demonstrably demoted-and-refetched byte-identical; in-flight weight never moved; the O1a/P4a discriminators still firing.

## 4. Scope guard
The ownership conversion + the bounded `live_slots()` fix only. **Do NOT** change the O1a arena protocol (consume it; insufficient ⇒ BLOCKER); **do NOT** re-key the §9.7 dedup registry (named follow-on — keep `Weak`, deduped stays unclaimable); **do NOT** change capability rights, the grant/revoke model, or any syscall's *intended* semantics (ISC-4 is invariance, not redesign); **do NOT** redesign the daemon (ISC-6 is bounded); **do NOT** build the serving surface (O1 *unblocks* it — separate line); **do NOT** add `unsafe` or a new lock; **do NOT** change *what* any op computes (I-1).

## 5. Merge (PM, on Stage-B PASS)
Close-gate: `git fetch origin && git rebase origin/main`, re-run Stage-A + the stress loop, push. PM `pm-merge-check` → `--ff-only` → `main`. With O1b, **model weights — the largest object in any AI workload — come under the proven policy layer for the first time**: placed, evicted, retained, prefetched, and moved in the background, all result-invariant, all capability-secured. The O1 line closes; the recorded next candidates are the production inference-serving surface (now unblocked), device-side copy-engine DMA overlap (hardware), the §9.7 dedup-to-slot re-key, and the Phase-6 SIMD32 backport.
