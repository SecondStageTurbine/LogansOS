## 0. The thing this build makes safe
Every residency decision through P3 executes inside the executor pass, which is the **only mutator** of its value table (`evict.rs:126–135`). P4 relaxes that so a future daemon (P4b) can move tensors *concurrently with dispatch*. **P4a builds and proves the primitive that makes the relaxation safe — and nothing else.** No daemon yet. The deliverable is a **migration reservation**: a per-`(device, tensor_id)` state machine under the existing `SwitchMutex` such that a mover can migrate a cold/unreferenced tensor while another thread races to reference it, and the race is **provably** free of use-after-migrate, lost wakeups, double-claims, torn accounting, deadlock, and result divergence. The success criterion is not a feature — it is a **green NEO_SMP stress loop against an explicit race-failure matrix** (§3).

## 1. The primitive (minimal, refcount-preserving — Q1)
A per-`(device, tensor_id)` reservation state, held under an existing `SwitchMutex` (**no new lock primitive** — Q4):
```
Resident → Claimed → Migrating → committed (Resident' on success / Resident on rollback)
```
- **Claim (under the lock):** a mover may claim a tensor **only if** it is `Resident`, **unreferenced** (`Arc::strong_count == 1 && Arc::weak_count == 0` — the exact P2/P3 evictability gate, so a live operand/weight/shared tensor can never be claimed), and **not already claimed**. A claim that loses (already claimed, or now referenced) is **skipped, never blocked** (the Linux `MIGRATE_SYNC_LIGHT` bail-don't-block lesson). This is the `PG_isolated` analogue: two movers cannot claim the same tensor.
- **Migrate:** move the claimed tensor via the **existing `Tensor::migrate`** (no parallel residency path — same rule as P2/P3). Because it was claimed only when unreferenced, `get_mut` succeeds.
- **Accessor arrival (the race):** a thread that tries to take a **new** reference to a tensor in `Claimed`/`Migrating` **parks** via `block_current_with_token_and_guard` (token installed while the lock is held, released atomically with the context switch — **no lost-wakeup window**), and on wake **re-resolves residency** (the fault-replay analogue). A thread that already holds a reference cannot hit this — it could never have been claimed.
- **Commit:** the storage swap **and** the `TABLE`/`RECENCY` updates happen in **one critical section**, so accounting can never tear; the state returns to `Resident`, parked accessors wake and re-resolve.
- **Refcount-preserving (Q1):** `Arc::get_mut` stays the mutation gate; **no interior mutability over `TensorStorage`, zero new `unsafe`.** The primitive moves only what nothing else references.

## 2. ISCs
- **ISC-1 — The reservation state machine (the primitive).** A new reservation map keyed `(device_abi, tensor_id)` under `SwitchMutex`, with `claim → migrate → commit/rollback` and the park/wake on accessor arrival. Lives next to `accounting.rs`/`evict.rs`. Claim uses the existing evictability gate; contended claims return a skip. **No new `unsafe`, no new lock type.**
- **ISC-2 — Lock order (REQUIRED — discriminator #3).** Place the reservation lock in **one documented global order** extending `admission.rs`'s `QUEUES → TABLE → scheduler`. Add a **debug-build acquire-order assertion** in the `SwitchMutex` wrapper (`kernel/src/sync/switch_mutex.rs`) — a lightweight lockdep that **panics at the offending acquire** on an inversion (so a deadlock is a localized panic, not a mystery hang). Document the chosen order in the module and in §9.12.
- **ISC-3 — The discriminators (REQUIRED — capture-before-you-need-it, §6 of the THINK).** Instrument *in this build*, not after a failing run:
  - **#1 storage generation counter** per tensor — accessors assert the generation didn't advance mid-read; a **retry counter** that is *expected > 0* (proves the block-retry path actually fires) but every retry ends on a consistent generation.
  - **#2 parked-accessor quiesce hook** — at test end, parked-count == 0; a watchdog bounds any park (no infinite sleep).
  - **#4 migrate-owner uniqueness** — a tensor in `Migrating` has exactly one owner id; successful double-claims == 0.
  - **#5 per-migration accounting delta** — assert `resident_after == resident_before − moved` (source) / `+moved` (target) per migration, **and** the existing balance-to-zero-on-teardown holds under NEO_SMP=4.
- **ISC-4 — Result-invariance under the race (REQUIRED — discriminator #7).** A tensor read concurrently with its migration yields **byte-identical** data to the no-migration case; the storage swap is atomic from any accessor's view (it sees either the old resident bytes or, after re-resolve, identical bytes on the new device). Moving a tensor changes *where* it lives, never its bytes — the P1–P3 byte-oracle, now under concurrency.
- **ISC-5 — Re-prove and re-document the invariant (the whole point).** Update the `evict.rs:126–135` coherence note: the single-mutator property is now **relaxed for the daemon path and re-proven** by this reservation (concurrent movement is safe *because* a referenced tensor is never claimed and an arriving accessor parks-and-re-resolves). Update the `admission.rs` lock-order doc with the reservation lock. **P4a must not regress the synchronous P2/P3 path** (Q5): with no concurrent mover, the reservation is never contended and behavior is P3 bit-for-bit.
- **ISC-6 — The gate (QEMU, NEO_SMP stress loop — no silicon, no daemon).** A **two-thread concurrency test**: thread A claims a cold tensor and migrates it; thread B races to take a new reference to that same tensor (and a control tensor it legitimately holds). Run **N ≥ 50 iterations at NEO_SMP=4** (the `sys_wait` 50/50 precedent). Assert, every iteration: no use-after-migrate (gen counter, #1), the block-retry path fired at least once across the loop (retry counter > 0) yet every read was consistent, no lost wakeup (quiesce, #2), zero successful double-claims (#4), exact per-migration accounting delta + balance-to-zero (#5), no deadlock (the order assertion never trips, #3), and **byte-identical reads** (#7). A single divergent/hung iteration **fails** the gate.
- **ISC-7 — Standards.** Strictly additive (no concurrent mover → P3 verbatim, ISC-5); SPDX; **no new `unsafe`** (Q1); `cargo fmt`; host suite (reservation-primitive unit tests where host-expressible + P1/P2/P3/`infer_*`/accounting/admission/sharing regressions) green; `shard-coverage`; `clippy -D warnings` (CI/Linux); builds on+off. Open **ANSPEC-001 §9.12** (the concurrent-residency *mechanism*: the reservation state machine, claim/park/commit, the relaxed-and-re-proven single-mutator invariant, the lock order) + an **ADR** (next number).

## 3. Gate (two-stage — QEMU NEO_SMP stress loop, no OptiPlex)
This is a **concurrency** gate: a non-deterministic race that only ever passes is as dangerous as a blind hardware run designed only for success (CLAUDE.md). The gate is a **stress loop**, and every race mode in ISC-3/§6 is self-diagnosing on failure.
- **Stage A (you):** builds (on+off); reservation unit tests + regressions green; clippy; fmt; shard-coverage; the debug acquire-order assertion compiled and exercised.
- **Stage B (QEMU):** the two-thread race test, **N ≥ 50 at NEO_SMP=4**, all ISC-6 assertions green every iteration. No silicon, no daemon.
**Expected-failure-mode note (required, concurrency analogue of the blind-hardware section):** the most likely ways this still fails even if the primitive is "correct" are the seven modes in the THINK §6 table — each has its discriminator above. If the run fails, the captured evidence (gen counter / quiesce / order-assertion panic site / per-migration delta / owner-uniqueness) must localize *which* mode, conclusively.

## 4. Scope guard
The reservation primitive + its race proof only. **Do NOT** build the daemon, prefetch, or background demotion (**BUILD-P4b** — gated on this green); **do NOT** add device-side concurrent DMA (Intel copy engine — a later hardware build, Q3); **do NOT** add interior mutability over `TensorStorage` or any new `unsafe` (Q1 — refcount-preserving only); **do NOT** introduce RCU/seqlock or a new lock primitive (Q4 — extend `SwitchMutex` usage with the documented order); **do NOT** move a referenced tensor (impossible by the claim gate, and undesirable); **do NOT** change *what* any op computes (ISC-4); **do NOT** regress the synchronous P2/P3 path (ISC-5).

## 5. Merge (PM, on Stage-B PASS)
Close-gate: `git fetch origin && git rebase origin/main`, re-run Stage-A + the NEO_SMP stress loop, push the rebased branch. PM `pm-merge-check` → `--ff-only` → `main`. Then **BUILD-P4b** (the async residency daemon — a dedicated kernel thread woken at the P3 headroom low watermark / sleeping at the high watermark, using this primitive to bg-demote cold tensors and prefetch predicted-hot operands concurrently with dispatch, the `residency: … daemon …` trace, **strictly additive with a synchronous direct-reclaim backstop** — Q5; its gate is a multi-tenant forward pass run concurrently with the daemon under the same NEO_SMP stress loop, asserting byte-identical output every iteration + reduced critical-path eviction round-trips vs P3). With P4a, the kernel has the primitive that lets it move tensors while it works — the foundation re-proven under a stress loop before any concurrent mover rides on it.
