## 0. What this build is (and is not)
Five feature builds added in layers; none subtracted. This build **digests**: collapse the duplication the layering left behind, delete dead scaffolding, reconcile every doc pointer with the code as it now stands, re-verify the invariant ledger row-by-row, pay down the two *named* P4b debts, and pass the fresh-reader legibility test. **Zero new features, zero new invariants (Rule 2: consolidation adds no ledger rows), zero behavior change** outside the two named debt items — and those two are bounded defect-fixes with their own kill-switches. The proof of "zero behavior change" is the same machinery as always: the full regression family + the byte-oracles, green before and after.

## 1. ISCs

### Code digestion
- **ISC-1 — Collapse the residency decision surface.** After five builds, the consult path is spread across `exec.rs` (722 lines — the most-churned file in the arc, ±189 in P4b alone), `evict.rs`, `residency_daemon.rs`, and `watermark.rs`, with the candidate-snapshot logic (`values` walk → `EvictCandidate`/`ResidencyCandidate`, evictability predicate, recency lookup) existing in executor-path and daemon-path variants. Unify to **one snapshot/candidate implementation** consumed by both (the predicates are already identical by design — I-4); split `exec.rs` so dispatch, placement-consult, and pass-bookkeeping are separable reads. Pure-tier policy files (`*_policy.rs`, `predictor.rs`, `reservation_logic.rs`, `watermark.rs`) are **already clean — do not churn them**; this ISC is about the kernel glue.
- **ISC-2 — Dead-scaffolding sweep.** Six `ai/` modules carry blanket `#![allow(dead_code)]` (`admission.rs`, `evict.rs`, `exec.rs` ×6 item-level, `placement.rs`, `reservation.rs`, `residency_daemon.rs`, `sharing.rs`). Remove every blanket allow; delete what is genuinely dead; keep (with a *narrow, justified* `#[allow]` + comment) only what is load-bearing-but-not-yet-called (e.g. a P4b-named seam). **Rule 5 boundary: gate discriminators, counters, and instrumentation are NEVER dead code — they stay armed.** If something looks dead but is a discriminator, it gets a doc comment saying so, not deletion.

### The two named debts (bounded defect-fixes, each with a kill-switch — Rule 1)
- **ISC-3 — Decaying H (the monotonic-latch fix).** P4b's per-device `H` is max-latched: one outlier placement permanently inflates the watermark band, and the daemon over-reclaims forever after (the hazard is *named* in ADR-040). Replace with a decaying estimate (e.g. exponential decay toward the recent max-need on each daemon cycle — pick the simplest correct form, justify in the ADR amendment). **Kill-switch: decay-off reproduces the latch behavior bit-for-bit** (unit-test equality). Result-invariant as always: `H` changes *when* the daemon moves things, never bytes.
- **ISC-4 — Production-surface wiring into managed slots.** The daemon's demotion surface is the managed-slot registry; production tensor surfaces that should be daemon-managed (per the P4b note) bypass it. Wire them in so the daemon manages real workload tensors, not just the gate's. This is substrate-completion, not a feature: the daemon's behavior is unchanged, its *coverage* becomes what ADR-040 already describes. Pin protection / refcount-safety (I-4, I-9) apply unchanged — a wired surface that breaks a byte-oracle is a wiring bug.
- **Out of scope (explicitly):** the optional daemon timer tick (new wake behavior — a future feature build if ever needed; the placement-signal wake is sufficient) and device-side copy-engine DMA overlap (hardware lift, deferred per P4-THINK Q3).

### Documentation reconciliation
- **ISC-5 — Pointer sweep.** Every `ai/` + `drivers/accel/` module doc-comment points to its *current* ANSPEC § and ADR (the arc renumbered things: §9.10's "deferred" list, §9.11's P4 forecast, §9.12's two-part structure). ANSPEC §9.9–§9.12 cross-references match the code file names that exist *now*. `Plans/INDEX.md` gains the policy-arc artifacts (THINKs, dispatches P1–C1, close evidence) with correct statuses. Fix stale forecasts (e.g. any "BUILD-P3 will…" phrasing describing things that since landed differently).
- **ISC-6 — Ledger re-verification + re-measurement (the governance doc's first audit).** Walk `docs/complexity-governance.md` §1 **row-by-row**: for each of I-1…I-12, name the test/assertion that currently guards it and confirm it runs in CI/the gate family (a row whose guard can't be named and run is a finding, not a checkbox). Re-measure the §1 structural facts (static-lock count, pure-tier share of AI decision code) and update the doc with fresh numbers + audit date. Any drift between a ledger row and reality is fixed in this build or escalated as a BLOCKER — never papered over.
- **ISC-7 — The fresh-reader legibility test (alarm condition 4).** After ISC-1/2/5: a cold read of `kernel/src/ai/mod.rs` + the module doc-comments alone must reconstruct the layering (mechanisms §9.5–9.8 → policy §9.9–9.11 → concurrency §9.12 → where decisions live vs where glue lives vs where the daemon runs) **without spelunking git log**. Make `ai/mod.rs` the table of contents: a short module-map comment, one line per module, in dependency order. The RETURN must state the test was performed as a deliberate cold read and what it forced you to fix.

## 3. Scope guard
**Zero new features.** Do NOT add ops, policies, prediction machinery, locks, or invariants; do NOT touch the pure-tier policy files except for doc pointers; do NOT remove or weaken any discriminator/counter/lockdep (Rule 5 — paid-down debt stays armed); do NOT change any trace line's format (the gates parse them); do NOT take the timer tick or DMA overlap; do NOT let either debt fix grow — decaying H is one estimator swap behind a kill-switch, surface wiring is registration calls, and if either uncovers something deeper, BLOCKER back to PM rather than expanding in-flight.
