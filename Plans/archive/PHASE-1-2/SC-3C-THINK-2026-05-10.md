## 1. Mandate

Phase 2 BUILD-3 sub-commit 4 ("SC-3C" by the existing letter-suffix convention from SC-3A/SC-3B) addresses Phase 2 Q7's remaining sub-questions:

- **Q7.b — CR3 cache.** Avoid redundant CR3 reloads in the context-switch path. CR3 writes are expensive: every write triggers a full local TLB flush, and the CPU re-walks page tables on the next memory access.
- **Q7.c — IPI TLB shootdowns.** When a page-table modification on one CPU invalidates virtual addresses that other CPUs may have cached in their TLBs, send those CPUs an IPI to flush. Currently the kernel has no cross-CPU TLB invalidation; safe under single-process SMP because all user code shares one CR3-loaded address space, but broken the moment multi-process SMP routes work across CPUs with different active Pmaps.

This is foundational SMP plumbing. Phase 2 deferred Q7.a (the initial paging bring-up + per-CPU Pmap binding) to sub-commit 1a/1b, which already landed. Q7.b/c are the performance + correctness completion for SMP page-table management.

Per handoff §10, sub-commit 5 (Q8.a/b — capability table SMP composition) and sub-commit 6 (Q8.c — blocked-thread-kill walk) follow SC-3C. SC-3C is a prerequisite for safe cross-process SMP because Q7.c's IPI shootdown is the correctness gate for multi-Pmap SMP operation.

## 2. OBSERVE — substrate state at HEAD

### 2.1 CR3 management today

**Per-CPU CR3 cache field exists but not wired:**

`kernel/src/arch/x86_64/per_cpu.rs:33`:
```rust
pub active_pmap_cr3: AtomicU64,
```

The field exists on every `PerCpu` slot. Initialized to 0 (no Pmap loaded yet). **Not currently read or written by any code path.** This is the substrate Q7.b will wire.

**CR3 reads are routine; writes are confined to a small set of call sites:**

- `kernel/src/mm/pmap.rs:319-322` — `Pmap::cr3()` returns the `(PhysFrame, Cr3Flags)` pair for a given Pmap. Comment notes "no PCID for Phase 1.4 — full TLB flush on every CR3 write."
- `kernel/src/sched/process.rs:339-343` — `cr3_for_thread(pid: ProcessId) -> (PhysFrame, Cr3Flags)` returns the CR3 to load when switching INTO `pid`'s threads. Returns kernel CR3 for `KERNEL_PID`.
- Context switch path actually loads CR3 via `Cr3::write(...)` at the higher level (scheduler) before calling `arch::context_switch(...)`. The asm `context_switch` itself does NOT touch CR3 — it swaps RSP and pops callee-saved regs only.

**Local TLB flush primitive exists:**

`kernel/src/arch/x86_64/mod.rs:142-149`:
```rust
/// Reload CR3 with its current value to flush local TLB/paging-structure
/// caches after mutating the active address space.
#[inline]
pub fn flush_local_tlb() {
    let (frame, flags) = Cr3::read();
    unsafe {
        Cr3::write(frame, flags);
    }
}
```

This is the canonical "blow the entire TLB on this CPU" primitive. Cheap to call but full-flush; no per-page granularity.

**PCID is deliberately deferred.** `kernel/src/mm/pmap.rs:320` comment: "no PCID for Phase 1.4 — full TLB flush on every CR3 write." Translation: every CR3 write is currently free-of-PCID-side-effects (full TLB blow), and Q7.b inherits this baseline. PCID-aware CR3 caching is a separate sub-question deferrable to a future ADR-driven sub-commit.

**No INVLPG usage anywhere in kernel.** `git grep -i 'invlpg' -- kernel/` returns zero hits. Q7.c will introduce the kernel's first INVLPG callsite.

### 2.2 IPI infrastructure (post-Sub-step-5b)

Sub-step 5b (commit `2d8f65d`) landed the reschedule-IPI infrastructure. SC-3C inherits a working LAPIC + IPI substrate.

**LAPIC initialized for BSP and all APs:**

- `apic::init_bsp(lapic_id)` for BSP
- `apic::init_ap(cpu_id)` for each AP after Limine MP handoff
- xAPIC mode (x2APIC explicitly out of scope until later)
- Spurious vector wired (vector 0xff)

**LAPIC ID registry:** `apic.rs:34-36`:

```rust
static LAPIC_IDS: [AtomicU32; per_cpu::MAX_CPUS] =
    [const { AtomicU32::new(INVALID_LAPIC_ID) }; per_cpu::MAX_CPUS];
```

Per-CPU LAPIC ID lookup ready for targeted IPI sends.

**`send_reschedule_ipi(target_cpu)` exists and is functional:**

`apic.rs:107-119`. Sends an ICR-LEVEL_ASSERT-encoded IPI to the target CPU's LAPIC ID. Used by the SMP scheduler to wake a remote CPU when work is queued.

**Three constants explicitly anticipate Q7 callers:**

**Vector allocation:** `RESCHEDULE_IPI_VECTOR = 0xfd`, `SPURIOUS_VECTOR = 0xff`. Vector 0xfe is unused; vector 0xfc is unused. Either is a candidate for TLB shootdown.

### 2.3 IDT handler hookup

`kernel/src/arch/x86_64/idt.rs` (194 LOC) installs handlers including the reschedule IPI handler. SC-3C will add a TLB shootdown IPI handler — a new entry in the IDT, dispatching to the shootdown receive logic.

### 2.4 Page-table modification sites

Page-table modifications happen primarily in:

- `kernel/src/mm/pmap.rs` — Pmap construction (during ELF load), `map_page`, `unmap_page`, etc.
- `kernel/src/mm/paging.rs` — kernel page table setup, HHDM management.
- `kernel/src/mm/heap.rs` — kernel heap region management (ADR-015 KASLR-tolerant heap placement).

Most current page-table modifications happen during process construction (single-CPU context, no SMP concern) or during kernel init (no other CPUs running). The cross-CPU concern arises when:

- A live process munmaps a region while one of its threads runs on a different CPU.
- A live process exits while threads on other CPUs hold its CR3.
- Kernel heap mappings change while other CPUs may have cached entries.
- (Future) IPC grant/recv_grant rebinds capabilities involving page mappings.

Q7.c machinery is needed at all these points; current code has none.

### 2.5 Scheduler context-switch flow (relevant slice)

`kernel/src/sched/scheduler.rs` (700 LOC) contains the SMP scheduler. The high-level flow for cross-process context switch:

1. Scheduler picks next thread (some run-queue policy).
2. If next thread's PID differs from current PID, scheduler invokes `cr3_for_thread(next_pid)` to get the target Pmap's CR3.
3. Currently: scheduler unconditionally calls `Cr3::write(target_cr3)` (assumption — verify in PLAN-stage).
4. Scheduler calls `arch::context_switch(...)` or `context_switch_with_release2(...)` to swap stacks.
5. New thread resumes on new stack with new CR3 already loaded.

**Q7.b's win:** step 3's `Cr3::write` is unconditional today. It should be conditional on `target_cr3 != per_cpu.active_pmap_cr3`. Skip-when-equal removes a full TLB flush on every same-process context switch.

### 2.6 Relation to Hpw and ADR-018/019

SC-3C lives downstream of SC-3B's Hpw discipline. The TLB shootdown IPI handler runs at IF=0 (it's an interrupt handler). If the handler needs to acquire a lock that the same CPU's preemptible context holds, we'd hit a Hpw shape immediately. ADR-018/019 discipline applies fully:

- The handler runs in IF=0 context.
- Any locks the handler acquires must be IRQ-safe by construction (ADR-019 `IrqSafeMutex`) or use plain `spin::Mutex` only if the lock is exclusively-ISR-context per ADR-019 Q2 ratification.

PM lean: the shootdown handler is exclusively-ISR-context for its own state; the sender-side coordination (acknowledgment count, etc.) is mixed-context and uses `IrqSafeMutex` once that type lands via Jarvis sub-commit 3.

**Cross-dispatch dependency:** SC-3C's safe implementation depends on `IrqSafeMutex` existing. Order:
1. Jarvis kernel-rename bundle (in flight) lands `IrqSafeMutex` in sub-commit 3.
2. SC-3C BUILD-stage dispatch uses `IrqSafeMutex` for shootdown coordination state.

If Jarvis bundle stalls (sub-commit 3 doesn't land), SC-3C BUILD-stage falls back to `without_interrupts(...)` wrapping per Sub-step 5c discipline. This is acceptable bridge code; ADR-019 sub-phase B/C will migrate it later.

## 3. THINK — Q7.b CR3 cache

### 3.1 Design space

**B1 — Per-CPU compare-and-skip.** Read `per_cpu.active_pmap_cr3`, compare to target. If equal, skip the `Cr3::write`. If not equal, write and update the field.

**B2 — B1 + write CR3 first, update field after.** Ordering matters if an interrupt fires between the two operations. Two sub-options:
  - **B2.a — Write CR3, then store field.** Safe: if interrupted, the field is stale-low; next context switch sees stale-low and writes CR3 unnecessarily. Inefficient on rare path, but correct.
  - **B2.b — Store field, then write CR3.** Unsafe: if interrupted between store and write, the field claims the CR3 is loaded but it isn't. Next context switch sees match-on-stale and skips, leaving the wrong CR3 active. Bug.

**B3 — B2.a + PCID.** Tag each Pmap with a PCID (12-bit field in CR3 bits 0-11 when PCIDE is enabled). CR3 writes with the noflush bit set don't flush TLB entries for OTHER PCIDs. Lets the TLB cache entries for multiple address spaces simultaneously. Significant complexity:
  - Hardware feature detection (CPUID 0x01:ECX[17]).
  - CR4.PCIDE enable at kernel init.
  - Per-Pmap PCID assignment and recycling (PCIDs are 12-bit; finite).
  - Per-CPU PCID generation tracking to handle PCID reuse correctly.

**B4 — B3 + INVPCID instruction.** PCID-aware fine-grained TLB invalidation. Builds on B3.

### 3.2 PM lean for Q7.b

**B2.a — compare-and-skip with CR3-write-then-field-store ordering.**

Concrete shape (pseudocode for scheduler context-switch path):

```rust
fn switch_to_address_space(target_cr3_frame: PhysFrame, target_cr3_flags: Cr3Flags) {
    let pc = per_cpu::current_per_cpu();
    let target = encode_cr3(target_cr3_frame, target_cr3_flags);
    let active = pc.active_pmap_cr3.load(Ordering::Relaxed);
    if active != target {
        // SAFETY: caller holds the scheduler's IF=0 invariant; CR3 write
        // is atomic in hardware.
        unsafe {
            Cr3::write(target_cr3_frame, target_cr3_flags);
        }
        pc.active_pmap_cr3.store(target, Ordering::Relaxed);
    }
    // else: skip; same address space already active on this CPU
}
```

Atomic ordering on the field is `Relaxed` because:
- The field is per-CPU; no cross-CPU ordering concern.
- The write within a single CPU is ordered by the CPU's instruction stream (CR3 write is a serializing operation; subsequent stores observe its effects).

If an interrupt fires between the `Cr3::write` and the `store`, the next time this CPU runs `switch_to_address_space` it'll see a stale-low field (old CR3 value), compute `active != target`, and write CR3 again. One redundant write; no correctness issue.

**Defer B3/B4 (PCID, INVPCID)** to a future sub-commit driven by measurement. Bible 1.2 (correctness > performance) supports deferral; PCID is pure performance, no correctness gain.

### 3.3 Q7.b risks

**R-B1: Lifetime of CR3 frame.** The `PhysFrame` returned by `cr3_for_thread(pid)` is a wrapper over a physical page. If the Pmap is destroyed between fetch and use, the frame may be freed and reallocated. Mitigation: this is an existing concern, not specific to Q7.b — the scheduler already handles Pmap lifetime via reference counting (verify in PLAN-stage). Q7.b doesn't change the lifetime model.

**R-B2: Stale cache after explicit local TLB flush.** If `flush_local_tlb()` is called explicitly (e.g., after a kernel-half page-table mutation that affects only this CPU), the cached CR3 value remains valid (CR3 didn't change). No risk.

**R-B3: Stale cache after IPI TLB shootdown to this CPU.** Same analysis as R-B2 — CR3 didn't change. Cache stays valid.

**R-B4: Cache update visibility on the *other* end of cross-CPU events.** If CPU A's `per_cpu.active_pmap_cr3` is being read by CPU B (e.g., for SMP debugging or for the shootdown sender's "which CPUs have this CR3 active" query), the cross-CPU read needs Acquire ordering. PM lean: hold the cross-CPU read concern for Q7.c (shootdown design) where it's load-bearing.

### 3.4 Q7.b sub-commit boundary candidates

- **Sub-commit 4a — wire `active_pmap_cr3` in scheduler.** Lands B2.a logic. Single isolated change to scheduler.rs (and possibly process.rs). Verification: gate equivalent to SC-3B closure gate (200/200 NEO_SMP=4) plus a micro-bench showing CR3 writes per second dropped on same-process context-switch workload.

PM lean: standalone sub-commit. Captures Q7.b's win cleanly before the larger Q7.c machinery lands.

## 4. THINK — Q7.c IPI TLB shootdowns

### 4.1 Design space

The shootdown design has several largely-orthogonal axes:

**Axis 1 — Granularity of invalidation:**

  - **G1. Full local flush.** Handler reloads CR3 with current value (`flush_local_tlb()`). Coarse; cheap to implement; correct.
  - **G2. INVLPG per-page.** Handler executes `invlpg [virt_addr]` for each address in the shootdown payload. Fine-grained; only invalidates affected entries.
  - **G3. Hybrid threshold.** Handler uses INVLPG for ≤N addresses; full flush for >N. Linux uses N ≈ 33 historically (tunable); seL4 simpler; FreeBSD ~6.

**Axis 2 — Target selection:**

  - **T1. Broadcast.** Send IPI to all CPUs except self. Simple; no per-Pmap bookkeeping.
  - **T2. Targeted (per-Pmap CPU mask).** Each Pmap tracks which CPUs have ever loaded its CR3; IPI only those CPUs. Requires per-Pmap CPU mask bookkeeping.
  - **T3. Targeted (active-only).** Walk `PER_CPU[]`, find CPUs whose `active_pmap_cr3` matches the affected Pmap, IPI only those. Requires Q7.b's cache field plus consistent cross-CPU read.

**Axis 3 — Synchrony:**

  - **S1. Synchronous (sender waits for ACK).** Sender increments a counter; receivers decrement on completion; sender spins until counter is zero. Correct but blocking.
  - **S2. Asynchronous.** Sender fires IPI and continues. Risk: page can be unmapped, freed, reallocated, and reused before targets invalidate — read of old page returns wrong data. Almost always rejected for correctness.
  - **S3. Synchronous with bounded wait.** Sender waits N microseconds; if no ACK, escalate (panic, retry, log). Adds robustness against stuck receivers.

**Axis 4 — Lazy TLB:**

  - **L1. None.** Every CPU receives the IPI regardless of state.
  - **L2. Skip-idle-and-kernel-only.** CPUs in idle loop or running kernel-only threads don't need user-space TLB entries; mark them "lazy" and skip IPI to them. Lazy CPU re-syncs on next user-mode entry.
  - **L3. Per-CPU lazy bitmap.** Track per-CPU "needs flush on next user transition" bit; lazy receivers set bit instead of flushing immediately.

**Axis 5 — Batching:**

  - **B1. None.** Each shootdown sends its own IPI immediately.
  - **B2. Per-sender queue + flush.** Sender queues addresses; flushes the queue periodically or at end of a code section. One IPI invalidates many.

### 4.2 PM lean for Q7.c

**G3 hybrid (INVLPG-with-threshold), T1 broadcast, S1 synchronous, L1 no-lazy, B1 no-batching.**

Specifically:

- **Granularity:** INVLPG for ≤16 addresses; full local flush for >16. Threshold conservative (favors INVLPG); revisit after measurement.
- **Target selection:** Broadcast to all CPUs except self. T2/T3 are deferrable performance improvements; require additional bookkeeping; correctness lives at the broadcast level. Linux 1.0 era used broadcast; targeted came later as proven optimization.
- **Synchrony:** Synchronous with bounded wait. Sender increments a global atomic counter; receivers ACK by decrementing; sender spins on `count > 0` with a 1ms wall-clock timeout. Timeout escalates to panic with diagnostic (likely indicates a stuck receiver — Hpw-style condition or hardware fault).
- **Lazy TLB:** Out. Deferred to a future sub-commit driven by measurement.
- **Batching:** Out. Deferred. Bible 1.2: correctness > performance.

This matches the "simple correct shootdown" baseline that every modern OS started with and then optimized atop.

### 4.3 Concrete shape

**New IPI vector:** `TLB_SHOOTDOWN_IPI_VECTOR: u8 = 0xfc`.

**Shootdown payload (shared state, allocated per-shootdown):**

```rust
struct ShootdownPayload {
    /// Address range to invalidate. (None, None) = full flush.
    /// (Some(start), Some(end)) = INVLPG each page in [start, end).
    range: Option<(VirtAddr, VirtAddr)>,
    /// Target CPU bitmask (for sender's own bookkeeping).
    targets: u64,
    /// Counter for ACK. Sender sets to popcount(targets); each receiver
    /// decrements; sender spins until 0.
    pending: AtomicU32,
}
```

**Sender flow:**

```rust
fn shootdown_range(start: VirtAddr, end: VirtAddr) {
    // 1. Self-invalidate first (synchronous; no IPI to self).
    invalidate_local_range(start, end);

    // 2. Build payload.
    let targets = other_cpus_mask();
    let n_targets = targets.count_ones();
    if n_targets == 0 { return; }

    let payload = Arc::new(ShootdownPayload {
        range: Some((start, end)),
        targets,
        pending: AtomicU32::new(n_targets),
    });

    // 3. Publish payload to per-CPU shootdown slot.
    publish_to_targets(targets, payload.clone());

    // 4. Send IPI to all targets.
    for cpu in iter_cpus_in_mask(targets) {
        apic::send_tlb_shootdown_ipi(cpu);
    }

    // 5. Wait for ACK with bounded timeout.
    let deadline = now() + Duration::from_millis(1);
    while payload.pending.load(Ordering::Acquire) > 0 {
        if now() > deadline {
            panic!("TLB shootdown timeout: targets={:b} pending={}", 
                   targets, payload.pending.load(Ordering::Relaxed));
        }
        core::hint::spin_loop();
    }

    // 6. Drop Arc — receivers also held a reference; payload freed when last drops.
}
```

**Receiver (IPI handler) flow:**

```rust
fn tlb_shootdown_handler() {
    // 1. Take payload from per-CPU slot.
    let payload = consume_local_shootdown_payload();

    // 2. Invalidate per payload range.
    match payload.range {
        Some((start, end)) => {
            let n_pages = (end - start).as_u64() / 4096;
            if n_pages <= 16 {
                for addr in iter_pages(start, end) {
                    invlpg(addr);
                }
            } else {
                flush_local_tlb();
            }
        }
        None => flush_local_tlb(),
    }

    // 3. ACK.
    payload.pending.fetch_sub(1, Ordering::Release);

    // 4. EOI to LAPIC.
    apic::end_of_interrupt();
}
```

**INVLPG inline helper:**

```rust
/// Invalidate the TLB entry covering `virt_addr` on this CPU.
#[inline]
pub fn invlpg(virt_addr: VirtAddr) {
    // SAFETY: INVLPG is a privileged instruction; correctness depends on
    // caller running in kernel mode (CPL=0). Has no operand-validity
    // preconditions beyond a canonical address.
    unsafe {
        core::arch::asm!(
            "invlpg [{}]",
            in(reg) virt_addr.as_u64(),
            options(nostack, preserves_flags),
        );
    }
}
```

### 4.4 Per-CPU shootdown slot

Receivers need a place to read the incoming payload. Three options:

**Option α — Single per-CPU slot.** Each `PerCpu` carries `pending_shootdown: AtomicPtr<ShootdownPayload>`. Sender CAS-stores; receiver loads, processes, clears. Limitation: only one shootdown can be in flight to a given CPU at a time. Senders requesting a shootdown to a CPU with pending shootdown spin until cleared.

**Option β — Per-CPU shootdown queue.** Each `PerCpu` carries a small ring buffer; senders enqueue; receiver dequeues. More complex; allows multiple in-flight.

**Option γ — Shared global queue, IPI as wake.** One global lockable queue; IPI just says "check queue"; receiver scans for entries targeting itself. Lock contention high.

PM lean: **α** for sub-commit 4. Single slot. Multi-in-flight shootdowns are rare; spinning serializes them cleanly. Build α first; measure; upgrade to β if measurement shows contention. Bible 4.3 (every dependency a liability) extends to data-structure complexity.

### 4.5 Q7.c risks

**R-C1: Hpw shape in shootdown handler.** The handler runs at IF=0. If it acquires a lock that preemptible code on the same CPU holds, Hpw deadlock. Mitigation: handler's lock acquisitions are all on `IrqSafeMutex` (post-ADR-019 sub-phase A landing) or are exclusively-ISR-context per ADR-019 Q2 ratification. Sub-commit 4 PLAN-stage will enumerate every lock the handler touches and verify the discipline.

**R-C2: Page-table modification ordering.** Sender must modify page table FIRST, then send IPI. If IPI fires before PTE write retires from sender's store buffer, receiver may invalidate-then-the-old-PTE-is-still-cached-or-prefetched. Mitigation: a full memory barrier (or specifically, a CPU-architectural fence — `mfence` or equivalent) between PTE write and IPI send. x86_64's store-to-store ordering is normally strong enough, but `mfence` is the conservative choice and cheap.

**R-C3: Shootdown timing during process exit.** A process exits; its threads on other CPUs are reaped (Q8.c, separate sub-commit). The exiting process's Pmap is destroyed, page tables freed. If a thread on another CPU is still in user mode with that Pmap's CR3 loaded when its TLB entries are invalidated and the physical pages freed — kernel data corruption. Mitigation: process-exit path must (a) freeze all threads of the process via Q8.c machinery, (b) ensure no CPU has the process's CR3 active, THEN (c) free Pmap and pages. Q7.c provides the shootdown primitive; correct process-exit sequencing is Q8.c's territory.

**R-C4: Cross-CPU race on `active_pmap_cr3` read (Q7.b interaction).** If sub-commit 4 also implements T3 (active-only targeted shootdown), the sender reads other CPUs' `active_pmap_cr3` field. PM lean defers T3 to a future sub-commit driven by measurement, so this risk is N/A at sub-commit 4. If T3 lands later, the read must be Acquire-ordered, and the field must be updated by Acquire/Release pairs at write sites in the local scheduler — non-trivial.

**R-C5: Stuck receiver causes sender panic.** §4.3 step 5 panics if a receiver doesn't ACK within 1ms. Choice of 1ms is conservative for the bounded wait. If a legitimate workload exists where a receiver could be IF=0 for >1ms (e.g., long critical section in another high-priority IRQ), the threshold needs adjustment. Mitigation: in practice no legitimate kernel critical section runs >1ms with IF=0; if one does, it's a separate bug. The panic surfaces the bug with full diagnostic.

**R-C6: IPI delivery failure / lost IPI.** Hardware-level: APIC IPI can in theory fail (legacy systems). Mitigation: relying on hardware semantics is standard practice; modern Intel/AMD CPUs deliver IPIs reliably. Defensive code (re-send on timeout) deferrable.

**R-C7: Calibration on new INVLPG callsite.** First INVLPG usage in the project. The helper is trivial inline asm, but the SAFETY comment and integration with x86_64 crate's existing primitives need care. PLAN-stage verification ensures correct usage.

### 4.6 Q7.c sub-commit boundary candidates

- **Sub-commit 4b — TLB shootdown machinery.** Lands the IPI vector, IDT handler, payload struct, sender API, INVLPG helper, per-CPU shootdown slot. No callers yet. Standalone, testable in isolation via a synthetic test that triggers a shootdown across all CPUs.

- **Sub-commit 4c — wire shootdown into Pmap mutation sites.** Modifies `pmap.rs`'s `unmap_page` (and similar) to call shootdown on cross-CPU-visible changes. Verification gate runs full SMP test suite plus a stress test simulating concurrent munmap.

PM lean: 4b and 4c as separate sub-commits — landing 4b first lets us gate-verify the machinery without any callers, then 4c wires call sites with confidence the underlying machinery is correct.

## 5. THINK — risks crossing both Q7.b and Q7.c

**R-X1: Order of sub-commits.** SC-3C has three natural sub-commits: 4a (Q7.b CR3 cache), 4b (Q7.c TLB shootdown machinery, no callers), 4c (Q7.c wiring into Pmap call sites).

PM lean for order: **4a → 4b → 4c.** Q7.b is independent and cheap; lands first. Q7.b's `active_pmap_cr3` field becomes a useful introspection probe even before Q7.c uses it. Q7.b's correctness is provable with the existing test suite. Then 4b lands the machinery; then 4c wires call sites.

Alternative order — **4b → 4a → 4c** — would land shootdown infrastructure before CR3 cache. Sensible if Q7.b's measured performance benefit is small and the bigger structural change (Q7.c) is the priority. Not PM lean's preference; PM keeps the 4a → 4b → 4c order to land easy wins first and isolate the bigger machinery commit.

**R-X2: Dependency on Jarvis bundle's IrqSafeMutex.** SC-3C's Q7.c handler may use `IrqSafeMutex` for sender-side state. If Jarvis bundle's sub-commit 3 (introduce `IrqSafeMutex`) hasn't landed by SC-3C BUILD time, fall back to `without_interrupts(...)` wrapping per Sub-step 5c discipline. Acceptable bridge code; ADR-019 sub-phase B/C migration normalizes it later.

**R-X3: Test infrastructure for cross-CPU TLB events.** SC-3B closure-gate machinery (200-boot stress runs at NEO_SMP=4) is the closest existing harness. SC-3C needs an equivalent gate. New scenarios needed:
- Concurrent munmap from CPU A while CPU B accesses the unmapped region (expect: B faults; correctness preserved).
- Process exit while threads run on other CPUs (expect: Q8.c reaps threads cleanly; no use-after-free).
- Same-process context switch on a single CPU (expect: Q7.b skip-CR3-write; verify via micro-bench or instrumentation).

The third (Q7.b's local skip-write) is gateable from sub-commit 4a alone. The first two (Q7.c shootdown correctness under stress) require sub-commit 4c.

**R-X4: PCID deferral implies future audit.** Deferring PCID (B3/B4) means every CR3 change still triggers a full TLB flush. If profiling shows TLB miss rate is the dominant cost in cross-process context switches, PCID becomes a follow-up sub-commit. Track this in the Phase 2 forward markers — not a blocker for SC-3C.

**R-X5: Bible 8.5.4 (Hpw discipline) applies to SC-3C handler.** The TLB shootdown handler runs at IF=0; any lock it touches must obey post-ADR-018 discipline. PLAN-stage enumerates every lock; PM verifies before BUILD.
