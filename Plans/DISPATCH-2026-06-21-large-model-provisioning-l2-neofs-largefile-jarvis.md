**Status:** DISPATCHED. **The brain last-mile, slice 2 of 2 — let NeoFS actually store + serve the real model.** L1 (`6e78fd2`) made a real Qwen2.5 `.neom` producible (0.5B → **485 489 152 B**, validates) + a **vocab sidecar** (separate file, 151 936 tokens). But NeoFS v1 caps a file at **8 direct blocks × 4 KiB = 32 KiB** — it physically cannot hold a ~485 MB model. L2 adds **indirect-block addressing** (direct + single + double + triple, ext2-style) so a file up to the 2 GiB `.neom` cap can be written by `neofs-mkfs` and read by the kernel, and extends the model-bundle staging to carry the large `.neom` **plus** the sidecar.

## 0. The decision this build makes
Turn "NeoFS can only hold a 32 KiB file" into "**NeoFS stores + serves the ~485 MB `.neom` (and the ~1.1–1.3 GB 1.5B model) + the vocab sidecar**" — by extending the inode from 8 direct block-pointers to direct + single-indirect + double-indirect + triple-indirect (the minimal, classic extension of the existing structure), with an independent byte-oracle for the on-disk indirect layout. **This is the last FS-side step before a real brain can boot.**

## 2. The numbers (pin the design to these)
- `FS_BLOCK_SIZE = 4096`; 8-byte block pointers ⇒ **512 pointers per indirect block**.
- Direct (8) = 32 KiB · single-indirect = 2 MiB · double-indirect = **1 GiB** · triple-indirect = 512 GiB.
- **0.5B `.neom` = 485 MB** (fits in double-indirect). **1.5B ≈ 1.1–1.3 GB > 1 GiB** ⇒ **triple-indirect is required** to reach the 2 GiB `NEOM_MAX_FILE_SIZE` (L1) — implement all three levels, not just double.

## 3. ISCs
- **ISC-1 — Inode indirect block-pointers (the format change).** Extend the on-disk inode: after the 8 direct pointers, add **single / double / triple** indirect pointers (one each, ext2-style). Update `format.rs` (the inode layout + a `MAX_FILE_BLOCKS`/max-size constant reflecting triple-indirect ≥ 2 GiB). **Preserve the existing inode field order/offsets for the direct portion** — small files must stay byte-identical on disk (see ISC-5 equality).
- **ISC-2 — The logical→physical block walk (kernel read path).** Extend the block-resolution in `inode.rs` (the function mapping a file's logical block index → physical FS block, used by `read_at`/`read_verified_logical_content`) to walk the indirect tree: logical index < 8 ⇒ direct; < 8+512 ⇒ single; < 8+512+512² ⇒ double; else triple. Each indirect lookup reads the pointer block via the existing `cache.rs` `read_block`. **Bounds-check every level** (a corrupt/out-of-range pointer ⇒ `NeoFsError`, never an OOB read). Reads stay fail-closed + verified (the existing `read_verified_logical_content` contract).
- **ISC-3 — `neofs-mkfs` large-file write (host).** Extend the image writer to **allocate + populate** the indirect blocks when staging a file > 8 direct blocks: write the data blocks, build the single/double/triple indirect pointer blocks, set the inode pointers. Then extend the **model-staging path** (`--extra-model` / `prepare_neofs_storage_disk_with_model`) to stage **both** the large `.neom` **and** the vocab **sidecar** file (L1 emits two files). **No model/GGUF/vocab blob in git** — staged from an on-disk path at image-build time only (the bundled-model/firmware discipline).
- **ISC-4 — Byte-oracle (independent, hand-laid — the format rule).** A **hand-laid fixture** for the indirect on-disk layout: the inode's indirect-pointer fields at their exact offsets, and a single-indirect block as a 512-entry LE-u64 pointer array, asserted **independent of the writer+reader round-trip** (round-trip alone is insufficient — the ADR-028 lesson). Include the **boundary indices**: the last direct (7), the first single-indirect (8), the first double-indirect (8+512), the first triple-indirect (8+512+512²) — each maps to the hand-computed physical block. Round-trip a multi-level file (write via mkfs → read via the kernel walk → bytes identical) as the *complementary* check, not the oracle itself.
- **ISC-5 — Kill-switch / additivity (equality regression).** The change must be **additive: every file ≤ 8 direct blocks reads + writes byte-for-byte identically** (the indirect fields are zero/unused for small files). Prove it: an equality regression that all existing NeoFS files/scenarios are bit-identical on disk before/after (the inode direct-portion offsets unchanged; indirect pointers zero when unused). If any small-file on-disk byte changes, that's a fail. (A `neofs-large-file` feature gate is optional given additivity-by-construction; if used, default-off ⇒ bit-for-bit today and large reads ⇒ a clear "unsupported" error.) **No new cross-cutting invariant** (a bounded extension of an existing format); I-15 file-caps unaffected (a large file is the same `Handle::File` capability).
- **ISC-6 — Standards.** SPDX on new files. `fmt`/`clippy --workspace --all-targets -D warnings` via Docker (kernel clippy blocking). ADR-064 (NeoFS large-file / indirect blocks) + an ADR-063 amendment (L2 closes the 8-direct-block limit). New `unsafe`: none expected (block I/O + pointer arithmetic in safe Rust). Update the `complexity-governance.md` lock census only if a new lock is added (prefer reusing the existing NeoFS cache lock — flag if a new one is needed, per OT-13).

## 4. Gate
- **Host KATs:** the ISC-4 byte-oracle (inode indirect fields + the 512-entry indirect block + the four boundary indices → hand-computed physical blocks); `neofs-mkfs` writing a multi-level file then the pure block-walk resolving every logical index correctly; the **equality regression** (small files bit-identical); out-of-range/corrupt-pointer ⇒ error (no OOB).
- **QEMU scenario `neofs_large_file`:** boot → mount a NeoFS image containing a file that spans **into the double-indirect range** (a few MB — large enough to exercise direct→single→double, small enough for CI guest RAM; the full 485 MB is the bare-metal/integration proof, not CI) → read it back → byte-exact vs the known content; a small file in the same image still reads correctly (the additivity regression on silicon). At `NEO_SMP=4`. **Kernel-gated — serialize behind the in-flight kernel gates (M2), rebase LAST.**

## 5. Scope guard
NeoFS indirect-block large-file support (read + mkfs-write) + the large-`.neom`+sidecar staging + the oracles **only**. **Do NOT** change the `.neom` format or the importer (L1, landed — L2 *stores* what L1 produces), the kernel forward graph / inference (OT-16 frozen — L2 makes the model *readable*; actually *running* it is the integration/Stage-B step), the capability model (I-15 — a large file is the same `Handle::File`), or other FS features (no extent trees, no sparse files, no journaling changes — just indirect blocks). **No model/GGUF/vocab blob in git.** No new invariant.
