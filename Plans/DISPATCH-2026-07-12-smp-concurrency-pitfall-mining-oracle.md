## The framing (why this is valuable AND bounded)
"The answer is out there" is true for the **principle**, not for **drop-in code**: prior-art fixes are welded to their host kernel's primitives, we made different (capability-secured, our-own-lock-type) design choices, and the bugs manifest at seams we built new (the OT-59 second race — a shootdown at a published-but-not-yet-ring-3 CPU — lives at *our* spawn/ring-3 seam). So the deliverable is a **checklist of documented traps + the discipline that avoids each + our-exposure mapping + a discriminator to pre-seed** — NOT a code port. It shortens the search for the known classes; it does not replace the AAG or testing (patterns-known ≠ correctness-proven — the seL4 lesson).

**Hard licensing rule (state it in the FINDINGS):** Linux/GPL and other copyleft sources may be **read for principle/understanding and cited**, but **NO code is copied** into our MPL kernel — extract the pattern/discipline, cite the source, re-derive in our primitives. This is a learn-the-answer pass, never a lift.

## ISC-2 — the pitfall categories to cover (at minimum)
- **Lock ordering / deadlock** — ABBA cycles, the lockdep discipline, hierarchical lock ranking.
- **IRQ-safe locking** — the exact class we hit: holding a lock with interrupts disabled while awaiting another CPU that needs the lock; when to disable IRQs, when NOT to; interruptible vs non-interruptible waits; IF-state restoration.
- **TLB shootdown / IPI** — shootdown-must-be-IRQ-safe on the critical path; `INVLPG` and paging-structure-cache ordering; the ack/EOI ordering; **shooting down a CPU that isn't running your address space** (the `mm_cpumask`/active-mm concept — a documented answer directly relevant to our second race); the publication-before-target-ready class.
- **Memory ordering / barriers** — x86-TSO specifics (what's free, what needs a fence), acquire/release, `mfence`/`lfence`/`sfence`/`lock` semantics, when a `compiler_fence` vs a CPU fence is required.
- **Per-CPU data + scheduler/wake races** — the reap→wake→scheduler-lock class (directly relevant to Cerebro's OT-59 lane), missed-wakeup vs lost-wakeup, park/unpark rearm ordering.
- **Atomics / RMW pitfalls** — ABA, torn reads, the wrong Ordering on an atomic.
- **The "publication before ready" class** — a resource made visible before it's safe to act on (our second OT-59 race is a member — name the general pattern + the known guard: readiness handshake / state gating before cross-CPU action).
