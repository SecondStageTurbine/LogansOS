**What it does.**
- **Kernel:** per-thread FS.base on `Thread`, loaded on every user switch-in through a per-CPU cache that starts at
  a non-canonical sentinel. `SYS_THREAD_SET_TLS = 0x4F`, gated on the C1 capability (EPERM/EFAULT).
- **Userland:** `libneo::ntls` (keys with a generation check; destructors clear before calling, up to 4 passes; the
  key block is on the heap), wired through `nthread`'s bootstrap and exit.
- **Gate:** a key-only xtask gate rejects any staged user ELF with PT_TLS, SHF_TLS, STT_TLS or TLS relocations.
- **Kill-switch:** `browser-runtime` off gives a byte-identical kernel.

## Checklist

Answer each item PASS or FAIL with `file:line`. For a FAIL, give a concrete schedule (which CPU runs which thread, in
what order) or input, and the wrong result.

1. **Switch-in.** Every path that resumes a user thread loads that thread's FS.base before its first user
   instruction:
   - context switch;
   - first run of a new thread;
   - return after migration;
   - the IPC handoff's migrating wake;
   - any direct-switch fast path.
   Is there any path that returns to ring 3 without it?
2. **The per-CPU cache.** It's correct across:
   - CPU bring-up (the sentinel);
   - a kernel thread running in between (the load is skipped, and the cache must still describe the MSR);
   - an interrupt or NMI on the way out;
   - a CPU that ran another process's thread.
   Can the cache ever claim a value the MSR doesn't hold?
3. **SYS_THREAD_SET_TLS on the running thread.** It updates `Thread.fs_base`, the MSR and the cache together, with
   no window where a preemption restores the old base. A non-user or non-canonical base is refused (EFAULT), and so
   is a call without the capability (EPERM).
4. **Exit.** Destructors run in userland before SYS_THREAD_EXIT. Check:
   - clear-before-call;
   - at most 4 passes;
   - the generation check stops a deleted-then-recreated key from running a stale destructor;
   - the heap key block is freed after the last destructor;
   - a thread killed from outside doesn't run user code.
5. **The key-only gate.** It scans the final ELF for every TLS form (PT_TLS, SHF_TLS, STT_TLS, TLS relocations and
   `%fs:` accesses outside libneo's sanctioned site). Its falsification tests fail on a planted `#[thread_local]` and
   a C `__thread`.
6. **The kill-switch.** With `browser-runtime` off, nothing new is compiled or reachable (the byte-identity SHA-256s
   are in the PR).
7. **The pitfall bank.** CP-83 is stated correctly. Check the pitfall table in the PR body against
   `docs/concurrency-pitfalls.md` for the classes this change touches: migration, IPI and NMI paths, lock ordering on
   the switch path.
8. **What the gate didn't cover.** Name any case that QEMU NEO_SMP=4 can't exercise but real silicon could, such as
   an NMI between the switch and iretq, or an MSR write cost on a hot path.
