- [x] **PASS — #261, syscalls and OS ABI.** The C/C++ shim emits no raw syscall; its calls go through std (`userland/neo-crt/src/lib.rs:5-16`; `docs/THINK-2026-10-31-ot61-c3a-cxx-runtime.md:54-61`). Existing PAL operations exercised by the runtime are `SYS_WRITE`, `SYS_EXIT`, `SYS_MAP_REGION` (allocator), `SYS_CLOCK_GETTIME`, `SYS_FUTEX_WAIT`/`SYS_FUTEX_WAKE` (guard mutex/condvar), and `SYS_SCHED_YIELD` (`__lock`); the smoke's Rust threads additionally use the existing thread/TLS calls. The manifest lists these existing operations at `tools/ot61-pal-manifest.toml:54-65,130`. No syscall number or kernel syscall ABI is added or changed; this adds a private C/C++ runtime ABI.

- [ ] **FAIL — #261, allocator input validation; no futex lost-wakeup found.** Allocation-size arithmetic is checked (`userland/neo-crt/src/lib.rs:85-99,123-130`), and the function-local-static guard serializes state changes and notifies under its mutex (`:368-404`); its wait/wake sequencing has no lost wakeup in the examined path. The pthread override intentionally provides only shared read-only locale state, while errno is std TLS; pthread/futex APIs are not implemented (`userland/neo-crt/c/override/pthread_impl.h:4-18,24-36`; `userland/neo-crt/c/neo_bottom.c:64-95`). Concrete invalid inputs: `aligned_alloc(0, 1)` is accepted because zero is raised to `MIN_ALIGN` in `raw_alloc`, and `aligned_alloc(16, 17)` is accepted without enforcing the size/alignment multiple (`userland/neo-crt/src/lib.rs:85-90,180-183`). These violate the allocator's input contract. The smoke does not cover either case.
