## The framing (what makes this OUR study, not a listicle)
Three LogansOS realities shape every verdict:
1. **"Recompile as a cap-native client" has prerequisites.** Our userland today is `no_std` Rust on libneo (SDK-ABI); real desktop Rust apps assume full `std` (filesystem, threads, net) and often a GPU (`wgpu`). So every candidate gets an honest **feasibility tier**, and the study must state the **prerequisite ladder** (what the SDK/ABI must grow — a `std` port target is itself a build; which toolkit backend lands first). "It's Rust" is the *start* of feasibility, not the end.
2. **Purity is verified, never assumed.** "Written in Rust" frequently hides a C skeleton (GTK-rs binds C GTK; many apps pull `*-sys` crates — freetype-sys, openssl-sys, sdl2-sys…). **The un-fakeable check: read each candidate's actual dependency tree** (`Cargo.toml`/`Cargo.lock`/`cargo tree` from the real repo) and disqualify or flag every C-binding. This is the acquisition rule applied to dependency claims.
3. **The AI-native twist — prefer the library over the app.** For many categories, LogansOS's best "app" may be a **pure-Rust library wired into Arthur/a Workfield** rather than a ported windowed program: e.g. `symphonia` (pure-Rust audio decoding) as the media substrate rather than porting a player; an email *library* behind an Arthur skill + a Workfield rather than a mail client's own UI. Evaluate each category BOTH ways: best portable app AND best embeddable library — and say which fits the Atrium better. (Arthur + `neo>` already *are* the file manager and the calculator — don't shop for what we natively supersede.)

- **ISC-1 — the feasibility-tier framework (define first, then sort everything into it).** Suggested tiers, refine as evidence demands: **T1 — console/transcript-compatible** (runs against a text interface; nearest-term — but state honestly what TUI apps assume [VT100/termios] vs what our transcript console provides — a real gap to name); **T2 — CPU-rendered GUI** (egui/softbuffer/tiny-skia/Slint-software-renderer class — feasible once the G1 winit/softbuffer backend + a `std` target exist; NOTE: verify which toolkits truly have software renderers — Slint's and iced's tiny-skia backend are claims to check firsthand); **T3 — GPU-required** (`wgpu`-based — waits on our accel path speaking a compute/graphics API); **REJECTED — C-dependent** (any load-bearing `*-sys`/C toolkit). Each tier states its prerequisite builds.
- **ISC-2 — the category sweep (the PL's list + the obvious shelf).** For each: **text editor/notepad** (e.g. Lapce, Zed, Helix, the egui/iced editors — check each's toolkit + GPU + std needs; Helix is terminal-first, which may make it the earliest real editor); **email** (GUI clients are thin in pure Rust — check Himalaya [CLI + lib], and evaluate the library-behind-Arthur shape); **image editing "like GIMP"** (probably the honest gap of the study — check Graphite [Rust core, web-delivered frontend?], any egui/iced raster editors; an image *viewer* [e.g. oculante] is a separate, easier row); **image viewer**; **media/music player** (psst, ncspot vs the `symphonia`/`rodio` library route); **PDF/document viewer**; **notes/markdown**; **calculator** (vs Arthur-native); **file manager** (vs Arthur/`neo>`-native — likely superseded); **terminal multiplexer/tools** (gitui, zellij, yazi — the T1 shelf); **web browser** (be honest: Servo's real state + deps, and whether "browser" is a day-1 aspiration at all). Per candidate: **toolkit, dependency purity (verified from the tree), license (from the LICENSE file — MPL-2.0-shippable?), maintenance health (last release/commits, bus factor), std/GPU/net needs, tier, and a one-line verdict.**
- **ISC-3 — the day-1 shelf recommendation.** From the sweep: the concrete **preload shortlist** per tier — what a first shipping image could honestly carry at each stage of the prerequisite ladder (T1 shelf at v1-console; T2 shelf at G1+std; T3 later). Flag which categories the north-star review's S7 ("never a dead end") makes load-bearing.
- **ISC-4 — the library-not-app table.** Per category, the best pure-Rust **library** (symphonia, image/zune-image, cosmic-text/pulldown-cmark, an email lib, a PDF lib…) + what wiring it into Arthur/a Workfield would look like vs porting the app — and your recommendation per category. This is where LogansOS stops imitating a distro's preload list and starts being itself.
- **ISC-5 — the prerequisite ladder, honestly costed.** What must exist before each tier ships: the `std`-on-LogansOS target (the relibc-analog question — how big is that really? What did Redox's path cost — read their docs firsthand as the prior art), the G1 winit/softbuffer backend (already banked), net/TLS surface for email/browser-class apps (we have an HTTPS path — what's its userland exposure?), audio out (banked in OT-46 as the voice-lane driver dependency — same driver serves media). Sequence: which single prerequisite unlocks the most shelf.
- **ISC-6 — gaps + ledger disposition.** Name the categories where **nothing shippable exists** in pure Rust (candid list — likely GIMP-class raster editing and the browser) and the honest options (library-route, wait, or the bounded-island pressure valve).
