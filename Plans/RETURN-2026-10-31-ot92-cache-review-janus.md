An isolated Rust host harness compiled the head's actual cache structs, constants, insertion/eviction helpers and `forget_range` method with platform types stubbed, in both feature-on and feature-off configurations. Assertions confirmed dirty-block preservation, the over-capacity case in item 5, and the off-mode counterexample in item 4. This was source review plus helper execution; no kernel/QEMU or stalled-device injection was run.

- **1. PASS — eviction preserves dirty blocks and active accesses.** `kernel/src/fs/neofs/cache.rs:678-696` selects only `!dirty` victims under `inner`. Reads copy into caller-owned storage while holding that same lock (`:190-245`); writes merge and mark dirty before eviction, still under the lock (`:273-279`, `:307-347`). No borrowed cache buffer escapes to another CPU. The flusher snapshots owned bytes (`:742-767`), keeps the block dirty during I/O, and clears dirty only after successful I/O and a matching block/role/content recheck (`:789-805`). Evicting that subsequently clean block cannot invalidate the snapshot. The miss epoch prevents stale reinsertion, and partial writes retry when it changes (`:307-340`, `:661-671`). `forget_range` (`:358-366`) is a separate pre-existing invalidation of newly allocated, unreferenced blocks, not the clean-only capacity policy.

- **2. PASS — no writer/flusher lock cycle found.** Eviction takes `inner` (IRQ-safe), then the heap allocator when dropping the victim's byte vector; heap deallocation masks interrupts and takes its heap lock (`kernel/src/mm/heap.rs:134-143`). The throttle samples `inner` and releases it (`kernel/src/fs/neofs/cache.rs:445-450`), then takes `entries` (`kernel/src/fs/neofs/inode.rs:832-835`). `drain_all` briefly takes/releases `inner` to pause the worker, acquires `drain`, and alternates short `inner` sections with device I/O outside `inner` (`cache.rs:369-405`, `:742-805`). Thus the nested order is `entries -> drain -> inner`, or `entries -> drain -> device locks`, never `inner -> device wait`. Mutators call the throttle before their own pause/namespace/metadata guards (`inode.rs:231-233`, `:308-310`, `:490-492`, `:550-553`, `:591-592`, `:671-672`, `:772-773`); the inode record/block guards are released before the regular-file commit call (`:1909-1926`, `:1942-1957`). The worker takes no `entries` lock and only tries `drain`, so a throttled writer holding `entries` does not block a lock the flusher needs. Syscall write/truncate bodies run with interrupts enabled (`kernel/src/arch/x86_64/syscall.rs:6737`, `:6790`).

- **3. FAIL — the throttle can wait forever on a non-completing device request (high).** `kernel/src/fs/neofs/inode.rs:833-835` synchronously drains while holding `entries`; `kernel/src/fs/neofs/cache.rs:374-381` has no deadline around acquiring `drain` or running the pass. Concrete input: accumulate at least 128 dirty blocks with writeback held, then make the next virtio block write never complete and start another mutation. The throttle reaches `write_fs_block` (`cache.rs:789`), and the driver parks without a timeout (`kernel/src/drivers/block/virtio_blk.rs:895-909`), retaining the throttle's namespace/drain guards indefinitely. Alternatively, stall an already-running worker's request: the throttle spins acquiring its `drain` lock. The driver's unbounded wait is inherited; this PR makes ordinary mutations enter it automatically at the dirty threshold. Returned device errors do propagate (`cache.rs:789`, `:835-849`; `inode.rs:2677-2691`); the 10,000 retry limits bound returned busy results, not an individual call that never returns. There are no externally pinned cache-buffer references: an all-dirty cache makes eviction return immediately (`cache.rs:690-691`), rather than waiting for a victim.

- **4. FAIL — `None` does not preserve the previous behavior bit for bit (medium).** The main switches do bypass capacity eviction and the throttle (`kernel/src/fs/neofs/cache.rs:33-46`, `:446-447`, `:679-680`), but `forget_range` unconditionally increments the new epoch (`:358-366`), and miss insertion unconditionally checks it (`:667-668`). Concrete input: build with `neofs-large-write` enabled and `neofs-cache-evict` disabled; cache block A, start a miss for unrelated block B and pause after its device read, call `forget_range(A, 1)`, then finish B's miss. The epoch moves from 0 to 1 and B is not inserted. Before this PR, B was unconditionally inserted on re-lock if absent. The host harness confirmed both the off-mode epoch increment and the skipped insertion. The real invalidation caller is `kernel/src/fs/neofs/inode.rs:436`. This is a cache-behavior/statistics difference, not evidence of lost file bytes; the PR's claim that the off-mode epoch never moves is false.

- **5. FAIL — the required CP rows are present, but the CP-64 bound does not hold (medium).** The PR description has CP-37/56, CP-56/91, CP-64 and CP-2/3 rows, plus the stale-miss analysis. The lock/drop claims are supported by item 2. However, CP-64 claims each eviction scans at most 257 entries and shifts at most 256 headers. Concrete input: from a clean cache, truncate an empty writable file to `300 * 4096` bytes on a sufficiently large volume. `kernel/src/fs/neofs/inode.rs:671-688` checks the throttle once, pauses the worker, and then caches the entire new content. Each new dirty block is ineligible for eviction (`kernel/src/fs/neofs/cache.rs:276-277`, `:687-691`); no admission bound enforces 256 during the transaction. The helper harness retained all 300 dirty blocks, then insertion of one clean block scanned 301 entries and left 300 cached. Concurrent writers can also pass the threshold before either adds its transaction. Thus the claimed 257-entry IF-off scan bound, and the general assertion that dirty blocks stay below capacity, are unsupported. This demonstrates the false bound; it does not claim a measured shootdown timeout. The relevant bank entry is `docs/concurrency-pitfalls.md:3038` (CP-64).
