1. **PASS — one acquisition surface.** `kernel/src/ai/arena.rs:160` is the sole direct `ARENA.lock()`; alloc (217), register_static (250), lookup (275), free (347), retain (378), release (404), live_keys (444), handle_count (468), and the test seam (516) all use it. No try_lock or other bypass. The accelerator simulator's separate ARENA is outside this review.

2. **PASS — production nesting is IRQ-safe.** No tensor-slot, RESERVATIONS, REGISTRY, DEDUP, accounting or daemon lock is taken under the production table guard. `alloc` populates its newly allocated slot before acquisition (`kernel/src/ai/arena.rs:212`); `lookup` only clones a SlotRef (275); mint calls guarded_clone after lookup returns (298); free/release move the occupant out before drain (346,403). The comment permitting 12 < 15 nesting is permission, not an actual production nesting edge. The implicit nested lock is the heap: entries.push (237,261), free-list recycling (365,425; `kernel/src/ai/arena_logic.rs:71`), and live_keys collect (444). Every heap inner-lock acquisition (including used/init) masks interrupts (`kernel/src/mm/heap.rs:72,84,100,120`); the inner guard ends before IF restoration. It neither calls back into ARENA nor parks. Heap instrumentation uses atomics (`kernel/src/observability.rs:292,301,309,391`). Thus no preemptible same-CPU heap holder can strand an IF=0 ARENA holder.

   **Test-only exception to “no section takes another lock”:** debug_with_arena_held executes its callback under ARENA (`kernel/src/ai/arena.rs:515`). Its sole caller nests RESERVATIONS (20), INFLIGHT (22), TABLE (25), RECENCY (28), DELIVERY, STATE and BOOT_LINES, then the ISR's WAITER and possibly I/O-APIC/scheduler wake locks (`kernel/src/drivers/i2c_hid/touchpad.rs:1732-1745,1080`; `kernel/src/ai/reservation.rs:543`; `kernel/src/drivers/accel/accounting.rs:284`). BUS_OWNER is a CAS flag, not a spinning acquire. DELIVERY/STATE/WAITER mask interrupts structurally. The governance SwitchMutexes do **not**: e.g. IF-on accounting callers exist (`kernel/src/drivers/accel/accounting.rs:107,161,192`). The supplied absent-device scenario launches no competing AI reservation/accounting workload before this direct ISR probe (`kernel/src/test_harness.rs:25385-25425`), so this does not invalidate that scenario. Do not reuse the seam under arbitrary concurrent AI activity: CPU 0 could preempt an IF-on TABLE holder, enter this seam, mask IF on ARENA, and spin on TABLE forever. This is a limitation of the test seam, not proof that these other locks became IRQ-safe. The production “no other lock” claim also needs the heap qualification above.

3. **PASS — no production park or tensor destruction under ARENA.** All table sections manipulate entries, counters, Arc clones and vectors. free/release extract an occupant into an outer variable; the guard ends before drain (`kernel/src/ai/arena.rs:346-371,403-432`). drain may park/yield or drop Tensor, but is outside ARENA (498). New ManagedSlot allocation/put precede the guard (212-217). Allocation under the guard occurs in entries growth, free-list growth, and live_keys collection as listed above; allocator operations are IRQ-safe and do not grow/map the heap or wait for I/O. Vector relocation/linear live_keys traversal are size-dependent work: the claim “costs nothing” (132-133) is not a latency bound. No new loop or allocation algorithm was added by this PR.

4. **PASS — both IF states for the table itself.** Forward weight mint (`kernel/src/ai/exec.rs:110`), KV alloc/mint/release (`kernel/src/ai/kv_cache.rs:78,172,182`), tensor syscall mint/alloc/handle_count/release (`kernel/src/arch/x86_64/syscall.rs:1894,1898,1961,1969`), and handle-table retain/release (`kernel/src/sched/process.rs:1276-1287`) reach the same wrapper. `IrqSafeMutex::lock` snapshots IF and masks before the inner spin (`kernel/src/sync/irqsafe_mutex.rs:48`); Drop releases the inner guard before restoring IF (139). IF=0 stays off; IF=1 returns on. No production section requires ticks or scheduler preemption to finish. This certifies ARENA, not every later lock in mint/drain: reservation's slot protocol remains unchanged and outside this conversion (`kernel/src/ai/reservation.rs:419`).

5. **PASS — I-14(a) still executes.** `handle_interrupt()` is called directly at `kernel/src/drivers/i2c_hid/touchpad.rs:1745`, inside all held sections, not delivered by a masked self-IPI. Its body increments IRQS, masks the device line, sets PENDING and takes/wakes WAITER (1080-1093); it does not acquire the deliberately held governance/driver locks. The scenario asserts exactly one IRQ-body increment and successful BUS_OWNER acquisition (`kernel/src/test_harness.rs:25425-25432`). It proves direct body completion with these locks held; it does not prove hardware interrupt delivery while IF=0. See item 2's isolation requirement.

6. **PASS — witness and negative control wiring.** The witness samples IF after acquisition, while the guard is live (`kernel/src/ai/arena.rs:160-168`); it cannot count merely the caller's entry state. `run_arena_if_off` asserts entry IF=1, allocates, checks inference closure IF=1, mints/counts under without_interrupts, releases, and rejects a nonzero delta (`kernel/src/test_harness.rs:29228-29276`). The control replaces the lock with plain SwitchMutex, so IF-on alloc/mint/release increment and lead to arena_held_with_interrupts_on. IF-off mint/count do not increment. Control feature implies the witness scenario (`kernel/Cargo.toml:1237-1241`); xtask registers only the ordinary arena_if_off feature and mentions control solely as an EXTRA_FEATURES opt-in (`tools/xtask/src/main.rs:4612-4623`). No control gate entry found.

7. **PASS — exact old lock type.** Under the control, ArenaLock aliases SwitchMutex and uses the unchanged table initializer and lock_order::ARENA (`kernel/src/ai/arena.rs:136-147`). The diff otherwise replaces acquisition sites with the wrapper and adds instrumentation; table lifecycle decisions are unchanged. The ordinary build aliases IrqSafeMutex at the same level 12.
