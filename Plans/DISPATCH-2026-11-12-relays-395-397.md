- **Dispatch:** `Plans/DISPATCH-2026-11-11-seat-e-f0-neofs-dir-ops.md`.
- **Design:** `docs/THINK-2026-10-29-ot88-app-model.md` §4.2.

1. **One commit per operation.**
   - [ ] `mkdir_at`, `unlink_at`, `rename_at` and `stat_at` (`kernel/src/fs/neofs/inode/dir_ops.rs`) each commit
     exactly once through the commit barrier.
   - [ ] The superblock is written last.
   - [ ] Freed blocks are not reused before the commit is durable.
   - [ ] A crash cut after any write leaves the old tree or the new one, never a mix. Check the host cut KATs in
     `tools/neofs-dir-ops-logic-tests/src/cut_tests.rs` against the code.
2. **Rights.**
   - [ ] Without WRITE on the directory handle, mkdir, unlink and rename are refused with `EACCES`.
   - [ ] Without LOOKUP, `stat_at` is refused.
   - [ ] For `rename_at`, both handles are checked.
   - [ ] No operation reaches outside the handle's scope by name. Check `..`, `/`, an empty name and an over-long
     name.
3. **The rules.**
   - [ ] Unlink refuses a non-empty folder.
   - [ ] Rename refuses to replace an existing name, and refuses to cross volumes (`EXDEV`).
   - [ ] Renaming a folder into its own descendant is refused.
   - [ ] Every limit gives a clean error: 64 entries per folder, 47-byte names, 32 KiB files.
4. **The format.**
   - [ ] An empty or newly created folder is written with no data block, as the format requires.
   - [ ] The scenario's 9-block byte oracle is hand-laid, independent of both the writer and the reader.
5. **User arguments.**
   - [ ] Every user pointer and length is validated before use (`EFAULT`/`EINVAL`) in `syscall.rs`.
   - [ ] The `stat_at` record matches its ABI entry in `docs/SDK-ABI.md`, with a byte oracle.
6. **Concurrency.**
   - [ ] The PR's CP-table rows hold for the NeoFS lock order. That covers the per-volume lock, the cache and the
     handle table.
   - [ ] No lock is held across a blocking device wait that a writer elsewhere also takes.
7. **Kill-switch.**
   - [ ] With `neofs-dir-ops` off, none of the four syscalls exists and the syscall table is unchanged.
