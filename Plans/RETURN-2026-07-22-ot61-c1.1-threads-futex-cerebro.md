## What shipped
**P1 futex** (`kernel/src/sched/futex.rs`): `SYS_FUTEX_WAIT(uaddr, expected, deadline_monotonic_ns)`
with an **ABSOLUTE monotonic deadline** (`u64::MAX`=∞, `0`=already-expired, `-EAGAIN` on value mismatch,
`-ETIMEDOUT` on deadline) + `SYS_FUTEX_WAKE(uaddr, count)` returning the **preserved wake count**. Kernel
wait-queue keyed by the futex word's **physical** address (`Pmap::translate` — aliased mappings share a
queue), built on the named substrate `try_block_current_with_token_and_guard` + `wake_thread_token`. Timer-
tick absolute-deadline expiry scan (one relaxed load on the no-timed-waiter fast path).

**P2 threads** (`kernel/src/sched/{process,thread,scheduler}.rs`):
`SYS_THREAD_{CREATE,EXIT,JOIN,DETACH,SELF,SET_NAME,GET_INFO}` + `SYS_SCHED_YIELD` in the reserved
**`0x44..0x4D`** block (`0x4E..0x4F` left for C1.2 TLS). Per-process **thread registry + refcount** (the
`Pmap`/`Process` drops only on the LAST thread's reap — `on_thread_reap_threaded`); **`thread_get_info →
{tid, usable_low, usable_len, guard_low, guard_len}`** with downward-stack semantics, populated for the
**initial** process thread too (the SpiderMonkey `JS_SetNativeStackQuota` stack-limit seam); **TLS-free
bootstrap trampoline** (`enter_userspace_arg_trampoline` — `arg` in RDI, other caller-saved regs zeroed);
guarded thread stacks via C1.0's `vm_map(guard)`; join/detach/exit-status via a per-thread done-record
(single-joiner POSIX semantics, zombie record survives reap until collected). Ring-3 `#PF` **fault-kill
(I-14b)**: the faulting **process** dies (exit 139), the kernel + governance stay live.

**Userland** (`userland/libneo/{nsync,nthread}.rs` + shims): futex-backed **mutex / condvar / rwlock** —
the frozen `futex → {mutex, condvar, rwlock}` convergence, all userland — the rwlock's write-unlock
**consumes the wake-count** for its writer→reader fallback (the amendment's live consumer); `nthread::spawn`
over the TLS-free trampoline. pthread mutex/cond ride the same two ops (C2/C3 integration).

**Kill-switch / cap / invariant:** every C1.1 syscall behind the default-off `browser-runtime` feature

## Concurrency-pitfall consultation (`docs/concurrency-pitfalls.md`, CP-1…CP-29)
- **CP-8 / CP-14 / CP-17 (lost wakeup / publication-before-ready) — GUARDED, battery-proven.** The futex
  compare-then-park is atomic against a concurrent wake: `*uaddr == expected` is re-checked **under the
  FUTEX_QUEUE guard**, and `try_block_current_with_token_and_guard` releases that guard atomically with the
  context switch **on the new stack** (move-into-token-table + take-once + release-on-new-stack = the
  "not-runnable-elsewhere-until-off-CPU" invariant). **Discriminator:** the `lost-wakeup` battery — 2000
  wake-races-wait ping-pong rounds; any timeout is a lost wakeup. Green.
- **CP-1 (lock ordering) — GUARDED.** Order is FUTEX_QUEUE (leaf) → scheduler lock; every dual-lock path
  respects it (wait holds the queue guard into the block primitive; wake/expiry **drop** the queue guard
  before `wake_thread_token` takes the scheduler lock — the CP-16 discipline). Nothing takes the scheduler
  lock then the futex queue. The futex path takes **no** AI-governance lock (I-14a, grep-checkable +
  asserted in the module header).
- **CP-16 (wake under a foreign lock) — GUARDED.** `futex::wake` / `on_tick_expire` collect matching tokens
  under the queue guard, **drop it**, then call the scheduler wake path outside it.
- **CP-12 (ABA / generation reuse) — GUARDED (reused).** Wakes go through `wake_thread_token`, which is
  generation-checked; a stale/torn-down target wakes as `Stale`/`Gone`, a safe no-op.
- **CP-19…CP-28 (teardown / cross-CPU handoff race) — GUARDED, and this slice found + fixed a real member.**
  The refcount teardown must not use-after-free the shared `Pmap` on the last reap. **NEW pitfall learned on
  the local gate (added to the bank as CP-30 below):** a thread **force-zombified while blocked in a
  syscall** has its kernel stack freed as **raw memory** — Drop never runs — so any **owned `Arc<Process>` /
  `Arc<Pmap>` on that stack leaks its refcount** and strands the whole process + Pmap (observed: a
  guard-fault kill left +157 frames leaked because the joining thread held `Arc<Process>` and the
  futex-parked thread held `Arc<Pmap>` across their blocks). **Fix:** the user-blocking paths hold **no
  owned Arc** across the block — the futex translates `uaddr→paddr` and drops the Arc in the syscall impl;
  join captures a raw pointer to the registry lock and drops the `Arc<Process>` before parking (the
  `PROCESSES` registration keeps the process alive while its blocked member thread is unreaped). Fault-kill
  itself now runs the **minimum** in the exception frame (record exit code, purge futex, reap siblings,
  `exit()`); the heavy teardown runs on the last reap through the normal `on_thread_reap` path from the
  reaper's clean context.
- **Cross-CPU wake — GUARDED (reused).** `wake_thread_token` sends the reschedule IPI to a foreign CPU; a
  stale/generation-checked wake is a safe no-op.

**Proposed bank addition — CP-30 (force-zombify raw-stack Arc leak):** *"Force-retiring a thread blocked in a
syscall frees its kernel stack as raw memory (no unwinding, no Drop), so any owned `Arc`/`Box`/guard living
in that syscall's stack frame leaks. Invariant: a user-blocking syscall holds NO owned reference-counted
resource across `block_current_*`; translate/copy what you need and drop it first, or reach shared state via
a pointer whose target is kept alive by a registry, not by the blocked thread's own stack."* Discriminator:
the frame-leak audit at process teardown (`main.rs` baseline==final assert) — it caught this at +157.

## Governance fault-containment analysis (I-14)
- **(a) Lock isolation.** The thread/futex/join paths acquire **no** AI-governance lock
  (`INFLIGHT`/`RECENCY`/`ARENA`/reservation/`TABLE`) — only FUTEX_QUEUE (leaf), the scheduler lock, the
  per-process thread registry (leaf), `PROCESSES`, and (teardown only) handle/channel locks. Asserted in the
  `futex.rs` header + grep-checkable.
- **(b) Liveness degradation.** A browser thread that monopolizes a CPU is preempted by the timer; a futex
  with no waker degrades to `-ETIMEDOUT` at its deadline. Governance never *fails*, only shares the CPU.
- **(c) Memory isolation.** No device-initiated DMA in this slice (pure compute/scheduler primitives), so
  I-14(c1/c2) is N-A — the thread stacks are ordinary user pages from the caller's `Pmap`, W^X-enforced
  (R+W+NX), guard-paged.
- **Containment proof (battery `threads_guard_fault`):** a guarded-stack overflow faults into the guard →
  ring-3 `#PF` → the kernel **fault-kills only that process** (exit 139 delivered to the parent's `sys_wait`)
  → the parent process **still creates/runs/joins threads afterward** (scheduler + futex + registry live).
