- FAIL — **Overall: Sections 1, 2, 5 and 6 are not fully satisfied.** The registered copy and exception shim look correct, but coverage and syscall failure semantics fall short. Concrete counterexamples and verification limits follow.

- PASS — **1: Converted direct syscall copies use the fixup.** `kernel/src/arch/x86_64/syscall.rs:1551`, `:1561`, `:1573`, `:1586`, `:1619`, `:1732`, `:6911`: byte buffers, scalar/record reads and writes, arrays, zeroing, and chunked file-replacement input reach the single registered routine. In the changed syscall file, remaining raw pointer operations outside these helpers are on kernel-owned storage, not additional direct user-buffer copies.

- FAIL — **1: Futex still has a production faulting user access outside the registration.** `kernel/src/arch/x86_64/syscall.rs:7331`, `:7342`; `kernel/src/sched/futex.rs:158`, `:285`. This path has a range check plus a page-table translation, but then performs an unregistered `read_volatile` under `FUTEX_QUEUE`. Concrete input: map a writable page, call `SYS_FUTEX_WAIT(page, 0, u64::MAX)` on CPU A, and have a sibling on CPU B unmap that page after A's translation and before the value re-check. The load can fault at a different RIP and halt, with the queue guard held. This is an acknowledged pre-existing omission, not fixed by this PR; an eventual fix must preserve the aligned compare's atomicity and propagate its fault through the guarded wait path.

- FAIL — **1: The test-only tail hook still relies on a range check alone.** `kernel/src/arch/x86_64/syscall.rs:1331`; `kernel/src/sched/process.rs:5487`. Concrete input in a `neo-test-threads-exit-group` build: `SYS_TEST_TAIL_HOLD(unmapped_user_page)`. The four-byte range passes validation; `tail_hold_for_test` writes through `write_volatile` outside the registered copy and halts. Unlike futex, no concurrent unmap is needed. This is the other acknowledged pre-existing omission.

- FAIL — **1: IPC payload copies also bypass the new routine.** `kernel/src/arch/x86_64/syscall.rs:6069`, `:6094`, `:6116`; `kernel/src/ipc/mod.rs:718`, `:732`, `:744`; `kernel/src/mm/pmap.rs:1259`. `SYS_SEND`, `SYS_RECV` and feature-gated `SYS_TRY_RECV` range-check and then use page-table translations plus an ordinary HHDM copy. These have more than a range check, but no new fixup or destination-write-permission check. Concrete input: give the receiver a mapped `PROT_READ` page and rendezvous a one-byte send into it. The HHDM store writes the page despite its user mapping being read-only, instead of returning EFAULT. This unchanged path is missing from the claimed list of exceptions.

- PASS — **2: The registered copy returns through the normal cleanup path.** `kernel/src/arch/x86_64/user_copy.rs:24`, `:33`; `kernel/src/arch/x86_64/idt.rs:178`, `:184`, `:194`; `kernel/src/arch/x86_64/syscall.rs:1554`; `kernel/src/arch/x86_64/mod.rs:311`. The shim masks live AC/DF, saves/restores RAX, preserves RCX and the other interrupted registers, removes the error code and returns with `iretq`. Restoring the copy's saved AC lets the assembly fixup return normally; `with_user_access` then executes `clac` before the wrapper reports EFAULT. Neither the assembly copy nor its recovery branch acquires a lock or schedules. Failed input copies discard their temporary storage normally; `Vec` lengths are not advanced over uninitialized bytes. This is source/disassembly verification, not a live SMAP test.

- FAIL — **2: EFAULT can leave committed kernel state.** `kernel/src/arch/x86_64/syscall.rs:6549`, `:6553`; `kernel/src/fs/mod.rs:434`. Concrete input: open a readable file containing `AB` at offset zero; call `SYS_READ(fd, unmapped_user_page, 1)`, then read one byte into a valid buffer. The first call returns EFAULT after `read_as` advanced the offset; the second returns `B`. Also, `kernel/src/arch/x86_64/syscall.rs:3720`, `:3729`, `:3749` installs inference output handles before its fallible copy-out. Concrete input: a valid model/input producing one output, with `outputs_ptr` an unmapped user page and `output_len=1`. It returns EFAULT while retaining the newly installed tensor handle and arena ownership. These violate the dispatch's explicit no-partial-kernel-state criterion; recovery does not provide syscall rollback. Join and receive paths likewise consume status/data before copying it out (`:7671`, `:7682`, `:5711`, `:5713`, `:8828`, `:8834`).

- FAIL — **2: One converted copy explicitly discards its fault.** `kernel/src/arch/x86_64/syscall.rs:5507`, `:5511`; `kernel/src/net/tcp.rs:491`; `kernel/src/net/tls_record.rs:17`. Concrete input: an established non-TLS TCP socket and an otherwise valid 88-byte key buffer on a readable, read-only user page. Copy-in succeeds, TLS is installed, the attempted zeroing faults, and `let _ = zero_user_bytes(...)` discards EFAULT and returns success. This is an explicit best-effort-wipe policy in the code, but contradicts the requested blanket fault-to-EFAULT guarantee and the PR's wording. A buffer crossing from writable into read-only memory can also be partially wiped, contrary to the adjacent comment that it stays as it was.

- PASS — **3: Recovery is confined to the registered instruction and user-half fault address.** `kernel/src/arch/x86_64/idt.rs:182`, `:186`, `:189`, `:191`, `:202`, `:910`, `:934`; `kernel/src/arch/x86_64/user_copy.rs:26`. There is no exception-table walk or array-bound calculation: registration is an exact saved-RIP comparison with `neo_user_copy_insn`. Only CPL 0, the enabled byte, and `CR2 < 2^47` can select recovery. A different RIP, a kernel-half CR2, or a disabled build takes the old aligned Rust handler and fatal kernel-fault path. Emitted machine code matches those checks and the stack offsets.

- PASS — **4: Length and boundary semantics of the copy itself.** `kernel/src/arch/x86_64/user_copy.rs:24`, `:28`, `:34`, `:57`. Zero returns without touching either pointer; one byte performs one transfer; a valid page crossing continues; a fault on the last byte leaves RCX=1 and reports failure. A temporary host harness compiled the actual reviewed Rust module and recovered SIGSEGV only at its exported instruction RIP. It passed zero/one-byte cases, a valid crossing, first-byte faults in both directions, last-byte faults in both directions, partial crossings and a read-only destination (seven recoveries). It checked the transferred prefixes and rejected an unrelated faulting RIP. This validates the real copy instruction and remainder behavior; Linux signal delivery does not validate this kernel's exception entry or SMAP behavior.
