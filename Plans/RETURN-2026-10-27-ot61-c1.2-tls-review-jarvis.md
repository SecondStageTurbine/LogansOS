# RETURN: relay #89, OT-61 C1.2 per-thread TLS review

MODEL: GPT-6.1-Sol. EFFORT: high. Reviewer: Jarvis, Codex family.
Reviewed commit: `c06b3a9912fb08f1c605223fbd245b0a82fd6031` (PR #150 squash).
Branch: `codex/ot61-c1.2-tls-review-jarvis`. **Overall verdict: FAIL.**

The switch topology and normal key lifecycle are coherent, but the FS cache assumes that disabling
FSGSBASE prevents every user modification of FS.base. A non-null FS selector load also changes the base.
Separately, the final-ELF gate accepts unsanctioned FS accesses. Both findings were checked against the
pinned source; the latter was reproduced by executing the pinned parser. No implementation or main
branch changes are included in this review.

1. **PASS — switch-in topology, subject to the incorrect cache premise in item 2.**
   `kernel/src/sched/scheduler.rs:909`, `:915`, `:990`, `:1003` route ordinary rotation into the two
   preparation helpers. First-run user frames use the same scheduler entry and the iret trampoline
   (`kernel/src/sched/thread.rs:449`, `kernel/src/arch/x86_64/context.rs:315`). All four blocking
   switch variants also call those helpers (`scheduler.rs:1831`, `:1885`, `:1945`, `:2015`). Migrating
   wake transfers the thread object, so the destination uses its own CPU cache and the incoming
   thread's field; IPC handoff fast paths do not bypass preparation. A no-switch syscall/interrupt
   return retains the current hardware value, which is the problem when user code changes it.

2. **FAIL — per-CPU cache can claim B while the MSR holds zero.**
   The sentinel and kernel-thread skip are correctly implemented at
   `kernel/src/arch/x86_64/per_cpu.rs:94`, `:111` and `scheduler.rs:997`; ordinary IRQ/NMI code does
   not change FS. However, `scheduler.rs:1019` compares only the software cache and never reads the
   hardware base. `kernel/src/arch/x86_64/gdt.rs:134` installs a flat DPL3 user data descriptor,
   exposed as selector `0x23` at `:205`. On CPU 0, thread A calls `thread_set_tls(B)` for a mapped
   nonzero user TCB address B, then executes `mov ax, 0x23; mov fs, ax`. Loading this valid non-null
   descriptor sets hardware FS.base to zero, independently of CR4.FSGSBASE; software remains B.
   A subsequent A -> kernel thread -> A switch hits the cache and leaves hardware zero.
   This is a static source-plus-architecture proof, not a claimed QEMU/hardware execution.
   [Intel SDM Vol. 3A, section 3.4.4, printed page 3-12](https://www.intel.com/content/dam/support/us/en/documents/processors/pentium4/sb/25366821.pdf#page=90)
   specifies descriptor-base loading by MOV/POP FS/GS and its relationship to the base MSRs.

3. **FAIL — even a successful setter can leave the wrong base after that sequence.**
   Continue item 2 on the same CPU: A calls `thread_set_tls(B)` again. The setter validates B
   (`kernel/src/arch/x86_64/syscall.rs:6696`) and sets `s.current.fs_base = B`, but
   `scheduler.rs:1041` calls the cached loader and `:1019` skips WRMSR because the cache already
   equals B. The syscall returns 0 with hardware FS.base still zero; the next `fs:[0]` faults.
   The IRQ-masked lock transaction itself is correct (`scheduler.rs:1038`), as are the capability
   check (`syscall.rs:6515`, `:6697`) and user-half validation (`:6700`, limit `:1320`): inputs
   `0x0000800000000000` and `0xffff800000000000` produce EFAULT, and missing authority produces
   EPERM before mutation. The defect is the cached write being skipped after a selector reload.

4. **PASS — the specified normal exit/key lifecycle.**
   `userland/libneo/src/ntls.rs:191` bumps generation on delete; `:201`, `:230`, `:263` reject an
   old-generation slot after delete/recreate. The destructor driver clears before calling (`:267`,
   `:272`) and bounds rescans by four passes (`:48`, `:256`). `nthread.rs:143` runs destructors,
   frees the heap block (`ntls.rs:145`, `:153`), then calls SYS_THREAD_EXIT. Bootstrap return uses
   that exit (`nthread.rs:183`). External scheduler kill moves victims to zombies
   (`kernel/src/sched/scheduler.rs:2640`) and does not invoke user callbacks. The existing exact-source
   host KAT was rerun and passed. This establishes its serialized delete/recreate cases; it is not
   a proof of all concurrent key-deletion interleavings or generation-counter wraparound.

5. **FAIL — final-ELF gate omits unsanctioned FS accesses.**
   `tools/xtask/src/main.rs:15649` checks before staging, and all user-ELF staging calls use this
   wrapper (`:6544` through `:6575`). The parser checks PT_TLS, SHF_TLS, STT_TLS and TLS RELA
   records (`tools/xtask/src/ot61_tls_gate.rs:93`, `:132`, `:141`, `:153`), but explicitly excludes
   instruction checks (`:20`). The valid sectionless ELF below has an executable PT_LOAD containing
   `mov rax, fs:[8]` outside libneo, no TLS metadata, and is accepted with `Ok([])`.
   The three existing parser tests pass; they cover metadata only. The Rust `#[thread_local]` and C
   `__thread` link/falsification results are recorded author evidence in
   `Plans/NOTE-2026-10-27-ot61-c1.2-key-only-spike.md:27`, not builds rerun during this review.

6. **PASS — disabled kernel source exclusion and recorded byte identity.**
   Added Thread fields/constructors, PerCpu field/init and scheduler/syscall production additions
   are under `browser-runtime` (`thread.rs:185`, `:316`; `per_cpu.rs:48`, `:110`;
   `scheduler.rs:998`, `:1007`, `:1016`; `syscall.rs:6695`). Test hooks depend on the dedicated
   TLS scenario feature. [PR #150](https://github.com/SecondStageTurbine/LogansOS/pull/150)
   records stripped kernel equality versus `0b39255b` for default, desktop and usb-host, respectively:
   `a38f7eeaea5e56d03dba6ba314a82a8f5583cd62d4438f4a0e90595337356973`,
   `bb76df4be6fba4c626661a3a4239542cfd9cb7fdd87e8e5d079eb32757073797`,
   `54470c764ddbd1339bc6cfc3add2731374c3d2dd8e5f107a41745e8f77734b05`.
   Independently read PR evidence; byte-identity builds were not repeated here. The userland staging
   check is unconditional, as the key-only loader rule requires; this item concerns the kernel switch.

7. **FAIL — CP-83's premise is incomplete.**
   `docs/concurrency-pitfalls.md:3767` states that ring 3 can change FS.base only via the syscall
   while FSGSBASE is disabled; items 2/3 supply a valid counterexample. The corresponding Thread
   contract at `kernel/src/sched/thread.rs:181` has the same omission. The bank and implementation
   must cover selector loads as well as future WRFSBASE support. The other PR pitfall mappings were
   checked against the bank: CP-9/11 use scheduler and wake-lock publication, not the Relaxed cache
   as cross-CPU publication; CP-17 initializes child base zero; CP-26/36 release the TLS park mailbox
   after the stack save (`scheduler.rs:1052`, `:1904`); CP-35 placement/wake preserve reservations;
   CP-37 masks IRQs around the scheduler lock; CP-45 starts children at zero; CP-12 generations cover
   the host KAT's delete/reuse case. No new NMI lock or remote lock acquisition is added by WRMSR.

8. **PASS — limits identified.**
   NEO_SMP=4 alone does not force an NMI at the field/MSR/cache update boundaries or the final iret
   window. The source argument is that NMI/IRQ handlers neither use nor write FS and do not schedule
   in NMI context; it is not an injected-NMI result. QEMU also does not establish real-silicon MSR
   cost, firmware CR4 handoff variations, or higher-core-count scheduling latency. `enable_sse`
   preserves unrelated boot CR4 bits (`kernel/src/arch/x86_64/mod.rs:150`); no explicit clear/check
   of FSGSBASE was observed. That handoff assumption needs a dedicated discriminator. The selector
   finding above does not depend on firmware enabling FSGSBASE and is not merely a hardware limit.
