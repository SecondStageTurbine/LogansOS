## What is under review

PR #31, branch `claude/desktop-s2-fonts`. It will be rebased onto `main` after S1 (#25) merges. The PM names the
exact head SHA in the PR comment that relays this dispatch; review the whole diff at that head
(`git diff origin/main...origin/claude/desktop-s2-fonts`).

Desktop S2: Arthur's TEXT surface switches from a 5x7 uppercase grid to anti-aliased proportional IBM Plex Sans,
with a Plex Mono `neo>` rail.

- **`userland/neo-text/` (new, `no_std` + `alloc`, no syscalls)**
  - `raster.rs`: own exact-area accumulation rasterizer. Row stride is `width + 2`, points are clamped into
    the bitmap, and `floor`/`ceil` are implemented via `as i32` casts. Curves are flattened with a
    second-difference bound (`FLATTEN_TOL = 0.005` px, at most 64 segments).
  - `font.rs`: `ttf-parser` 0.25 `Face`, bitmap sized from `glyph_bounding_box`, a `BTreeMap` glyph cache
    keyed by (glyph, size×64, ¼-px bin), and `darken_stems` (a coverage curve below 16 px).
    `kerning_units` walks the GPOS `kern` feature lookups with two fall-through rules:
    - a Format-1 miss tries the next subtable;
    - a Format-2 match with right class 0 and a zero record also tries the next subtable (HarfBuzz behaviour).
  - `layout.rs`: pen layout, ¼-px quantisation, greedy `wrap` / `line_break`.
  - `flow.rs`: streaming `TextFlow` (push / backspace / scroll), with damage accumulated as one `Rect`.
  - `canvas.rs`: `Canvas` over `&mut [u32]`, plus gamma-correct `blend_pixel` using 12-bit linear LUTs
    generated by `build.rs`.
  - `fonts.rs`: `include_bytes!` of the two TTFs (features `plex-sans` / `plex-mono`).
- **`assets/fonts/`**: IBM Plex Sans Regular 3.005 and Plex Mono Regular 2.005 (OFL-1.1, Reserved Font Name
  "Plex"), unwrapped from IBM's npm WOFF by `scripts/fonts/woff_to_sfnt.py`, which copies tables verbatim.
  Not subset. Provenance and sha256 are in `assets/fonts/README.md`; there is a `NOTICE` entry.
- **`userland/neo-arthur/`**
  - `showcase_text.rs` (pure renderer).
  - `showcase_surface.rs`: the client mapping is now a `&'static mut [u32]` built with `from_raw_parts_mut`;
    the old code used `write_volatile` through a raw pointer. Commits now carry band-sized damage instead of
    full-surface.
  - `showcase_logic.rs` `LegacyGrid`: the old renderer moved to slice writes, behind the kill-switch
    `arthur-legacy-5x7-font`.
- **`Cargo.toml`**: `[profile.dev.package.{ttf-parser,neo-text}] opt-level = 3`. Without it, debug `Face::parse`
  overflowed Arthur's 64 KiB user stack (ring-3 #PF, rsp ~66 KiB down).
- **Oracles**
  - `userland/neo-text/src/tests/`: a hand-computed exact `H` table; `exact_*.rs` from
    `scripts/fonts/area_oracle.py` (fontTools + f64 Sutherland–Hodgman); `ft_*.rs` from
    `scripts/fonts/freetype_oracle.py` (sanity only); `hb_kern_sans.rs` from
    `scripts/fonts/harfbuzz_kern_oracle.py`, which covers every printable pair.
  - `fixtures/arthur-s2/title_window.rs`: per-pixel [lo, hi] bounds used by the kernel assert
    `arthur_compositor_pixel_asserts` (`kernel/src/test_harness.rs`) and by the host KATs in
    `tools/arthur-logic-tests/src/showcase_s2_tests.rs`.

## Your job: refute it

Default to suspicious. Specifically try to break:

1. **Rasterizer / flow memory safety and panics.** Arthur is `panic=abort`, so any panic kills the showcase.
   Target:
   - indexing in `Rasterizer::span` / `line` with NaN, ±inf or huge coordinates;
   - f32 drift that could push a column index past `width + 1`;
   - `floor` / `ceil` saturation;
   - glyph bitmaps whose outline exceeds `glyph_bounding_box` (composites);
   - `Canvas::draw_glyph` / `scroll_up` with negative or oversized rects;
   - `TextFlow::push` slicing and `truncate` at non-char boundaries (U+00B7 appears in the footer), and
     recursion on `\t` or control characters;
   - a region narrower than one glyph;
   - arithmetic overflow in debug builds, where QEMU userland runs with overflow checks on.
2. **The `&'static mut [u32]` over the shared buffer.** Is replacing `write_volatile` with plain stores sound
   and safe in practice? The compositor maps the buffer `MAP_READ`, and the kernel copies damaged rows at
   present time. The commit syscall `asm!` (`userland/libneo/src/lib.rs` `raw3`) has no `nomem`. Can stores
   sink past it or be elided, under LTO in release or in debug?
3. **Damage correctness.** Damage is committed via `commit_damage`, which replaces rather than unions the
   pending rect (`kernel/src/atrium/buffer.rs`), and presented by `recv_commit_and_present`
   (`userland/neo-init/src/arthur_compositor.rs`; after S1, also the desktop WM path).
   - Is there any path with two commits before one present, or a band that changed but isn't in the rect
     (word carry-over across lines, scroll, backspace onto a wrapped line), that leaves stale pixels on the
     framebuffer?
   - Re-check against S1's WM once rebased.
4. **Oracle independence (the core question).** Each oracle claims to share no code with neo-text. Find where
   they nevertheless share a *non-spec convention* that would let a wrong engine pass. Known shared items to
   judge:
   - ¼-px rounding;
   - abs-of-summed-signed-area winding, which is untested for overlapping contours;
   - `line_glyphs` in `area_oracle.py`, which mirrors `layout.rs`'s pen algorithm;
   - the kerning fall-through rules: verify them against the OpenType GPOS spec text, not just HarfBuzz;
   - the ±2/255 coverage slack in the kernel window.
   Note that the 28×20 kernel window cannot see kerning at all. Does that leave a gap the host tests don't
   close? Would you trust `H_20PX_QUARTER`? Re-derive at least one row.
5. **Licence / OFL reading.** Is shipping unsubset Plex inside the `neo-arthur` ELF, with the licence only in
   git and in the font's `name` table (not staged into the ISO), compliant with OFL-1.1 §2/§3? Is the WOFF→TTF
   unwrap really not a "Modified Version"? Note that `head.checkSumAdjustment` no longer matches the
   whole-file checksum because table order changed. Is the `NOTICE` entry adequate? Any issue with
   `ttf-parser` / `core_maths` / `libm` licences?
6. **`include_bytes!` + user-stack budget.**
   - The fonts add ~370 KB to the ELF image. Check how the loader maps it, whether it affects the
     `SHOWCASE memory` lines or the footprint discriminator, and whether any image-size limit exists.
   - The stack fix relies on dev opt-level for two crates; the high-water mark is unmeasured. Find the next
     deep path: first glyph rasterization at 22 px, the first `kerning_units`, `TextSurface` moved by value
     through `Result` into `ArthurSurface`.
   - Propose a cheap measurement, e.g. stack painting.
7. **Kill-switch.** `arthur-legacy-5x7-font` is proven bit-for-bit only by the host KAT, which compares
   against a verbatim copy of the pre-S2 code (82d0f59). Is the copy truly verbatim? Is "no QEMU scenario"
   acceptable under CLAUDE.md's kill-switch rule?
8. **Anything else** a Claude reviewer would structurally miss.

A finding bounces the branch only if it survives your own re-verification; uncertain items go in the RETURN as
