**Status:** DISPATCHED — **PL-ratified D1 = Option A (2026-06-22).** The crux of the brain last-mile (OT-28). The kernel Qwen2 forward matmul is **q4_K-only** (`matmul_q4_k_q8_k`), but the real Qwen2.5 model's weights are **mostly q5_0 (133) + q6_K (12) + q8_0 (13) + q4_K (12) + f32 (121)** — only 12 of 291 tensors are q4_K. F1 makes the forward path run **all five quant types** by routing each quantized weight tensor through the **landed `gguf_dequant_logic` dequant-to-f32 primitives** (streaming, per-matmul), then the proven f32 matmul. **Correctness-first; native per-type kernels are the banked perf slice F4.**

## 0. The decision this build makes
Turn "the forward matmul crashes/can't run on the first non-q4_K weight" into "**the forward path runs the real mixed-quant Qwen2.5 weights end-to-end**" — via per-tensor dequant-to-f32 (Option A, == ggml's `ggml_mul_mat` fallback when a native quant kernel is unavailable). Reuses primitives that already have host KATs ⇒ **no new matmul byte-oracle for the dequant itself** (the oracle is the dequant→matmul *path*, ISC-4).

## 2. ISCs
- **ISC-1 — `TensorDtype` + per-tensor dtype on the weights.** Add a `TensorDtype` enum (`F32, Q4_K, Q5_0, Q6_K, Q8_0`). Extend `Qwen2LayerWeights` (and the embedding/output tensors) so each weight field carries its dtype. The model loader (`model_logic.rs`) reads each tensor's dtype from the `.neom` inventory and populates it.
- **ISC-2 — dtype-dispatched matmul (the wiring).** In `matmul_vec_weight()` (the function feeding weights to the matmul), dispatch on the weight tensor's dtype: **when the feature is ON**, every *quantized* type (q4_K/q5_0/q6_K/q8_0) is **dequantized to an f32 scratch buffer via `gguf_dequant_logic`, fed to the existing f32 matmul, and the scratch dropped before the next tensor** (streaming — never hold the whole model dequantized; the largest single weight ≈ 17.5 MB f32, so the transient bound is < 20 MB). f32 tensors go straight to the f32 matmul. **Reuse the landed dequant primitives verbatim — do not reimplement dequant.**
- **ISC-3 — kill-switch `phase9-real-quant` default-OFF ≡ fixture bit-for-bit.** When the feature is **off**, the forward path behaves **exactly as today** (the existing `matmul_q4_k_q8_k` native path + f32 fallback; the fixture `arthur_boots_thinking` scenario green **bit-for-bit**, the equality anchor). When **on**, the dtype-dispatched dequant-to-f32 path is active. Prove the equality (the fixture scenario unchanged off). **No new invariant** (composes dequant's existing correctness + the f32 matmul — state this explicitly; if you think you need one, STOP and flag). **No new `unsafe`** expected — flag if you reach for it.
- **ISC-4 — byte-oracle: the dequant→matmul *path* (the format/ABI rule).** A **host KAT, independent of round-trip**: for **each** quant type (q4_K/q5_0/q6_K/q8_0), a **hand-laid quantized block** with known scale/quant bytes → `dequantize_tensor_data_to_f32` → assert the **exact f32 output values** (hand-computed from the quant formula, not from the reader) → then a small f32 matmul of that dequantized weight × a known activation vector → assert the **hand-computed dot-product result**. This proves the *wired path* (dequant→matmul) end-to-end against hand-computed numbers, not just that the writer and reader agree. (The dequant primitives have their own KATs; this adds the matmul-through-dequant assertion.)
- **ISC-5 — QEMU scenario `forward_mixed_quant` — DECOUPLED from L2.** **Do NOT wait on L2 / the 485 MB model.** Build a **small mixed-quant fixture model** (a tiny Qwen2-shaped `.neom` containing at least one tensor of *each* quant type q4_K/q5_0/q6_K/q8_0 + f32, sized **< 32 KiB so it fits current NeoFS** — the existing fixture-staging path, no indirect blocks needed) and run the forward path on it: **feature ON ⇒ produces a deterministic, sane token** (the real-model analog of `arthur_boots_thinking`, but exercising all five quant types); **feature OFF ⇒ the existing fixture scenario is green bit-for-bit.** At `NEO_SMP=4`. **Capture-before-you-need-it:** on the serial console, log each weight tensor's `(role, dtype, dequant_bytes)` at first forward so a wrong-dtype or wrong-dequant is self-diagnosing. *(The full 485 MB real-model forward is the post-L2 Stage-B integration proof — NOT F1's gate; F1 proves the mixed-quant path on the mini fixture.)*

## 3. Failure-mode + discriminator (the scenario must be conclusive on pass AND fail)
- **Wrong dtype mapping** (loader reads the inventory wrong) ⇒ the per-tensor `(role,dtype)` serial log shows the mismatch.
- **Dequant wired wrong for one type** (e.g. q5_0 vs q6_K block layout) ⇒ the ISC-4 per-type KAT fails on that type specifically (each type asserted separately).
- **Streaming buffer bug** (use-after-free / wrong size) ⇒ caught by the per-matmul transient bound + the mini-fixture forward producing a wrong token; log the dequant byte-length per tensor.
- **Kill-switch leak** (off ≠ fixture) ⇒ the `arthur_boots_thinking` bit-for-bit equality fails.

## 4. Scope guard
Mixed-quant forward via dequant-to-f32 + the dtype plumbing + the mini-fixture scenario + the path byte-oracle **only**. **Do NOT**: write native per-type matmul kernels (that's the banked perf slice **F4** — Option B was rejected for now); change the config source (that's **F2** — F1 keeps the hardcoded 0.5B consts/fixture config); touch the vocab/tokenizer (**F3**, userland); change the `.neom` format/importer or `gguf_dequant_logic`'s primitives (reuse them); rewrite the forward graph topology (OT-16 frozen — F1 is dtype dispatch in the matmul feed, not a new graph); depend on L2 (use the < 32 KiB mini fixture). No new invariant/`unsafe`.
