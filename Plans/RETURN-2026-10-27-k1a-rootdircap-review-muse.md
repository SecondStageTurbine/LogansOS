# RETURN — relay #111: K1a, the root-directory capability (PR #168)

Reviewer: Muse (Gwen), a separate model family, reviewing Claude-authored code. Files read from the repo at the reviewed SHA. Pasted by the PL on 2026-10-27; banked verbatim by the PM.

Reviewed SHA: `2922bf0c` (PR head `bfb8f37b` plus a merge of main). Gate batch 10, run 40500773798, all green. This change relies on relay #108 (K1a-0) for revocation reachability.

1. **No root-form open without the cap — PASS.** With `cap-rooted-open` on, root-form open goes through `open_path_and_install` (`kernel/src/arch/x86_64/syscall.rs:6008ff`), which calls `root_dir_cap_for` first and returns its errno before resolving. READDIR, MOUNT and UMOUNT are fd-based, not root-form: readdir goes through `file_lookup(fd, empty)` then `OpenFile::readdir_one` (`kernel/src/fs/mod.rs:411`, requires READDIR in the handle's rights); mount/umount go through `do_mount`/`do_umount` (`syscall.rs` ~6264/~6287) then `mount_child`/`umount_child` (`fs/mod.rs:427`/`446`, require Directory kind plus the MOUNT right). `sys_model_load` is gated at the top of `model_load_path` (`syscall.rs:2618ff`, READ check ~2623) before the boot-module and preloaded-model branches, so no model source bypasses it. Other callers of the root resolver: `root_dir_cap()` itself (the mint, item 2) and two test-only callers, `debug_prepare_boot_neofs_busy_mount` (`fs/mod.rs:758`) and `debug_open_root_temporary_for_policy` (`fs/mod.rs:1343`, under `neo-test-phase3-neofs-2e`). No other syscall-reachable ambient path was found. No `open_at`/directory-relative syscall exists in this build, so a client holding only a subdirectory cap cannot yet open inside it except through a root cap — a functional gap from the THINK's K1, not a bypass.
2. **Minting — PASS.** The only mint is `process::root_dir_cap()` (`kernel/src/sched/process.rs:1156–1168`), which builds the handle via `fs::open_root_temporary("/", ...)` with `ROOT_DIR_CAP_RIGHTS` (defined at `:1146` = KNOWN_BUILD4B | GRANT_RESERVED | DERIVE_RESERVED). Its only caller in `kernel/src` is `kernel/src/main.rs:434`, which pushes it last into neo-init's inherited caps at boot. No syscall mints one. `root_dir_cap_for(proc, requested)` (`process.rs:1173ff`) scans only the caller's own handles for `Handle::File` with `file.is_vfs_root()` and returns the first whose rights cover `requested`; EPERM when no root cap is held, EACCES when all held root caps are too narrow. A forged index or a non-File handle cannot match, because the check is on the stored handle's `OpenFile` flag, not on any user-supplied kind byte. Note: opening "/" through an existing cap legitimately yields another `vfs_root` handle with rights = requested ∩ cap — that is derivation by design, not a second mint.
3. **Rights never widen — PASS.** The opened file's rights are `handle_rights & root_cap_rights.bits()` (`syscall.rs:6046`), with `root_file_handle_rights` (`kernel/src/sched/file_cap_logic.rs:230`, adding owner GRANT|DERIVE reserved bits when file-caps is enabled) ANDed with the cap's bits. Scenario leg 5 (neo-init `cap_rooted_tests`, `userland/neo-init/src/main.rs:7088ff`) confirms the read-only derived cap reads fine and gets EACCES on write.
4. **Revocation reaches opened files — PASS.** The opened file is installed with `parent = Some(root_cap)` (`syscall.rs:6048`), so the K1a-0 revoke walk reaches it. Scenario leg 6 checks EBADF on the opened file after the cap is revoked, and EPERM on the next root-form open.
5. **Spawn inheritance — PASS, with one observation.** Under the feature, the spawn path (`syscall.rs` ~1747–1775) admits a File handle only if `process::is_spawn_inheritable_dir_cap(&h)` (`process.rs:1203ff`): the own-dir branch (rights bits exactly LOOKUP|READDIR) or a directory handle carrying GRANT_RESERVED; any other File handle is EPERM (`syscall.rs` ~1775), and non-File handles require GRANT meta. The child's copy is `h.clone().with_cap(alloc_cap_id(), h.rights())` — same rights, fresh CapId, parent = source CapId — so a child cannot gain more than the parent passed. Observation, not a failure: the own-dir branch does not itself check `is_directory()`. I verified every filesystem's `available_rights()` at this SHA (NeoFS `fs/neofs/inode.rs` ~1310: Regular ⇒ stored bits masked to KNOWN_BUILD4A; FAT32 and ext4: Directory ⇒ LOOKUP|READDIR, Regular ⇒ READ/WRITE-style bits; testfs and boot modules: Regular ⇒ READ). A normally created regular file cannot carry exactly LOOKUP|READDIR; the only theoretical route is a crafted NeoFS on-disk record whose stored `available_rights_bits` for a Regular inode are LOOKUP|READDIR. Even then the inherited handle confers nothing usable: it is not `vfs_root`, readdir/mount re-check Directory kind in `OpenFile`, and read/write rights are absent. Recommend adding `file.is_directory() &&` to the own-dir branch as defence in depth.
6. **`SYS_HANDLE_INFO` and `SYS_PROCESS_SELF` — PASS.** `SYS_HANDLE_INFO` (`syscall.rs:6921ff`) rejects `len != RECORD_LEN` with EINVAL, maps a u64 index to u32 or EBADF, looks up only in the caller's own process, and returns EBADF for an empty or out-of-range slot. `sys_process_self_impl` (~`syscall.rs:6910`) returns only the caller's `proc.pid.0`. The 16-byte LE record (`kernel/src/sched/handle_info_logic.rs`) is version(4)=1, kind(4), file_rights(4), cap_meta at byte 12, cap_semantic at 13, flags at 14, reserved byte 15 = 0; `FLAG_ROOT_DIR = 1 << 0` (`handle_info_logic.rs:45`), set only for `Handle::File` with `file.is_vfs_root()` (`process.rs:1027–1032`), 0 otherwise. It reports kind and rights only — never the object — so it grants nothing.
7. **Feature off — PASS, with a measurement caveat.** `cap-rooted-open` is not in the default feature set (`kernel/Cargo.toml:77`, default = kernel-diagnostic, accel-sim, inference-preemptible); it is defined as `["file-caps"]` (`:97`), and `neo-test-cap-rooted-open = ["neo-test", "cap-rooted-open"]` (`:590`). Every K1a addition in the reviewed files is `#[cfg(feature = "cap-rooted-open")]` with `cfg(not(...))` arms preserving the old behaviour (parent = None, unmasked handle_rights; the `OpenFile` `vfs_root` field and its initialisation in `fs/mod.rs` are cfg-gated so struct layout is unchanged off; `main.rs` only pushes the cap under the feature). The ".text/.rodata byte-identical with NEO_BUILD_ID pinned" claim rests on gate run 40500773798 and was not independently re-measured here.
8. **Coverage — PASS, with named gaps.** A third-party process spawned by Arthur and the browser process (OT-61 C2.1b) do not exist yet, so their root-cap behaviour is untested. `open_at` from the THINK's K1 is not implemented (see item 1). The THINK §10.1 test-only root-grant build KATs are a THINK obligation this change does not add; the scenario instead uses init's genuinely minted cap, which is stronger evidence for the mint path.

**Overall verdict: PASS.** All 8 items pass. The item 5 own-dir observation and the item 7 measurement caveat are recorded limitations, not failures.
