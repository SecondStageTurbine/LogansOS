# RETURN #100 — A9-C Arthur scrollback review

Reviewed merged commit `675495c9` (PR #159 squash; its commit message records the gated head relationship) and the full change against `Plans/DISPATCH-2026-10-27-a9-arthur-scrollback-review-chad.md`. RAG health was healthy and the example semantic query returned results. Targeted existing host KATs passed: `cargo test -p arthur-logic-tests scroll -- --nocapture` (5 passed). No files other than this RETURN were changed. Overall: **FAIL**, for a scrollback-cap eviction case that leaves the saved view index stale. This is a contained post-merge issue; recommend revert-first on a confirmed failure rather than making code changes in this review.

1. **Scrollback bounds — FAIL (oldest-line eviction leaves stale `view_top`).** The collection is capped at 512 lines, and `render_view` clamps the local draw index to `first_kept` (`userland/neo-text/src/flow.rs:37-43,96-120`). But `TextSurface::settle` passes the stored `view_top` to that draw without updating it, and `scroll` later computes its next page from the same stored value (`userland/neo-arthur/src/showcase_text.rs:319-337,360-368`). Concrete surface sequence with the 12-row Arthur viewport (page = rows − 1 = 11): produce 512 finished visual lines; PgUp repeatedly until `view_top=0`; append 10 newline-terminated lines while retaining the view; settle/commit. `first_kept` is now 10, so the screen is drawn from line 10, but the saved `view_top` remains 0. The next PgDn computes 0 + 11 and lands at line 11; from the displayed top line 10, a page-down should land at line 21. The view index must be clamped/advanced when eviction occurs, not only clamped temporarily during drawing. The current 512-line KAT coverage checks bounded storage and direct clamping but does not test append-and-evict while held (`userland/neo-text/src/tests/mod.rs:589-682`; Arthur hold-view KAT: `tools/arthur-logic-tests/src/showcase_s2_tests.rs:524-545`). The normal main loop's synchronous generation means a user-triggered answer typically follows the view before generation starts (`userland/neo-arthur/src/main.rs:1005-1022`); this limits ordinary UI reachability, but `write_byte`→`commit_next`→`settle` explicitly supports text arriving while scrolled, and the stated view-index invariant fails on that operation.

2. **Following — PASS.** The view follows when `view_top` is `None`; scroll-up holds the absolute top while writes mark the view stale, and `settle` redraws it. PageDown clamps to the current bottom and clears `view_top`, resuming follow (`showcase_text.rs:308-337,348-368`). The existing KAT verifies a reply arriving while scrolled stays visually held and `follow()` returns to the latest text (`tools/arthur-logic-tests/src/showcase_s2_tests.rs:524-545`). The eviction boundary case is reported separately in item 1.
