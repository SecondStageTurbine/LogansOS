## The finding (CONFIRMED, PM re-verified in the code)
**The dispatched contract "peer-death of the channel = surface-death (destroy-by-drop) must also work" is delivered nowhere in running code, and ADR-073 (line 31) asserts it as a shipped v1 property.**

- `SurfaceRegistry::peer_died` (`userland/libneo/src/atrium_protocol.rs:508`) has **zero production callers** — grep of the whole tree finds only its definition and two host-KAT call sites (`tools/atrium-logic-tests/src/lib.rs:531,598`) that invoke the method **directly**. It proves the registry *transition* in isolation; it does not prove the *convention*.
- The compositor recv path never routes peer-death: `neo-worker`'s `recv_request` (`userland/neo-worker/src/main.rs:112-119`) maps `len <= 0` → `Err(())` → a bare `return <code>`. It **discards** the `-EPIPE` the kernel already raises when a channel peer dies (`kernel/src/arch/x86_64/syscall.rs:4704` "channel peers wake with `-EPIPE`"; `kernel/src/sched/process.rs:1621`).
- **The primitive to fix this already exists** (`-EPIPE` on recv). So this is a genuine *unwired* gap, not a "blocked on a missing kernel primitive" follow-up — the wiring is a userland one-liner in Slice-2 scope.

**Why it matters (not merely "untested"):** the registry is a bounded `[Surface; 8]`. A client that drops its SurfaceCap channel **without** an explicit `destroy` leaves its surface `alive` forever. Eight drop-without-destroy clients wedge the registry at `Err(Limit)` with **no recovery path** — exactly the resource-exhaustion the destroy-by-drop convention exists to prevent. Latent today (the Slice-2 "compositor" is a scripted single-run scenario, no long-lived compositor accumulates leaks), but it becomes live the moment a persistent dispatch loop lands, and the ADR already promises it works.

## The completeness gap (why the green gate missed it)
The QEMU `atrium_surface_protocol` scenario walks create-root → reject-2nd-root → import → commit → focus → destroy but **never drops a channel** — its pass string honestly declares `peer_death=host_kat` (Jarvis did not hide it). So a green 4-shard gate is fully consistent with destroy-by-drop being unwired. The gate result (still queued) does not change the bounce.

## The fix (both parts — one re-spin)
1. **Wire peer-death → `peer_died` (the real fix).** In the compositor recv path, distinguish **peer-death** (`-EPIPE`) from a generic recv error, and on peer-death invoke `registry.peer_died(<the provenance/identity bound to that SurfaceCap channel>)` so the surface transitions to the same terminal state as `destroy`. Keep it I-14-clean (no governance lock; bounded) and single-threaded as today.
2. **Prove it end-to-end in QEMU (mandatory — close the completeness gap).** Extend `atrium_surface_protocol` with a **destroy-by-drop case**: the client **drops/closes a live SurfaceCap channel without sending `destroy`**; the compositor's next recv returns `-EPIPE` → it calls `peer_died`; then assert a subsequent verb on that surface returns `SurfaceGone` (and, if a fresh `create` is issued, that the freed slot is reusable). This is the falsifiable proof the convention holds — currently it's asserted in the ADR + host-KAT'd in isolation, never proven in the running compositor. Update the pass string (`peer_death=qemu` or equivalent).
3. **ADR-073 authority fix (byte-oracle discipline).** ADR-073 is billed as the ABI authority but specifies only the 24-byte header by reference — it carries **no per-verb offset table**, so the wire layout lives only in the code + fixtures and a second implementer could not reconstruct it (violates the "authoritative worked example belongs in the ADR" rule, cf. ADR-028). Add a per-verb offset table to ADR-073 covering, little-endian: **header** (magic@0, version u16@4, opcode u16@6, payload_len u32@8, flags/reserved u32@12, request_id u64@16), **Identity@24** (namespace@24, surface@32, cap_provenance@40), **CREATE** (role@48, width@52, height@56, reserved@60 [==0], client_tag@64; total 72), **IMPORT** (transfer_id@48, buffer_cap_provenance@56; total 64), **COMMIT** (client_serial@48; total 56), **FOCUS** (reason@48, reserved@52 [==0], request_serial@56; total 64), **DESTROY** (final_client_serial@48; total 56), **REPLY** (opcode|0x8000, status u32@24, reserved@28 [==0], identity@32..56; total 56). Transcribe from your code/fixtures (ground truth) — the PM re-verifies the table against the literal fixtures in the re-AAG-delta.
