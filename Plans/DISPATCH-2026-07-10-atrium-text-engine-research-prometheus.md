## ISCs — the study (all cited from primary sources)
- **ISC-1 — the rendering-technique landscape, with honest tradeoffs.** Survey and compare the real families for resolution-independent glyph rendering: **(a) SDF/MSDF** (msdfgen, Valve's original paper) — cheap, great at large sizes, the honest failure modes at small sizes / sharp corners / thin stems; **(b) analytic-coverage GPU outlines — Slug** (Eric Lengyel's paper + the patent-freed claim — verify) — quality-per-glyph, GPU-feature needs; **(c) compute-rasterizer path — Vello / piet-gpu** (its own docs/source) — full-path fills, antialiasing model, GPU-compute dependency; **(d) Pathfinder** (Nical/pcwalton) as a data point. For each: quality at small vs zoomed sizes, memory, GPU-feature dependencies (compute shaders? our Phase-6 accel path can it drive them?), and CPU/software-fallback viability. Recommend a primary + a fallback, with reasons — not a survey without a verdict.
- **ISC-2 — the shaping reality (the flagged hard part — spend the most here).** Make concrete what "SDF ≠ shaping" means: a glyph *renderer* is NOT a *shaper*. Enumerate the real stack an honest text engine needs and what each layer costs — **hinting** (FreeType autohint/bytecode; when it matters, our zoomable-surface context may relax it), **shaping** (HarfBuzz-class: cluster mapping, ligatures, kerning, mark positioning), **complex scripts + BiDi** (Arabic joining, Indic reordering, the Unicode BiDi algorithm), **emoji/color** (COLR/CBDT). State clearly: what is the **smallest honest scope for v1/G2** (almost certainly Latin + measured type quality, shaping-stack designed-for-but-deferred), and what "before localization" actually requires. This is the section that saves us a build.
- **ISC-3 — licensing / patent posture (fits our MPL-2.0 distribution ethos).** Slug patent status (verify firsthand — it's load-bearing on whether we can adopt the technique freely); the license of any reference implementation we'd lift (Vello/piet-gpu = Apache/MIT? FreeType = FTL/GPL dual? HarfBuzz = MIT?); font licensing (a bundled UI typeface — OFL vs proprietary). Flag the one or two license/patent calls worth an early PL steer, like you did for the Kokoro/Piper TTS-license fork.
- **ISC-4 — our-stack fit (what only THIS OS can do, and what's genuinely constrained).** Map the techniques onto our reality: the Phase-6 GPU accel path (what it can actually drive — texture sampling? compute?), userland-vs-kernel split (glyph rasterization as a userland service producing cap-surface buffers? zero-copy into the cap-native compositor?), the software fallback that must exist (G0 is on the raw framebuffer — so beautiful *hinted bitmap/CPU* type has to carry G0 before any GPU path exists). Tie to the compositor's cap-surface model (a text surface = a cap-gated buffer).
- **ISC-5 — the smallest-first buildable path (the spine, text-engine edition).** Stage it so each step is shippable and honestly-measured: **T0** — beautiful CPU/hinted type on the v1 framebuffer good enough for G0 (the transcript reads *crisp* before it's zoomable); **T1** — the GPU-outline leap (the chosen ISC-1 primary) = G2's core, Latin, resolution-independent/zoomable; **T2** — the shaping stack (HarfBuzz-class) before localization; **T3** — complex scripts / color. Each stage: its honest quality bar, its GPU/dependency prerequisites, and what it unlocks. Sequence against the GUI spine (G0 → G1 compositor → G2 text).
- **ISC-6 — the trap bank (prior-art trap-mining — seed it before anyone builds).** Enumerate the **documented field gotchas** from the real communities (FreeType/HarfBuzz mailing lists + docs, the Slug paper's caveats, Vello/piet-gpu issues, Pathfinder retrospectives, OSDev/handmade-community text-rendering write-ups): subpixel/gamma-correct AA, the small-size SDF collapse, conflate-vs-nonzero fill rules, glyph-atlas cache thrash, hinting-vs-zoom conflicts, cluster/grapheme edge cases, BiDi mirroring. Each trap → the discriminator / the design choice that avoids it. This bank is the deliverable that most repays the study.
- **ISC-7 — the honest forks for the PL.** Where it's a genuine choice (primary technique, how far to carry shaping for v1, bundled typeface, GPU-required-vs-software-first), state the fork + your recommendation + the reason — like the six-fork close on your voice research.
