## 2. Defects found in the scaffold (these are the C0.5 work)

1. **A std panic hangs the whole machine.** `panic_abort::__rust_start_panic` → `std::rt::__rust_abort`
   → `sys::pal::unsupported::abort_internal` → `core::intrinsics::abort()` (`ud2`). The kernel's `#UD`
   handler (`kernel/src/arch/x86_64/idt.rs`, `invalid_opcode`) does `halt_forever()`. So it is not a
   process abort; it is a kernel halt. **Fix:** a neoplutarch `abort_internal` that issues `SYS_EXIT(134)`,
   so the process dies with a deterministic exit code and the kernel reaps it. The kernel's
   user-`#UD`→halt containment gap is a kernel matter. It is out of scope for this rung, so I log it to
   OPEN-THREADS.
2. **Panic messages are silently discarded.** `stdio::panic_output()` returns `Some(Vec::new())`, so std
   writes the panic message into a throwaway `Vec`. **Fix:** return `Some(Stderr)`.
3. **Every stdio write error is silently swallowed.** `is_ebadf()` returns `true` for *any* error, and
   std's `handle_ebadf` turns that error into `Ok`. **Fix:** `raw_os_error() == Some(EBADF)` only.
4. **`Stdin::read` returns `Ok(0)` (fake EOF).** **Fix:** `Err(Unsupported)`, so the failure is loud.
5. **No errno table** (above). **Fix:** a custom `sys/io/error/neoplutarch.rs` with an exhaustive
   `decode_error_kind` over `kernel/src/errno.rs`, a real `error_string`, and `is_interrupted ≡ false`.
   That last point is load-bearing: no LogansOS errno maps to `Interrupted`, so std's retry loops
   (`write_all`) cannot spin.
6. **A4 gate blind spots:**
   - (a) The `exit` arm's `in("rax") 0u64` lives inside `apply-overlay.sh`, which the gate never scans.
   - (b) An aliased constant (`const X: u64 = 41; in("rax") X`) bypasses both scans.
   - (c) `inout("rax")` is not matched.

   **Fix:** move every injected arm body into a scanned `.rs` fragment. Also scan the overlay's `.sh`
   files. Require every `rax` input operand to be a `SYS_*` name or a literal. Extract the scanner into
   `neo-std-pal/a4_gate.rs`, shared by `build.rs` and a **committed host negative test** (xtask unit
   tests, which run in push-CI host checks).
7. **The overlay is not re-application-safe.** `insert_arm` skips a file that is already patched. On a
   persistent toolchain an *updated* arm body would therefore never land, and the build would silently
   use the stale one. **Fix:** keep a pristine backup and restore-then-patch on every apply.
8. **No toolchain-bump guard on the fallbacks.** The "everything else is loud" claim depends on each
   `sys/*` `_ =>` arm being `unsupported`/`no_threads`. **Fix:** `apply-overlay.sh` asserts the expected
   fallback for each module and fails loud if a toolchain bump changes one.

## 3. Build steps (dependency order)

1. Overlay: restore-then-patch (§2.7), with modules for stdio fixes, alloc (kept), exit, abort, io/error
   table, and random routing (kept, loud panic), plus the fallback audit (§2.8).
   **"Route to the PAL unsupported stubs" means std's own `sys/pal/unsupported` tier.** std sits below
   `neo-std-pal` and cannot link it, so the std-internal unsupported modules *are* the stub tier inside
   std. Each one is audited to be loud (`Err(Unsupported)` or a panic that now aborts via exit 134),
   never silently wrong.
2. A4 gate refactor and hardening, plus committed negative tests (§2.6).
3. Errno KAT (host): parse `kernel/src/errno.rs` and the overlay table. Assert that the table is
   exhaustive and that it agrees with an independent hand-written expected table, per the byte-oracle
   rule.
4. Smoke, extended:
   - `std-real-smoke` adds runtime errno-kind checks and checks that fs/net/process/thread/stdin return
     `Err(Unsupported)`.
   - A second bin, `std-real-panic`, calls `panic!`.
   - The `std_real_smoke` scenario spawns both, and PASSes only if the smoke exits 0 **and** the panic
     bin exits 134 (and its message reaches serial).
   - Still gated behind its scenario.
5. Evidence:
   - The syscall-table diff vs `main` (expect empty).
   - `readelf -lW` on both ELFs: no W+X segment, data/heap NX.
   - Default-kernel binary hash, `main` vs branch (expect identical).
   - `std-pal-smoke` rebuild.
   - The A4 negative-test output.
6. Findings doc `docs/RESEARCH-2026-10-21-ot61-c05-FINDINGS.md`, OPEN-THREADS entries, the Codex review
   dispatch `Plans/DISPATCH-2026-10-21-ot61-c05-codex-review.md` (Chad), and a PR titled
   `[DO NOT MERGE: PL decision]`.
7. Run `scripts/worker-close-gate.sh`, then post "PM: ready for gate" with the head SHA.

## 4. Boundaries held

- No new syscall: `SYS_WRITE`, `SYS_MAP_REGION` and `SYS_EXIT` only.
- No executable memory; A1 untouched.
- No POSIX surface at the kernel/user ABI.
- No forks of html5ever, Stylo, layout, DOM, WebRender or the GC.
- No C1/C2/C3 work. Threads, TLS, time, entropy, fs and net stay deterministic `unsupported`.
- The default build is untouched: everything stays behind the `std_real_smoke` scenario.

**Kill-switch:** the overlay is opt-in per scenario. With it off, the build ≡ `main`, bit-for-bit
(proven by the hash compare).

**Pitfall bank:** this rung adds no cross-CPU, IRQ, lock or atomic code. The overlay keeps std
single-threaded (`no_threads` sync/TLS), so every CP class is N/A. This is stated in the findings.
