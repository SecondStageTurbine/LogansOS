## Scope — what is IN this spike vs. deferred
- **IN (your lane — paper + host tooling, push-CI only):**
  1. **Compiler-closure paper + host artifact.** Is there a *named, reproducible, offline* toolchain that takes WGSL (or Naga-emitted SPIR-V) and emits a **Gen9 EU binary + the ABI metadata our command streamer consumes** (the `zeinfo`-equivalent: kernel entry, payload/binding layout, SLM size, barrier/atomic requirements)? Survey the real options — `ocloc`'s SPIR-V ingestion path, IGC's SPIR-V front-end, Mesa's Intel compiler (**principle only, GPL — no lift**), any Rust-native option — and say which, if any, is a *reproducible offline finalizer* vs. a driver-internal pipeline that never emits a standalone blob. **Then actually produce one host artifact:** take ONE representative compute shader with **workgroup/shared-local memory + a barrier + an atomic** (write it in WGSL, or take a Vello stage), run it through the candidate offline toolchain **on the host**, and capture the **real** Gen9 binary + disassembly + ABI metadata. **Silicon execution is OUT (the next gate, main-tier + PL).** The deliverable is: "here is a reproducible command line that turns this shader into a Gen9 artifact, and here is the artifact + its ABI," or "no such reproducible offline path exists, here is why."
  2. **Backend-closure inventory.** Read Vello's internal `Recording` IR + its `WgpuEngine` executor (commit-pinned). Inventory *everything a Neo executor must reproduce* to run a frozen `Recording` subset without wgpu: resource lifetime/pooling, uploads, dynamic bump buffers, direct/indirect dispatch, image formats, inter-command hazards, failure/bump readback, and every shader's binding ABI. Price it honestly (person-month class, with the uncertainty bands). Identify the smallest useful frozen subset.
- **DEFERRED (NOT this spike — name them as the next gates):** running the artifact on the real UHD 630 (silicon shape — main-tier + PL); building the actual Neo Vello backend; any kernel/QEMU-gated code.

## Discipline (load-bearing for THIS spike)
- **Exact bytes from raw source — critical here.** Any ABI/disassembly/`zeinfo` bytes you report MUST come from the **real tool output** (run `ocloc`/the toolchain, read the literal file) — **never** a WebFetch/LLM-summarized read (they mangle exact bytes and poison the very oracle). This is the byte-oracle acquisition rule; a compiler-ABI spike lives or dies on it.
- **No GPL lift.** Mesa/IGC internals for *principle* only — nothing copied into our MPL tree. License-check (raw LICENSE) any tool you'd propose *adopting* into the build (as opposed to invoking as an external offline compiler).
- **Host-only / push-CI.** Any code you write (a host harness to invoke the compiler / parse the artifact) is a bounded HOST build — push-CI only, no QEMU `workflow_dispatch`. If it wants to touch the kernel, stop and hand back to a main-tier seat.
- Deliverable: `docs/RESEARCH-2026-07-21-gpu-p2-vello-compiler-closure-FINDINGS.md` (CC-BY-4.0): §0 the go/no-go verdict (is a reproducible offline WGSL→Gen9 path *demonstrated* or *not*, + the honest Neo-backend price) with confidence; §1 the compiler-closure survey + the one host artifact (command line + captured ABI/disasm); §2 the Vello `Recording` backend inventory + smallest useful subset + price; §3 the deferred silicon/backend gates; §4 sources (commit-pinned) + confidence. If the artifact can't be produced, that *negative* result is the highest-value finding — say so plainly.
