## 0. The decision this build makes
Turn "boots, then you supply a model" into "**boots with Arthur already thinking — and you can swap the brain at runtime.**" **PL-decided 2026-06-20: bundle BOTH models** (Qwen2.5-**1.5B-Instruct** as the default brain + Qwen2.5-**0.5B-Q4_K_M** as the fast fallback) onto the boot image's NeoFS, enable `arthur-real-infer`, and add a **`/model` runtime switch** so that if 1.5B is too slow on a given machine (e.g. the OptiPlex CPU before the AVX2 speedup), the user types `/model 0.5b` and Arthur reloads the lighter brain live. Prove boot→load→generate **and the switch** end-to-end. **Models stay data (Article 23.3 — not in the kernel);** this is *provisioning + wiring + a runtime drop/reload*, not embedding.

## 2. ISCs
- **ISC-1 — Provision BOTH models onto the boot image's NeoFS.** At image-staging (xtask): convert each GGUF → `.neom` (via `neomc`, the existing tool) and bake **both** into the **NeoFS partition** as distinct files — e.g. `/neofs/model-qwen2.5-1.5b.neom` (default) + `/neofs/model-qwen2.5-0.5b.neom` (fallback). **NeoFS files, not Limine modules** — a model as a Limine module loads the whole thing into RAM at boot; on-disk (NeoFS, read on demand) is the realistic install shape and avoids the RAM blowup (and lets the *unselected* model sit on disk costing only space, not RAM). Models are **fetched/staged at build time, NOT checked into the repo** (no model blobs in git — the build pulls or references local GGUFs). Generalize the hardcoded single `MODEL_PATH` into a small **model registry** (name → NeoFS path) so both are addressable.
- **ISC-2 — Enable the real-infer path, default 1.5B.** Flip `neo-arthur` to `arthur-real-infer`: at startup load the **default (1.5B)** `.neom` via `sys_model_load`, run the 8.5 generate path on the user's prompt, `sys_send` the reply. The code path exists — wire it on against the *provisioned* model (not a host path). **Kill-switch: `arthur-real-infer` (and the model-in-image staging) default-off ⇒ no models in the image, dummy-echo Arthur, ISO lean + bit-for-bit today.**
- **ISC-2b — The `/model` runtime switch.** In Arthur's conversation loop, parse a slash-command: **`/model <name>`** → `sys_model_drop` the current handle + `sys_model_load` the requested registry entry → continue with the new brain; **`/model`** (or `/model list`) → report the available models + which is active. The drop/reload ABI exists (`sys_model_load`/`sys_model_drop`); this is parsing + a registry lookup + the swap, with the **fail-safe**: a failed load (bad name / OOM) leaves the *previous* model active (never drops into modelless/crash) and tells the user. This is the "1.5B too slow ⇒ `/model 0.5b`" escape hatch.
- **ISC-3 — The proof, split QEMU/silicon by cost.** **QEMU scenario `arthur_boots_thinking`:** the booted OS → neo-arthur loads the default model from NeoFS → generates a token → **`/model` switches to the other model (drop+reload) → generates a token from the switched brain** (proves the **boot→load→generate plumbing + the runtime switch**). *Use QEMU-tractable model(s)* — a full forward per token in TCG is slow, so the QEMU proof uses the smallest genuine model(s) that exercise the path + the switch; **the full real-brain interactive generation (1.5B at usable speed, and the live `/model 0.5b` fallback) is the bare-metal Stage-B** on the OptiPlex. At NEO_SMP=4.
- **ISC-4 — Standards + the ISO-size honesty.** Bundling **two** models **bloats the ISO** (~1.4 GB for 0.5B+1.5B q4_K — burnable to USB/DVD, fine) — so the model-in-image is **opt-in at build** (default-off keeps the ISO lean; the engine ships, the models are added when you want a thinking boot). The *unselected* model costs disk, not RAM (NeoFS on-demand). No new `unsafe`; no new invariant (provisioning + a feature flip + a drop/reload that uses the existing model ABI). `fmt`/`clippy --workspace --all-targets -D warnings` via Docker. ADR/ANSPEC note on the model-provisioning path + the registry + `/model`.

## 3. The model decision — RESOLVED (PL, 2026-06-20)
**Ship both, default 1.5B, `/model` to switch.** Bundle **Qwen2.5-1.5B-Instruct** (the ratified v1 brain, RESEARCH-2026-06-17) as the **default** + **Qwen2.5-0.5B-Q4_K_M** (8.5-proven) as the **fast fallback**, with the `/model` runtime switch (ISC-2b) as the escape hatch when 1.5B is too slow on a given machine. Both are the **same Qwen2 architecture** the engine already runs (config-driven forward graph) — 1.5B is expected to load+generate; **this build is also its first end-to-end validation** (the scenario proves both load+generate). Rationale: 1.5B is the better conversation (the wow), 0.5B is the snappy fallback, and `/model` means you never have to re-flash to change brains.

## 4. Scope guard
Provision **both** models onto the NeoFS image + the model registry + enable `arthur-real-infer` (default 1.5B) + the **`/model` drop/reload switch** + the boot→load→generate+switch proof **only**. **Do NOT** embed any model in the kernel (23.3 — they stay data), check a model blob into git, change the inference engine (8.5's path, frozen), build a model **download/update-over-network** mechanism (later — `/model` only switches between the *already-bundled* models), or change Arthur's conversation/intent logic beyond parsing the `/model` slash-command. Reuse `neomc` (GGUF→.neom) + the existing `sys_model_load`/`sys_model_drop`/generate paths. No new invariant/`unsafe`.
