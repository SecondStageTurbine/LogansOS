# RETURN (relay #64): post-merge review of Arthur startup fix (#126)

**Reviewed SHA:** `745dd314dd8e74e60839fb2529d3187222a93f5e`  
**PR:** [#126](https://github.com/SecondStageTurbine/LogansOS/pull/126)  
**Overall verdict: FAIL** — checklist items 4 and 5 have concrete violations. No code fix or build was part of this review.

1. **Profile scope — PASS.** `Cargo.toml:131-145` changes only `profile.dev` code generation for `neo-arthur`, `core`, `alloc`, and `compiler_builtins`. The PR body reports before/after QEMU stack high-water for the 32 KiB boot-model hash path and the 256 KiB inference stack, with the largest increase +320 B; it also reports the listed timing/contention scenarios passing. Those measurements cover the kernel's identified stack-tight boot hash and inference paths. Kernel timer/wait loops inspected use tick or TSC deadlines rather than iteration-count timing; no `#[inline(never)]` timing assumption was found. The measurements do not claim to exercise every kernel call path.

2. **Release profile and host builds — PASS.** The change is confined to `profile.dev` (`Cargo.toml:131-145`). The PR body says host builds do not use `build-std`, so `core`, `alloc`, and `compiler_builtins` match no host package. The product build uses an explicit opt level in xtask (`tools/xtask/src/main.rs:4976`, `6031-6035`); the PR reports product `.text` and symbol count unchanged, with only anonymous-constant names/string merge order differing.

3. **Overlay vocab split — PASS, with global-latest scope.** `syscall.rs:965-976` searches a successful open's copied path for `/vocab/`; `watchdog.rs:222-228` stores that open's fd and pid. `watchdog.rs:230-237` records a close only when both fd and current pid match, so a different process closing the same fd number cannot mark it done. The timeline formatter renders each zero milestone independently as `-` (`watchdog_timeline_logic.rs:44-47,59-73`). The tracker is one global latest-open slot and does not restrict the opener to Arthur, so another process opening a `/vocab/` path would replace the displayed interval.

4. **Think/presents per pid — FAIL.** The 8-slot table is indexed by `pid % 8` (`prefill_perf.rs:43-48,174-176`), and a commit writes TSC and PID as separate relaxed stores (`prefill_perf.rs:270-272`). More than eight committing pids evict each other's entries. There is also a concurrent misattribution window: if PIDs 8 and 16 commit on different CPUs, their slot-0 stores can interleave as `TSC(8), TSC(16), PID(8)`; PID 8 can then begin generation, pass the PID check, and read PID 16's timestamp. The overlay then prints a false `think=-Xms` delta from that unrelated commit (`prefill_perf.rs:311-320,374-383`). The syscall entry hook has no shared serialization before those stores (`syscall.rs:895-897,965-982`). Exited pids' slots do not match another live pid under the monotonic `NEXT_PID` allocator (`process.rs:72,376`), but that guard does not prevent the concurrent pair mismatch.

5. **Syscall hook — FAIL.** The second path copy is safe for the shipped product feature set: the first successful open validates and copies the path in `sys_open_impl` (`syscall.rs:5755-5773`), and product features omit `browser-runtime`, which gates `SYS_VM_UNMAP` (`tools/xtask/src/main.rs:4912-4965`; `syscall.rs:914-920,6361-6362`). The changed path contents could affect labeling, but the product runtime cannot unmap the buffer through that syscall. However, the explicit no-lock/no-IF invariant is violated: both `note_vocab_open` and `note_close` call `current_pid` (`watchdog.rs:222-237`), and `current_pid` enters `without_interrupts` and takes the scheduler lock (`scheduler.rs:1680-1683`). This is an extra lock acquisition and IF-off window on each matching open/close; I found no evidence of a deadlock and make no such claim. The syscall hooks themselves are compiled under `#[cfg(feature = "freeze-watchdog")]` (`syscall.rs:969,981`), so they are absent when the feature is off.

6. **Host tests — PASS, with one uncovered case.** `fb-progress-logic-tests` checks empty `vocab=-..-`, a normal open/close interval, and large values (`lib.rs:188,208,222-230`). It does **not** test open without close (`vocab=O..-`).
