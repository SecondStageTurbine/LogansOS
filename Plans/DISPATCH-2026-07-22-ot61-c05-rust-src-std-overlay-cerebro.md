## Scope — what C0.5 IS (the surface you already enumerated)
1. **The bounded `rust-src` `sys/*` overlay.** Per your C0 finding (`docs/RESEARCH-2026-07-22-ot61-c0-libstd-pal-FINDINGS.md`) + the manifest (`tools/ot61-pal-manifest.toml`): route **most** `library/std/src/sys/*` → the C0 PAL **unsupported stubs** (loud, named), and implement the small custom set the smoke actually needs:
   - **3 custom `sys` modules** — `stdio` (→ the PAL `print`/stderr primitive), `alloc` (→ the PAL heap), `exit`/process (→ the PAL `exit`).
   - an **io-errno table** (map the PAL/libneo error space → `std::io::ErrorKind`).
   - a **panic_unwind arm** — consistent with the target's `panic=abort` (no unwinder that needs executable memory — **A1: introduce NO W^X mapping**).
   Keep the overlay **minimal** — exactly what the C0.5 smoke links, no speculative `sys/*` implementations (an unimplemented surface stays a loud stub; that's the point).
2. **A real `std`-linked smoke.** A program that uses **actual `std`** (`std::println!`, a heap `Vec`/`String`, `std::process::exit`) — NOT the raw-syscall `std-pal-smoke` from C0 — compiled with `-Z build-std=std` against the overlay, linking to a static ELF on the `x86_64-unknown-neoplutarch` target.
3. **The on-target QEMU close (the runtime gate).** A QEMU scenario that **spawns the real-`std`-linked smoke ELF via the existing `sys_spawn`** and verifies it **prints + allocates + exits cleanly** on-target — the runtime proof that C0's "prints/allocates/exits" gate holds for genuine `std`, not just the primitive tier. **This adds NO new syscall** (it rides the existing spawn/ELF-loader/process surface); if the real-`std` ELF surfaces a gap in that existing path (TLS setup, ELF segment handling, the loud-stub firing on an unexpected `sys/*` call), that is a valuable C0.5 finding — capture it, don't paper over it.

## Constraints / standing rules
- **A4 manifest still holds (structural).** The overlay routes through the C0 PAL primitives, whose syscalls are already manifest-gated. If the overlay needs a syscall NOT in the manifest, the A4 build-breaking gate MUST fire (add it to the manifest *with its capability provenance* in the same change, or route through an existing PAL primitive). Confirm the gate stays armed over the overlay.
- **A1 — no W^X (reserved invariant, do NOT violate).** The panic arm is **abort** (no unwinder needing executable pages); the overlay introduces **no** executable-memory mapping. C0.5 stays R+W+NX. (JIT remains the future budgeted rung.)
- **Kill-switch / no-regression:** purely additive (the overlay + the smoke + the scenario are opt-in behind the browser target/feature). The **default kernel/toolchain build stays bit-for-bit unchanged**; no POSIX personality reaches the kernel/user ABI. Ship the equality (default build unaffected).
- **Loud-absence preserved:** any `sys/*` surface the smoke does NOT need stays a **deterministic loud stub** (named, `exit`-with-reserved-code) — never a silent fallback. The overlay implements only what links.
- **No new invariant / A2 untouched** (the per-content-process memory quota is the C1/C2 rung, not C0.5).
- **SPDX** on new files; **no-human-time** framing (C0.5 is a bounded sub-rung; C1 is the depth bottleneck downstream — restate any figure).

## Gate coverage (honest)
- **Host/toolchain:** the overlay compiles a real-`std`-linked smoke to a static ELF on the target (build verification, like C0's disasm check); the A4 gate stays armed.
- **QEMU (the runtime close — this is what makes C0.5 kernel-touching):** the on-target `sys_spawn` of the real-`std` smoke ELF prints/allocates/exits cleanly. **This is the first real-`std` ELF through the existing spawn/ELF-loader path** — a genuine integration test; a self-diagnosing failure (an unexpected loud-stub fire, an ELF-loader gap) is a valid RETURN.
