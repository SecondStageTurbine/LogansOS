# RETURN: Zenbook touchpad cross-family review (Chad)

**Reviewed commit:** `f323a733bad68ceb7bef4949be7094e756d410c9` (`origin/claude/zenbook-i2c-hid-touchpad`)

**Verdict: BOUNCE.** Two checklist requirements are not met: the ISR runtime lock test does not hold every named lock, and the photo path does not replay a no-match result.

1. **PASS — quirk values equal the DSDT bytes.** Read the raw `dsdt.dat` blob from `origin/claude/acpi-aml-rung0`: its 423,950 bytes contain OEM `_ASUS_` / `Notebook`; `_ADR` operand `01 00 19 00` at `0xFFF5`; ETPD package header `5B 82 4B 12 45 54 50 44` at `0x675B7`; the UUID at `0x67652`; register operand `01` at `0x6767E`; and the exact 44-byte CRS template at `0x676B3`. The template contains address `15 00`, speed `80 1A 06 00`, controller `\\_SB.PC00.I2C5`, and interrupt flags `15` with GSI `69 00 00 00`. Values/table and offsets: `kernel/src/drivers/i2c_hid/quirk_logic.rs:73-96,99-153`.
2. **PASS — non-matching machines are not probed.** `init` reads the DSDT and only calls `device_at` if DSDT selection succeeds or the control feature is enabled; every non-match returns before `bring_up`: `kernel/src/drivers/i2c_hid/touchpad.rs:236-274,286-304`. The forced path is conditioned on `neo-test-i2c-hid-absent-control` at `:245-258`.
3. **PASS — the match is specific.** AML `PkgLength` and integer decoders are at `kernel/src/drivers/i2c_hid/quirk_logic.rs:240-268`; `inspect_dsdt` bounds the named ETPD package around the CRS and searches after the HID UUID for the function-1 constant at `:296-332`; verdict also requires OEM and PCI identity at `:338-360`. The matcher is byte-pattern based rather than a full AML tree walk, but the exact CRS, ETPD scope, OEM pair, UUID/return pattern, and PCI ID make a non-touchpad match implausible; the eight other corpus DSDTs are reported not to match in `docs/RESEARCH-2026-10-23-zenbook-i2c-hid-touchpad-FINDINGS.md:74-90,220-227`.
4. **PASS — PIO only.** LPSS reset writes are `0` then `0x3`, followed by a read-back and refusal if iDMA bit 2 is set: `kernel/src/drivers/i2c_hid/touchpad.rs:391-420`. `IC_DMA_CR` is set to zero at `kernel/src/drivers/i2c_hid/dw_logic.rs:312-315`; PCI bus mastering is cleared and checked at `touchpad.rs:352-378`. No LPSS DMA register programming appears in the implementation.
5. **PASS — DesignWare configuration.** `IC_CON=0x65`, SCL counts, SDA hold RX-field preservation, zero interrupt mask, and zero DMA control are at `kernel/src/drivers/i2c_hid/dw_logic.rs:129-153,295-315`. The formula gives 78/150 at 100 MHz: ceil((600+208) ns × 100 MHz)−3 = 78 and ceil((1300+208) ns × 100 MHz)−1 = 150. Linux maps PCI `8086:E351` to `ehl_i2c_info` at [intel-lpss-pci.c](https://github.com/torvalds/linux/blob/master/drivers/mfd/intel-lpss-pci.c#L2703-L2705), whose configured clock is 100 MHz at [the platform-info definition](https://github.com/torvalds/linux/blob/master/drivers/mfd/intel-lpss-pci.c#L1923-L1929). `IC_TAR` and timing configuration follow `disable()`/status polling at `dw_logic.rs:251-280,295-304,342-344`.
6. **PASS — transfer sequencer.** The first read after a write gets RESTART; only the final command gets STOP; FIFO fill and outstanding reads are bounded; abort source is read and cleared; deadline expiry aborts and disables: `kernel/src/drivers/i2c_hid/dw_logic.rs:342-408`. Abort is checked before the success condition at `:359-376`. The model covers enable-status lag, TX flush until abort clear, and STOP_DET at `tools/i2c-hid-logic-tests/src/model.rs:159-219,229-317`.
7. **PASS — HID-over-I2C.** Descriptor offsets and length/version validation: `kernel/src/drivers/i2c_hid/hid_logic.rs:6-11,64-101`. RESET/SET_POWER byte layout: `:117-137`; input length includes its prefix and rejects `0xFFFF` as a report: `:152-162`. Bring-up powers on, waits 60 ms, resets, waits for the ack, then powers on again except VID `0x04F3`: `kernel/src/drivers/i2c_hid/touchpad.rs:543-560,676-702`.
8. **PASS — report descriptor walk and decode.** The parser handles globals/locals, usage ranges and 4-byte usages, limits mouse fields to a Generic Desktop/Mouse Application, tracks offsets by report ID, and advances offsets for constant inputs: `kernel/src/drivers/i2c_hid/hid_logic.rs:264-289,337-490`. Signed extraction follows the logical minimum (`:399-402,514-534`). Digitizer IDs are classified and counted separately (`:374-381,431-435,501-512,563-602`). Push/Pop and long items return named `Unsupported` errors (`:232-240,351-356,474-479`), printed as `parse FAILED` by `touchpad.rs:505-512`.
9. **FAIL — ISR lock isolation test is narrower than specified.** The production path itself only masks the pin and updates atomics (`kernel/src/drivers/i2c_hid/touchpad.rs:725-733`); the IDT body then EOIs (`kernel/src/arch/x86_64/idt.rs:1019-1024`). However, `isr_with_driver_locks_held_for_test` acquires `BUS_OWNER` and `STATE` only, then invokes the body (`touchpad.rs:1135-1152`). It does not hold `BOOT_LINES`, `DELIVERY`, or an AI-governance lock despite the scenario comment claiming every driver lock is held (`kernel/src/test_harness.rs:24854-24855`). **Concrete sequence:** run `i2c_hid_absent`; the test reaches the ISR with `STATE`/`BUS_OWNER` held while `BOOT_LINES` and `DELIVERY` remain unlocked, so those listed lock cases are not exercised.
10. **PASS — level-triggered handling.** ISR masks before setting pending; the service reads before its normal unmask; level reassertion is observed through `PENDING.swap`; 16 empty assertions switch to masked polling and eight consecutive transfer errors stop the reader: `kernel/src/drivers/i2c_hid/touchpad.rs:727-733,857-890`; policy limits/actions: `kernel/src/drivers/i2c_hid/hid_logic.rs:606-678`. Route-failure and no-reset-IRQ modes explicitly mask the pin before polling (`touchpad.rs:561-573`).
11. **PASS — I/O APIC writes.** `route_gsi` programs the entry masked (`kernel/src/arch/x86_64/ioapic.rs:170-210`); runtime writes are through `GsiPin::set_masked` (`:150-166`), and `read_low` is documented and used only while masked (`:162-166`; `touchpad.rs:567-573`). Grep of `ioapic::` users found only boot-time `route_isa_irq` for i8042, this boot-time `route_gsi`, the diagnostic read, and the touchpad pin handle; the thread's unmask uses interrupts-off (`touchpad.rs:904-909`).
12. **PASS — ring and pump.** One service-thread producer and one pump/boot-check consumer; release/acquire publication and counted full drops: `kernel/src/drivers/i2c_hid/touchpad.rs:69-74,803-823`. The pump follows the same pointer event, raw-button, stage/legacy-route and flush path at `:927-954`. No USB mouse source file changed between `origin/main` and the reviewed commit.
13. **PASS — liveness.** Bring-up and transfer deadlines use TSC bounds (`kernel/src/drivers/i2c_hid/touchpad.rs:57-62,154-159`; `dw_logic.rs:217-238,263-280,349-408`). The service caps a pass at 64 pending assertions and naps one tick (`touchpad.rs:64-65,857-890`); failed transfers stop after the governor limit (`hid_logic.rs:606-609,656-675`).
14. **PASS — kill-switch source gating.** The module, IDT entry, APIC route, ACPI DSDT accessor, PCI helpers, pump and boot calls are feature-gated: `kernel/src/drivers/mod.rs:24-28`, `kernel/src/arch/x86_64/idt.rs:257-259,376-390,1019-1024`, `kernel/src/arch/x86_64/ioapic.rs:134-179`, `kernel/src/acpi/mod.rs:324-325`, `kernel/src/drivers/pci.rs:851-895`, `kernel/src/main.rs:726-730,801-803`, and `kernel/src/arch/x86_64/syscall.rs:5555-5560,7495-7497`. Widened cfgs retain the prior `ps2-keyboard`/`xhci-silicon` font paths. Findings §7.3 reports the requested `.text` identity rows (`docs/RESEARCH-2026-10-23-zenbook-i2c-hid-touchpad-FINDINGS.md:275-289`); I did not rebuild the desktop comparison in this review, so that reported binary identity is not independently remeasured here.
15. **PASS — absent scenario and control.** The absent scenario fails if `PROBED` is true, checks both no-controller timeout calls against the handshake budget, and invokes the lock test (`kernel/src/test_harness.rs:24861-24905`). The control forces a match and takes the PCI-absent fail-closed branch (`touchpad.rs:245-258,286-298`); the zeroed RAM page uses the same `Mmio` implementation and bounds the no-response path (`:1155-1178`). This is fair for timeout/control-flow coverage, while it does not exercise real BAR mapping or device semantics.
16. **FAIL — no-match failure mode is not replayed at the touchpad photo check.** `evidence_check` reprints `BOOT_LINES` only when `PROBED` is true (`kernel/src/drivers/i2c_hid/touchpad.rs:1053-1069`), but `init` returns on every non-match before setting `PROBED` (`:264-275`). **Concrete sequence:** boot with a DSDT whose OEM pair or CRS no longer matches; `i2c-hid: no match ...` is printed during early boot, then the later post-USB touchpad check emits no replay and returns because `READY` is false. The photo at that check therefore lacks the failure discriminator required by the bank.

**Notes:** The fixed-template matcher is specific against the available DSDT corpus, but it does not parse full AML method structure. The RAM-backed MMIO check establishes bounded behavior for a non-responding register block, not real hardware behavior. Bare-metal touchpad operation remains unverified by this source review.
