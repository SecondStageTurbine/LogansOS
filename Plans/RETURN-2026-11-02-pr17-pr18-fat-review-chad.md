# RETURN: #17 + #18 FAT read-only review (Chad)

Reviewed heads: #17 `71249d6cd4ba29d57ec783b06a3f4fe80bd19701`; #18 `028c04d313085343ed59e1c1a4f45256ce6d9fe9` (stacks on #17).

- **FAIL** — `kernel/src/drivers/block/mbr_logic.rs:15-18, 137-149, 171-178`: overlap rejection only compares an entry against earlier *believed FAT* ranges, and extended chains are not examined. Concrete input: a signed 512-byte MBR with slot 1 type `0x0C`, start 2048, count 4096 and slot 2 type `0x83`, start 4096, count 4096 on a 65536-block device. Slot 1 is accepted and mountable although it overlaps slot 2. An EBR loop is neither traversed nor detected/rejected; unsupported primary extended types are simply classified as non-FAT.
- **FAIL** — `third_party/fatfs/src/table.rs:642-655`: `ClusterIterator::next` follows the FAT without a visited-cluster or volume-cluster bound; a cycle can be yielded indefinitely. There is no cycle discriminator in `tools/fat-logic-tests/src/lib.rs` or a gate scenario. Concrete input: a FAT16 file whose chain is `A → B → A`, with file size larger than two clusters, can be read by revisiting the same clusters instead of returning corruption. The other named discriminators are present: cluster-count type selection is in `third_party/fatfs/src/fs.rs:401-405`; geometry and dirty-indicator KATs are in `tools/fat-logic-tests/src/lib.rs:69-205, 212-273`; long-name lookup is checked in `kernel/src/test_harness.rs:37262-37265`.
- **PASS** — read-only is enforced at the device boundary: `kernel/src/drivers/block/mod.rs:47-67` gives `ReadOnlyDevice` only `geometry` and `read_block`; `kernel/src/fs/fat.rs:147-156, 450-455` refuses library and VFS writes. The registered device is a `GuardedDevice` (`drivers/block/mod.rs:657-685`), and MBR partitions wrap that registered device (`drivers/block/mod.rs:772-779`, `drivers/block/partition.rs:43-55`). The no-write gate checks zero attempts and unchanged sectors (`kernel/src/test_harness.rs:37504-37579`).
- **PASS** — `third_party/fatfs/VENDORED.md:1-20` records the MIT licence, upstream URL and commit `38b3a7950bf0e765e34286d1dfe76c519ee347e2`, and states the vendored sources have only SPDX headers added and no patches.
- **FAIL** — `kernel/src/fs/mod.rs:15-19, 1332-1335`: with `fat-fs` off the optional rust-fatfs code is excluded, but the native `fat32` module is still compiled and selected. The approved THINK explicitly chose that old FAT32 driver as the kill-switch's off-path and control (`kernel/Cargo.toml:1803-1809`, `kernel/src/test_harness.rs:37445-37472`), which conflicts with this dispatch criterion's literal requirement that feature off leaves “no FAT code in the kernel.”
