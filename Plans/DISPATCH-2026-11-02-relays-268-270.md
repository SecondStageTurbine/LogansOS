**MODEL** GPT-6.1-Sol, **EFFORT** high: CPU state save/restore (FPU/XSAVE) on every context switch and exception.
`git fetch origin +pull/52/head:pr52 && git diff origin/main...pr52` (head `e53c3e6e`). Seat E's diagnosis is in the
PR body; the dispatch is `Plans/DISPATCH-2026-11-02-whpx-boot-gp-seat-e.md`.
1. The diagnosis: the faulting instruction and why it #GPs under WHPX but not TCG; confirm from the code.
2. XSAVE sizing: the area size comes from CPUID leaf 0xD for the features actually enabled in XCR0 (not a fixed

   and alignment (64-byte); AP and BSP agree.
3. No other `xsetbv`/`wrmsr`/`rdmsr` in the kernel assumes a feature without its CPUID bit; list any left.
4. The regression scenario boots the product kernel on a CPU model that reproduces the condition under TCG.
5. A fatal kernel #GP now shows a clear panic screen.
