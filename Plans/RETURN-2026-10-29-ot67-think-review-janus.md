1. **FAIL — T0 is a useful starting point, but the stated grapheme/layout and T2 substitution claims are too strong.** The inventory in `docs/THINK-2026-10-29-ot67-editor.md:24` matches `userland/neo-text/src/lib.rs:2`: no_std/alloc, parsing, raster, cache, kerning, canvas and TextFlow exist, with both bundled fonts. But scalar-to-glyph mapping is not Latin grapheme shaping. `userland/neo-text/src/layout.rs:36` iterates chars, and `:90` breaks at char boundaries. Independently ran its real Inter wrapper on `"a\u{0301}"` at 18 px, width 5.053711: it returned `[0..1, 1..3]`, splitting one grapheme across rows. Filtering cursor stops afterwards does not fix that layout. T0 also does not expand tab into the proposed four-space width. E1 already provides a grapheme-based wrap path (`userland/neo-edit-core/src/wrap.rs:29`); the proposed T0 adapter should use that behavior, with matching tab/draw geometry, rather than directly delegating to neo_text::layout::wrap as the THINK says at `:157`.

   T2 affects document content, including combining marks and missing glyphs, even with an English UI; 'only localization' at `:40` is misleading. The cited text-engine research explicitly calls Latin ccmp and clusters correctness requirements (`docs/THINK-2026-07-10-atrium-text-engine-research.md:187`). An explicitly limited LTR MVP can defer complex scripts, but must state its rendering limits and preserve bytes. `TextLayer` (`editor THINK:147`) can keep the byte buffer independent of a shaper; it cannot promise that all later bidi cursor/selection work is hidden by this trait: caret affinity, visual movement and discontiguous selection geometry are absent. Its draw method takes &self whereas current neo-text drawing requires &mut Font for the glyph cache (`layout.rs:126`); choose mutable adapter methods or intentional interior mutability. That is an API implementation decision, not a reason to change the gap buffer.

2. **FAIL on the complete editable/save bound; PASS on the implemented load/history bounds.** The THINK's no_std gap/line-index approach matches the built E1 core. `userland/neo-edit-core/src/format.rs:50` rejects a load above 4 MiB before normalization. `history.rs:16`, `:126` bound retained removed+inserted payload to 1 MiB, discard oldest complete edits, adjust/invalidate the saved marker, and set trimmed. A single paste larger than the history bound is retained in the document but is entirely non-undoable; an independent probe printed `retained=0 undo=0 trimmed=true dirty=true`. The 1 MiB bound is edit payload, not total metadata/transient allocation, and the future E2 status-line notification is still UI work. Saving preserves history; an unreachable saved position becomes None, avoiding a false clean state after trimming/branching.

   **Concrete cap input:** load 4,194,304 ASCII bytes, move to document end, type `x`. `Document::type_text`/`paste` (`document.rs:223`, `:233`) reach unchecked apply (`:286`); the executed probe produced both document length and serialized length **4,194,305**, beyond W1's specified cap. E-D4 says the cap bounds the buffer/undo, but only opening is capped today. Define and enforce growth/refusal before edit mutation, based on serialized bytes including CRLF expansion/BOM, or explicitly design an unsavable oversized state. The core and app must agree; the load check alone is insufficient.

3. **PASS — invalid UTF-8 or NUL is refused, not opened read-only.** The THINK §3.4 explicitly says 'this isn't a text file'; `format.rs:50` returns InvalidUtf8 or Nul, and `Document::load` propagates it. CRLF/LF/BOM handling is implemented and tested. OT-88 §4.3 agrees on the planned editor association, but Files itself is not built on this main: 'Files uses' is a future shared-classifier requirement, not evidence of two existing implementations. A valid UTF-8 file containing unsupported glyphs passes this classifier, which is why item 1's rendering scope must be explicit.

4. **PASS for the need for atomic replacement; qualify 'two commits today'.** `kernel/src/fs/neofs/inode.rs:564` builds a whole-file COW write and refuses a resulting extent over eight direct blocks at `:584` (32 KiB). `:629` truncates through an indirect layout; each calls one commit_child_update (`:618`, `:678`). A generic shorter replacement implemented as truncate-to-zero then write therefore has an externally visible empty intermediate version and can recover empty after a cut. This is not atomic replacement. Same-length overwrites can already use one write, so not every possible save necessarily takes two commits. #206 now includes old-tree freeing in that same publish (`:590`, `:1253`); the THINK's as-built amendment correctly supersedes its historical second-release-publish description. The old ordinary-write leak is explicitly labeled fixed/historical in §5.2.2, not a current main defect.

5. **FAIL — W1's COW publication model is viable, but the pitfall claims do not establish its lifetime safety.**

   **PASS for crash atomicity of the proposed transaction, conditional on using the existing barrier/reuse protocol.** New data/indirect blocks/inode/root precede superblock writes; `kernel/src/fs/neofs/cache.rs:613` and `:663` flush non-superblock data before publishing a root. `commit_logic.rs:11` states the barrier and deferred-reuse rules; `inode.rs:2737` excludes deferred blocks until the freeing generation is durable. An old durable root still has its old blocks, while a durable new root names flushed new blocks: old or new, not mixed. Cached commit success alone is not fsync durability; a cut after only an in-memory publish can still recover old. §5.2.4 should distinguish that from a cut after a durable superblock publish. The hand-laid 3→9→2-block inode/indirect oracle and cut tests are appropriate, and the syscall's byte cap/right/error checks need their own discriminators. The per-generation CAS now checks both inode block and generation (`inode.rs:768`, `:791`), consistent with the later amendment.

   **FAIL F3 — CP-67/CP-30 is not discharged by holding no IPC object.** The row at `editor THINK:321` says the file Arc is dropped on kill like sys_write's. A thread preempted Ready inside replace can own the user-copy Vec, OpenFile Arc, layout vectors and a writeback-pause guard. Current main's kill scan can zombify it (`kernel/src/sched/scheduler.rs:317`, `:2646`); `Thread::free` frees its stack raw (`thread.rs:243`), so those locals' Drops do not run. Concrete interleaving: writer increments foreground_writers via pause_worker, is preempted inside the COW operation, another CPU kills it, reaper frees its stack. The pause decrement and owned releases are skipped; 'like sys_write' repeats the same exposure. OT-93/#204 addresses the Ready portion, but its unmerged state and infallible-wait limitations must be accounted for. Require a real mid-syscall kill discriminator that checks cache-pause/accounting as well as frame/block counts; 'no IPC' is not a lifetime proof.

   **FAIL F4 — ESTALE plus deferred durability does not by itself pin a live reader's old version.** The reader row at `editor THINK:319` says an old reader never reads freed blocks. `kernel/src/fs/mod.rs:379` validates generation separately from `inode.read_at` at `:387`. `NeoInode::read_at` snapshots its old record and reads blocks without holding the namespace/allocator transaction (`inode.rs:1628`). Concrete interleaving: a previously verified old-version reader passes validate_current and pauses; another handle replaces the file, fsync makes all new superblock copies durable, then another allocation reuses an old data block; the first reader resumes using its old record. Its cached verification can skip rehash (`inode.rs:1858`). Deferred-free durability protects recovery roots, not this in-flight reader. The source does not establish the categorical never-freed-block assertion. Add a reader lifetime/transaction rule and a test with the pause after validation, not merely a fresh read that starts after replacement and gets ESTALE. This is an existing shared-path exposure the new design relies on; no new filesystem implementation is alleged here.

   **PASS — W1 supersedes rename replacement cleanly.** OT-88 §4.2 now refuses replacement rename (`app-model THINK:394`) and §6.1 names FILE_REPLACE and explicitly removes temp-file/rename (`:489`). A granted WRITE file handle is sufficient; K1b/F0 are not needed for the replacement operation. #209 is still an open feature PR at review time; the editor THINK's 'as built' note must be understood as branch implementation evidence, not a syscall already present on main.
