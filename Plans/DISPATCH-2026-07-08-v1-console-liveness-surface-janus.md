## The four things the v1 console MUST show (OT-26 clarification, PL 2026-07-07)
1. **Boot confirmation** — the OT-36 boot frame = "it's alive" (already honest post-OT-36: `v0.0.1 — PHASE 8 - ARTHUR`, preemptive-SMP). Ensure the boot→ready handoff is clean.
2. **Ready-state affordance** — Arthur's opening **greeting** telling a first-timer what to do (`VISION-arthur-persona.md` example 10 — the butler first-boot line: *"Good afternoon. I'm Arthur… Tell me what you'd like, in your own words… If ever you'd rather do it yourself, 'help' shows you the way."*). This is the usability dive's first-boot affordance (F-checklist) — the difference between "inviting" and "a cursor blinking at a stranger."
3. **The scrolling transcript** — the recognition-over-recall surface (usability principle P4): the conversation stays visible, both `arthur>` and `neo>` turns interleaved (the two-surface duality — the transcript IS the UI).
4. **LIVENESS feedback while Arthur runs a forward pass** — **the load-bearing new piece.** A thinking indicator / streaming tokens while the model generates, so the user never wonders "is it frozen / did it hear me." This is the exact gap that plateaued Alexa/Siri (usability dive Q3: the "did it hear me" feedback gap) — closing it is a v1 differentiator.
