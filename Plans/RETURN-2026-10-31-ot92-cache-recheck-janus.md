However, the partial-write retry remains unconditional (`:339-374`), including off mode. Concrete helper-level input/interleaving: enable `neofs-large-write`, disable `neofs-cache-evict`, cache block A, start `write_bytes_at(A * 4096, &[0x5a], Data)`, pause after the first cache check finds A (`:345-353`), call `forget_range(A, 1)`, then resume. The old `origin/main` implementation (`kernel/src/fs/neofs/cache.rs:280-310`) reaches `maybe_bytes.ok_or(BlockDevice)` because it skipped the read and A is now absent, and returns an error. The new implementation retries, reads A, merges the byte, and succeeds if the device succeeds. This is a cache-helper behavior difference, not a demonstrated reachable file-data corruption. The new sequential forget test (`kernel/src/test_harness.rs:32972`) checks removals and eviction accounting, not this interleaving. Thus the original epoch finding is closed, but “old behaviour bit for bit” is too strong unless the off path also preserves the old partial-write behavior or the claim is narrowed.

- **2. FAIL — item 5's dirty bound remains false and the PR's CP-64 row is still uncorrected.** `kernel/src/fs/neofs/cache.rs:38-65` now candidly documents that one mutation can exceed capacity and that 128 is a pre-mutation trigger. Enforcement is still a single pre-mutation throttle (`kernel/src/fs/neofs/inode.rs:799`, `:964-970`), followed by caching the whole expanded content (`:802-823`); eviction skips every dirty block (`kernel/src/fs/neofs/cache.rs:809-819`). Concrete input: from a clean cache, truncate an empty writable file to `300 * 4096` bytes on a sufficiently large volume. The paused worker cannot drain those 300 newly dirty data blocks during the mutation. Inserting a clean block after those data inserts requires scanning at least 301 entries. No 257-entry maximum follows. The live PR description's Pitfall bank still marks CP-64 “bounded” and says “One eviction scans at most 257 entries” and shifts at most 256 headers. Its dirty-throttle prose also still asserts the cache stays within 256. The source comment correction does not correct that row. The real scan bound depends on the accumulated dirty population, including mutation overshoot; it is not the stated constant.

- **3. PASS — the partial-write retry count is bounded, and exhaustion returns an error.** `kernel/src/fs/neofs/cache.rs:35` sets `MISS_RETRIES = 16`; `:339-343` allows 16 loop bodies per block and returns `Err(NeoFsError::BlockDevice)` before a seventeenth. A block-specific eviction record avoids retrying for unrelated evictions while the last 64 removals cover the interval (`:844-861`); more than 64 conservatively forces a retry. At exhaustion the current block's merge has not occurred (`:375-379`), but earlier blocks in the same call may already have been modified (`:384`): the helper returns an error, not a byte count or rollback guarantee. Where propagated through `neofs_to_vfs`, callers see `VfsError::Invalid` (`kernel/src/fs/neofs/mount.rs:526-532`). This bounds retries, not elapsed time: each device read (`kernel/src/fs/neofs/cache.rs:357`) must itself return. The separate stalled-device finding from the earlier RETURN is outside this dispatch's requested re-check.
