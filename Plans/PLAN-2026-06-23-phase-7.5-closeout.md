## 0. The headline finding (all four lanes converge)

**Phase 7.5 is not honestly closeable today, but the tail is bounded closeout work, not unknown-feature work.** Substrate (0/A/B/V) + WPA crypto landed with QEMU and/or OptiPlex evidence; MT7601U scan + cold firmware self-upload + WPA2 pairwise-CCMP association are silicon-proven. The remaining work is hardening a proven driver to a *usable, self-sufficient WiFi link* + the identity capstone + a final integrated proof + consolidation.

**Scope fork — RESOLVED (no fresh ruling needed).** Cerebro and Janus both confirmed the `iwlwifi → MT7601U` amendment is already ratified (`docs/bible.md:179`, Article 24.1, 2026-06-13; `Plans/PL-DECISION-2026-06-13-wifi-target-mt7601u.md`; ADR-017). Cerebro's cost case is decisive: iwlwifi = ~80K LOC (14×), a from-scratch **PCIe** bus stack the USB lane doesn't have, and **SoftMAC = zero supplicant savings** — it would discard proven silicon for strictly more work. **MT7601U closes Phase 7.5; iwlwifi stays a future-chipset follow-on behind its own ADR.** Action: *restate* this in the close report (Janus checklist step 1), not re-decide it.

## 1. The ordered build sequence

Priority follows Cerebro's P0/P1 split. **P0 = "WiFi connects and gets an IP, cold, on bare metal"** (the real headline). P1 = hardening to a complete, self-sufficient link. Each build is kill-switched, carries the I-14 fault-containment analysis (connectivity standing rule), and ends on the close-gate ritual (`scripts/worker-close-gate.sh`).

### CB-1 — P0: cold end-to-end association + GTK/broadcast-RX + DHCP-over-`wlan0`  *(owner: Cerebro; kernel-touching ⇒ QEMU + bare-metal)*
The headline gate. **Wedge-free by construction** — uses the driver's Linux-faithful targeted-connect path (single tune to the AP's configured channel, never the cumulative 1→14 sweep that wedges; Cerebro A.2). Composes:
- **Association** (proven): cold firmware self-upload (`f378f12`) → targeted single-tune → auth/assoc/4-way/pairwise-CCMP (`4f82155`) with the real-CSPRNG SNonce (`d1c8bb6`).
- **GTK / broadcast RX** (new — the missing piece for a usable link): parse the GTK KDE from 4-way Message 3 (Prometheus **T-038**, byte layout flagged needs-raw-source-confirm vs wpa_supplicant — confirm during the build), install it to **WCID 0** (the reserved multicast slot — Prometheus **T-036**: `MT_WCID_KEY(0)=0x8000`, `MT_WCID_ATTR(0)=0xa800` with `PAIRWISE=0`, cipher `AES_CCMP=4`), and ensure the RX filter accepts broadcast/multicast (**T-047**) and the WCID-attr memory is explicitly programmed off its all-1s init (**T-041**).
- **DHCP-over-`wlan0`** (new): enforce the **GTK-before-DHCP** ordering (Prometheus **T-043** — DHCP Discover is broadcast, can't pass until the port is authorized + GTK installed), set the BROADCAST flag (**T-045**), the 802.11→Ethernet addr translation in the NetDevice (**T-048**), and hardware-encryption WCID path (`hw_key_idx != 0xff`, **T-046**). The Phase-4 DHCP state machine is reused; only the WiFi-link differences above are new.
- **Gate:** a QEMU scenario for the GTK-install + broadcast-RX + DHCP path that can run hermetically; the **cold-end-to-end bare-metal run** (cold-upload → targeted-associate → GTK → DHCP DORA over `wlan0`, sink-captured) is the PL's bare-metal run, designed self-diagnosing (serial breadcrumbs at each stage).

### CB-2 — P1: the intermittent SMP AP-bringup hang (OT-27(c))  *(owner: Oracle; kernel-touching ⇒ QEMU)*
Oracle's instrument-first plan (no fix until a discriminator fires). Build the **captures first** (Oracle A.4/A.6): per-CPU reschedule-IPI **sent vs handled** counters (sibling to the existing TLB counters at `tlb_shootdown.rs:172–194`) + the AP-lifecycle timestamp trail (`ap_entry` entered / `scheduler_ptr` published / `enable_interrupts` / first dequeue). Drive the repro at `NEO_SMP=4` under the W1/W2 workload; read the verdict off the breadcrumbs (H1 swallowed-wakeup vs H2 OT-31 exit/reap vs the refuted TLB class). **Cheap standalone first step:** the OT-31 `exit()`/reap lock-release audit vs the `context_switch_with_release2` precedent (a static read, no run) — it removes or confirms H2 for free. Fix only what a discriminator confirms.

### CB-3 — P1: 7.5-D identity / interface wiring (the capstone)  *(owner: Oracle or Janus; kernel-touching ⇒ QEMU)*
Oracle's design (Charter B), **Option 3**: an interface is a named node addressed by a **`Handle::File` cap (I-15)** under a connection-management namespace (e.g. `/net/if/wlan0`). Deliverables: a small `InterfaceId` registry above `NetDevice` with runtime naming (`eth0/wlan0`, replacing the baked `&'static str` literals), hotplug lifecycle (USB attach/detach + WiFi assoc/disassoc → registry link-state), and multi-interface `select_source` (extend the Phase-4 RFC-6724 pick across UP interfaces, replacing the hardcoded `get_device(0)`). **The cap rides the frozen graph unchanged** — an interface grants/revokes exactly like the OT-18 E1b-derive/E3-revoke file scopes (zero new Handle kind). **Two-layer kill-switch:** `interface-identity` off ≡ 7.5-C2 bit-for-bit (index semantics, ambient `get_device(0)`); cap-*gating* of net access is a second default-off sub-switch so identity/naming lands before access is ever gated. **No new cross-cutting invariant** (the registry lock is a leaf below the USB band — within OT-13's ceiling); I-14: (a)/(c) N/A-by-construction (no ISR, no DMA — metadata only), (b) inherited.

### CB-4 — P1: `d-survey` — the xHCI endpoint-reset primitive  *(owner: Cerebro; kernel-touching ⇒ QEMU + bare-metal)*
Cerebro's H1/H2 fix, grounded in Prometheus's Target-1 mine. Add a generic kernel **xHCI endpoint-reset** capability (`xhci.rs`): Reset-Endpoint TRB → Set-TR-Dequeue-Pointer → ring doorbell, plus a device **Clear-Feature(ENDPOINT_HALT)** for the STALL case (Cerebro H2; Prometheus **T-028/032** — upstream mt7601u has *zero* recovery), and adopt the **mt76 queued-response model** (Prometheus **T-033**) so unsolicited MCU events stop consuming expected responses (the root of the cumulative wedge, **T-029/030/031**). Wire `dump_halt_state` + the raw completion code + a post-recovery MCU probe (Cerebro's 3 captures) so the bare-metal run is conclusive per the discriminator truth-table. Enables a full 14-channel **survey** (discovering an AP on an unknown channel). **Fallback:** if H1 proves stubborn, the targeted-connect path (CB-1) is the standing fallback — the phase can close on association with `d-survey` tracked as a follow-on (see §2 ratification point R2).

### CB-5 — P1: WPA3/SAE on-air confirmation  *(owner: Cerebro; bare-metal)*
W0 shipped SAE crypto KAT'd against IWD vectors, but **on-air SAE association is code, not yet silicon-proven** (Janus + Cerebro both flagged). The bible promises "WPA2/**WPA3** client mode."
