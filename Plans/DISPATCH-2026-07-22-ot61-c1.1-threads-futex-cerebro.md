## Scope — P2 (thread) + P1 (futex)
1. **P2 thread lifecycle.** `thread_create(entry, arg, stack_size, guard) → tid|errno` (allocate the new thread's user stack from the caller's `Pmap` via C1.0's `vm_map(guard:true)`, `Thread::new_user`, `try_push_ready`); `thread_join(tid, *exit) `, `thread_detach`, `thread_exit(code)→!`, `sched_yield`, `thread_set_name`, `thread_self`. `sleep(dur)` = `futex_wait` on a dummy (no new syscall). **Per-process thread refcount** (today `thread_count:1` hardcoded, any reap drops the process) so the `Pmap`/`Process` drops only on the **last** thread's reap. Join/detach/exit-status via a per-thread done-word waited on P1.
2. **P2 amendment (Janus cross-check):** add **`thread_get_info(self-or-same-proc-tid, out) → {tid, usable_low, usable_len, guard_low, guard_len}`** with explicit downward-stack semantics, populated for the **initial** process thread too, validity through exit/reap. Reason: SpiderMonkey's `JS_SetNativeStackQuota` stack-limit path needs the running thread's own bounds (NOT a GC scan — that framing was wrong). The kernel `Thread` must **retain** user-stack bounds (it carries none today). Child entry is a **TLS-free bootstrap trampoline** (record bounds → [C1.2 TCB/key block placeholder] → per-thread `errno` cell → app start).
3. **P1 futex.** `futex_wait(uaddr, expected, deadline_monotonic_ns) → 0|-ETIMEDOUT|-EAGAIN` (`u64::MAX`=∞, `0`=already-expired — **ABSOLUTE monotonic deadline** off C1.0's clock, NOT relative; a relative timeout restarts on re-wait). `futex_wake(uaddr, count) → #woken` (**preserve the wake count** — Rust's rwlock uses it for writer→reader fallback). Kernel wait-queue keyed by the futex's **physical** address (`Pmap::translate` so aliased mappings share a queue); reuse `block_current_into_with_guard` + `wake_thread_token` (the named futex substrate). Build `std`'s mutex/condvar **and rwlock**, and pthread's mutex/cond, **in userland** on these two ops — no separate sync syscalls.

## Standing rules
- **Kill-switch (Rule-1):** all C1.1 syscalls behind the default-off `browser-runtime` feature; disabled ⇒ `ENOSYS`, default kernel **bit-for-bit** pre-C1.1 (cfg-structural, like C1.0).

- **No new cross-cutting invariant** (new syscalls/caps, not ledger invariants). **Cap-confinement:** thread/VM authority is the `browser-runtime` cap (NetDial pattern — no self-mint, fail-closed).

## Batteries (QEMU — the merge gate)
