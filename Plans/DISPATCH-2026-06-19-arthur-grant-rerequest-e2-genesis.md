## 0. The decision this build makes
Turn "I can't do that" (a dead stop) into "I can't do that — want to grant me [scope]?" (graceful, bounded re-request). E2 ships the **decision logic**: infer the minimal scope from a `Denied`, surface a scope-level request, handle the user's answer, remember a "no" for the session, and serialize an "always" grant into `grants.json` (which E1b's spawn-path re-derives next session). **The LIVE effect of "yes" (Arthur actually acquiring the cap mid-session) is the runtime counterpart of E1b and is DEFERRED — it needs I-15 (file caps) + the runtime-grant path; E2 produces the grant *intent/record*, not the live cap.** State this boundary; do not try to grant a live kernel cap here.

## 2. ISCs
- **ISC-1 — Scope inference from `Denied` (D4).** From `ActionError::Denied { required }`, infer the **minimal scope** that would satisfy the action: `RequiredCapability::File { path, rights }` → scope = **parent directory of `path`** + the same rights (e.g. denied read of `/home/user/cal/june.cal` → `FileRead /home/user/cal/`). **File scopes are the required case** (FileRead/FileWrite — the only scopes E1a maps to grants). Network/Process/Model/Memory inference is **deferred** (return "not inferable yet" / `None` — those scopes aren't grantable until later slices); do not invent them.
- **ISC-2 — The re-request surface (a structured `ScopeRequest`).** Produce a `ScopeRequest { scope, resource, rights }` the conversation layer can present ("I can't [action] — I'd need [scope]. Grant it?"). The *logic* is the deliverable; keep NL rendering thin/minimal. Offer three outcomes: **Session**, **Always**, **No**.
- **ISC-3 — Decision handling + remember-the-denial (D3).** **No** → record the scope in a per-session `denied_scopes` set; **do not re-request the same scope again this session** (the anti-nag property — host-test it: a second Denied on a remembered scope produces no `ScopeRequest`). **Always** → serialize the scope into `grants.json` (ISC-4) for durable persistence (takes effect at the next Arthur spawn via E1b's re-derivation). **Session** → record the scope in an in-memory session set (the in-process policy intent); **note in the code + RETURN that the live cap acquisition is deferred to the I-15/E1b runtime-grant path** — E2 records intent, it does not mint a live kernel cap.
- **ISC-4 — The `grants.json` writer + its independent byte oracle.** Add the serializer that appends a `GrantEntry` to the store and emits valid `grants.json` bytes. **Format rule (CLAUDE.md):** the writer's output for a known set MUST equal E1a's **hand-laid `ORACLE` fixture** byte-for-byte (assert writer-bytes == the hand-laid example — an independent oracle), AND round-trip through E1a's `parse_grants` (`write(entries)` → `parse` == entries). Both, not just the round-trip.
- **ISC-5 — Standards + kill-switch.** **Kill-switch (sub-feature, e.g. `arthur-grant-rerequest`, or extend `arthur-grants`) default-OFF ⇒ on `Denied`, Arthur stops with "I can't do that" — no escalation, no writer — ≡ E1a behavior** (ship the equality regression). No-alloc / no_std-clean where it lands in libneo. No new `unsafe`; **no new invariant** (it composes E1a + action.rs — state this; if you think you need one, STOP and flag, like the E1b STOP). SPDX. `fmt`/`clippy --workspace --all-targets -D warnings` via Docker. ADR-060 amendment (E2: the re-request + writer).
