## The hole (from the C1.1 AAG, Finding 2 "same window, containment hole")
Forced whole-process termination (`terminate` / `fault_kill_current_user` / `purge_pid`) retires **parked** threads (token scan) and **Ready** threads (`kill_thread_by_pid`), but a sibling that is **currently RUNNING on another CPU is invisible to both scans** — it is neither parked nor on a ready queue. So:
- **I-14 containment breach:** a whole-process *fault-kill* (the containment guarantee that a faulting subsystem is fully torn down) can leave a running sibling alive on a peer CPU — the process is "killed" but a thread of it keeps executing. That violates I-14(b): a subsystem fault must not leave governance-relevant execution running.
- It is the **same Ready→Running window** as the CP-36 UAF: a thread that becomes current between the kill scans is missed.

## The mechanism (3 parts — all new)
1. **Per-process kill flag.** An atomic `killing` flag on the process, set by `terminate`/`fault_kill` *before* the scans. Monotonic (set-once), so a thread that observes it never un-observes it.
2. **Check the flag at the two return boundaries.** At **syscall return** and **interrupt/exception return** to a user thread (and at **wake**, before a woken thread runs), the thread checks *its own process's* kill flag; if set, it **self-retires** (enters the zombie/reap path) instead of returning to user or running. This catches the running sibling at its next kernel↔user boundary — which, for a running thread, is imminent (the next syscall, the next timer tick).
3. **Retire-running-siblings IPI.** `terminate` sets the flag, then **sends an IPI to every CPU currently running a sibling** of the target process (identify via per-CPU `current` PID). The IPI forces that CPU into the interrupt-return path *now*, where step 2 fires — so retirement is bounded (one IPI + one tick worst case), not "whenever the sibling happens to syscall next." Reuse the reschedule-IPI plumbing (`send_reschedule_ipi`) or a dedicated vector — your call, justify it.
