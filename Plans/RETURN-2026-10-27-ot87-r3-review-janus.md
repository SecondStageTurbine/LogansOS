7. **Ledger and guard invariant — FAIL (blocking).** I-17 at `docs/complexity-governance.md:72` says a partition claim is valid only on space no partition table allocates. The current validator does not uphold that invariant for R3's new partition claim. `gpt_logic::validate` accepts `last_usable == last_lba` (`:149-153`), does not require `alternate_lba` to identify the other header (`:140-169`), and checks only the header's primary entry-array range (`:161-169`). `read()` uses a valid primary without checking agreement with the backup (`:220-225`). Concrete input: a 4 GiB, 512-byte-sector disk with a CRC-valid primary at LBA 1, `alternate_lba=L=8,388,607`, `first_usable=34`, `last_usable=L`, primary array at LBA 2, and a LogansOS entry spanning LBA 2,048..L with a sealed NEOFSv1 superblock at LBA 2,048 whose nonzero `total_blocks` fits. The primary array ends at LBA 34, so the current checks accept it. The partition then includes the backup array at LBA 8,388,575 and backup header at L. `judge()` computes allocated metadata and filters earlier whole-device claims (`write_guard_logic.rs:401-429,599-600`), but `judge_with_partitions()` appends `partition_claims()` afterward (`:503-508`), whose extent covers the partition (`:466-497`). `PartitionDevice::new` accepts end==device block_count (`partition.rs:40-46`), and `GuardedDevice::write_range_allowed` authorizes any request contained in an arming claim (`block/mod.rs:287-293`). A write to the partition's final sector is therefore accepted and overwrites the backup GPT header. Existing overlap tests keep the normal `last_usable` and only mutate entry LBAs (`partition_guard_tests.rs:152-179`), so they do not cover this CRC-resealed boundary case. This is an exposed current-path violation of I-17, not a future-writer concern. The consolidation keeps the ledger compact, but the I-17 guard/evidence claim is inaccurate until GPT validation/partition claims exclude backup metadata.
8. **Prior art — PASS.** PR #160 restates the rows used by R3 from THINK §11 with license and last-commit data (`gpt`, `gptman`, Redox, systemd-repart); none is vendored. Cargo metadata makes `gpt` a host dev-dependency only (item 2).
