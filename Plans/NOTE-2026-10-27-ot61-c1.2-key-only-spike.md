# NOTE: OT-61 C1.2 key-only spike (ratified amendment P3)

**Seat:** S4. **Dispatch:** `Plans/DISPATCH-2026-10-27-ot61-c1.2-tls-s4.md`. **Base:** `main` 0b39255b.
**Result: clean for the Rust `std` consumer.** `std` compiles and links key-only, and the final ELF carries no
native TLS. The SpiderMonkey side can't be built in this environment; what was and wasn't checked is below.

## What the spike changed (branch `claude/ot61-c1.2-tls`)

- `userland/x86_64-unknown-neoplutarch.json`: `"singlethread": false` (was `true`). `"has-thread-local": false`
  is unchanged.
- `apply-overlay.py`: neoplutarch is no longer added to `sys/thread_local/mod.rs`'s two `no_threads` lists. So
  std takes its `os` key-based mechanism (`thread_local/os.rs`) and the `guard/key.rs` cleanup. The `key` select
  gets a neoplutarch arm: std's `racy::LazyKey`, plus an overlay key module.
- `std/tls_key_neoplutarch.rs` → `sys/thread_local/key/neoplutarch.rs`: **spike-grade**. A process-global slot
  table (128 keys, key 0 reserved as std's sentinel), correct only while the process has one thread. C1.2 replaces
  it with the per-thread key block.

## Evidence (pinned toolchain nightly-2026-04-16, rustc 1.97.0 e8e4541ff)

Each ELF was checked with `readelf`/`objdump` for: a `PT_TLS` program header, `.tdata`/`.tbss` sections, `STT_TLS`
symbols, TLS relocations (TPOFF/DTPMOD/DTPOFF/TLSGD/TLSLD/GOTTPOFF) and `%fs:`-relative instructions.

| ELF | PT_TLS | .tdata/.tbss | TLS syms | TLS relocs | `%fs:` insns |
|---|---|---|---|---|---|
| `main` baseline: std-real-smoke (debug), `singlethread=true`, `no_threads` route | 0 | 0 | 0 | — | — |
| spike: std-real-smoke (debug), `singlethread=false`, OS-key route | 0 | 0 | 0 | 0 | 0 |
| spike: std-real-smoke (release) | 0 | 0 | 0 | — | 0 |
| spike: std-real-panic (release) | 0 | 0 | 0 | — | 0 |

| C side: the same program on a key table, no `__thread` | 0 | 0 | 0 | — | 0 |

**The route is really in use**, not vacuously clean:
- std's own thread-locals (output capture, spawn hooks, the thread-id cell) compile to
  `std::sys::thread_local::os::Value<…>` with heap `AlignedSystemBox` storage;
- `std::sys::thread_local::key::neoplutarch::VALUES` is linked;
- no `thread_local::no_threads` symbol remains.

**The leak-in links successfully.** A static link happily carries TLS that our PT_LOAD-only loader would never
instantiate, exactly as the RETURN warned for Mozilla's link-only probe. So the gate has to be a post-link scan of
the final ELF; a compile or link failure won't catch it.

## What this does not cover

- **SpiderMonkey: not built.** This environment has no mozjs tree and no C/C++ runtime or libc for the target,
  so I can't show that SpiderMonkey links key-only with `HAVE_THREAD_TLS_KEYWORD` forced off. What I can show:
  - the same post-link criteria catch a C `__thread` (the `HAVE_THREAD_TLS_KEYWORD` path), and pass a key-table
    equivalent;
  - the claim that Mozilla's keys fallback (`ThreadLocal.h:145-169,238-250`) is reachable with the keyword off
    rests on Janus's RETURN (Firefox ESR `f8025617`), not on a build here.

  The first build that can answer it is C3. The gate will fail that build if any TLS leaks in, which is the point
  of the gate.
- **std's sync primitives are still `no_threads`.** `Once`, `Mutex`, `Condvar` and `RwLock` stay on C0.5's
  single-threaded route (four `sync::once::no_threads` symbols in the release smoke), and `std::thread` is still
  `unsupported`. Key-only TLS is necessary but not sufficient for threaded `std`. Routing std's sync to C1.1's
  futex, and `std::thread` to `SYS_THREAD_CREATE`, is separate work, not in this dispatch's scope.
- **`singlethread=false` changes C0.5's code generation** (real atomics instead of single-thread lowering). The
  `std_real_smoke` QEMU scenario must still pass on the C1.2 branch before merge.

## Design points this surfaced for C1.2 (sent to the PM with the result)

1. **The per-thread locator meets the A4 gate.** Rule G3 allows `asm!` only inside the one `syscall3`
   trampoline per file. A key layer that finds its block through FS (`mov reg, fs:[0]`, the x86-64 TCB
   self-pointer convention) needs a second sanctioned asm site. The A4 discipline requires that to come as a
   gate-rule change with its own negative tests. `RDFSBASE` isn't an option: the kernel doesn't enable
   CR4.FSGSBASE, and the FS-base MSR is never written today (`context.rs:18`).
2. **One key implementation for both consumers.** `std` can't link `neo-std-pal`; C0.5 keeps a twin trampoline
   in the overlay. To avoid twin key layers, the key logic can be one dependency-free source file over a
   `*mut KeyBlock`, owned by `neo-std-pal` and copied into rust-src by `apply-overlay.py` (as the other overlay
   modules are), so std's keys and a future pthread layer share one table and one destructor driver.
3. **A4 manifest.** `SYS_THREAD_SET_TLS` joins `[gate].allowed_syscalls` with its provenance and a negative test
   in the same change.
4. **The battery doesn't need threaded `std`.** Isolation, the iterated destructors and FS.base across a switch
   or migration can run in a `no_std` test binary on the `neo-std-pal` key layer and raw C1.1 thread syscalls.

## Outcome: C1.2 built on the key-only route (branch `claude/ot61-c1.2-tls`)

The PM had the spike result before any TLS syscall existed. On the clean result, C1.2 went ahead without the
reserved `PT_TLS` rung.

- **Kernel** (all under `browser-runtime`):
  - `Thread.fs_base`, loaded into `IA32_FS_BASE` by both user switch-in prep paths through a per-CPU cache that
    starts at a non-canonical sentinel;
  - `SYS_THREAD_SET_TLS = 0x4F`, gated on the C1 capability (`EPERM`), `EFAULT` for a kernel-half base.
- **Userland:** `libneo::ntls`, following C1.1's precedent of userland layers in libneo (`nthread`, `nsync`):
  - keys with a generation check;
  - destructors that clear before the call, at most 4 passes;
  - the key block reached as `fs:[0]` and heap-allocated on first use.

  The `nthread` bootstrap and `init_main_thread_control_block` point FS.base at the control block, and
  `nthread::exit` runs the destructors before `SYS_THREAD_EXIT`.
- **The gate:** `tools/xtask/src/ot61_tls_gate.rs` scans every staged user ELF for PT_TLS, SHF_TLS, STT_TLS and
  TLS relocations.
- **Battery:** `threads_tls`, at `NEO_SMP=4`. Removing the switch-in load makes it fail (code 2003).
- **Kill-switch:** with `browser-runtime` off, the stripped kernel is byte-identical to `main` 0b39255b for the
  default, `desktop` and `usb-host` feature sets.
- **A defect the regression runs caught:** the first version embedded the 2 KiB key block in the control block
  at the stack base. Building it in the unoptimised bootstrap overran `threads_guard_fault`'s 8 KiB thread
  stack: the worker died at `rip=0` before its AC=1 overflow, and the kernel check `user_fault_ac_not_armed`
  fired. The block is now on the heap, and a const assert keeps the control block ≤ 64 bytes.
