## Scope — what Slice 3 IS (and defers)
**IS:** the **real r=8 Q16 separable-Gaussian blur kernel, hand-authored in OpenCL C**, compiled through the **proven ocloc/IGC path** (the Phase-6 Add/Matmul/GELU toolchain — NOT WGSL/Naga/Vello, which is the *deferred P2* per Prometheus's compiler-closure spike) to a **Gen9 EU binary + zeinfo ABI**, pinned in-tree, and wired so `ComputePipeline::SeparableBlur` dispatches it. **Provable now:** the artifact reproducibly compiles; the submit carries the real kernel's ABI (bindings/payload/SLM/barrier); accel-sim validates the SeparableBlur submit→fence with that ABI shape; the GPU-on output for the 8×8 oracle equals the Slice-1 CPU floor (kill-switch equality extended to the real kernel path where sim can check it).
**DEFERS (Slice 4, honestly label):** the **real Gen9 EU execution** — "the compiled kernel actually produces the blur bytes on silicon" — is the **UHD 630 / M710q bare-metal gate** (accel-intel is bare-metal-only; QEMU cannot run the EU). And the graphics **VT-d physical fence** stays **Slice 5**; Slice 3 remains kernel-internal (amendment 4).

## Load-bearing constraints (do not relax)
1. **Exact-bytes from the REAL tool (the byte-oracle acquisition rule — critical here).** The EU binary + zeinfo ABI MUST come from **actually running ocloc** on the M75q Linux Docker host and reading the **literal** output — **never** a WebFetch/LLM-summarized read (those mangle exact bytes → poison the oracle). Pin **reproducibly** in-tree: the exact `ocloc` command + flags + device target, the artifact, its disassembly, and the extracted ABI metadata (entry, payload/binding layout, SLM size, barrier/atomic requirements). A future rebuild must reproduce the same bytes.
2. **PRM-derived command-byte oracle (amendment 6).** The two-pass H→V coherence (`PIPE_CONTROL` flush + MOCS) needs a **PRM-sourced command-byte oracle** — the exact command DWORDs from the Intel Gen9 PRM (raw source, no WebFetch), asserted independently, so the coherence isn't just "it seemed to work." The H-pass diagnostic must not perturb the H→V hazard (amendment 6's non-perturbing split).
3. **Kill-switch ≡ CPU floor (Rule-1).** `GPU_COMPUTE_ENABLE` off ⇒ the Slice-1 CPU floor, bit-for-bit (unchanged). On ⇒ the real kernel; its 8×8-oracle output must equal `ORACLE_DST` (the same literal bytes Slice 1 + your independent Python + the PM recompute all agree on) — so the GPU path **cannot silently diverge** from the floor. Ship the equality regression on every path sim can reach.
4. **Kernel-internal only (amendment 4).** Still no `Handle::GpuCompute`, no syscall, no userland reach. The kernel dispatches the pinned kernel; userland wiring is Slice 6.
5. **I-14 + the Slice-2 AAG hardening (fold it in — the real path now exists).** The kernel's DMA buffers route via **per-context PPGTT** (Phase-6); no new userland DMA; the physical VT-d fence is Slice 5. **AND** discharge the Slice-2 carry-forward: on an **enabled GPU-wait timeout, degrade to the CPU floor** (don't error-out before the floor runs) — graceful I-14(b) for the real path. Optionally give `COMPUTE_IO_GATE` a lockdep order.
6. **Silicon-shape (Slice-4 setup).** The real kernel introduces the shape the cross-check named — 2-D `GPGPU_WALKER`, SIMD occupancy, SLM/barriers if the separable blur uses them (keep it linear-buffer + no-SLM if achievable, per Slice-1's design, to minimize new silicon risk). Enumerate exactly what **Slice 4** must prove on the UHD 630.
