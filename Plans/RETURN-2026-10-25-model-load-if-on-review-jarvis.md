The production helper delegates to `with_interrupts_enabled` (`kernel/src/arch/x86_64/syscall.rs:5802-5810`); its guard records the prior IF and restores it on return (`kernel/src/arch/x86_64/mod.rs:486-500`). 3. **PASS — preloaded models bypass both windows.** The boot-model prefix branch comes before the disk branch; a preloaded result immediately returns through shared-handle installation (or its stored error) at `kernel/src/arch/x86_64/syscall.rs:2501-2511`. `preloaded` clones the cached result/Arc (`kernel/src/boot_modules.rs:573-579`). A preload miss retains the old boot-module load fallback and still returns before either disk window (`kernel/src/arch/x86_64/syscall.rs:2513-2516`). Enabling the feature alone does not guarantee a cache hit; a successful cached model is handed out without reading or building it again.

4. **PASS — model_load is first; same contention weakness remains.** The junk model file is created before the directory handle, and `contend("model_load", ...)` precedes `contend("fsync", ...)` (`kernel/src/test_harness.rs:29266-29291`). The kernel-path helper invokes the same post-copy body (`kernel/src/arch/x86_64/syscall.rs:6171-6179`); the leg expects EINVAL after the invalid contents are read. With an actually held lock, the IF-off control reaches open's `entries` lock first, so a hang there witnesses model_load rather than a later leg (`kernel/src/arch/x86_64/syscall.rs:5807-5809`, `kernel/src/fs/neofs/inode.rs:153-155`). The NOTE reports that control hanging on four attempts; this review verifies its ordering and mechanism statically.

   **Known weakness, also present in this leg:** the scenario observes HELD before entering `without_interrupts(call)` (`kernel/src/test_harness.rs:29229-29236`) and only rejects `done < released` afterward (`kernel/src/test_harness.rs:29248-29255`). Concrete vacuous-pass sequence: the scenario reads HELD=true, is timer-preempted before disabling interrupts, the holder runs until its 20 ticks expire and releases `entries` (`kernel/src/fs/neofs/inode.rs:503-514`), then the scenario resumes and makes an uncontended model load. It returns EINVAL with `done >= released`, so the leg passes. Even the control can escape under that schedule. Ordering passes; guaranteed held-at-call-start does not, and remains the separately assigned relay #58 item 5 fix. Contention at open also does not independently witness contention during the later read; read coverage here is established by the closure boundary in item 1.

5. **PASS — remaining provenance path is unchanged, not worsened.** Query, infer and generate still validate before their compute windows (`kernel/src/arch/x86_64/syscall.rs:2669`, `kernel/src/arch/x86_64/syscall.rs:2993`, `kernel/src/arch/x86_64/syscall.rs:3711`). `Model::validate_current` delegates to file provenance (`kernel/src/ai/model.rs:293-296`), which calls the inode generation check (`kernel/src/fs/mod.rs:211-223`); a named NeoFS inode reaches `current_child_generation` and `resolve_path`'s `entries.lock()` (`kernel/src/fs/neofs/inode.rs:1186-1189`, `kernel/src/fs/neofs/inode.rs:174-176`, `kernel/src/fs/neofs/inode.rs:153-155`).
