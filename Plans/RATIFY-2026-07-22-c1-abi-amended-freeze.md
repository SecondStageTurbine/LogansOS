## Amended freeze — fold into the design doc BEFORE C1.1/C1.2 cut these syscalls

### P1 futex (CONVERGES — 2 freeze-notes)
1. **Absolute monotonic deadline, not relative.** `futex_wait` takes an **absolute** `CLOCK_MONOTONIC` deadline (the P4 clock's timebase), not a relative `timeout_ns`. Rationale: `pthread_cond_timedwait` is absolute; a relative timeout restarts on every spurious re-wait → lost-deadline bug. The userland condvar computes the deadline once; the kernel treats it as an instant. (`0`/sentinel = infinite stays.)
2. **RwLock is a third consumer, and it's covered.** The futex builds `std::sys::sync::rwlock::futex` and any SpiderMonkey rwlock in userland — no new kernel primitive. Freeze the convergence as futex → {mutex, condvar, **rwlock**}, all userland.

### P2 thread (DIVERGES — redo-forcing; add before C1.1)
- **Add a runtime stack-bounds query.** A thread must read its **own usable stack + guard bounds at runtime**, not merely receive a size at spawn. **Reason correction (Janus, raw source):** the cited seam is **stack-limit enforcement** (`JS_SetNativeStackQuota` via `NativeStack.cpp::GetNativeStackBaseImpl` → `pthread_getattr_np`/`pthread_attr_getstack`, fatal-asserted; stored in `JSContext::init`) + optional profiler registration — **not** the "conservative GC stack scan" the dispatch (and my first relay) claimed. The framing was wrong; the requirement is unchanged. Freeze `thread_get_info(self-or-same-proc-tid, out) -> {tid, usable_low, usable_len, guard_low, guard_len}` with explicit downward-stack semantics, **populated for the initial process thread too**, validity defined through exit/reap, bound to the private CRT's `pthread_getattr_np`/`pthread_attr_getstack`. The kernel must **retain** this metadata — `Thread` carries no user-stack bounds today (`thread.rs:87-125`) and `new_user` takes only `user_rsp` (`:309-315`). The child entry is a **TLS-free bootstrap trampoline**: record/query bounds → install the C1.2 TCB/key block + a per-thread `errno` cell → call the app start routine. Omitting the query forces a thread-ABI redo.

### P3 TLS (DIVERGES — the hardest target; decide before C1.2)
1. **Iterated destructor passes + generation-safe keys.** The userland key/destructor layer **clears each non-null slot BEFORE calling its destructor**, rescans keys when a callback re-establishes a value, and repeats up to `PTHREAD_DESTRUCTOR_ITERATIONS` (≥4 POSIX passes) — a single pass, or an "exactly-once" battery, cannot satisfy Rust `std` (its `guard/key.rs` cleanup re-arms its own key for a later round). Key delete/reuse needs a **generation check** so a stale destructor can't target a recycled key. Batteries: (a) a destructor that re-arms its key and runs in a later pass; (b) a Rust cleanup-order test; "exactly once" stays valid only for a destructor that does not repopulate. (C1.2 userland-layer; no kernel-ABI change.)
2. **Native-TLS decision — PM call: key-only-enforcement FIRST, `PT_TLS` a reserved rung.** Cerebro's "loader stays PT_LOAD-only, runtime-key TLS only" bet DIVERGES — Rust `std` uses `#[thread_local]` and SpiderMonkey `MOZ_THREAD_LOCAL` can lower to native `__thread` (compiler-emitted FS-relative access needing a `PT_TLS` image). Decision:
   - **Primary: structurally enforce key-only TLS.** A **build-time gate** (same shape as the A4 anti-compat-island scanner) that forces the runtime-`pthread_key` model both consumers support (Rust's non-`target_thread_local` heap/key path; SpiderMonkey's key-backed `MOZ_THREAD_LOCAL` fallback). **Concrete recipe (Janus, exact):** keep Rust `has-thread-local=false` **and** flip `singlethread=false`; replace the C0 overlay's forced `no_threads` route with a NeoPlutarch OS-key/PAL route; force Mozilla `HAVE_THREAD_TLS_KEYWORD` **off** (its configure defaults it *on* from a link-only `static __thread` probe that doesn't know our loader can't instantiate TLS — so a static link can silently carry TLS); and **reject any final ELF containing `PT_TLS` or `SHF_TLS`** (the artifact gate). Define the FS-based TCB/key-block locator **without** `__thread`, installed in the bootstrap trampoline before std/CRT/engine code. Native/dynamic TLS then defers cleanly to C2/C3. Note the live consumers that make this non-optional: `TlsContext` (`Runtime.cpp:58`) + `TlsGCContext` (`GC.cpp:291`) are native-`__thread` and initialized **before** `InitializeJit` — so no-JIT does *not* remove them.
   - **Reserved rung (the A1-JIT pattern): implement `PT_TLS`.** If a C1.2 spike proves a consumer genuinely **cannot** build key-only, `PT_TLS` (loader parses the TLS image, per-thread setup, fixed-offset FS.base) becomes a named, justified rung in the build that needs it — not a surprise. **C1.2 opens with that spike** (do both consumers compile+link clean under the key-only gate?) and reports before freezing the TLS model.

### P5 VM/W^X (CONVERGES — under enforced no-JIT)
- No ABI change. The "enforced" qualifier folds into the browser-runtime build: **no-JIT is structurally enforced** (SpiderMonkey interpreter-only; no baseline/Ion codegen path reaching `mprotect`-to-exec), consistent with the C1.0 W^X negative battery and the A1 reservation. This is a C3 build-config gate, named now so it isn't assumed.

## Net
Freeze = the five primitives, amended: P1 absolute-deadline + rwlock-covered; P2 + stack-bounds query; P3 iterated destructors + key-only-enforcement-first (PT_TLS reserved); P5 no-JIT structurally enforced. C1.0 ships on the unamended VM/clock subset now; C1.1 folds P1+P2; C1.2 opens with the P3 key-only spike.
