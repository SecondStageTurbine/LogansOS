**Status:** DISPATCHED. **The brain last-mile, slice 1 of 2.** bundled-model proved the boot→load→infer→reply `/model` pipeline **in QEMU with a *fixture* `.neom`** — ADR-063 is explicit it does **not** bundle the real Qwen2.5 brains. This slice produces a **real Qwen2.5 `.neom` on the host**: wire the *already-landed, host-tested* GGUF parse + BPE tokenizer logic into an end-to-end `neomc import` command, and lift the `.neom` file-size cap so a real model validates. **L2 (NeoFS large-file / indirect blocks — so the kernel can actually store+serve a ~500 MB file) is the separate next slice; L1 stops at "the real `.neom` is produced and host-validates."**

## 0. The decision this build makes
Turn "`neomc` has no GGUF importer; the real brain can't be made" (ADR-063 §Context) into "**`neomc import qwen2.5-0.5b.gguf -o model-qwen2.5-0.5b.neom` produces a real, validating `.neom` (weights + tokenizer vocab) for the Qwen2 forward graph the kernel already runs.**" This is mostly **integration of landed pieces**, not new parsing — `gguf_logic.rs`, `gguf_dequant_logic.rs`, `tokenizer_logic.rs` are on main and host-tested. The only new *kernel* touch is the validator cap constant.

## 2. ISCs
- **ISC-1 — `neomc import <model.gguf> -o <model.neom> [--arch qwen2]` (end-to-end, userspace).** Wire the **existing** `gguf_logic`/`gguf_dequant_logic` parse → the `NeomBuilder`/`writer` emit. **Reuse the landed pure-logic; do not re-implement the GGUF parser.** Resolve the crate-sharing mechanism so `neomc` (a `tools/` host crate) can call the `kernel::ai` pure-logic modules — **state the chosen mechanism** (e.g. a shared `no_std` logic crate the kernel and `neomc` both depend on, vs. a path-include, vs. promoting `gguf_logic`/`tokenizer_logic` out of `kernel/src/ai` into a `tools`-shared crate). Whatever you pick, the constraint is firm: **the kernel runtime model-load path stays `.neom`-only — GGUF never enters ring 0 at runtime** (gguf_logic is build/test tooling that happens to live in the kernel crate; ADR-055/063). Fail-closed on unsupported arch / quant / malformed GGUF (clear error, no panic).
- **ISC-2 — GGUF→`.neom` tensor mapping for the Qwen2 graph (the correctness crux).** The kernel forward graph is **Qwen2-hardcoded (OT-16)** — the imported `.neom` MUST carry the tensors `forward_logic.rs` reads, with the **names, shapes, dtypes, and quant-block layout** it expects. Map GGUF tensor names (`token_embd`, `blk.N.attn_{q,k,v,output}`, `blk.N.ffn_{gate,up,down}`, `blk.N.{attn,ffn}_norm`, `output_norm`, `output`) → the `.neom` `TensorSpec`s. **Quant-block fidelity is load-bearing:** the kernel matmul consumes `q4_K`/`q8_K` blocks bit-exactly (`qk_matmul.rs`/`q4_k.rs` have byte-oracles) — the importer must pass GGUF `Q4_K_M`/`Q8_0` tensor data through in **exactly** the block layout the kernel dequant expects (a wrong block layout = silent garbage inference, the worst failure mode). Verify against the kernel's existing q4_K/q8_K block oracle.
- **ISC-3 — Lift `NEOM_MAX_FILE_SIZE` (the one kernel touch).** Raise from `64 * 1024 * 1024` to a value that holds the real brains (Qwen2.5-0.5B-Q4_K_M = **491 MB**; 1.5B-Q4_K_M ≈ **1.1–1.3 GB**) — recommend **2 GiB** (`2 * 1024 * 1024 * 1024`) with headroom. Audit **all three sites**: the const (`model_logic.rs`), the validator checks (`validate_neom`, the `total > NEOM_MAX_FILE_SIZE` / `bytes.len() > NEOM_MAX_FILE_SIZE` guards), and the syscall guard (`syscall.rs:~1306`). **Overflow audit:** confirm no `usize`/`u64` truncation at 2 GiB (the header `total_size` is `u64`, `bytes.len()` is `usize` — fine on x86_64, but assert it). Verify the *other* `NEOM_MAX_*` budgets still fit a real model: **Qwen2.5-1.5B ≈ ~340 tensors ≪ `NEOM_MAX_TENSORS=4096`** (and nodes/IO) — confirm, don't assume. **Honest L1 boundary:** lifting the cap makes a real `.neom` *valid*; the kernel **actually loading 491 MB** (NeoFS storage + arena residency) is **L2** — L1 proves host-side production + validation, not a kernel large-model load.
- **ISC-4 — Tokenizer vocab/merges extraction (no real vocab ⇒ no real text).** Extract the tokenizer vocab + merges from the GGUF KV-metadata (`tokenizer.ggml.*`) and provision them so `tokenizer_logic.rs` can consume them (it "accepts raw-source vocab and merge slices"). **State the storage choice** — a `.neom` section vs. a sibling provisioned NeoFS file (e.g. `model-qwen2.5-0.5b.vocab`) — and wire the load path Arthur/`tokenizer_logic` reads. Qwen2.5 vocab is ~151 K tokens; ensure the chosen representation is bounded and the extraction is host-tested.
- **ISC-5 — Byte-oracle (independent, hand-laid — the format rule).** A **hand-laid minimal GGUF fixture** (magic `GGUF`, version, `tensor_count`, `metadata_kv_count`, one KV entry, one tensor-info entry, aligned tensor data) → the **expected `.neom` bytes/offsets** (computed by hand against ADR-028 §"Authoritative worked example"), asserted **independent of the writer+reader round-trip** (round-trip alone is insufficient — the ADR-028 BUILD-2/3 lesson). Plus the **quant-block-layout** assertion (ISC-2) against the kernel's q4_K oracle. **GGUF reference bytes raw-sourced** (ggml `gguf.md` / a real tiny GGUF's literal bytes) — **never WebFetch** (BUILD-W0).
- **ISC-6 — Standards + kill-switch.** SPDX on new files. `fmt`/`clippy --workspace --all-targets -D warnings` via Docker (kernel clippy blocking — there's a kernel-crate const touch). **Kill-switch framing (no new runtime behavior):** the default ISO build runs no `import` and stages no real model ⇒ Arthur is dummy-echo, **bit-for-bit today**; the cap widening **changes no existing model's validity** — the equality regression is *every existing `.neom` fixture validates identically before/after the cap lift*. No new invariant (a wider bound on an existing validated format). ADR-063 amendment (L1 done: importer + cap; L2 remaining: NeoFS large-file).

## 3. Gate
- **Host KATs:** the ISC-5 GGUF→`.neom` byte-oracle (hand-laid fixture → expected offsets) + the quant-block-layout match; the cap-lift **equality regression** (all existing fixtures validate identically; a just-over-old-cap synthetic validates now, a just-over-new-cap rejects); vocab extraction round-trip; `import` error paths (bad magic / unsupported arch / unsupported quant / truncated → clean error, no panic).
- **The real proof L1 can deliver (host):** `neomc import` on the **actual local Qwen2.5-0.5B-Q4_K_M GGUF (491 MB, on the PL's disk — out-of-band, NEVER committed)** → a `.neom` that **`validate_neom` accepts** + the tensor inventory matches the Qwen2 graph. Paste the inventory (tensor count, total bytes, dtypes) in the RETURN. *(This is the conclusive L1 evidence — a real brain in `.neom` form, validating.)*
- **4-shard QEMU `workflow_dispatch` gate** (required — the cap const + `syscall.rs` guard are kernel-touching): green, **no regression** of the existing model/`arthur_boots_thinking` scenarios under the higher cap. **Serialize behind the in-flight kernel gates (W2-cold-firmware, M2) — rebase LAST onto the then-current main.** The importer host-work proceeds in parallel with the funnel; only the cap-lift commit needs the QEMU slot.

## 4. Scope guard
The `neomc import` GGUF→`.neom` path + vocab extraction + the file-size-cap lift + the oracles **only**. **Do NOT** build **L2 (NeoFS large-file / indirect blocks)** — a produced 491 MB `.neom` host-validates but cannot yet be stored/served by NeoFS v1's 8-direct-block model reads; that's the separate next slice. **Do NOT** change the **in-kernel forward graph** (OT-16 frozen — the importer emits *for* the existing Qwen2 graph; if a real Qwen2.5 tensor doesn't map, surface it as an OT-16 finding, don't patch the kernel graph). **Do NOT** re-implement the GGUF parser or the BPE tokenizer (reuse `gguf_logic`/`gguf_dequant_logic`/`tokenizer_logic`). **Do NOT** commit any GGUF or `.neom` model blob to git (out-of-band, the bundled-model/firmware discipline). New `unsafe`: none expected (host tooling + a const). No new invariant.
