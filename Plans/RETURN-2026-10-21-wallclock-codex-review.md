# Cross-family review: wall-clock rung (OT-85)

Reviewed `claude/wallclock-rtc-atrium` at `191018a2a1195269790efd491f67b955fdedabbe`, against the dispatch and findings on that branch. Verdicts below are from source and KAT inspection; I did not rerun the gate.

## 1. RTC read protocol

- **1a PASS.** `kernel/src/arch/x86_64/rtc.rs:74-93` checks register A's UIP bit before collecting fields, with a 100,000-poll bound at lines 42 and 78-82; `None` propagates to `Read::Stuck` and the `uip-stuck` fallback at lines 136 and 141-142. The 100,000 limit is a finite but generous bound.
- **1b PASS.** `kernel/src/arch/x86_64/rtc_logic.rs:113-128` accepts only adjacent equal snapshots, retries to the supplied maximum (8 at `rtc_logic.rs:56`), and otherwise returns `Unstable`; the KATs at `tools/rtc-logic-tests/src/lib.rs:296-318` cover a changing pair and exhaustion. A snapshot begins only after UIP is clear (`rtc.rs:74-93`); the RTC's UIP indication also covers the 244-us pre-update window (`rtc_logic.rs:17-18`), longer than this short register-file read. If a snapshot did cross an update, the next snapshot sees UIP and waits for completion, so the adjacent-pair check rejects a changed image. This is not a latched hardware snapshot, but I found no concrete equal-and-wrong interleaving under the documented UIP behavior.
- **1c PASS.** `kernel/src/arch/x86_64/rtc_logic.rs:132-142,179-185` selects binary vs BCD from register B bit 2 and rejects either BCD nibble above 9; the bad-BCD KAT is in `tools/rtc-logic-tests/src/lib.rs:173-187`.
- **1d PASS.** `rtc_logic.rs:145-159` removes the hour's bit-7 PM flag before decoding in 12-hour mode and maps `h % 12 + PM`; it refuses hours outside 1..=12. `tools/rtc-logic-tests/src/lib.rs:158-171` covers both data modes, 12 AM, 12 PM, 0, and 13.
- **1e PASS.** `kernel/src/acpi/rtc_fadt_logic.rs:32-48` reads `CENTURY` at byte 108, suppresses it for hardware-reduced ACPI, and reads the bit-5 flag only for revision 2+; `rtc_fadt.rs:13-30` validates the table/checksum. `rtc_logic.rs:192-205` accepts only decoded centuries 19..=21, otherwise uses 20 (2000 + yy). FADT cases and the stale-century case are covered at `tools/rtc-logic-tests/src/lib.rs:207-217,345-420`.
- **1f PASS.** `rtc_logic.rs:179-221` checks VRT, seconds/minutes, year, month/day and Gregorian month length; `MAX_YEAR` is 2199 at line 53. The invalid-date and range KATs are at `tools/rtc-logic-tests/src/lib.rs:224-287`. With the max year and end-of-year seconds, ns remain below `i64::MAX`.
- **1g PASS.** `rtc.rs:60-69` masks index bit 7 and reads both ports inside `seed`'s `interrupts::without_interrupts` closure (`rtc.rs:135-140`). A source search of `kernel/src` found no other CMOS port access: only these RTC constants/usages and documentation (the `pic.rs` 0x70 mention is an IRQ vector range).

## 2. Days-from-civil correctness

- **2a PASS.** The kernel implementation is `kernel/src/arch/x86_64/rtc_logic.rs:227-238`. Hand-counted assertions for epoch, 2000-01-01, 2000-02-29, the 2100 non-leap transition, 2026-10-21, and 17:48 Unix seconds are at `tools/rtc-logic-tests/src/lib.rs:61-115`.
- **2b PASS.** `userland/libneo/src/civil.rs:59-83` implements the inverse and weekday rule; `civil.rs:178-203` maps hour 0/12 to 12 AM/PM. Its independent expected-value KATs cover epoch/Thursday/12:00 AM (`tools/rtc-logic-tests/src/lib.rs:435-459`), 2000 and 2100 leap boundaries (`:485-502`), the pinned Wednesday 5:48 PM (`:461-483`), and 12-hour edges (`:527-542`).
- **2c PASS, with bounded assurance.** The exhaustive day loop and date-by-date inverse check are at `tools/rtc-logic-tests/src/lib.rs:553-575`. The hand-computed epoch, leap-century and pinned-date anchors break a shared offset/leap-rule error; `tools/xtask/src/main.rs:13940` independently walks years/months for values emitted by the runtime scenario. That oracle independently validates logged values, not every day in the exhaustive loop, so its scope is a useful anchor plus implementation round-trip rather than an independent full-range proof.

## 3. The fallback

- **3a PASS.** `kernel/src/arch/x86_64/rtc.rs:114-116` stores `FALLBACK` and emits one named line. Every error arm in `seed` (`rtc.rs:127-152`) returns through that function; successful publication is the only path to `SEEDED` (`:154-155`). A failed FADT-presence check is handled at `:130-134`, stuck/unstable at `:136-142`, and decode failures at `:143-152`. The base starts at zero (`:31`) and is not written on a failure. None of these paths panics or waits without a bound.
- **3b PASS.** The forced hook constructs all raw fields as `0xFF` (and the century field when present) at `kernel/src/arch/x86_64/rtc.rs:96-111`; `seed` still calls the real `decode` at `:143-152`, which rejects the binary 255 hour as out of range (`rtc_logic.rs:145-153`). The fallback scenario checks one expected fallback line, boot-relative realtime, and completion in `tools/xtask/src/main.rs:12134-12156`; its kernel harness reports the same outcome at `kernel/src/test_harness.rs:2032-2048`.
- **3c PASS.** `userland/neo-init/src/desktop_session.rs:5116-5144` shows a clock only when sampled realtime differs from monotonic; fallback makes them equal. Otherwise `intro_rows` falls through to the old `intro_lines` at `desktop_session.rs:3511-3522`, preserving “Good day.”

## 4. Monotonic isolation

- **4a PASS.** `kernel/src/arch/x86_64/syscall.rs:6278-6288` reads `TICKS` to form monotonic for both IDs, then reads the RTC base only inside the `CLOCK_REALTIME` branch. `CLOCK_MONOTONIC` returns the tick-derived value.
- **4b PASS.** The one-time claim is `rtc.rs:122-128`; the base is stored before the Release publication at `:154-155`; the query Acquire-loads `STATE` before loading the base at `:50-53`. Source search found no other writes to either static.
- **4c PASS.** RTC and ACPI compilation/use are gated by `rtc-epoch` (`kernel/src/arch/x86_64/mod.rs:34-38`, `kernel/src/main.rs:664-670`, `kernel/Cargo.toml:272-275`). Without that feature the syscall has no base branch (`syscall.rs:6285-6288`) and boot does not call `seed`, so FADT and CMOS are untouched. The off-feature path returns monotonic as realtime.
- **4d PASS.** `rtc.rs:50-69,122-155` uses atomics and bounded port reads; `seed` disables interrupts but takes no governance lock. The new RTC module has no lock acquisition.

## 5. Persona lines

- **5a PASS.** The new greeting/name and formatter are at `userland/neo-atrium/src/clock.rs:23-50` and `intro.rs:22-30`. `neo-atrium/src/tests.rs:2448-2515` checks printable ASCII, no `!`, row length bounds, card fit at two resolutions and clock text fit; its samples include the longest date/time. New clock rows stay within the existing 80-byte bound, and the prior B1b exception stays at 100 bytes. The clock-specific KAT does not relax those bounds.
- **5b PASS.** `clock.rs:23-36` implements morning 05–11, afternoon 12–17, evening otherwise; the 24-hour expected table is `neo-atrium/src/tests.rs:2406-2445`. The persona KAT at `:2490-2512` requires exactly one time-of-day word in row 1 and checks it against the hour.
- **5c PASS.** `intro_lines_now` replaces row 1 and inserts the separate name row while retaining the remaining rows (`userland/neo-atrium/src/intro.rs:133-145`). The clock-less branch still calls the original `intro_lines` (`neo-init/src/desktop_session.rs:3511-3522`), and the unchanged “Good day” fixture/KAT is retained (dispatch reference: `desktop_intro_boot`; source fixture and comparison are unchanged in this diff).

## 6. Minute refresh and wakeups

- **6a PASS.** `userland/neo-init/src/desktop_session.rs:5090-5098` sets the deadline to `mono + 60s - realtime % 60s`; an exact boundary has remainder zero and schedules the next boundary 60 seconds later. Home passes that deadline to park at `desktop_session.rs:3036-3045`; when no readout is seeded, `deadline()` returns `u64::MAX` (`:5036-5041`).
- **6b PASS.** `clock::tick` returns before sampling until the deadline, resets the deadline on sample, and does no drawing if the minute is unchanged (`desktop_session.rs:5162-5178`). On a changed minute it repaints/presents only `layout.clock_slot()` (`:5180-5183`); `intro::refresh_clock` acts only for `Card::Intro` and presents its card slot (`:3525-3534`).
- **6c PASS, with an operational caveat.** No clock thread or timer is introduced; the parked build uses the existing wait with the minute deadline (`desktop_session.rs:3036-3047`). The current non-park product already spins at `:3047-3048`; in that build `tick` adds one monotonic syscall/read per idle turn and realtime reads only after the deadline (`:5162-5175`). Thus it adds no separate busy-wait loop or wake source, but the wall-clock deadline is polled once per turn while that existing loop spins. The findings document this distinction at `docs/RESEARCH-2026-10-21-wallclock-FINDINGS.md:182-184`.
- **6d PASS (coverage note, not a failure).** The findings explicitly state no gate crosses a live minute boundary (`docs/RESEARCH-2026-10-21-wallclock-FINDINGS.md:178-181`); the repaint equivalence is host-KAT'd at `userland/neo-atrium/src/tests.rs:2625-2650`. I would not block this rung on a live-boundary scenario because the due-time logic, repaint box, and intro-card gate are directly inspectable and host-covered, and the product WM currently spins. I would add a deterministic guest-time boundary scenario before treating the parked one-wake-per-minute behavior as gate-proven.
