# Relays 297-299: reviews of the browser stack re-landed on main (#65, #66, #67)

Same rules as `Plans/DISPATCH-2026-11-01-m910q-reviews-and-l2b.md`: a plain checklist, PASS or FAIL with the
enforcing `file:line`, a concrete input for any FAIL, the head SHA you reviewed. `git fetch origin +pull/<N>/head:pr<N>
&& git diff origin/main...pr<N>`. Seat D re-stacked these onto main after #2 (C3a, the C/C++ runtime) landed; the
PR bodies say what changed from the private originals.

Every review also checks one item: the prior-art section the build needs (the vendoring survey with licences and
commit dates, or the CP table) is present and its claims hold.

## Section 297: Janus, #65 (C3c-1 prerequisites: `arc4random_buf` in neo-crt, smoke check 19)
**MODEL** GPT-6-Luna, **EFFORT** high: contained userland, no SMP core, no new syscall. Head `30a3f3e8`.
1. `arc4random_buf` fills the whole buffer through std's `DefaultRandomSource`, for lengths 0, 1, and above the
   kernel's 64 KiB per-call ceiling; it adds no raw syscall site.
2. Check 19's oracle can fail: two fills that matched, or an unfilled tail, make it fail.
3. The 256 KiB `posix_memalign(4096)` block is aligned and writable to its last byte; the alignment contract for
   other powers of two holds.
4. The scenario runs with `kernel-rng` on `-cpu max` (the RDRAND hermeticity rule), and the default build is unchanged.
RETURN: `Plans/RETURN-2026-11-03-pr65-review-janus.md`, branch `codex/pr65-review-janus`.

## Section 298: Jarvis, #66 (rung 4 S1: upstream SWGL over neo-crt, into a caller-owned buffer)
**MODEL** GPT-6-Luna, **EFFORT** high: one contained subsystem (vendored C++ rasteriser and its build), no kernel core. Head `81c291ca`.
1. `third_party/ot61-swgl/VENDORED.md` names the upstream URL, commit, licence (MPL-2.0) and the local changes; the
   licence files are present.
2. The raster target is the caller's buffer: SWGL never writes outside it (width, height, stride bounds), and a
   zero-sized or misaligned buffer is refused.
3. The serial oracle compares real pixels (a known pattern), not only "it returned".
4. The default build includes none of this; `swgl_cc_env` pins the toolchain the way `crt-build` does.
RETURN: `Plans/RETURN-2026-11-03-pr66-review-jarvis.md`, branch `codex/pr66-review-jarvis`.

## Section 299: Chad, #67 (C3b: POSIX threads in neo-crt; libc++ rebuilt with threads)
**MODEL** GPT-6.1-Sol, **EFFORT** high: new threading primitives over std's futex-backed locks (concurrency).
Head `abbd20b4`.
1. Mutex kinds: a recursive mutex counts correctly, an error-checking mutex refuses a relock and an unlock by a
   non-owner, and a destroyed-while-locked mutex is refused or documented.
2. Condvars wait on `CLOCK_MONOTONIC`; a timed wait with a past deadline returns `ETIMEDOUT` without a lost wakeup;
   spurious wakeups are handled by callers' loops only.
3. Thread-specific keys run destructors at thread exit, repeat up to `PTHREAD_DESTRUCTOR_ITERATIONS`, and a key
   deleted while threads hold values is safe.
4. `pthread_once` runs exactly once under a race; `pthread_join` and `detach` can't leak or double-free the thread.
5. libc++ built with `_LIBCPP_HAS_THREAD_API_PTHREAD` matches what neo-crt provides (no missing or mismatched symbol).
6. The CP table (THINK §9, CP-106) is present and holds.
RETURN: `Plans/RETURN-2026-11-03-pr67-review-chad.md`, branch `codex/pr67-review-chad`.
