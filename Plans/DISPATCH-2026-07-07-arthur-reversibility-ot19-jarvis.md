## ISCs (the four ratified slices — §10.1; land them as sub-commits, each independently kill-switchable)
- **ISC-R1 — Undo dir + copy-before-write for `WriteFile`.** Arthur reads the target, writes the backup to `.arthur/undo/<category>/<path-hash>/prewrite.bin`, then performs the write. Undo window = one Arthur session. **Reuse OT-17's ChaCha20-Poly1305** for the backup at rest (risk-register R1: a corrupt/forged backup must be detectable — AEAD-authenticate it; auth-fail on restore ⇒ honest "undo artifact corrupt", never a silent wrong-restore).
- **ISC-R2 — Tombstone + undo restore.** Delete-equivalent actions move the original to `.arthur/undo/` instead of unlinking; "undo last write" restores from the backup. LRU prune at startup; max-storage config (default 10 MB).
- **ISC-R3 — Stakes policy + disagreement surface.** `.arthur/stakes.json` (user-declared high-stakes paths/patterns) — **Arthur applies it mechanically, NEVER judges stakes itself** (the OT-18-L3 trap; D3). Irreversible + high-stakes ⇒ surface consequence once + require confirm. The informational disagreement surface (D4): one line, grounded in OT-17 memory ("because you told me this project has two months of work"), then proceed — **no double-prompt with OT-18** (missing cap → can't act; disagreement → can act but thinks it's wrong; they never stack). All strings in the **OT-46 butler register** (`docs/VISION-arthur-persona.md` — ex. the "very good, and I've made it undoable" line IS OT-19 wearing its face).
- **ISC-R4 — Fail-safe degradation (D6).** Can't-reverse ⇒ **confirm-before-destructive**, never silent-proceed-without-undo: undo storage full → prune LRU then confirm; backup write fails (ENOSPC/EIO) → confirm; read-before-write fails (file vanished) → confirm; undo dir missing → create, else confirm.
- **ISC-KILL — Kill-switch** (`arthur-reversibility`, default **off**). Off ≡ today bit-for-bit: no `.arthur/undo/`, no new destructive capability, stakes policy still honored, **never less safe than today** (the switch removes undo; it never adds authority). Prove the equality (unit-test where expressible).

## The safety boundary to state explicitly (don't over-claim — risk register §11)
The undo mechanism protects against Arthur being **wrong**, NOT against Arthur being **malicious**: a compromised Arthur holds the same `.arthur/` cap and could delete backups or write directly, bypassing undo entirely. Malicious Arthur is bounded by **caps (OT-18 D5 revocation)**, not by this mechanism. Reversibility is a best-effort safety net, not a security boundary — say so in the RETURN, don't imply otherwise.

## Boundaries (D5 — don't cross)
- **NetSend / irreversible-external is NOT made reversible** — you can't un-send a leak; that's OT-18's host:port restriction, out of scope.
- **OT-17 memory forget preserved:** undo backs up `.mem` *ciphertext* under OT-17's per-category key, but **NEVER backs up `.key` files** — key-burn must still crypto-erase the backup too (the forget guarantee is inviolable). `KillProcess` is irreversible → falls to the stakes-policy row.
