**Status:** DISPATCHED. **The headline AI-native capability: stop memorizing commands — *tell* the OS what you want and Arthur safely does it.** "go to the temp folder," "find my notes about the OptiPlex," "save this" — instead of `cd`/`ls`/`cat`. The substrate is largely built (the typed action surface + capability enforcement + grants + file-caps); this designs the **untrusted-model → structured-action → kernel-cap-checked-execution** loop, *honestly accounting for the fact that a 0.5B/1.5B model is fallible.* The deterministic `neo>` commands remain the fast floor; this is the natural-language ceiling.

## 0. The decision this build (eventually) makes
Turn Arthur from a **chatbot** into an **agent that operates the OS under capability control**: natural language → a structured `Action` (from the existing `action.rs` vocabulary) → `execute_action()`'s kernel cap-check → result, reported back in natural language. The design must make this **safe even when the model is wrong** (small-model tool-use is unreliable) — *that* is the load-bearing problem, not the happy path. This THINK produces the ratifiable D-block; the build follows in slices.

## 2. The design to resolve (D-block, ratifiable)
- **D1 — Intent→Action mechanism (THE crux — small-model reliability).** A 0.5B/1.5B model is *weak* at free-form tool-use: it malforms JSON, invents fields, hallucinates actions. Options: (A) free-text → regex/heuristic parse (brittle, fails silently); (B) few-shot "emit JSON" (small models malform it often); (C) **constrained / grammar-guided decoding** — force the model's output to conform to a formal grammar over the `ActionKind` set (the model *literally cannot* emit an invalid action; llama.cpp's GBNF / logit-masking is the precedent). **Recommend C** — it converts "the model might emit garbage" into "the model can only emit a valid action (or the explicit `clarify`/`no-op` token)." State the grammar's shape (the action schema), how it maps to `action.rs`, and the decoding-integration cost against the 8.5 engine. This is the difference between a demo that wows and one that frustrates.
- **D2 — Action vocabulary + graduation by reversibility×stakes.** Which `ActionKind`s are in scope, and how each is gated — graduated per OT-18 D5 / OT-19: **read/navigate (ListDir, ReadFile, "cd", status) → execute directly** (low stakes, reversible-by-nature); **mutating (WriteFile, delete, SpawnProcess) → confirm and/or execute-with-undo** (OT-19 snapshot/tombstone); **irreversible-external (NetSend) → restriction** (OT-18 D5 — not made "reversible," scoped by host:port + confirm). The first build slice is the read/nav tier only.
- **D3 — The safety model (state it crisply — it's why this is allowed at all).** **The NL layer is UNTRUSTED; the kernel capability check is the boundary.** A misinterpreted or adversarial "delete everything" still produces an `Action` that `execute_action()` denies if Arthur lacks the cap (29.3 + OT-18 grants + I-15). The model's fallibility is *contained* by the cap-check, *softened* by confirm/undo (OT-19), and *bounded* by least-privilege grants (OT-18 D7). "Safe to be wrong" is the explicit property — design to it, prove the failure modes degrade safely (wrong action → denied or confirmed-away or undoable, never silent damage).
- **D4 — Confirmation + clarification (the human-in-the-loop).** Low model-confidence or ambiguous intent → **Arthur asks** ("did you mean /home/tmp or /var/tmp?") rather than guessing; consequential actions → **show the interpreted action + confirm** before executing ("I'll write 4KB to /notes/x.md — ok?"). Specify the confidence signal (constrained-decode probability? an explicit `clarify` grammar branch?) and the confirm UX in the conversation loop.
- **D5 — Coexistence + latency honesty.** Every NL operation is a **full LLM forward pass** (slow on CPU). So NL is for *intent* ("organize my notes," "find the file about X"), not hot-loop ops; the typed `neo>` commands stay the deterministic, instant floor. Both modes coexist (`arthur>` = talk-to-operate, `neo>` = type-to-operate). Do not design NL as a *replacement* for commands — as the *companion* layer.
- **D6 — Kill-switch + the slice plan.** Agentic mode feature-gated **default-off ⇒ Arthur is chat-only, ≡ today bit-for-bit**. Slices: **A1** = read/nav agentic (NL → ListDir/ReadFile/cd/status → cap-check → NL result; constrained decode; clarify-don't-guess) — the provable safe loop; **A2** = mutating actions with OT-19 confirm/undo; **A3** = multi-step intents / short action sequences. A1 is the first build and depends only on what's landed (action surface + I-15 + E1a grants); A2 depends on OT-19's reversibility build.
