# RETURN (relay #58): VFS syscall IF-on review (#121)

**Reviewed SHA:** `a790c1f41fecc42cf1a6a7fba0ecbb645496d41e` (base `1a094c1d`)
**RAG:** healthy (`ollama=true`, `qdrant=true`). **Build:** not run, per dispatch. The dispatch reports the merge gate at 23/23.

## Checklist

1. **PASS — interrupt-on window.** `vfs_body_if_on` delegates only its closure to `with_interrupts_enabled` (`kernel/src/arch/x86_64/syscall.rs:5793-5802`), whose restore guard returns to the caller's prior IF even when the closure returns an error (`kernel/src/arch/x86_64/mod.rs:472-500`). Open copies the path before the window and installs the file capability after it (`kernel/src/arch/x86_64/syscall.rs:5729-5779`). Readdir copies the cursor before the window and writes the record/cursor to user memory afterward (`kernel/src/arch/x86_64/syscall.rs:5886-5916`). Fsync and ftruncate do their file lookup before the window and map the VFS result afterward (`kernel/src/arch/x86_64/syscall.rs:6108-6126`). The same closure boundary serves the kernel-buffer readdir and test open helpers (`kernel/src/arch/x86_64/syscall.rs:6162-6200`).

2. **PASS — no lock crosses the IF switch.** `file_lookup` clones an `Arc<OpenFile>` inside `without_interrupts`; its handle-table guard ends before it returns (`kernel/src/arch/x86_64/syscall.rs:6208-6225`). Open carries a process `Arc` and copied path into `open_path_and_install`, with no guard in its frame (`kernel/src/arch/x86_64/syscall.rs:5736-5759`). The fsync, readdir, and ftruncate closures similarly capture only the returned file `Arc` and values (`kernel/src/arch/x86_64/syscall.rs:5902`, `kernel/src/arch/x86_64/syscall.rs:6110-6123`). No ISR lock is held when these calls enable IF.

3. **PASS — MOUNTS in the new open window.** `open_root_temporary` reaches `MOUNTS` through `normalized_targets_root_child_mount` for create and `resolve_path_to_inode` for resolution (`kernel/src/fs/mod.rs:1105-1143`). Both sections run inside `without_interrupts`; the resolve section copies the filesystem `Arc`, ID, live counter, and rights, then drops the guard before calling `fs.create_regular` or `fs.lookup` (`kernel/src/fs/mod.rs:657-699`). I found no further `MOUNTS` acquisition in this open body. Mount, umount, and provenance callers still use their caller's IF (`kernel/src/fs/mod.rs:211-223`, `kernel/src/fs/mod.rs:965-985`), so these two short sections must remain IF-off.

4. **FAIL — `entries` still has IF=0 syscall takers.** The disk-file branch of `sys_model_load_impl` calls `fs::open_root_temporary` and `read_model_file` without an IF-on wrapper (`kernel/src/arch/x86_64/syscall.rs:2513-2529`). NeoFS lookup reaches `NeoFsState::resolve_path`, which acquires `entries` (`kernel/src/fs/neofs/mount.rs:82-99`, `kernel/src/fs/neofs/inode.rs:153-171`). An already loaded, disk-backed model has another route: `SYS_MODEL_QUERY` calls `model.validate_current` at syscall IF=0 (`kernel/src/arch/x86_64/syscall.rs:989-991`, `kernel/src/arch/x86_64/syscall.rs:2648-2664`); provenance validation calls the inode's `current_generation`, which reaches `current_child_generation` and the same `entries` lock (`kernel/src/ai/model.rs:293-296`, `kernel/src/fs/mod.rs:211-223`, `kernel/src/fs/neofs/inode.rs:1149-1153`, `kernel/src/fs/neofs/inode.rs:174-176`). The infer/generate entry paths also call `model.validate_current` before their compute window (`kernel/src/arch/x86_64/syscall.rs:2980-2985`, `kernel/src/arch/x86_64/syscall.rs:3698-3704`). **Concrete sequence:** CPU 0 preempts a `sys_write` holder of `entries` at IF=1; CPU 0 next enters `SYS_MODEL_QUERY` for a NeoFS-backed model at IF=0, reaches `entries.lock()` through provenance, and spins so the holder cannot run. The new four syscall windows do not close that path.

5. **FAIL — the scenario can pass without contending on `entries`.** The holder is spawned onto the current CPU's ready queue (`kernel/src/sched/kthread.rs:272-275`, `kernel/src/sched/scheduler.rs:697-728`) and sets `HELD` after taking `entries` (`kernel/src/fs/neofs/inode.rs:496-514`). The four positive legs call the intended syscall bodies (`kernel/src/test_harness.rs:29261-29293`), and the control bypasses `with_interrupts_enabled` (`kernel/src/arch/x86_64/syscall.rs:5793-5802`). However, the only contention assertion is `done < released`; it never establishes that the holder was still holding the lock when the call began (`kernel/src/test_harness.rs:29220-29249`). **Concrete sequence:** on CPU 0, the scenario reads `HELD=true`, then is timer-preempted before `without_interrupts(call)`; the holder yields until its 20 ticks expire and releases `entries`; the scenario resumes, makes an uncontended call, and passes because `done >= released`. The NOTE's local timings show actual contention in its observed fix run, and its control hung at the first leg, but this race leaves a vacuous green run possible. The control feature is defined in `kernel/Cargo.toml:1222-1228` and is not a separate gate scenario (`tools/xtask/src/main.rs:4589-4600`).

6. **FAIL — the NOTE's open-items description is partly wrong and incomplete.** The disk-backed `sys_model_load` IF=0 read is real (`kernel/src/arch/x86_64/syscall.rs:2513-2529`). `sys_tensor_write_impl` only copies user bytes and writes a tensor through the arena; it does not read a VFS file (`kernel/src/arch/x86_64/syscall.rs:2051-2110`). Umount can drop the last NeoFS mount under `MOUNTS`: `remove_child` removes and drops the entry while the guard is held, and `NeoFsState::drop` stops and joins its writeback worker (`kernel/src/fs/mod.rs:590-599`, `kernel/src/fs/mod.rs:977-985`, `kernel/src/fs/neofs/inode.rs:1066-1069`, `kernel/src/fs/neofs/cache.rs:439-454`). **Concrete sequence:** CPU 0 parks while joining that worker with `MOUNTS` held; a different thread on CPU 0 enters open at IF=0 and spins on `MOUNTS` while the umounter cannot resume. The proposed `add_child` error-path concern is overstated for NeoFS: `vfs_mount_at_parent` retains `_neofs_typed` across the guard, so an `AlreadyExists` drop of `fs` under the guard is not the last NeoFS reference (`kernel/src/fs/mod.rs:565-575`, `kernel/src/fs/mod.rs:917-935`, `kernel/src/fs/mod.rs:965-974`). A further last-reference drop path is `install_root_child` replacing `entries[idx].fs` under `MOUNTS` (`kernel/src/fs/mod.rs:533-549`). The test-only `neofs_typed` replacement/clear is another such site (`kernel/src/fs/mod.rs:751-755`, `kernel/src/fs/mod.rs:979-984`). Model query's provenance-to-`entries` path in item 4 is another CP-37 shape omitted from the reviewed NOTE. A later main commit, `b12df62a`, addresses displaced filesystem drops; these findings assess the requested `a790c1f4` snapshot.

## Overall verdict

**FAIL at the reviewed SHA.** The four added IF-on windows and their `MOUNTS` sections pass items 1-3. Item 4 leaves a reachable same-CPU IF=0 spin through disk-backed model operations. Item 5's gate can pass without contention. Item 6's NOTE incorrectly includes tensor write and misses other reachable paths. No build was run, as instructed.
