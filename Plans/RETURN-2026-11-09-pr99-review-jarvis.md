## Findings

1. **PASS — Spanish (Spain, ISO) table against raw sources.** The independent hand-laid KAT covers 50 keys and checks plain, Shift, Caps, Caps+Shift, AltGr, AltGr+Caps, AltGr+Shift, both Shift keys, left Alt, and Num Lock states: `tools/xtask/src/keymap_layout_tests.rs:45-115`. The production Spanish base/Shift table and AltGr table are at `kernel/src/drivers/keymap_layout_logic.rs:69-109`. Spot checks against CLDR's raw `keyboards/windows/es-t-k0-windows.xml` included `ñ/Ñ` (C10), `ç/Ç` (C12), AltGr `@`, `€`, `[` and `{`, plus the grave/circumflex and acute/diaeresis positions. CLDR's levels agree with the KAT; the PR documents its deliberate AltGr+4 plain-tilde and AltGr+5 euro choices in the PR body. Raw references: [CLDR release-43 Spanish keyboard XML](https://github.com/unicode-org/cldr/blob/release-43/keyboards/windows/es-t-k0-windows.xml), [xkeyboard-config 2.41 Spanish symbols](https://gitlab.freedesktop.org/xkeyboard-config/xkeyboard-config/-/blob/xkeyboard-config-2.41/symbols/es).

2. **PASS — dead-key composition and fallback.** The composition table contains the acute and diaeresis vowel cases at `kernel/src/drivers/keymap_layout_logic.rs:111-155`; `Composer::feed` composes, emits spacing accent plus a non-composing character, emits two accents for a following dead key, and emits the accent for Space at `:310-326`. The host KAT checks acute + `a`, acute + `n`, acute + Space, diaeresis + `u`, and two successive dead keys at `tools/xtask/src/keymap_layout_tests.rs:181-210`. A repeated same dead key takes the same `Typed::Dead` branch as the tested pair at production line 320.

3. **PASS — US decoder equivalence.** `us_by_id_is_the_us_table_for_every_key_modifier_and_lock` compares `typed_in` and `ascii_in` for every usage, modifier byte, and lock state against `printable`: `tools/xtask/src/keymap_layout_tests.rs:235-254`. The WM's enabled-layout decoder is also compared with the existing decoder for every usage, modifier byte, lock state, and press/release at `userland/neo-atrium/src/keys_layout_tests.rs:12-29`.

4. **PASS — ASCII-only Home and Arthur input.** `ascii_in` filters non-ASCII output before it reaches the ASCII decoders: `kernel/src/drivers/keymap_layout_logic.rs:246-259`; the WM returns no character when that decoder has no ASCII byte (`userland/neo-atrium/src/keys.rs:96-113`). Arthur uses the same ASCII-only layout decoder at `userland/neo-arthur/src/showcase_logic.rs:141-153`. The `setup_menu_keys` script sends the ñ key in both Home and Arthur, checks the following Shift+2 character, and requires Arthur's session to finish with exit 0: `tools/xtask/src/main.rs:1580-1592,21631-21668`. The forbidden US-semicolon log is explicitly absent for both paths at `:21651-21657`.

5. **PASS — settings, create reply, and restart path.** The setup writes the chosen keyboard layout under `Key::KeyboardLayout` (key 7) at `userland/neo-init/src/desktop_session/setup.rs:152-167`; keys 6 and 7 are packed/unpacked in the settings representation at `userland/neo-init/src/desktop_session/settings.rs:115-143`. Loading a persisted settings record restores it through `store` at `:303-318`, and `store` applies the keyboard layout to the WM decoder at `:183-191`. The WM places the session layout in Arthur's create reply at `userland/neo-init/src/desktop_session.rs:1632-1657`; Arthur decodes and installs it at `userland/neo-arthur/src/showcase_surface.rs:89-97`. The protocol's reserved word encoding/decoding is at `userland/libneo/src/atrium_protocol.rs:526-558`. The scenario verifies layout 1 is applied live and key 7 is set to 1 on the volatile test overlay (`tools/xtask/src/main.rs:21624-21638`); settings record KATs accept 1 and reject 2 at `userland/settings-core/src/setup_keys_tests.rs:151-176`. The boot-load path above preserves the stored value across restart.

6. **FAIL — prior-art source metadata is incomplete.** The PR body's prior-art survey gives CLDR's license and last-commit date/SHA, and gives kbd's license and date/SHA. Its xkeyboard-config row gives the license and version `2.41`, but no last-commit date or commit SHA, so it does not meet the dispatch's source-date requirement. The PR body says the table was written by hand and no rows were copied; the implementation and independent KAT support that claim. No incompatible-license rows are identified as copied. **Concrete correction:** add the xkeyboard-config 2.41 source's last-commit date (and SHA so the checked revision is reproducible) to the survey row. The survey is in the PR description, not a repository file.
