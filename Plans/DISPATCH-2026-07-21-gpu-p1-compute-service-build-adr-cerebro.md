## The ratified direction you are writing the ADR for
Compute-first **survives**; the "2-4 pm Vello backdrop-blur" claim **does not**. The GPU-API lane splits into two independently-estimated projects. **This ADR is P1 ONLY. Vello is explicitly OUT of P1 (it is P2, a separate quarantined compiler-closure spike). Do NOT put Vello, WGSL, or Naga on the P1 critical path.**

- **P1 (this ADR):** a minimal, **manifest-only, cap-native Gen9 compute service**, proven first with **one project-authored linear-buffer glass blur kernel** hand-authored in OpenCL C and offline-compiled through the **already-proven `ocloc`/IGC path** (the Phase-6 toolchain: `OpenCL C → pinned ocloc → device binary + zeinfo → extracted EU ABI → in-kernel pinned blob`). No shader compiler is built. No WGSL. No wgpu.

Reference it as future; do not design it here.

## What the ADR must specify
1. **The exact glass effect + kernel (Chad's replacement gate 1 — effect closure).** Name the precise effect: a **separable Gaussian blur over an already-composited linear RGBA pixel buffer** (the G1 `SharedPixelBuffer` backdrop region), NOT a vector-raster winding backdrop. Specify: backdrop capture (which buffer, which damage/occlusion region), radius/edge rules, pixel format, the two-pass (horizontal/vertical) structure, and the workgroup shape. This is the one kernel P1 proves.
2. **The minimal cap-native compute ABI.** The smallest device/queue/buffer/fence surface that runs one pinned kernel: manifest-only (the kernel set is fixed/pinned, not user-supplied), submit gated by the existing **`GpuSubmitCap`** (OT-63 Slice-2, merged), completion via the present-fence/seqno path already in-tree. Define `GpuBufferCap`/`GpuQueueCap`/`GpuFenceCap` (or justify a smaller set). Kill-switch (Rule-1): **service-disabled ≡ no compute service, CPU raster floor only, bit-for-bit** — ship the regression proving it.
3. **The I-14(c) boundary — physical fence BEFORE any userland compute queue (Chad's gate 5 + the amendment).** Chad's load-bearing containment finding: **PPGTT isolates GPU *contexts* from each other but is NOT the boundary against the device reaching arbitrary host physical memory.** So the ADR MUST sequence the **graphics VT-d domain / fenced-physical-DMA arena** (ADR-045 fenced-DMA-arena, ADR-050 VT-d) to land **before** a userland compute queue is granted — a manifest-only *trusted kernel-service* bring-up stage may be an explicitly risk-accepted step, but calling I-14(c) *closed* requires the physical fence. State the governance fault-containment analysis (I-14 a/b/c) for the compute path, same as a connectivity dispatch.
4. **The silicon-shape gates (Chad's gate 4), scoped to P1's ONE kernel.** Phase-6 proved Add/Matmul/GELU (simple 1-D, pinned ABI, stateless). P1's blur kernel introduces new hardware shape — enumerate exactly what *this kernel* needs (workgroup size, any workgroup/shared-local memory, barriers, storage-image vs linear-buffer output) and which need a fresh silicon gate vs. which Phase-6 already covers. Keep the kernel deliberately simple to minimize new shape (a linear-buffer separable blur can avoid images/atomics — design it that way).
5. **The build ladder.** Ordered slices from here to glass blur on the iGPU: CPU raster/blur floor (the honest MVP fallback, lands first) → the compute ABI + service (kill-switch default off) → the one pinned blur kernel via ocloc → the silicon gate on real UHD 630 → wire into the G1 backdrop path. Each slice: kill-switch, gate, the bare-metal discriminator bank (reference `docs/runbook-baremetal-arthur-optiplex.md` for any bare-metal slice). Honest effort per slice; no single number that hides a compiler.
