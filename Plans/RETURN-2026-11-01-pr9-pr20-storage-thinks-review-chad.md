# Return: #9 and #20 storage THINK review (Chad)

Heads reviewed: #9 `200c4efbbb4b750539628e6c5f051443d336b216`; #20 `65209158e31cdc84cdbdf4c474ad64472a3ed82b`.

- **FAIL — FAT trap bank:** FAT12/16/32 cluster-count detection, LFN cases, chain loops, and huge `sectors_per_fat` have named KATs (`docs/THINK-2026-10-31-l3a-fat-readonly.md:63-72`). The dirty-bit case does not discriminate the two dirty indicators independently: it marks both and checks unchanged sectors, while the text says rust-fatfs reads only the BPB byte (`:66-67`). Add FAT[1]-only and BPB-byte-only dirty fixtures and assert the detection/log result. “Bad BPB values” is also too narrow: one huge FAT-size value, a type/shape mismatch, and exFAT are covered, but there are no explicit discriminators for zero/invalid sectors-per-cluster, impossible reserved/FAT counts, or inconsistent total-sector/FAT/data geometry (`:63,72,74`).
- **FAIL — FAT read-only and kill-switch:** The adapter has a compiled `Write` implementation that returns errors, so read-only is runtime enforced rather than “no write path compiled” (`docs/THINK-2026-10-31-l3a-fat-readonly.md:95-97`). More seriously, feature-off dispatch is contradictory: `fs_type == 3` returns `Invalid` at `:100-103`, but the next item and kill-switch proof say it uses the native driver at `:104-107,116-119`. Pick one behavior and gate that exact control. The MBR oracle itself is specified as a hand-laid 512-byte literal, independently asserted against the parser, with superfloppy and bad-entry cases (`:153-160`).
- **FAIL — USB device-quirk discriminators:** Capacity off-by-one has a last-LBA read failure log (`docs/THINK-2026-10-31-l3u-usb-mass-storage.md:55`), but there is no explicit boundary test that a >128-block read splits into 128 plus the remainder (`:57,70-71`). The named avoid list for MODE SENSE, SYNCHRONIZE CACHE, and PREVENT/ALLOW does not test the unknown-command stall behavior; add a scripted device that stalls on unsupported opcodes and assert the command allowlist (`:60,66-69`). Slow spin-up is missing: UNIT ATTENTION is retried, but NOT READY/`3A` is immediately treated as no medium and there is no bounded retry for a device that becomes ready after a delay (`:52`).
- **PASS — USB I-14 containment:** The plan puts BOT work in the caller thread, says the xHCI ISR takes no governance lock, bounds each BOT step, and places transfer buffers in fenced `DmaBuffer`s under existing IOMMU containment (`docs/THINK-2026-10-31-l3u-usb-mass-storage.md:75-79`).
- **PASS — USB kill-switch and Zenbook write rule:** Feature-off leaves the interface unbound and has a no-block-device scenario; the MSC block device rejects writes and is registered behind `GuardedDevice` (`docs/THINK-2026-10-31-l3u-usb-mass-storage.md:70-74`). The FAT adapter also rejects writes and its dirty-volume sector hash checks for mutation (`docs/THINK-2026-10-31-l3a-fat-readonly.md:67,118-127,135-137`). Together these keep writes away from the internal NVMe in this read-only lane.
