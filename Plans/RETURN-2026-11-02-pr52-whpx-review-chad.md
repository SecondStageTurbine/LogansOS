- PASS — 2, save/restore consumers and alignment for a common CPU policy. `kernel/src/arch/x86_64/fpu.rs:99`, `:130`, and `:273` allocate thread images in 64-byte blocks using the published size. Its save helper clears that same size (`:52`) and XSAVE/XRSTOR use the shared mask (`:58`, `:72`). All three switch helpers use those routines (`kernel/src/arch/x86_64/context.rs:122`, `:152`, `:184`), with pointers supplied by `kernel/src/sched/thread.rs:437`. Timer (`timer.rs:284`, `:299`), syscall (`syscall.rs:899`, `:924`), and shared device/IPI IRQ entry (`idt.rs:409`, `:425`) align down to 64, reserve the same size, and restore from the saved area. - FAIL — 2, AP/BSP agreement is assumed rather than enforced (inherited). BSP calls `enable_sse` at `kernel/src/main.rs:650`; every AP calls it again at `kernel/src/arch/x86_64/smp.rs:248`. Each call republishes global size/mask/mode (`fpu.rs:195`, `:266`) without comparing with the BSP policy, although earlier AP schedulers can already be running. Concrete input: a VM whose BSP reports XSAVE+AVX and XCR0 support 7, but whose first AP reports no AVX. The AP publishes global FXSAVE/512 while the BSP still has XCR0=7, so BSP AVX state is no longer preserved. A later XSAVE-capable AP can republish 832 after 512-byte thread images exist. This mismatch was assessed from code, not reproduced dynamically. Reject an incompatible AP before it changes the global policy, or establish one immutable policy supported by every admitted CPU. The homogeneous four-vCPU TCG run did show BSP and all three APs agreeing on 832/mask 7.

- FAIL — 3, the claim that every optional MSR is feature-gated is too broad (inherited). `kernel/src/arch/x86_64/syscall.rs:610` unconditionally writes IA32_SYSENTER_CS (0x174); no CPUID.1:EDX[11] SEP check or safe WRMSR surrounds it. Concrete input: a long-mode VM with SEP=0 that rejects writes to unimplemented SYSENTER MSRs. CPU trap initialization takes a kernel #GP instead of skipping an unavailable entry mechanism. This is a static counterexample, not a claimed TCG reproduction: TCG can accept MSR writes even when the corresponding CPUID bit is hidden. Gate this optional write on SEP. [Intel's instruction reference](https://www.intel.com/content/dam/www/public/us/en/documents/manuals/64-ia-32-architectures-software-developer-vol-2b-manual.pdf) enumerates SYSENTER through SEP.
